Индекс по `(tenant_id, status, created_at)` — это телефонный справочник: сначала по фамилии, внутри — по имени. Найти всех Ивановых легко, всех Петров — нет.

Правило, по которому выбирают порядок колонок:

1. **Сначала колонки с равенством** (`tenant_id = $1 AND status = 'new'`).
2. **Потом одна колонка с диапазоном или сортировкой** (`created_at > $2` или `ORDER BY created_at`).
3. После колонки с диапазоном остальные уже не сужают поиск — только фильтруют найденное.

Поэтому для `WHERE tenant_id = $1 AND created_at > $2 ORDER BY created_at` нужен `(tenant_id, created_at)`, а `(created_at, tenant_id)` заставит пройти все строки за период по всем арендаторам.

Составной индекс заменяет индекс по своему префиксу: при наличии `(a, b)` отдельный индекс по `(a)` обычно не нужен. А вот два отдельных индекса по `a` и по `b` — не то же самое, что `(a, b)`: PostgreSQL умеет склеить их через BitmapAnd, но это дороже одного спуска.

Селективность колонки при выборе порядка вторична. Первична форма запросов: какие колонки всегда стоят в условии через равенство.
