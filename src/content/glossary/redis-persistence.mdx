Redis держит данные в памяти, диск нужен только чтобы пережить перезапуск.

**RDB — снимок.** По правилу `save` (по умолчанию: раз в час при одном изменении, раз в 5 минут при ста, раз в минуту при десяти тысячах) Redis делает `fork`. Дочерний процесс пишет `dump.rdb`, родитель продолжает обслуживать клиентов. Память общая благодаря copy-on-write: копируются только страницы, которые родитель меняет во время снимка. При падении теряется всё, что записано после начала последнего снимка.

**AOF — журнал.** Каждая команда записи дописывается в файл. Когда вызывать `fsync`, решает `appendfsync`:

| значение | потеря при падении | цена |
| --- | --- | --- |
| `always` | ничего | каждая запись ждёт диска |
| `everysec` (по умолчанию) | до 1–2 секунд | почти бесплатно |
| `no` | сколько решит ОС, обычно до 30 секунд | бесплатно |

Журнал растёт, поэтому фоном (снова через `fork`) его переписывают: новое начало — снимок в формате RDB, дальше — команды после него.

Подводные камни:

- **fork на большой памяти не мгновенный** — копирование таблиц страниц у инстанса на десятки гигабайт занимает десятки–сотни миллисекунд, и всё это время Redis стоит;
- **copy-on-write может удвоить память** при активной записи — нужен запас, иначе придёт OOM killer; прозрачные огромные страницы (THP) делают это хуже, их отключают;
- **снимок ≠ бэкап**, если `dump.rdb` лежит на том же диске.
