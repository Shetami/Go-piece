```go
var g singleflight.Group

func (s *Service) User(ctx context.Context, id int64) (User, error) {
    key := fmt.Sprintf("user:%d", id)
    if v, err := s.rdb.Get(ctx, key).Bytes(); err == nil {
        return decode(v)
    }
    // Сколько бы горутин ни пришло сюда одновременно с одним key,
    // loadFromDB выполнится один раз, а результат получат все.
    v, err, _ := g.Do(key, func() (any, error) {
        u, err := s.db.User(ctx, id)
        if err == nil {
            s.rdb.Set(ctx, key, encode(u), ttl)
        }
        return u, err
    })
    …
}
```

Важные детали:

- Объединение работает **в пределах процесса**. Если реплик десять, база получит до десяти запросов, а не один. На большом масштабе к этому добавляют блокировку в самом кэше (`SET NX` на ключ обновления).
- **Ошибку получают все**, кто ждал. Для дорогих запросов это плюс (не будет повторной лавины), но ошибку стоит не кэшировать надолго.
- **Ожидание надо ограничивать**: если ведущий запрос завис, ждут все. Отменяемый вариант — `DoChan` вместе с `select` по `ctx.Done()`.
- Отменённый контекст ведущего запроса не отменяет работу для остальных — отсюда известная ловушка с `context.Canceled` у случайного клиента.

Тот же приём полезен не только с кэшем: им дедуплицируют одинаковые запросы к соседнему сервису и любые дорогие вычисления.
