`LIMIT 20 OFFSET 100000` заставляет базу найти и отбросить сто тысяч строк, чтобы вернуть двадцать. Чем дальше страница, тем дольше запрос. Вдобавок строки, вставленные между запросами, сдвигают выдачу — одни записи повторяются, другие пропадают.

Пагинация по ключу запоминает последнюю увиденную строку и продолжает после неё:

```sql
-- индекс: (created_at DESC, id DESC)
SELECT id, created_at, title
FROM posts
WHERE (created_at, id) < ($1, $2)   -- последняя строка прошлой страницы
ORDER BY created_at DESC, id DESC
LIMIT 20;
```

`id` в ключе нужен, чтобы порядок был однозначным при одинаковом `created_at`. Сравнение кортежей `(a, b) < (x, y)` PostgreSQL умеет выполнять по составному индексу — каждая страница стоит как первая.

Цена — нельзя перейти сразу на страницу 500. Для лент и API с курсором `next` это не нужно. Для административных таблиц с номерами страниц OFFSET терпим, пока страниц немного.
