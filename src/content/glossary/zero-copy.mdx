Обычная отдача файла по сети — четыре копирования и два переключения в ядро и обратно: диск → кэш ядра → буфер процесса → буфер сокета → сетевая карта.

Kafka хранит сообщения на диске в том же формате, в каком их отдаёт по сети, — пакетами, как их прислал продюсер. Поэтому брокеру не нужно ничего разбирать и собирать заново: он вызывает `sendfile` (в Java — `FileChannel.transferTo`), и ядро перекладывает данные из [страничного кэша](/glossary/page-cache/) в сокет само, минуя процесс.

Отсюда способность одного брокера раздавать сотни мегабайт в секунду десяткам групп потребителей почти без нагрузки на процессор.

Где zero-copy не работает:

- **TLS.** Шифровать приходится в процессе, данные идут через JVM. Шифрование трафика заметно увеличивает нагрузку на брокер.
- **Конвертация форматов** для старых клиентов, которые не понимают современный формат пакетов.

Поэтому же сжатие лучше делать на продюсере: брокер хранит и отдаёт сжатый пакет как есть, а распаковывает только потребитель.
