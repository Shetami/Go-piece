Пока [разметка](/glossary/tricolor/) идёт одновременно с программой, программа может переложить указатель так, что живой объект окажется невидимым: белый объект переезжает под уже просмотренный чёрный, а другая ссылка на него исчезает. Разметка к чёрному не вернётся — объект останется белым и будет освобождён.

Барьер записи ловит именно такие перестановки. С Go 1.8 он гибридный — из двух правил сразу:

```go
writePointer(slot, ptr):
    shade(*slot)                    // удаляемый объект  (Юаса)
    if стек этой горутины серый:
        shade(ptr)                  // записываемый объект (Дейкстра)
    *slot = ptr
```

Первая строка важнее: она закрашивает то, что **исчезает** из поля. Пока ссылка где-то была, сборщик обязан считать объект живым до конца цикла.

Две вещи, которые часто удивляют:

- **Записи в стек барьером не закрываются.** Спрятать объект на стеке можно, только прочитав указатель из кучи; когда его оттуда уберут, сработает первое правило. Плюс всё, что создано во время разметки, рождается чёрным.
- **Гибридный барьер убрал повторный просмотр стеков.** До Go 1.8 в конце цикла мир останавливали и пересматривали стеки заново — это была самая долгая пауза. Теперь просмотренный стек остаётся чёрным до конца цикла.

Платят за это несколькими инструкциями на каждую запись указателя — и только пока идёт разметка. Вне цикла барьер выключен.

На стенде барьер можно выключить и досмотреть цикл до конца: появится событие «освобождена живая память». В настоящем Go такой ручки нет ни во флагах, ни в GODEBUG.
