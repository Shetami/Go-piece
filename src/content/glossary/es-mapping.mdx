| Тип | Индексация | Для чего |
| --- | --- | --- |
| `text` | разбивается на токены | поиск по сообщениям и тексту ошибок |
| `keyword` | значение целиком | фильтры, агрегации, сортировка |
| `flattened` | весь объект — одно поле | произвольные ключи без роста маппинга |
| `date`, `long`, `float`, `ip` | как значение | диапазоны и агрегаты |

**Конфликт типов.** Первый документ с полем `user`-строкой фиксирует тип. Документ, где `user` — объект, получает `mapper_parsing_exception` и отвергается целиком — вместе со всем, ради чего лог писали. Агент отбрасывает его, и логи сервиса «пропадают».

**Взрыв полей.** Словарь с произвольными ключами (заголовки, параметры, ID в ключах) добавляет поле на каждый ключ. После `index.mapping.total_fields.limit` (1000) новые поля отвергаются, а до этого раздутый маппинг нагружает весь кластер.

Защита:

- явный шаблон индекса с типами общих полей;
- `"dynamic": false` — неизвестные поля хранятся в документе, но не индексируются и не отвергаются;
- `flattened` для произвольных атрибутов;
- общая схема полей между сервисами: Elastic Common Schema или семантические соглашения OpenTelemetry.
