У Go три кэша:

- **модулей** (`GOMODCACHE`, `~/go/pkg/mod`) — исходники зависимостей, годен, пока не изменился `go.sum`;
- **сборки** (`GOCACHE`, `~/.cache/go-build`) — скомпилированные пакеты. Ключ — хеш исходников, флагов, версии компилятора и влияющих переменных окружения. Изменился вход — это другой ключ;
- **результатов тестов** — там же. Если тестовый бинарник и входы не изменились, `go test ./...` печатает `(cached)` и не запускает тест.

Входы теста — это код, флаги, прочитанные через `os.Getenv` переменные и открытые файлы внутри модуля. Состояние базы в соседнем контейнере или ответ внешнего API входом не являются. Поэтому тесты, которые ходят наружу, запускают с `-count=1`.

Кэш результатов работает только в режиме списка пакетов (`go test ./...`), а не для `go test` без аргументов.

В CI оба каталога сохраняет `actions/setup-go` с ключом по `go.sum`. Кэш с таким ключом не обновляется, пока `go.sum` не изменится, и кэш сборки со временем отстаёт от кода.
