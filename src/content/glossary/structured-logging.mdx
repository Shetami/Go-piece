```go
logger.ErrorContext(ctx, "payment failed",
    "order_id", order.ID,
    "provider", provider,
    "err", err,
)
// {"time":"…","level":"ERROR","msg":"payment failed","order_id":"123","provider":"stripe",
//  "err":"timeout","trace_id":"4bf9…","service":"orders"}
```

Правила, которые окупаются:

- **сообщение постоянное**, переменное — в полях. `msg` — это тип события, по нему группируют;
- **варианты `…Context`** — чтобы обработчик мог достать `trace_id` из контекста;
- **ошибку логируют один раз** — там, где её обрабатывают. «Залогировать и вернуть» на каждом слое умножает строки на глубину стека;
- **успешные запросы не логируют** — для них есть метрики;
- **одинаковые ошибки — с выборкой**, иначе авария кладёт систему доставки логов;
- **секреты и персональные данные — никогда**: тип с методом `LogValue()` скрывает значение в любом логе;
- **уровень меняется на лету** через `slog.LevelVar` — `DEBUG` включают на время разбора.

Имена полей стоит договорить между сервисами: одно поле с разными типами в общем индексе Elasticsearch — это [отвергнутые документы](/glossary/es-mapping/).
