Лимит памяти — это `memory.max` в cgroup. Превысил — ядро выбирает процесс и убивает. Приложение ничего не узнает: ни паники, ни сообщения в логе. Видно только в `kubectl describe pod`: `Last State: Terminated, Reason: OOMKilled, Exit Code: 137`.

Считается не только куча Go: стеки горутин, память рантайма, страницы файлового кэша, которые процесс успел «испачкать», tmpfs-тома (`emptyDir` с `medium: Memory`).

Для Go главная причина — сборщик мусора не знает о лимите. По умолчанию (GOGC=100) куча может вырасти вдвое по сравнению с живыми данными: 300 МБ живых — до 600 МБ кучи. При лимите 512 Mi это смерть. Лекарство — [GOMEMLIMIT](/glossary/gomemlimit/) чуть ниже лимита контейнера: тогда сборщик начнёт работать чаще, приближаясь к нему.

Отличайте от [вытеснения](/glossary/k8s-eviction/): OOMKilled — ядро убило контейнер за превышение своего лимита; вытеснение — kubelet выселяет под, потому что памяти не хватает всему узлу.
