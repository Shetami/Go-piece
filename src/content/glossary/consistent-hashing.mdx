При раскладке «хеш по модулю числа узлов» добавление узла меняет владельца почти у всех ключей: было `% 3`, стало `% 4`. Для кэша это разовая потеря всего содержимого, для базы — перенос всех данных.

Согласованное хеширование решает это так: хеш отображается на окружность, узлы тоже получают на ней позиции, а ключ принадлежит первому узлу по часовой стрелке. Новый узел вклинивается в одно место кольца и забирает только те ключи, что лежат перед ним, — в среднем 1/n всех ключей.

**Виртуальные узлы** нужны, чтобы раскладка была ровной. Если у каждого узла одна позиция, их интервалы получаются очень разными по длине, и один узел может получить вдвое больше данных. Поэтому каждому узлу дают десятки или сотни позиций: интервалы усредняются, а при удалении узла его ключи расходятся по всем остальным, а не сваливаются на одного соседа. Виртуальные узлы удобны и для разных по мощности машин: сильной дают больше позиций.

Так устроены раскладка ключей в Cassandra и Dynamo, распределение ключей в кластерах memcached, балансировка по хешу в Envoy (`ring_hash`, `maglev`). Родственный приём — **rendezvous hashing**: для ключа считается хеш с каждым узлом и выбирается максимальный; свойства похожи, а кольцо хранить не нужно.

Важно помнить, чего согласованное хеширование не делает: оно не спасает от [горячего ключа](/glossary/hot-partition/). Один ключ — один узел, сколько виртуальных позиций ни заводи.
