Новая колонка появилась, новый код пишет в неё новые строки. Остаются миллионы старых — их заполняет бэкфилл.

Один `UPDATE` на всю таблицу — это одна огромная транзакция: часы блокировок строк, гигабайты WAL, отставание реплик и удвоение размера таблицы из-за новых версий строк. Поэтому бэкфилл делают так:

- **пачками по ключу** — `WHERE id > $last AND id <= $last + 5000`, каждая пачка — своя короткая транзакция;
- **с паузой**, подобранной по [отставанию реплик](/glossary/replication-lag/) и нагрузке базы;
- **идемпотентно** — повторный прогон пачки даёт тот же результат, поэтому процесс можно прервать и продолжить;
- **с сохранением прогресса** — последний обработанный `id` в отдельной таблице, а не в памяти процесса;
- **не затирая свежие данные** — `WHERE new_col IS NULL`: строки, которые уже записал новый код, трогать нельзя.

Бэкфилл — отдельная работа, а не часть миграции схемы. Миграция, которая час заполняет данные, блокирует выкатку и отменяется вместе с ней.
