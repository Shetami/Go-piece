Задержку описывают не одним числом, а несколькими точками распределения:

- **p50** (медиана) — половина запросов быстрее, половина медленнее. Так работает сервис «обычно».
- **p99** — медленнее только один запрос из ста. Так работает сервис для невезучих.
- **p99.9, max** — редкие выбросы: паузы сборщика мусора, холодный кэш, переподключения.

Среднее для задержки почти бесполезно. Если 99 запросов отвечают за 10 мс, а один за 2 секунды, среднее будет 30 мс — такой задержки не видел ни один пользователь.

Две ловушки при подсчёте:

- **Перцентили нельзя усреднять.** Среднее p99 по десяти серверам — это не p99 всего сервиса. Складывать можно только гистограммы: так делают Prometheus (`histogram_quantile`) и HdrHistogram.
- **Ошибки и таймауты — тоже задержка.** Если считать только успешные ответы, сервис при перегрузке будет выглядеть быстрее: самые долгие запросы кончаются таймаутом и выпадают из статистики.

Цели по задержке (SLO) формулируют через перцентили: «p99 меньше 300 мс в 99,9% пятиминуток».
