Два направления:

- **Обратная совместимость** — новый код читает старые данные. Нужна всегда: в топике лежат сообщения, записанные до выкатки, а в базе — строки прошлого года.
- **Прямая совместимость** — старый код читает новые данные. Нужна во время выкатки и при откате, а также пока не обновились все потребители.

Что обычно безопасно, а что — нет:

| Изменение | Безопасно? |
| --- | --- |
| добавить необязательное поле | да, если читатели игнорируют незнакомые поля |
| добавить обязательное поле | нет: старые писатели его не присылают |
| удалить поле | только когда его перестали читать все |
| переименовать поле | нет — это удаление плюс добавление |
| сменить тип поля | нет |
| добавить значение в enum | опасно: старый код с `switch` без `default` не знает, что делать |

В protobuf поле определяется номером, а не именем. Номер удалённого поля нельзя использовать снова — его помечают `reserved`, иначе старые сообщения прочитаются как новые с чужим смыслом. `encoding/json` в Go по умолчанию игнорирует незнакомые поля — это делает его терпимым к добавлению. `DisallowUnknownFields` ломает прямую совместимость.

Для событий в Kafka совместимость проверяют автоматически: реестр схем (Schema Registry) отклоняет регистрацию схемы, несовместимой с предыдущими, — ещё до того, как продюсер отправит первое сообщение.
