Процессор и компилятор свободно переставляют операции с памятью. Модель памяти Go говорит, в каких случаях одна горутина обязана увидеть то, что записала другая, и канал — главный такой случай.

Правила, которые стоит знать наизусть:

- **Отправка в канал происходит раньше завершения приёма** этого значения. Всё, что отправитель записал до `ch <- v`, получатель увидит после `<-ch`.
- **Приём из небуферизованного канала происходит раньше завершения отправки.** Поэтому небуферизованный канал синхронизирует обе стороны, а не одну.
- **Закрытие происходит раньше приёма нулевого значения** из закрытого канала. Значит, `close(done)` — корректный способ опубликовать результат, записанный до закрытия.

Практический вывод: если данные передаются через канал, никаких дополнительных мьютексов и `atomic` не нужно.

```go
data = compute()   // обычная запись, без синхронизации
ch <- struct{}{}   // ...становится видимой получателю

<-ch
use(data)          // корректно: запись data произошла раньше
```

Именно это имеет в виду девиз «Don't communicate by sharing memory; share memory by communicating». Канал — не просто очередь, а точка синхронизации: [передача из рук в руки](/glossary/chan-handoff/) переносит между горутинами не только значение, но и всю память, записанную до неё.
