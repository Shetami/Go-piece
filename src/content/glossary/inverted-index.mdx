При записи анализатор разбивает текст на токены (по пробелам и знакам препинания, в нижний регистр) и для каждого токена дописывает документ в его список:

```
1: "connection refused by upstream"
2: "upstream timeout"

connection → [1]    refused → [1]    upstream → [1, 2]    timeout → [2]
```

`upstream AND timeout` — пересечение `[1, 2]` и `[2]`. Скорость не зависит от длины текстов.

Следствия:

- **`refus` не найдёт `refused`** — такого токена нет. Запрос `*timeout` перебирает весь словарь токенов;
- **результат зависит от анализатора**: `OrderService.Charge` может оказаться одним токеном или двумя;
- **поля `keyword` не разбиваются** — индексируется значение целиком, для точных фильтров;
- **для агрегаций и сортировки** используется другая структура — doc values, колоночное хранение значений.

Та же идея лежит в основе [GIN-индексов](/glossary/gin-index/) PostgreSQL для полнотекстового поиска и массивов.
