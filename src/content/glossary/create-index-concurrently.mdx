Обычный `CREATE INDEX` берёт блокировку, которая запрещает INSERT, UPDATE и DELETE, на всё время построения. На таблице в десятки гигабайт это минуты простоя записи.

`CREATE INDEX CONCURRENTLY` строит индекс в несколько проходов, не блокируя запись:

1. создаёт пустой «невалидный» индекс, который уже обновляют новые изменения;
2. строит его по снимку таблицы;
3. второй проход добирает то, что изменилось за время первого;
4. ждёт, пока закончатся все транзакции, которые могли не видеть индекс, — и помечает его валидным.

Подводные камни:

- **Ждёт старые транзакции.** Одна [забытая транзакция](/glossary/idle-in-transaction/) — и построение висит.
- **Нельзя в транзакции.** Инструменты миграций, которые оборачивают всё в `BEGIN`, для этого нужно настроить отдельно.
- **При ошибке остаётся невалидный индекс** (например, нарушение уникальности). Он замедляет запись, но не используется запросами. Найти: `SELECT indexrelid::regclass FROM pg_index WHERE NOT indisvalid`, удалить и построить заново.

Раздувшийся индекс пересобирают так же без простоя — `REINDEX INDEX CONCURRENTLY`.
