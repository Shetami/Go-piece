Название пришло из судостроения: корпус делят перегородками, чтобы пробоина в одном отсеке не затопила корабль. В сервисе отсеки — это пулы воркеров, горутин или соединений.

Что обычно изолируют:

- **вызовы разных зависимостей**: медленный сервис рекомендаций не должен занимать воркеры, нужные для оплаты;
- **виды запросов**: тяжёлые отчёты отдельно от коротких чтений (это же лечит [блокировку очереди головой](/glossary/head-of-line-blocking/));
- **классы клиентов**: фоновые задачи не должны вытеснять живых пользователей.

Простейшая реализация в Go — семафор на канале вокруг вызова:

```go
// Ждать рекомендации могут не больше 8 горутин одновременно;
// остальные сразу получают ответ без них.
var recSem = make(chan struct{}, 8)

func recommendations(ctx context.Context, userID int64) ([]Item, error) {
    select {
    case recSem <- struct{}{}:
        defer func() { <-recSem }()
        return client.Recommend(ctx, userID)
    default:
        return nil, errBusy // вызывающий покажет страницу без рекомендаций
    }
}
```

Размер отсека считают по [закону Литтла](/glossary/littles-law/): поток × нормальное время ответа плюс запас. Слишком маленький отсек начнёт отказывать в обычной жизни, слишком большой не защитит.
