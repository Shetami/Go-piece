```json
{
  "policy": {
    "phases": {
      "hot":    { "actions": { "rollover": { "max_primary_shard_size": "50gb", "max_age": "1d" } } },
      "warm":   { "min_age": "3d",  "actions": { "forcemerge": { "max_num_segments": 1 } } },
      "delete": { "min_age": "30d", "actions": { "delete": {} } }
    }
  }
}
```

| Фаза | Что происходит |
| --- | --- |
| **hot** | текущий индекс на быстрых дисках, сюда идёт запись; rollover начинает новый |
| **warm** | только чтение, дешевле узлы, слияние сегментов |
| **cold / frozen** | редкие запросы, данные могут жить в объектном хранилище |
| **delete** | удаление индекса целиком |

Удалить индекс целиком — мгновенно, а удаление документов по запросу — это пометки и слияния. Поэтому срок хранения логов реализуют только через жизненный цикл индексов.

`min_age` фаз отсчитывается от rollover, а не от создания индекса. Разные сроки для разных данных (ошибки — 90 дней, отладка — 3) делают разными потоками с разными политиками. В OpenSearch тот же механизм называется ISM.
