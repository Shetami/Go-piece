Сама команда Redis исполняется за микросекунды, а круг по сети до него — сотни микросекунд. Тысяча `GET` по очереди — это тысяча кругов, то есть сотни миллисекунд ожидания сети.

Конвейер отправляет все команды сразу и потом читает все ответы:

```go
cmds, err := rdb.Pipelined(ctx, func(pipe redis.Pipeliner) error {
    for _, id := range ids {
        pipe.Get(ctx, "user:"+id)
    }
    return nil
})
```

Что важно:

- **атомарности нет.** Между командами пачки могут выполниться команды других клиентов. Если нужно «всё или ничего без вмешательства» — `MULTI`/`EXEC` (в go-redis — `TxPipelined`) или Lua-скрипт;
- **ошибки — по командам.** Одна упавшая команда не отменяет остальные, смотреть нужно результат каждой;
- **огромная пачка держит память** на обеих сторонах — десятки тысяч команд лучше резать на куски по несколько сотен–тысяч;
- для однотипного чтения есть `MGET`/`MSET`, но в кластере они работают только внутри одного [слота](/glossary/redis-hash-slot/). ClusterClient в go-redis умеет раскладывать конвейер по узлам сам.
