Единицы: CPU в ядрах, `500m` — половина ядра; память в байтах, `256Mi` — 256 мебибайт (не путать с `256M` — мегабайтами).

**Requests** работают на двух уровнях. Планировщик ставит под только туда, где сумма requests уже размещённых подов плюс новый не превышает ёмкость узла. А ядро при конкуренции делит CPU пропорционально requests (веса cgroups): под с requests 1 CPU получит вдвое больше процессора, чем под с 500m.

**Limits** — жёсткие потолки в cgroups:

- CPU: квота процессорного времени на каждые 100 мс. Выбрал квоту — [троттлинг](/glossary/cpu-throttling/) до конца периода;
- память: превышение — [OOMKilled](/glossary/oom-killed/), мгновенно и без предупреждения.

Типовой рецепт для сервиса: requests по памяти равны limits (память несжимаема, и лучше знать потолок заранее); requests по CPU — по реальному среднему потреблению; limit по CPU — с большим запасом или без него, особенно для сервисов, чувствительных к задержке.

Requests, заданные наугад, — самая частая причина и пустых узлов («всё заказано, ничего не используется»), и перегруженных.
