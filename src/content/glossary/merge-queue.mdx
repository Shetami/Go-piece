Проблема: PR A переименовывает функцию, PR B добавляет её вызов. Оба зелёные, git-конфликта нет, после слияния обоих `main` не компилируется. Каждый проверяли против `main` без другого.

Решения:

- **требовать актуальную ветку** перед слиянием — надёжно, но при частых слияниях все стоят в очереди на перепрогон;
- **очередь слияния** — система сама собирает ветку из `main` и PR, стоящих впереди, и проверяет её. Прошла — слияние. Не прошла — PR выкидывается, остальные перепроверяются без него.

Очереди проверяют несколько PR параллельно, спекулятивно предполагая, что предыдущие пройдут. Поэтому [нестабильные тесты](/glossary/flaky-test/) в очереди особенно дороги: одно ложное падение выкидывает PR и перезапускает всех за ним.

В GitHub в workflow нужно добавить событие `merge_group`, иначе проверки в очереди не запустятся.
