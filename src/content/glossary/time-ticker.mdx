short: 'time.Timer срабатывает один раз, time.Ticker — периодически. С Go 1.23 неостановленные таймеры собирает сборщик мусора, а Stop и Reset гарантируют, что старое значение не придёт.'
aliases: [time.Ticker, time.Timer, time.After, time.NewTicker, time.AfterFunc]

---

```go
t := time.NewTicker(10 * time.Second)
defer t.Stop()
for {
    select {
    case <-t.C:
        flush()
    case <-ctx.Done():
        return
    }
}
```

Что изменилось в Go 1.23 и почему это важно для старых советов:

- Раньше `time.After` в цикле `select` держал в памяти каждый созданный таймер до его срабатывания — отсюда совет «не пишите `time.After` в горячем цикле». Теперь неиспользуемый таймер собирается сразу, даже без `Stop`.
- Раньше после `Stop` или `Reset` из канала таймера могло прийти устаревшее значение, и его вычитывали идиомой `if !t.Stop() { <-t.C }`. Теперь канал фактически небуферизованный, и эта идиома не нужна (а в новом коде может заблокироваться).

Поведение зависит от версии Go в `go.mod`, а не от версии компилятора.

Тикер **не копит пропущенные тики**: если обработчик занял больше периода, лишние тики выбрасываются, в канале лежит максимум один.
