Кластер не хэширует ключи прямо на узлы. Между ними — фиксированный слой из 16384 слотов:

1. клиент считает `CRC16(ключ) mod 16384` — например, `CLUSTER KEYSLOT user:42` = 15880;
2. по своей таблице «слот → узел» идёт прямо на нужный ведущий;
3. если таблица устарела, узел отвечает `-MOVED 15880 host:port`, клиент обновляет таблицу и повторяет запрос.

При [решардировании](/glossary/resharding/) переезжают целые слоты. Пока слот в пути, узел может ответить `-ASK`: «за этим ключом сходи туда один раз, но таблицу не меняй».

Команды над несколькими ключами (`MGET`, `SUNION`, `MULTI`, Lua-скрипты) работают только если все ключи в одном слоте, иначе — ошибка `CROSSSLOT`. Для этого есть **хэш-теги**: если в ключе есть `{…}`, слот считается только по части в скобках. `{user:42}:cart` и `{user:42}:profile` гарантированно лежат вместе.

Обратная сторона хэш-тегов — перекос: слишком общий тег вроде `{tenant:big}` соберёт всю нагрузку клиента на одном узле. А один горячий ключ кластер вообще не разделит — это задача приложения: локальный кэш, копии ключа с суффиксом, разбиение значения.
