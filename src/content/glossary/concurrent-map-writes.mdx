Карта Go не потокобезопасна: читать из многих горутин можно, но если хоть одна пишет, все обращения нужно синхронизировать.

Рантайм пытается поймать нарушение. Запись переключает в карте флаг `writing`, а каждая операция его проверяет. Заметив чужую запись, рантайм вызывает `fatal`:

```text
fatal error: concurrent map writes
fatal error: concurrent map read and map write
```

Это не `panic`: `recover` не сработает, отложенные вызовы не выполнятся, процесс завершится со стеками всех горутин. Одновременная запись могла повредить внутренние структуры таблицы, и продолжать работу с ней опаснее, чем упасть.

Проверка эвристическая: гонка, которая не совпала по времени точно, пройдёт незамеченной. Надёжно находит такие ошибки только детектор гонок — `go test -race`, см. [гонка данных](/glossary/data-race/).

Чем защищать:

- **[`sync.Mutex`](/glossary/mutex/) + карта** — по умолчанию;
- **[`sync.RWMutex`](/glossary/rwmutex/)** — когда чтений намного больше, а секции не крошечные;
- **шарды** — N пар «мьютекс + карта», шард выбирается по хэшу ключа; под горячей записью делит конкуренцию на N;
- **`sync.Map`** — для ключей, которые пишутся один раз и потом только читаются, или для непересекающихся ключей у разных горутин. Не типизирована и не универсально быстрее.
