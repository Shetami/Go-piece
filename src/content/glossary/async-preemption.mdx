До Go 1.14 горутина уступала процессор только в определённых местах: при вызове функции, аллокации, операции с каналом. Цикл вроде

```go
for i := 0; ; i++ { sum += i }
```

не содержит ни одного такого места и занимал P навсегда. При `GOMAXPROCS=1` это вешало программу целиком. Ждал даже сборщик мусора, которому нужно остановить все горутины.

Асинхронное вытеснение решило это: [sysmon](/glossary/sysmon/) посылает потоку сигнал `SIGURG`, обработчик проверяет, что горутина в [безопасной точке](/glossary/safe-point/), и подменяет ей адрес возврата на функцию `asyncPreempt`, которая отдаёт управление планировщику.

Выключается через `GODEBUG=asyncpreemptoff=1`. Ровно это делает переключатель на стенде в сценарии «Жадный цикл».
