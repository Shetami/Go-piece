Правило простое: прежде чем читать строку — возьми разделяемую (S) блокировку, прежде чем писать — исключительную (X). S совместима с S, X ни с чем. Отпускать блокировки можно только в конце транзакции — отсюда «две фазы»: сначала только берём, потом только отпускаем.

Это даёт настоящую сериализуемость, но дорого:

- **Читатель ждёт писателя, писатель — читателя.** Длинный отчёт блокирует изменение всех прочитанных строк до своего конца.
- **Дедлоки — обычное дело**: две транзакции читают одну строку (обе держат S) и обе хотят её изменить (обе ждут X).
- **Фантомы требуют блокировать диапазоны**, а не строки.

Так работали SQL Server по умолчанию, DB2, ранние версии многих баз. Современные чаще используют [MVCC](/glossary/mvcc/): читатели работают со снимком и не берут блокировок вовсе, а исключительные блокировки остаются только между писателями. В PostgreSQL блокировки на запись — это [блокировки строк](/glossary/row-lock/), а чтение не блокирует ничего.
