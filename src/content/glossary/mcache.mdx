У каждого [P](/glossary/p-processor/) свой mcache. В нём лежит по одному спану на каждый [класс размеров](/glossary/size-class/) плюс блок для [мелочи](/glossary/tiny-allocator/).

Быстрый путь аллокации целиком состоит из работы с ним:

1. по размеру найти класс;
2. взять текущий спан этого класса;
3. найти свободный слот по битовой карте `allocCache`;
4. обнулить память и вернуть указатель.

Ни одной блокировки: mcache принадлежит процессору, а исполнять Go-код без P нельзя — значит, никто другой сюда не заглянет. Это и есть ответ на вопрос «почему в Go аллокация дешёвая».

Когда спан в кэше кончается, начинается медленный путь — [пополнение](/glossary/mcentral/) из общего списка под блокировкой. Чем реже это происходит, тем лучше: на стенде видно, как с ростом GOMAXPROCS растёт и число встреч у этой блокировки.
