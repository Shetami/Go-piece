aliases: [partial index, CREATE INDEX … WHERE, условный индекс, частичный уникальный индекс]

Из миллиона заказов в статусе `pending` — сотня, а запрос «взять следующий необработанный» выполняется постоянно. Индекс по `status` огромен и почти бесполезен: 99,99% его записей о тех заказах, которые никто так не ищет. Частичный индекс хранит только нужные:

```sql
CREATE INDEX orders_pending_idx ON orders (created_at) WHERE status = 'pending';
```

Он в тысячи раз меньше, всегда в кэше, и обновления заказов в других статусах его вообще не трогают.

Планировщик воспользуется им, только если может доказать, что условие запроса влечёт условие индекса. `WHERE status = 'pending'` — да. `WHERE status = $1` с параметром — только если план строится под конкретное значение.

Частичный уникальный индекс — способ выразить правило, которое `UNIQUE` не умеет:

```sql
-- один активный email на пользователя, удалённые не мешают
CREATE UNIQUE INDEX ON users (email) WHERE deleted_at IS NULL;
```
