```go
type slice struct {
    array unsafe.Pointer // первый видимый элемент
    len   int
    cap   int            // сколько элементов до конца массива
}
```

Переменная типа `[]T` занимает 24 байта на 64-битной платформе, сколько бы элементов в ней ни было. Элементы лежат в отдельном массиве — обычно в куче.

Из этого следует почти всё поведение слайсов:

- **присваивание и передача в функцию копируют заголовок.** Функция может изменить элементы, и вызывающий это увидит, но длину его слайса изменить не может — она в его собственной копии заголовка;
- **срез `s[i:j]` не копирует данные.** `array` сдвигается на `i`, `len = j - i`, `cap = cap(s) - i`. Трёхиндексный `s[i:j:k]` задаёт ещё и `cap = k - i`;
- **пока жив заголовок, жив весь массив** — даже если видно из него два элемента. Это частая причина [удержания памяти](/glossary/memory-retention/).

Строка устроена так же, но без `cap`: указатель и длина.
