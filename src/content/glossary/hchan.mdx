`make(chan T, n)` выделяет в куче одну структуру:

```go
type hchan struct {
    qcount   uint           // сколько значений лежит в буфере
    dataqsiz uint           // вместимость буфера (0 у небуферизованного)
    buf      unsafe.Pointer // кольцевой буфер: dataqsiz ячеек по размеру элемента
    elemsize uint16
    closed   uint32
    sendx    uint           // куда писать следующее значение
    recvx    uint           // откуда читать
    recvq    waitq          // горутины, ждущие приёма
    sendq    waitq          // горутины, ждущие отправки
    lock     mutex
}
```

Отсюда видно всё устройство каналов сразу:

- **Буфер — это кольцо**, а не список: `sendx` и `recvx` бегут по кругу, ничего не перевыделяется. Буферизованный канал занимает память под все `n` ячеек сразу, в момент `make`.
- **Очередей две.** Одновременно непустой может быть только одна: если кто-то ждёт приёма, значит, класть значение некому, и наоборот.
- **Есть мьютекс.** Канал — не lock-free структура. Каждая операция берёт `c.lock`, поэтому один канал на сотню горутин под нагрузкой становится точкой сериализации.

Сама переменная типа `chan T` — это указатель на `hchan`. Поэтому канал можно свободно передавать в функции и копировать: копируется указатель, а канал остаётся один. И поэтому же необъявленный через `make` канал — это [nil-указатель](/glossary/nil-channel/).
