Горутина не может лежать в очереди канала сама: одна и та же горутина умеет ждать несколько каналов сразу (это [select](/glossary/select/)), да и очередей у неё может быть несколько. Поэтому в `sendq` и `recvq` лежат не горутины, а `sudog` — «горутина в контексте ожидания»:

```go
type sudog struct {
    g       *g
    next    *sudog
    prev    *sudog
    elem    unsafe.Pointer // адрес значения — прямо в стеке горутины
    c       *hchan
    isSelect bool
    ...
}
```

Главное поле — `elem`. У ждущего отправителя это адрес значения **в его собственном стеке**: получатель копирует оттуда напрямую, и промежуточной памяти не нужно. У ждущего получателя — адрес переменной, куда положить результат.

Именно поэтому [передача из рук в руки](/glossary/chan-handoff/) обходится одним `memmove`. И поэтому же рантайм обязан поправить `elem`, если стек горутины [переедет](/glossary/stack-growth/).

`sudog` берутся из пула на каждом P (`acquireSudog`/`releaseSudog`), так что парковка не делает аллокаций в обычном случае.
