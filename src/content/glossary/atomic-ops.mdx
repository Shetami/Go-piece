С Go 1.19 удобнее всего типизированные обёртки:

```go
var requests atomic.Int64
requests.Add(1)

var cfg atomic.Pointer[Config]
cfg.Store(loadConfig())       // писатель подменяет снимок целиком
c := cfg.Load()               // читатели без блокировок
```

Атомарные операции в Go последовательно согласованы: всё, что записано до `Store`, видно после `Load`, вернувшего это значение.

Границы применимости:

- **Одна переменная — один атомик.** Два атомарных поля не образуют атомарной пары: между `a.Store` и `b.Store` кто-то прочитает новое `a` и старое `b`. Для инвариантов из нескольких полей — [мьютекс](/glossary/mutex/) или подмена целого снимка через `atomic.Pointer`.
- **Прочитал-решил-записал — это CAS-цикл**, а не `Load` + `Store`:

```go
for {
    old := max.Load()
    if v <= old || max.CompareAndSwap(old, v) {
        break
    }
}
```

- **Горячий атомарный счётчик на много ядер** — узкое место: строка кэша ходит между ядрами. Шардированный счётчик (по счётчику на P или на горутину, сумма при чтении) масштабируется лучше.
