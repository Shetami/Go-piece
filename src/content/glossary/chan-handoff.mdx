Первое, что делает `chansend`, — смотрит в очередь получателей. Если там кто-то есть, значение **не кладётся в буфер**: рантайм копирует его прямо в память ждущей горутины и будит её.

```go
if sg := c.recvq.dequeue(); sg != nil {
    send(c, sg, ep, func() { unlock(&c.lock) }, 3)
    return true
}
```

То же самое в обратную сторону: `chanrecv` сначала проверяет очередь отправителей.

Почему это важно:

- **Для небуферизованного канала другого пути нет.** Хранить значение негде — канал только сводит две горутины.
- **Для буферизованного это экономия копирования.** Если получатель уже ждёт, буфер пуст; положить туда значение и тут же забрать означало бы скопировать его дважды.
- **Работу делает тот, кто пришёл вторым.** Он и копирует, и будит первого. Разбудить спящего, чтобы тот сам дочитал, стоило бы двух переключений вместо одного.

Разбуженная горутина попадает в [runnext](/glossary/runnext/) того же P: только что скопированное значение ещё лежит в кэше этого ядра.
