Обычный UPDATE в PostgreSQL создаёт новую версию строки по новому адресу — а значит, во **все** индексы таблицы нужно добавить запись, указывающую на неё. Даже если меняли одну неиндексированную колонку. Пять индексов — пять лишних вставок на каждое обновление.

HOT избегает этого при двух условиях:

1. ни одна индексированная колонка не изменилась;
2. в той же странице есть место для новой версии.

Тогда новая версия кладётся рядом, старая получает пометку «продолжение — здесь же», а индексы продолжают указывать на старый адрес. Поиск по индексу приходит к старой версии и идёт по цепочке внутри страницы. Мёртвые версии в такой цепочке может убрать даже обычное чтение страницы, не дожидаясь VACUUM.

Как помочь HOT:

- **Не индексировать лишнего.** Индекс на часто меняющуюся колонку (`updated_at`, счётчик) выключает HOT для всех обновлений этой колонки.
- **Оставлять место в страницах**: `ALTER TABLE … SET (fillfactor = 80)` — страница заполняется на 80%, остальное ждёт новых версий.

Долю HOT видно в `pg_stat_user_tables`: `n_tup_hot_upd / n_tup_upd`.
