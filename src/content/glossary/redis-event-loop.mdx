Соединений у Redis могут быть тысячи, но данные трогает один поток. Он спрашивает у ядра (`epoll`), какие сокеты готовы, читает из них команды и исполняет их по очереди. Блокировок на данных нет — они не нужны.

Отсюда два следствия:

- **Каждая команда атомарна.** `INCR`, `SET NX`, `LPUSH`, `ZADD` никто не прервёт посередине.
- **Медленная команда останавливает всех.** `KEYS *` по миллиону ключей, `SMEMBERS` множества на сто тысяч элементов, `DEL` огромного хэша, долгий Lua-скрипт — всё это время остальные клиенты ждут.

Что с этим делать:

- вместо `KEYS` — `SCAN` с курсором, вместо `HGETALL`/`SMEMBERS` на больших ключах — `HSCAN`/`SSCAN`;
- большие ключи удалять через `UNLINK`: память освобождается в фоновом потоке;
- искать виновников через `SLOWLOG GET` и `redis-cli --bigkeys`, а `KEYS` и `FLUSHALL` в проде переименовать или запретить через ACL.

С версии 6.0 есть `io-threads`: дополнительные потоки читают и пишут сокеты. Исполнение команд по-прежнему однопоточное, поэтому ни атомарность, ни проблему медленных команд они не меняют.
