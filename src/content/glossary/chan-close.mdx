`close(ch)` ставит флаг и проходит по обеим очередям ожидания, будя всех. Значение получает один, а закрытие видят все — другого способа сообщить сразу всем горутинам в Go нет.

Что происходит дальше:

| Операция | На закрытом канале |
| --- | --- |
| приём, в буфере что-то есть | вернёт настоящее значение |
| приём, буфер пуст | сразу вернёт нулевое значение, `ok == false` |
| отправка | **паника** `send on closed channel` |
| повторное закрытие | **паника** `close of closed channel` |
| закрытие nil-канала | **паника** `close of nil channel` |

Отсюда два правила, которые стоит помнить дословно.

**Закрывает отправитель, и только один.** Получатель закрывать не должен: он не знает, не осталось ли других отправителей. Если получателю нужно сказать «хватит», для этого заводят второй канал, а не закрывают первый.

**Проверить заранее нельзя.** Между `if !closed` и самим `close` другая горутина успеет закрыть канал первой. Если закрытие может прийти из нескольких мест, его заворачивают в `sync.Once` или отдают одной горутине-координатору.

Закрывать канал не обязательно: его заберёт сборщик, как любой объект. Закрытие — это сообщение, а не освобождение ресурса. Частый приём — канал, который никогда ничего не передаёт: `done := make(chan struct{})`, а потом `close(done)` как сигнал «всем стоп».

Проверить закрытие можно вторым результатом — `v, ok := <-ch` — или циклом `for v := range ch`, который просто закончится. А вот `for { <-ch }` без проверки на закрытом канале превращается в бесконечный цикл на полной скорости процессора.
