У каждой реплики есть **LEO** (log end offset) — оффсет, который получит следующая запись. У лидера есть ещё **HW** (high watermark):

```
HW = min(LEO всех реплик из ISR)
```

Всё ниже HW есть на каждой синхронной реплике — это и называется «закоммичено». От HW зависят три вещи:

1. **Что видят потребители.** Читать можно только до HW. Иначе потребитель прочитал бы запись, которая есть только на лидере и исчезнет, если лидер упадёт.
2. **Когда отвечает acks=all.** Запрос ждёт в «чистилище» (purgatory), пока HW не перейдёт его последнюю запись.
3. **Что переживёт смену лидера.** Новый лидер из ISR гарантированно имеет всё до HW.

Лидер узнаёт LEO фолловера из его следующего Fetch-запроса, поэтому HW отстаёт от репликации на один круг. На стенде видно: копия на фолловере появилась, а HW сдвинулся только тиком позже.

С транзакциями появляется ещё одна граница — LSO (last stable offset): потребитель с `isolation.level=read_committed` читает только до неё.
