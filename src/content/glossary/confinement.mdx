---
title: Владение данными
short: 'Данные, к которым обращается ровно одна горутина, не нуждаются в синхронизации. Остальные просят владельца через каналы. Самый надёжный способ избежать гонок — не делить.'
aliases: [confinement, владелец, owner goroutine, монитор, актор]

Два вида владения:

- **Лексическое.** Переменная создаётся внутри горутины и никуда не утекает. Или каждая горутина пишет в свой элемент заранее выделенного среза — `results[i]` — и никто не трогает чужие.
- **Горутина-владелец.** Состояние живёт в одной горутине, остальные присылают ей запросы:

```go
type op struct {
    key   string
    reply chan int
}

func owner(ops <-chan op) {
    counts := map[string]int{} // никто, кроме этой горутины, map не видит
    for o := range ops {
        counts[o.key]++
        o.reply <- counts[o.key]
    }
}
```

Владелец удобен, когда у состояния сложная логика — таймеры, фоновые события, несколько видов запросов. Для простой map под нагрузкой [мьютекс](/glossary/mutex/) быстрее: каждая операция через канал — это минимум две передачи и два переключения горутин.

Передача по каналу — это ещё и передача владения: отправив указатель, отправитель больше не должен трогать то, на что он указывает.
