B-дерево требует линейного порядка. У точек на карте или интервалов времени его нет: «меньше» для прямоугольников не определено. GiST хранит в каждом узле область, покрывающую всех потомков (для геометрии — прямоугольник, для диапазонов — объединяющий диапазон), и спускается только в узлы, чьи области пересекаются с искомой.

Главные применения:

- **Геоданные** в PostGIS: «в радиусе», «внутри полигона», ближайшие соседи через `ORDER BY geom <-> point LIMIT 10`.
- **Диапазоны**: `tsrange`, `int4range` и оператор пересечения `&&`.
- **Ограничение исключения** — запрет пересекающихся броней прямо в схеме, без гонок между транзакциями:

```sql
CREATE EXTENSION btree_gist;
ALTER TABLE bookings ADD CONSTRAINT no_overlap
  EXCLUDE USING gist (room_id WITH =, during WITH &&);
```

Это лучшее лекарство от [перекоса записи](/glossary/write-skew/) в бронированиях: база сама не даст двум транзакциям занять одну переговорку на пересекающееся время.

SP-GiST — родственник для несбалансированных разбиений (префиксные деревья, квадродеревья): IP-адреса, телефоны, точки.
