Срез и копия слайса не копируют элементы, поэтому несколько слайсов легко оказываются окнами в один массив. Для чтения и записи по индексу это ожидаемо. Неожиданно становится с `append`:

```go
base := make([]int, 3, 10)
a := append(base, 1)
b := append(base, 2)
fmt.Println(a[3], b[3]) // 2 2 — оба append писали в одну ячейку
```

У `base` есть свободная ёмкость, поэтому оба `append` пишут в `array[3]`, не переезжая. Какой из двух исходов — запись на месте или [переезд](/glossary/growslice/) — случится, зависит от ёмкости в момент вызова, и по коду её обычно не видно.

Защиты:

- **`s[:n:n]`** — трёхиндексный срез с ёмкостью, равной длине. Первый `append` к нему обязан переехать. Так отдают наружу часть внутреннего буфера;
- **`slices.Clone(s)`** — независимая копия, когда слайс будут менять;
- **функция, которая добавляет элементы, возвращает слайс**, а вызывающий присваивает результат: `s = add(s, x)`.

`append` в общий слайс из нескольких горутин — ещё и [гонка данных](/glossary/data-race/): элементы теряются без всякой паники.
