Руководитель поддержки хочет таблицу по приоритетам тикетов: сколько
пришло, сколько решено, как быстро и насколько довольны клиенты.

В `tickets` у открытого тикета `resolved_at` — `NULL`, оценка `csat`
(от 1 до 5) ставится не всегда. Часть тикетов создана без приоритета.

- `priority` — приоритет; тикеты без приоритета — одной строкой `'none'`;
- `tickets` — всего тикетов;
- `resolved` — решённых;
- `avg_hours` — среднее время решения в часах **по решённым тикетам**,
  `round(…, 1)`; если решённых нет — `NULL`;
- `avg_csat` — средняя оценка **по оценённым тикетам**, `round(…, 2)`;
  если оценок нет — `NULL`.

Порядок: по `priority`.

Что проверяют скрытые тесты: открытые тикеты не тянут среднее вниз, тикеты
без оценки не считаются оценкой «0», группа без приоритета не теряется.

<Reveal>

```sql
SELECT coalesce(priority, 'none') AS priority,
       count(*)           AS tickets,
       count(resolved_at) AS resolved,
       round(avg(extract(epoch FROM resolved_at - created_at) / 3600), 1) AS avg_hours,
       round(avg(csat), 2) AS avg_csat
FROM tickets
GROUP BY priority
ORDER BY 1;
```

Ответ:

```
high | 3 | 2 | 13.0 | 5.00
low | 2 | 1 | 48.0 | 3.00
none | 2 | 1 | 0.5 | 4.00
normal | 2 | 0 | NULL | NULL
```

**`count(*)` считает строки, `count(col)` — не-`NULL` значения.** Отсюда
`resolved` одной функцией, без `CASE` и без `WHERE`: `WHERE resolved_at IS NOT
NULL` выкинул бы открытые тикеты и из `tickets`.

**`avg` сам пропускает `NULL`.** Время решения открытого тикета —
`resolved_at - created_at = NULL`, и в среднее он не попадает. Обернуть это в
`coalesce(…, 0)` — значит объявить, что открытый тикет решили мгновенно:
у `high` получится 8.7 часа вместо 13. С оценкой то же самое: `avg(coalesce(csat,
0))` у `high` даёт 1.67 вместо 5.00.

**Если в группе все значения `NULL`, `avg` возвращает `NULL`**, а не 0 — у
`normal` ни одного решённого тикета, и честный ответ «не знаем», а не «ноль
часов».

**`NULL` в `GROUP BY` — полноценная группа.** Все тикеты без приоритета
попадают в одну строку; `coalesce` в `SELECT` лишь даёт ей имя. Группировать
можно по исходной колонке, а сортировать — по выражению (`ORDER BY 1`), тогда
`'none'` встанет по алфавиту.

**Что спросят дальше.** «А медиану?» — `percentile_cont(0.5) WITHIN GROUP
(ORDER BY …)`: время решения почти всегда с длинным хвостом, и среднее
врёт сильнее медианы.

</Reveal>
