Перед сборкой система проверяет новые заказы: хватает ли остатков по
всем товарам. Остатки лежат на нескольких складах, их можно складывать.
Товара, которого нет ни на одном складе, в `stock` просто нет.

Один товар может встречаться в заказе несколькими строками — нужное
количество складывается.

Для каждого заказа со `status = 'new'`:

- `order_id`;
- `items` — сколько **разных товаров** в заказе;
- `missing` — по скольким из них остатка не хватает;
- `can_ship` — `boolean`: хватает ли по всем.

Порядок: по `order_id`.

Что проверяют скрытые тесты: остаток на разных складах суммируется,
повторяющиеся строки заказа суммируются, товара нет в `stock` вовсе,
нулевой остаток, заказы в других статусах не проверяются.

<Reveal>

```sql
WITH on_hand AS (
  SELECT product_id, sum(qty) AS qty
  FROM stock
  GROUP BY product_id
),
need AS (
  SELECT i.order_id, i.product_id, sum(i.qty) AS qty
  FROM order_items i
  JOIN orders o ON o.id = i.order_id
  WHERE o.status = 'new'
  GROUP BY i.order_id, i.product_id
)
SELECT n.order_id,
       count(*) AS items,
       count(*) FILTER (WHERE coalesce(h.qty, 0) < n.qty) AS missing,
       bool_and(coalesce(h.qty, 0) >= n.qty)              AS can_ship
FROM need n
LEFT JOIN on_hand h ON h.product_id = n.product_id
GROUP BY n.order_id
ORDER BY n.order_id;
```

Ответ:

```
1 | 2 | 0 | t
2 | 2 | 1 | f
3 | 2 | 1 | f
5 | 1 | 1 | f
```

**`bool_and` пропускает `NULL`, как любой агрегат.** Товар 4 не лежит
ни на одном складе, после `LEFT JOIN` его остаток — `NULL`, сравнение
`NULL >= 1` — тоже `NULL`, и `bool_and` его просто не заметит: заказ 3
станет «можно собрать». Это самая коварная ловушка задачи, потому что
запрос выглядит правильным. Лечится `coalesce(остаток, 0)` до сравнения.

**Остатки — предагрегация по складам.** Если соединить позицию заказа с
`stock` напрямую, товар 1 даст две строки (Север 5, Юг 3), и каждая
отдельно меньше 7 — заказ 1 не соберётся, хотя вместе 8 штук есть. Плюс
fan-out: позиция посчитается в `items` дважды.

**Потребность — тоже агрегат.** В заказе 2 товар 1 заказан строками 4 и 5.
Каждая по отдельности помещается в остаток 8, а вместе 9 — уже нет. Поэтому
`need` группирует по `(order_id, product_id)`, и `items` становится
«разных товаров» сам собой.

**`bool_and` и `bool_or`** — это `every` и `any` по группе. Пара `bool_or(…)`
+ `bool_and(…)` удобна для трёх состояний «всё / частично / ничего».
Альтернатива без булевых агрегатов — `count(*) FILTER (WHERE …) = 0`,
который и даёт `missing`.

**Что спросят дальше.** Два заказа проверяются одновременно и оба видят
одни и те же 8 штук. Проверка — не резервирование: в проде остаток
списывают `UPDATE … SET qty = qty - $1 WHERE qty >= $1` в транзакции.
