Трекинг хранит журнал событий посылок. Текущий статус посылки — статус её
последнего события по `happened_at`; при равном времени последним считается
событие с большим `id`. События приходят с задержкой, поэтому `id` сам по
себе порядок не отражает.

Нужна сводка: сколько посылок сейчас в каждом статусе.

- `status`;
- `parcels` — посылок в этом статусе;
- `ids` — `id` этих посылок через `', '` по возрастанию.

Порядок: `parcels` по убыванию, затем `status`.

Что проверяют скрытые тесты: опоздавшее событие с большим `id`, но ранним
временем, два события в одну и ту же секунду, посылка с единственным
событием.

<Reveal>

```sql
WITH current AS (
  SELECT parcel_id,
         (array_agg(status ORDER BY happened_at DESC, id DESC))[1] AS status
  FROM parcel_events
  GROUP BY parcel_id
)
SELECT status,
       count(*) AS parcels,
       string_agg(parcel_id::text, ', ' ORDER BY parcel_id) AS ids
FROM current
GROUP BY status
ORDER BY parcels DESC, status;
```

Ответ:

```
delivered | 2 | 1, 5
created | 1 | 4
in_transit | 1 | 3
returned | 1 | 2
```

**«Значение из строки с максимумом» — одна из самых частых задач на
группировку.** `max(happened_at)` находит время, но не статус. Варианты:
`DISTINCT ON`, `row_number()` в подзапросе или агрегат с порядком:
`(array_agg(status ORDER BY happened_at DESC, id DESC))[1]` — собрать статусы
группы в массив от новых к старым и взять первый.

**Порядок — по времени события, а не по `id`.** У посылки 3 последним
вставлено событие `created` (id 10) — оно опоздало, хотя случилось раньше
всех. `max(id)` показал бы «создана» вместо «в пути».

**Тай-брейк обязателен.** У посылки 2 `in_transit` и `returned` в одну и ту
же секунду. Без `id DESC` в сортировке результат зависел бы от плана
выполнения и мог меняться от запуска к запуску.

**Второй уровень группировки и порядок внутри `string_agg`.** Без `ORDER BY
parcel_id` внутри агрегата порядок `id` в строке не гарантирован — внешний
`ORDER BY` сортирует строки результата, а не элементы внутри агрегата.

**Что спросят дальше.** Как это сделать быстро на ста миллионах событий:
индекс `(parcel_id, happened_at DESC, id DESC)` и `DISTINCT ON`, а в проде —
отдельная колонка `current_status`, которую обновляют вместе с записью
события (с проверкой, что событие действительно новее).

</Reveal>
