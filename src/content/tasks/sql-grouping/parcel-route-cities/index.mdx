В карточке посылки клиент видит маршрут: города, через которые она
прошла, в порядке первого появления, каждый город — один раз. Например,
посылка вернулась в Казань — маршрут всё равно `Казань → Москва`.

Сканы приходят от сортировочных центров с задержкой, поэтому `id` скана
не отражает порядок — порядок задаёт `scanned_at`. У части сканов нет
города.

- `tracking`;
- `cities` — сколько разных городов;
- `route` — города через `' → '`; если городов нет — `'—'`.

Нужны все посылки, включая посылки без сканов.

Порядок: по `tracking`.

Что проверяют скрытые тесты: порядок по времени, а не по `id`, повторные
сканы в одном городе, возврат в уже пройденный город, сканы без города,
посылки без сканов и без городов.

<Reveal>

```sql
WITH first_seen AS (
  SELECT parcel_id, city, min(scanned_at) AS first_at
  FROM scans
  WHERE city IS NOT NULL
  GROUP BY parcel_id, city
)
SELECT p.tracking,
       count(f.city) AS cities,
       coalesce(string_agg(f.city, ' → ' ORDER BY f.first_at), '—') AS route
FROM parcels p
LEFT JOIN first_seen f ON f.parcel_id = p.id
GROUP BY p.id, p.tracking
ORDER BY p.tracking;
```

Ответ:

```
TRK-001 | 3 | Москва → Тверь → Санкт-Петербург
TRK-002 | 2 | Казань → Москва
TRK-003 | 0 | —
TRK-004 | 0 | —
```

**`string_agg(DISTINCT city, ' → ' ORDER BY scanned_at)` не
работает.** С `DISTINCT` в агрегате `ORDER BY` может ссылаться только на
агрегируемое выражение — PostgreSQL ответит ошибкой. А `ORDER BY city` дал
бы алфавит вместо маршрута.

**Решение — два уровня группировки.** Сначала `(parcel, city)` →
`min(scanned_at)`: время первого появления города. Каждый город теперь
одна строка, и `string_agg(city, ' → ' ORDER BY first_at)` склеивает их в
нужном порядке. Без первого шага получилось бы `Москва → Москва → Тверь →
Санкт-Петербург`, а по `id` — вообще `Тверь → Санкт-Петербург → Москва`.

**`NULL` агрегаты пропускают.** `string_agg` и `count(city)` игнорируют
сканы без города, но их лучше отсечь в `WHERE` ещё в CTE, чтобы `min`
не собирал бессмысленную группу `city IS NULL`.

**Пустые посылки.** `LEFT JOIN` от `parcels` оставляет `TRK-004`, у
которой нет ни одного скана, и `TRK-003`, у которой только сканы без
города. Для обеих `string_agg` возвращает `NULL` — не пустую строку, — и
`coalesce` превращает его в `'—'`, а `count` даёт 0.

**Что спросят дальше.** Как показать маршрут с повторными посещениями, но
без подряд идущих дублей (`Казань → Москва → Казань`) — это уже острова:
`lag(city)` и отбрасывание строк, где город не сменился.

</Reveal>
