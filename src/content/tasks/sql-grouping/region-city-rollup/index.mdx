Отчёт для коммерческого директора: продажи по городам, подытог по каждому
региону и общий итог — одним запросом.

В `stores` у онлайн-витрины региона `city` — `NULL`. В одном городе бывает
несколько магазинов. Считаются только заказы со `status = 'paid'`.

- `region` — регион; в строке общего итога — `'Все регионы'`;
- `city` — город; у магазинов без города — `'онлайн'`; в подытоге региона и в
  общем итоге — `'Итого'`;
- `orders` — число оплаченных заказов;
- `revenue` — их сумма, `0`, если заказов нет;
- `avg_check` — средний чек, `round(…, 2)`; `NULL`, если заказов нет.

Город, в котором есть магазин, но нет оплаченных заказов, в отчёте нужен.

Порядок: регионы по алфавиту; внутри региона — города по алфавиту, затем
`'онлайн'`, затем `'Итого'`; строка `'Все регионы'` — последней.

Что проверяют скрытые тесты: подытог нельзя спутать с онлайн-витриной,
средний чек в подытогах считается по заказам, а не по городам, два магазина
одного города дают одну строку, пустой город не пропадает.

<Reveal>

```sql
SELECT CASE WHEN GROUPING(s.region) = 1 THEN 'Все регионы' ELSE s.region END AS region,
       CASE WHEN GROUPING(s.city) = 1 THEN 'Итого' ELSE coalesce(s.city, 'онлайн') END AS city,
       count(o.id) FILTER (WHERE o.status = 'paid')                 AS orders,
       coalesce(sum(o.amount) FILTER (WHERE o.status = 'paid'), 0)  AS revenue,
       round(avg(o.amount) FILTER (WHERE o.status = 'paid'), 2)     AS avg_check
FROM stores s
LEFT JOIN orders o ON o.store_id = s.id
GROUP BY ROLLUP (s.region, s.city)
ORDER BY GROUPING(s.region), s.region, GROUPING(s.city), s.city NULLS LAST;
```

Ответ:

```
Урал | Екатеринбург | 3 | 6000 | 2000.00
Урал | Пермь | 0 | 0 | NULL
Урал | Итого | 3 | 6000 | 2000.00
Центр | Москва | 3 | 4500 | 1500.00
Центр | Тверь | 1 | 1200 | 1200.00
Центр | онлайн | 2 | 1000 | 500.00
Центр | Итого | 6 | 6700 | 1116.67
Все регионы | Итого | 9 | 12700 | 1411.11
```

**`ROLLUP (region, city)` = `GROUPING SETS ((region, city), (region), ())`.**
Один проход по данным вместо трёх запросов через `UNION ALL`.

**Главная ловушка — два разных `NULL`.** В строке подытога `city` —
`NULL`, потому что колонка «свёрнута». Но у онлайн-витрины `city` —
`NULL` в самих данных. `coalesce(city, 'Итого')` склеит их в одно:
онлайн-продажи Центра превратятся во вторую строку «Итого». Различает их
только `GROUPING(city)`: 1 — колонка свёрнута, 0 — настоящее значение, пусть
и `NULL`.

**Средний чек подытога — не среднее средних.** `avg` в строке ROLLUP
считается заново по всем заказам группы: у Центра 6700 / 6 = 1116.67.
Среднее трёх городских чеков (1500, 1200, 500) дало бы 1066.67. Если итоги
собирают руками в коде приложения, это самая частая ошибка.

**`LEFT JOIN` от магазинов и `FILTER` вместо `WHERE`.** Условие `status =
'paid'` в `WHERE` выкинуло бы Пермь целиком — там только возврат. С
`FILTER` строка остаётся: `count` даёт 0, `sum` — `NULL` (отсюда
`coalesce`), `avg` — `NULL`, как и требует условие. Группировка идёт по
`(region, city)`, а не по магазину — два московских магазина складываются.

**Сортировка через `GROUPING()` в `ORDER BY`.** `GROUPING(region)` ставит общий
итог в конец, `GROUPING(city)` — подытог в конец региона, `NULLS LAST` —
онлайн после городов.

**Что спросят дальше.** Чем `CUBE` отличается от `ROLLUP` (все комбинации,
включая «город по всем регионам»), и как одним числом узнать уровень
строки — `GROUPING(region, city)` возвращает битовую маску.
