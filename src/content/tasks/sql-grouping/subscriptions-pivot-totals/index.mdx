Финансовый директор хочет сводную таблицу новых **платных** подписок:
строки — месяцы с января по апрель 2024, колонки — тарифы, плюс итоговая
колонка и итоговая строка.

Пробные подписки (`is_trial`) не учитываются. Кроме `basic`, `pro` и `team`
бывают и другие тарифы: своей колонки у них нет, но в `total` они входят.

- `month` — месяц в формате `'YYYY-MM'`; последняя строка — `'Итого'`;
- `basic`, `pro`, `team` — новых подписок на тариф;
- `total` — всех новых платных подписок.

Все четыре месяца нужны, даже если подписок не было.

Порядок: месяцы по возрастанию, `'Итого'` — последней.

Что проверяют скрытые тесты: месяц, где были только пробные подписки,
границы месяцев (`29 февраля 23:59`, `30 апреля`, `1 мая`), тариф без своей
колонки в `total`, итоговая строка.

<Reveal>

```sql
SELECT CASE WHEN GROUPING(m.month) = 1 THEN 'Итого'
            ELSE to_char(m.month, 'YYYY-MM') END AS month,
       count(s.id) FILTER (WHERE s.plan = 'basic') AS basic,
       count(s.id) FILTER (WHERE s.plan = 'pro')   AS pro,
       count(s.id) FILTER (WHERE s.plan = 'team')  AS team,
       count(s.id)                                 AS total
FROM generate_series(timestamp '2024-01-01', timestamp '2024-04-01', interval '1 month') AS m(month)
LEFT JOIN subscriptions s
       ON date_trunc('month', s.created_at) = m.month
      AND NOT s.is_trial
GROUP BY ROLLUP (m.month)
ORDER BY GROUPING(m.month), m.month;
```

Ответ:

```
2024-01 | 1 | 1 | 0 | 2
2024-02 | 0 | 1 | 1 | 3
2024-03 | 0 | 0 | 0 | 0
2024-04 | 2 | 0 | 0 | 2
Итого | 3 | 2 | 1 | 7
```

**Сетка месяцев + `LEFT JOIN` + условная агрегация.** Колонки тарифов —
`count(s.id) FILTER (WHERE plan = …)`, `total` — просто `count(s.id)`, поэтому
`enterprise` попадает в итог, хотя своей колонки нет. `count(s.id)`, а не
`count(*)`, — чтобы пустой месяц не насчитал одну подписку-заглушку.

**`NOT s.is_trial` — в `ON`, не в `WHERE`.** В марте была только пробная
подписка. Если отфильтровать в `WHERE`, для марта останется строка
соединения, у которой `s.is_trial` — `NULL`; `NOT NULL` — `NULL`, строка
отброшена, и март исчезнет из отчёта. Условие в `ON` лишь решает, какие
подписки присоединять, а строка месяца остаётся всегда. Это та же
классика «`LEFT JOIN` превратился в `INNER`».

**Итоговая строка — `GROUP BY ROLLUP (month)`.** Добавляет к группам по
месяцам ещё одну — по всем строкам. Её месяц — `NULL`, и отличить его
надёжно помогает `GROUPING(month) = 1`. Он же в `ORDER BY` ставит итог в
конец: строка `'Итого'` по алфавиту встала бы после `'2024-…'` случайно,
а не по смыслу.

**Итог — пересчёт, а не сумма строк.** Для `count` это одно и то же, но
если бы в колонках были `count(DISTINCT user_id)`, итог ROLLUP честно
посчитал бы уникальных за период — сумма по месяцам этого не умеет.

**Что спросят дальше.** Как сделать колонки динамическими, если тарифов
станет двадцать. Никак в чистом SQL: набор колонок фиксирован в запросе.
Либо `crosstab` с заранее известным списком, либо поворот на стороне
приложения/BI.
