Операционный отдел ищет курьеров с аномальной долей отмен. Смотрят только
курьеров, у которых не меньше 5 доставок, и сравнивают с долей отмен по
компании.

Доставки без курьера (`courier IS NULL`) не учитываются нигде.

- `courier`;
- `deliveries` — всего доставок курьера;
- `cancelled` — отменённых;
- `cancel_pct` — доля отмен в процентах, `round(…, 1)`;
- `vs_avg` — `cancel_pct` минус доля отмен **по всем доставкам с
  курьером** (включая курьеров, не прошедших порог), в процентных пунктах,
  `round(…, 1)`; вычитаются неокруглённые значения.

Порядок: `cancel_pct` по убыванию, затем `courier`.

Что проверяют скрытые тесты: целочисленное деление, курьер ниже порога
влияет на среднюю, но не выводится, доставки без курьера не влияют ни на
что.

<Reveal>

```sql
WITH per AS (
  SELECT courier,
         count(*)                                     AS deliveries,
         count(*) FILTER (WHERE status = 'cancelled') AS cancelled,
         sum(count(*)) OVER ()                                     AS all_deliveries,
         sum(count(*) FILTER (WHERE status = 'cancelled')) OVER () AS all_cancelled
  FROM deliveries
  WHERE courier IS NOT NULL
  GROUP BY courier
)
SELECT courier, deliveries, cancelled,
       round(100.0 * cancelled / deliveries, 1) AS cancel_pct,
       round(100.0 * cancelled / deliveries - 100.0 * all_cancelled / all_deliveries, 1) AS vs_avg
FROM per
WHERE deliveries >= 5
ORDER BY cancel_pct DESC, courier;
```

Ответ:

```
Иван | 6 | 3 | 50.0 | 16.7
Олег | 5 | 1 | 20.0 | -13.3
Сергей | 5 | 0 | 0.0 | -33.3
```

**Целочисленное деление.** `count(…) / count(*)` — это `bigint /
bigint`, и 3 / 6 = 0. Нужен `100.0 *` в начале выражения (или `::numeric`),
чтобы деление стало дробным.

**Окно выполняется после `HAVING`.** Если поставить `sum(count(*)) OVER ()`
в тот же запрос, где `HAVING count(*) >= 5`, окно увидит только прошедших
порог курьеров: средняя получится 25%, а по условию — 33.3% с учётом
Петра. Поэтому группировка и окно — в CTE без порога, а фильтр
`deliveries >= 5` — снаружи. Порядок логических шагов: `WHERE` → `GROUP BY` →
`HAVING` → окна → `SELECT` → `ORDER BY`.

**`NULL`-курьер — отдельная группа.** Без `WHERE courier IS NOT NULL` три
неназначенных отмены сформировали бы строку `NULL` (ниже порога — не
видна) и подняли бы среднюю до 42.9%. Самые незаметные ошибки — те, что
влияют на итог, не появляясь в выводе.

**Средняя по компании — не среднее долей.** Средняя долей курьеров
(50, 20, 100, 0) — 42.5%, а доля по доставкам — 6 / 18. Для метрики
«процент отмен» правильна вторая.

**Что спросят дальше.** Порог в 5 доставок — грубый способ бороться с
малыми выборками. Статистически честнее доверительный интервал (Уилсона)
или байесовское сглаживание к средней.

</Reveal>
