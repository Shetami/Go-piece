Продакт хочет распределение оплаченных заказов по сумме: корзины по 1000
рублей от 0 до 5000 и отдельная корзина «5000 и больше».

- корзина — полуоткрытый интервал `[lo, hi)`: заказ на 1000 — во второй;
- шесть корзин всегда, даже пустые;
- учитываются только заказы со `status = 'paid'`; заказы без суммы не
  учитываются нигде.

Колонки:

- `lo` — нижняя граница корзины, включительно;
- `hi` — верхняя, не включая; у последней корзины — `NULL`;
- `orders` — заказов в корзине;
- `share_pct` — доля от всех учтённых заказов, `round(…, 1)`.

Порядок: по `lo`.

Что проверяют скрытые тесты: суммы ровно на границе, сумма ровно 5000,
пустые корзины с нулём, отменённые заказы не заполняют пустые корзины,
заказ без суммы не попадает в знаменатель.

<Reveal>

```sql
WITH b AS (
  SELECT width_bucket(amount, 0, 5000, 5) AS bucket, count(*) AS cnt
  FROM orders
  WHERE status = 'paid' AND amount IS NOT NULL
  GROUP BY 1
)
SELECT (g - 1) * 1000                   AS lo,
       CASE WHEN g <= 5 THEN g * 1000 END AS hi,
       coalesce(b.cnt, 0)               AS orders,
       round(100.0 * coalesce(b.cnt, 0) / sum(coalesce(b.cnt, 0)) OVER (), 1) AS share_pct
FROM generate_series(1, 6) AS g
LEFT JOIN b ON b.bucket = g
ORDER BY lo;
```

Ответ:

```
0 | 1000 | 2 | 22.2
1000 | 2000 | 3 | 33.3
2000 | 3000 | 0 | 0.0
3000 | 4000 | 2 | 22.2
4000 | 5000 | 0 | 0.0
5000 | NULL | 2 | 22.2
```

**`width_bucket(x, lo, hi, n)`** делит `[lo, hi)` на `n` равных корзин и
возвращает номер от 1 до `n`. Всё, что `>= hi`, получает `n + 1`, всё, что
`< lo`, — 0. Отсюда открытая корзина «5000+» без отдельного `CASE`, а
границы — полуоткрытые, как и нужно: 999.99 — первая, 1000 — вторая.

**Пустые корзины придумывает сетка.** `GROUP BY` видит только корзины, в
которые что-то попало. `generate_series(1, 6)` + `LEFT JOIN` + `coalesce`
дают все шесть строк. Отменённый заказ на 4500 не должен «оживлять»
пятую корзину — фильтр стоит до группировки.

**Доля — окно по результату.** `sum(…) OVER ()` над сеткой считает только
учтённые заказы (9), а не все строки таблицы. Заказ без суммы получил бы
`width_bucket(NULL, …) = NULL`, и без явного фильтра его корзина-`NULL`
либо потерялась бы, либо раздула знаменатель в подзапросе `count(*)`.

**Почему не `floor(amount / 1000)`.** Он даёт бесконечное число корзин:
12000 уйдёт в свою двенадцатую, а «5000+» пришлось бы собирать руками.
`width_bucket` с массивом границ (`width_bucket(x, ARRAY[0, 500, 2000])`)
решает и случай неравных корзин.

**Что спросят дальше.** Как выбирать границы: равные корзины для денег
почти бесполезны из-за длинного хвоста, лучше логарифмические или по
перцентилям (`ntile`).

</Reveal>
