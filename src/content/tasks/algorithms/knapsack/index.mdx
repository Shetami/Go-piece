Есть предметы с весом и ценностью и рюкзак, который выдерживает
`maximumWeight`. Напишите `MaxValue`: наибольшая суммарная ценность предметов,
которые в него влезут. Каждый предмет можно взять не больше одного раза,
резать предметы нельзя.

```
вместимость 10
вес 5, ценность 10
вес 4, ценность 40
вес 6, ценность 30
вес 4, ценность 50

→ 90: второй и четвёртый предметы, вес 8
```

В тестах есть случаи, на которых ломается жадный выбор и по весу, и по
ценности, и набор из 15 предметов с вместимостью 750 — полный перебор 2¹⁵
подмножеств ещё пройдёт, но это не то, чего ждут.

Тесты — из открытого набора [Exercism](https://github.com/exercism/problem-specifications) (MIT).

<Reveal>

```go
func MaxValue(maximumWeight int, items []Item) int {
	best := make([]int, maximumWeight+1)
	for _, it := range items {
		for w := maximumWeight; w >= it.Weight; w-- {
			best[w] = max(best[w], best[w-it.Weight]+it.Value)
		}
	}
	return best[maximumWeight]
}
```

**Таблица «предметы × вместимость».** Классическая формулировка:
`dp[i][w]` — лучшее из первых `i` предметов при вместимости `w`. Для
`i`-го предмета два варианта: не брать — `dp[i-1][w]`, взять —
`dp[i-1][w-вес] + ценность`. O(n·W) по времени и памяти.

**Одна строка вместо таблицы.** Строка `i` зависит только от строки `i-1`,
поэтому хватает одного слайса, который переписывается на месте. Но идти по
нему нужно **сверху вниз**: тогда `best[w-вес]` — ещё значение
*предыдущей* строки, без текущего предмета. Снизу вверх получится рюкзак
с неограниченным числом копий — другая задача, и тест с пятью одинаковыми
предметами весом 2 это покажет.

**Псевдополиномиальность.** O(n·W) зависит от *значения* вместимости, а не
от длины входа: при `W = 10⁹` таблица не поместится в память. Задача
NP-трудна, и это хороший ответ на вопрос «а если вместимость огромная?» —
тогда динамику ведут по ценности или переходят к перебору с отсечениями.
