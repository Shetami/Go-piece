Напишите `ToRoman` — число от 1 до 3999 римскими цифрами.

| I | V | X | L | C | D | M |
|---|---|---|---|---|---|---|
| 1 | 5 | 10 | 50 | 100 | 500 | 1000 |

Цифры пишутся от больших к меньшим и складываются: `XVI` = 16. Но одна и та же
цифра не повторяется больше трёх раз подряд — вместо этого меньшая ставится
*перед* большей и вычитается: 4 — `IV`, 9 — `IX`, 40 — `XL`, 90 — `XC`,
400 — `CD`, 900 — `CM`.

Примеры: 1994 → `MCMXCIV`, 3999 → `MMMCMXCIX`.

Тесты — из открытого набора [Exercism](https://github.com/exercism/problem-specifications) (MIT).

<Reveal>

```go
var romans = []struct {
	value int
	digit string
}{
	{1000, "M"}, {900, "CM"}, {500, "D"}, {400, "CD"},
	{100, "C"}, {90, "XC"}, {50, "L"}, {40, "XL"},
	{10, "X"}, {9, "IX"}, {5, "V"}, {4, "IV"}, {1, "I"},
}

func ToRoman(number int) string {
	var b strings.Builder
	for _, r := range romans {
		for number >= r.value {
			b.WriteString(r.digit)
			number -= r.value
		}
	}
	return b.String()
}
```

**Главный трюк — вычитательные пары в таблице.** Если считать `CM`, `XL`,
`IV` такими же «цифрами», как `M` или `X`, правило про вычитание исчезает:
остаётся жадно брать самую большую цифру, которая влезает.

**Почему жадность здесь честная.** У размена монетами она в общем случае
ошибается (см. задачу про размен). Здесь — нет: таблица устроена так, что
каждый десятичный разряд пишется независимо, и для каждого разряда жадный выбор
даёт ровно каноническую запись.

**Слайс, а не мапа.** Порядок обхода мапы в Go случаен, а порядок здесь — весь
алгоритм.
