Напишите `Factors`: разложить натуральное число на простые множители и
вернуть их по возрастанию, с повторениями.

- `60` → `[2 2 3 5]`;
- `1` → пусто: у единицы простых множителей нет;
- `9` → `[3 3]`.

Самый большой тест — `93819012551` = 11 · 9539 · 894119. Перебор всех
чисел до `value` на нём не уложится в лимит времени.

Тесты — из открытого набора [Exercism](https://github.com/exercism/problem-specifications) (MIT).

<Reveal>

```go
func Factors(value int) []int {
	var out []int
	for d := 2; d*d <= value; d++ {
		for value%d == 0 {
			out = append(out, d)
			value /= d
		}
	}
	if value > 1 {
		out = append(out, value)
	}
	return out
}
```

**Почему каждый найденный делитель простой.** Делители перебираются по
возрастанию, и каждый, найдя его, мы выносим из `value` *полностью*. Значит,
к моменту, когда дошли до `d = 4`, двоек в `value` уже нет, и на 4 оно не
делится. Отдельная проверка «`d` простое?» не нужна.

**До корня — и остаток.** У составного числа есть делитель не больше корня.
Поэтому, когда `d*d > value`, то, что осталось, либо 1, либо простое число.
На `93819012551` цикл вынесет 11 и 9539, после чего остаток `894119` окажется
меньше `d*d`, и цикл кончится — а сам остаток добавится как простой множитель.
Вместо 94 миллиардов шагов — меньше десяти тысяч.

**Сложность** — O(√n) в худшем случае, когда число простое. Для чисел
в десятки знаков переходят на `ρ`-алгоритм Полларда, но на собеседовании
обычно хватает перебора и объяснения, почему он корректен.

</Reveal>
