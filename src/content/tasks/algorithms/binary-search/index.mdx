Напишите `Search`: слайс отсортирован по возрастанию, нужно вернуть индекс
`value` или `-1`, если его нет. Время — O(log n), то есть пробегать слайс
целиком нельзя.

Пакеты `sort` и `slices` не используйте — суть задачи как раз в том, чтобы
написать поиск самому.

Что проверяют тесты: слайс из одного элемента, значение в начале, в середине,
в конце, значение меньше всех, больше всех, между элементами и пустой слайс.

Тесты — из открытого набора [Exercism](https://github.com/exercism/problem-specifications) (MIT).

<Reveal>

```go
func Search(array []int, value int) int {
	lo, hi := 0, len(array)
	for lo < hi {
		mid := int(uint(lo+hi) >> 1)
		switch {
		case array[mid] == value:
			return mid
		case array[mid] < value:
			lo = mid + 1
		default:
			hi = mid
		}
	}
	return -1
}
```

**Инвариант полуинтервала.** Если `value` есть, он лежит в `[lo, hi)`. Каждый
шаг сохраняет это и сужает интервал хотя бы на один элемент: `lo = mid + 1`
выкидывает `mid` слева, `hi = mid` — справа. Пустой интервал (`lo == hi`)
значит «нет».

**Типичные ошибки — все про границы.** `hi = len - 1` с условием `lo < hi`
не проверит последний элемент. `lo = mid` вместо `mid + 1` зациклится на
интервале из двух элементов. Выберите одну схему — полуинтервал или отрезок
`[lo, hi]` с `lo <= hi` — и не смешивайте их.

**`uint(lo+hi) >> 1`** — так середину считает сама стандартная библиотека
(`sort.Search`): сумма двух больших `int` не переполнится в отрицательное
число. На слайсах в памяти это скорее педантизм, но его любят спросить.

</Reveal>
