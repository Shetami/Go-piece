Напишите `Primes`: все простые числа от 2 до `limit` включительно,
по возрастанию.

Используйте *решето Эратосфена*: выписать числа от 2 до `limit`, взять
первое невычеркнутое — оно простое, — вычеркнуть все его кратные и повторить.
Деление и `%` не нужны — в этом весь смысл.

Для `limit = 1` ответ пустой, для `limit = 10` — `[2 3 5 7]`. Самый большой
тест — `limit = 1000`.

Тесты — из открытого набора [Exercism](https://github.com/exercism/problem-specifications) (MIT).

<Reveal>

```go
func Primes(limit int) []int {
	if limit < 2 {
		return nil
	}
	composite := make([]bool, limit+1)
	var primes []int
	for n := 2; n <= limit; n++ {
		if composite[n] {
			continue
		}
		primes = append(primes, n)
		for m := n * n; m <= limit; m += n {
			composite[m] = true
		}
	}
	return primes
}
```

**Вычёркивать с `n * n`.** Кратные `n`, меньшие `n²`, имеют вид `k·n`
с `k < n` — их уже вычеркнул меньший простой делитель `k`. Отсюда же
классическая оптимизация: внешний цикл вычёркивания можно гнать только до
`√limit`, дальше остаётся собрать невычеркнутые.

**Сложность — O(n log log n),** почти линейная. Проверка каждого числа делением
до корня стоила бы O(n√n).

**`[]bool` против битсета.** Слайс булевых — по байту на число. Для лимита
в миллиарды переходят на биты (`[]uint64`, в 8 раз меньше) и на сегментированное
решето, которое держит в памяти только окно.
