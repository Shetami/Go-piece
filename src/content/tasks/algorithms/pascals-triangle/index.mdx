В треугольнике Паскаля каждое число — сумма двух чисел над ним, а по краям
стоят единицы:

```
    1
   1 1
  1 2 1
 1 3 3 1
1 4 6 4 1
```

Напишите `Pascal`: вернуть первые `count` строк. Для `count = 0` — пустой
результат, для `count = 3` — `[[1] [1 1] [1 2 1]]`.

Тесты — из открытого набора [Exercism](https://github.com/exercism/problem-specifications) (MIT).

<Reveal>

```go
func Pascal(count int) [][]int {
	rows := make([][]int, count)
	for i := range rows {
		row := make([]int, i+1)
		row[0], row[i] = 1, 1
		for j := 1; j < i; j++ {
			row[j] = rows[i-1][j-1] + rows[i-1][j]
		}
		rows[i] = row
	}
	return rows
}
```

**Каждая строка — своя память.** `make` на каждой итерации. Соблазн
переиспользовать один буфер и делать `rows = append(rows, row)` приводит
к классической ошибке: все строки смотрят в один массив и в конце одинаковы.

**Края без условий.** `row[0], row[i] = 1, 1` ставит обе единицы сразу; для
первой строки (`i = 0`) это одна и та же ячейка, и ничего не ломается.
Внутренний цикл при `i < 2` просто не выполняется.

**Зачем это на собеседовании.** Элемент `j` строки `i` — биномиальный
коэффициент C(i, j). Частое продолжение — «посчитай C(n, k) без переполнения»,
и треугольник даёт ответ только на сложениях.

</Reveal>
