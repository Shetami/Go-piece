Антифрод ищет группы связанных аккаунтов. Дружба взаимна, но в таблице
`friendships` пара записана один раз в произвольном направлении (иногда — в
обоих). Разбейте пользователей на **компоненты связности**: двое в одной
компоненте, если между ними есть цепочка дружб любой длины.

- номер компоненты — наименьший `id` пользователя в ней;
- пользователь без друзей — отдельная компонента из одного человека;
- `members` — имена через `', '` по алфавиту.

- колонки: `component`, `size`, `members`;
- порядок: по `component`.

Что проверяют скрытые данные: треугольник друзей (цикл), ребро, записанное в
обе стороны, цепочку, в которой рёбра смотрят в разные стороны, дружбу с
самим собой, пользователя без друзей.

Если запрос зациклится, через пять секунд его остановят.

<Reveal>

```sql
WITH RECURSIVE edges AS (
  SELECT a, b FROM friendships
  UNION
  SELECT b, a FROM friendships
),
reach AS (
  SELECT id AS start, id AS node
  FROM users

  UNION
  SELECT r.start, e.b
  FROM reach r
  JOIN edges e ON e.a = r.node
),
component AS (
  SELECT start AS user_id, min(node) AS component
  FROM reach
  GROUP BY start
)
SELECT c.component,
       count(*)                                 AS size,
       string_agg(u.name, ', ' ORDER BY u.name) AS members
FROM component c
JOIN users u ON u.id = c.user_id
GROUP BY c.component
ORDER BY c.component;
```

Ответ:

```
1 | 3 | Аня, Боря, Вера
4 | 4 | Гоша, Даша, Егор, Илья
7 | 1 | Жора
8 | 1 | Зина
```

**Неориентированный граф — это рёбра в обе стороны.** Цепочка `4 → 5 ← 6 ←
9` по направлению записи не связывает Гошу с Ильёй. `edges` дублирует каждое
ребро в обратную сторону, и обход идёт по нему.

**`UNION` в рекурсивном CTE — защита от циклов.** С `UNION` Postgres
отбрасывает строки, которые уже есть в результате. Пара `(start, node)`
конечна, поэтому, когда новые пары кончаются, рекурсия останавливается сама —
хотя в треугольнике Аня—Боря—Вера и в петле Жоры обход ходил бы по кругу
вечно. С `UNION ALL` запрос не остановится. Это работает, потому что в строке
нет ничего растущего (глубины, пути): добавь `depth + 1` — и дубли перестанут
быть дублями.

**Изолированные вершины — из стартовой части.** Каждый пользователь
достижим из себя самого, поэтому Зина без друзей попадает в ответ отдельной
компонентой, а номер компоненты — `min(node)` по всему достижимому, включая
себя.

**Что спросят дальше.** «Это же O(n²) пар?» — да: для каждого пользователя
хранится вся его компонента. На больших графах так не делают: итеративная
«пропаганда меток» (каждая вершина берёт минимум меток соседей, пока что-то
меняется) или union-find в коде.
