Отчёт по заказам клиентов из Казани работал, пока там был один клиент.
Появилась Вера, и запрос падает:

```
more than one row returned by a subquery used as an expression
```

Почините. Ожидаются заказы 2, 3 и 4.

<Reveal>

**`=` ждёт одно значение.** Подзапрос справа от `=` — скалярный: он обязан
вернуть не больше одной строки. Пока клиент из Казани один, так и было;
теперь их двое, и Postgres не знает, с кем сравнивать.

```sql
WHERE customer_id IN (SELECT id FROM customers WHERE city = 'Казань')
```

**Или соединением:**

```sql
SELECT o.id, o.amount
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE c.city = 'Казань';
```

С `JOIN` осторожнее: если бы справа могли быть дубликаты, заказы бы
размножились. `IN` и `EXISTS` от этого защищены — они только проверяют
наличие.

**Урок шире, чем синтаксис:** запрос, корректный на текущих данных, но
опирающийся на то, что «строка всегда одна», — бомба. Если единственность
важна, её держит ограничение `UNIQUE`, а не надежда.

</Reveal>
