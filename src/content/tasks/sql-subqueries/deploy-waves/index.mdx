Платформенная команда выкатывает сервисы волнами: сервис можно выкатывать,
когда уже выкачены все, от кого он зависит (`deps.service` зависит от
`deps.depends_on`).

- сервис без зависимостей — волна `1`;
- иначе — `1 +` максимальная волна среди его зависимостей;
- если сервис стоит в цикле зависимостей или зависит (через любое число
  шагов) от сервиса в цикле, волну определить нельзя — `wave` пустая.

- колонки: `service`, `wave`;
- порядок: по `wave` (пустые — в конце), затем по `service`.

Что проверяют скрытые данные: ромб (две дороги к одной зависимости разной
длины), цикл из двух сервисов, сервис, зависящий от самого себя, сервис,
зависящий от цикла, но сам в нём не стоящий, сервис без связей.

Если запрос зациклится, через пять секунд его остановят.

<Reveal>

```sql
WITH RECURSIVE walk AS (
  SELECT name AS root, name AS node, 1 AS depth,
         ARRAY[name] AS path, false AS is_cycle
  FROM services

  UNION ALL

  SELECT w.root, d.depends_on, w.depth + 1,
         w.path || d.depends_on,
         d.depends_on = ANY (w.path)
  FROM walk w
  JOIN deps d ON d.service = w.node
  WHERE NOT w.is_cycle
)
SELECT root AS service,
       CASE WHEN bool_or(is_cycle) THEN NULL ELSE max(depth) END AS wave
FROM walk
GROUP BY root
ORDER BY wave NULLS LAST, service;
```

Ответ:

```
cache | 1
db | 1
search | 1
auth | 2
queue | 2
billing | 3
api | 4
cron | NULL
ledger | NULL
notifier | NULL
reports | NULL
```

**Волна — это длина самого длинного пути вниз.** Из каждого сервиса
рекурсия перебирает все пути по зависимостям; число узлов на пути — его
глубина. `billing` зависит от `db` напрямую (путь из 2) и через `queue`
(путь из 3) — выкатывать его можно только в третьей волне, поэтому `max`, а
не `min` и не «первый найденный».

**Цикл замечается по пути, а не по глубине.** В строке несём массив
пройденных сервисов. Если следующий шаг ведёт в сервис, который уже есть в
пути, строка помечается `is_cycle` и дальше не растёт (`WHERE NOT
w.is_cycle`) — рекурсия гарантированно конечна. В Postgres 14+ то же самое
делает `CYCLE depends_on SET is_cycle USING path`.

**Испорченность распространяется вверх.** `notifier` не стоит в цикле, но
его путь `notifier → ledger → reports → ledger` упирается в цикл, и
`bool_or(is_cycle)` по всем путям из `notifier` его ловит. `cron`, зависящий
от самого себя, — цикл длины один.

**Что спросят дальше.** «Сколько это стоит?» — число путей в графе может
расти экспоненциально (много ромбов подряд). Настоящий планировщик строит
волны алгоритмом Кана: снять все вершины без входящих рёбер, удалить их,
повторить; что не удалось снять — циклы. Рекурсивным CTE Кана не
напишешь, а вот в коде — десяток строк.

</Reveal>
