Агрегатор авиабилетов строит подсказки «куда можно улететь из Москвы».
Для каждого города, достижимого из `MOW`, найдите самый дешёвый маршрут.

- не больше **3 перелётов**;
- ни один город в маршруте не повторяется (в том числе `MOW`), и сам `MOW` в
  ответ не входит;
- лучший маршрут — с меньшей суммарной ценой; при равной цене — с меньшим
  числом перелётов; дальше — с меньшей строкой `route`;
- `route` — коды городов через `' → '`, например `MOW → LED → KZN`.

- колонки: `city`, `legs`, `price`, `route`;
- порядок: по `city`.

Что проверяют скрытые данные: рейсы обратно в Москву и циклы; маршрут с
пересадками, который дешевле прямого; дешёвый маршрут из четырёх перелётов;
равные по цене маршруты; город, откуда рейсы есть, а туда — нет.

Если запрос зациклится, через пять секунд его остановят.

<Reveal>

```sql
WITH RECURSIVE routes AS (
  SELECT dst AS city, 1 AS legs, price,
         ARRAY[src, dst] AS path
  FROM flights
  WHERE src = 'MOW'

  UNION ALL

  SELECT f.dst, r.legs + 1, r.price + f.price,
         r.path || f.dst
  FROM routes r
  JOIN flights f ON f.src = r.city
  WHERE r.legs < 3
    AND f.dst <> ALL (r.path)
),
ranked AS (
  SELECT city, legs, price, array_to_string(path, ' → ') AS route,
         row_number() OVER (PARTITION BY city
                            ORDER BY price, legs, array_to_string(path, ' → ')) AS rn
  FROM routes
)
SELECT city, legs, price, route
FROM ranked
WHERE rn = 1
ORDER BY city;
```

Ответ:

```
AER | 1 | 5000 | MOW → AER
KGD | 3 | 7000 | MOW → KZN → SVX → KGD
KZN | 1 | 4000 | MOW → KZN
LED | 1 | 3000 | MOW → LED
MMK | 1 | 8000 | MOW → MMK
OVB | 3 | 9000 | MOW → KZN → SVX → OVB
SVX | 2 | 6000 | MOW → KZN → SVX
VVO | 3 | 19000 | MOW → SVX → OVB → VVO
```

**Граф с циклами — не дерево.** `MOW → LED → MOW` и `SVX → OVB → MOW`
замыкаются, и рекурсия без защиты либо крутится до лимита глубины, либо
выдаёт в ответ сам `MOW` и маршруты с повторами. Массив `path` хранит
пройденные города, а `f.dst <> ALL (r.path)` запрещает заходить в них
снова. Это та же защита, что делает конструкция `CYCLE` в Postgres 14+.

**Лимит — в рекурсивной части, а не снаружи.** `WHERE r.legs < 3` обрывает
рост путей. Фильтр `legs <= 3` во внешнем запросе дал бы тот же ответ, но
только если рекурсия вообще остановится; на графе с циклами без проверки
`path` — не остановится. Во Владивосток есть маршрут дешевле через Казань, но
из четырёх перелётов — он не в счёт.

**Три уровня тай-брейкера.** В Казань прямой рейс и `MOW → LED → KZN` стоят
одинаково — побеждает прямой. В Екатеринбург через Казань и через Питер —
по `6000` и по две ноги, решает строка маршрута. Без полного порядка в
`row_number` ответ зависел бы от плана запроса. `DISTINCT ON (city) … ORDER
BY city, price, legs, route` — равноценная запись.

**Что спросят дальше.** «Это же перебор всех путей?» — да, экспоненциальный.
Для настоящего поиска кратчайших путей SQL не лучший инструмент (Дейкстра в
коде, `pgRouting`); рекурсивный CTE хорош, пока граф маленький, а глубина
жёстко ограничена.
