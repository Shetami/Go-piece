Найдите клиентов, которые потратили больше, чем средний клиент.

- «потратил» — сумма `amount` его неотменённых заказов
  (`status <> 'cancelled'`);
- «средний клиент» — среднее этих сумм по клиентам, у которых есть хотя бы
  один неотменённый заказ;
- сравнение строгое.

- колонки: `name`, `total`;
- порядок: по `total` по убыванию, затем по `name`.

Что проверяют скрытые данные: клиента с большим числом мелких заказов,
клиента только с отменёнными заказами, клиента без заказов.

<Reveal>

```sql
WITH totals AS (
  SELECT customer_id, sum(amount) AS total
  FROM orders
  WHERE status <> 'cancelled'
  GROUP BY customer_id
)
SELECT c.name, t.total
FROM totals t
JOIN customers c ON c.id = t.customer_id
WHERE t.total > (SELECT avg(total) FROM totals)
ORDER BY t.total DESC, c.name;
```

Ответ:

```
Боря | 700.00
Аня | 600.00
```

**Агрегат над агрегатом.** `avg(sum(amount))` в одном запросе написать
нельзя, поэтому суммы по клиентам считаются в CTE, а среднее по ним — в
скалярном подзапросе к той же CTE. Средняя сумма клиента — `525`.

**`avg(amount)` — это средний чек, а не средний клиент.** Средний
неотменённый заказ здесь `210`, и тогда «выше среднего» оказываются все.
Этот подмен величины — самая частая ошибка в такой задаче.

**Кто в знаменателе.** Даша (только отменённый заказ) и Егор (без заказов)
в среднее не входят по условию. Если посчитать их нулями через
`LEFT JOIN`, среднее упадёт до `350`, и в ответ пролезет Вера с `500`.
Отменённые заказы тоже отсекаются до суммирования, иначе у Гоши будет `1200`.

**Что спросят дальше.** «Сделайте то же через окно» — `avg(total) OVER ()`
в CTE и сравнение снаружи. Результат тот же, а таблица читается один раз.

</Reveal>
