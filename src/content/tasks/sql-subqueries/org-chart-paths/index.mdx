HR-портал рисует оргструктуру деревом. Выведите всех сотрудников так, как
они стоят в дереве.

- `level` — 1 для сотрудников без руководителя, 2 для их прямых подчинённых
  и так далее;
- `path` — цепочка имён от верхнего уровня до сотрудника через `' / '`,
  например `Анна / Борис / Вика`;
- `team_size` — сколько человек у сотрудника в подчинении на **всех**
  уровнях ниже (у рядового сотрудника — `0`);
- порядок — обход в глубину: сначала руководитель, сразу под ним всё его
  поддерево, потом следующий коллега. Сотрудники одного руководителя (и
  верхний уровень) идут по имени.

- колонки: `name`, `level`, `path`, `team_size`.

Что проверяют скрытые данные: несколько независимых корней, в том числе
сотрудника без руководителя и без подчинённых; ветки разной глубины (до
пяти уровней); порядок, в котором короткое имя-сосед обгоняет длинную ветку.

Если запрос зациклится, через пять секунд его остановят.

<Reveal>

```sql
WITH RECURSIVE tree AS (
  SELECT id, name, 1 AS level,
         name AS path,
         ARRAY[name] AS sort_key,
         ARRAY[id]   AS ids
  FROM employees
  WHERE manager_id IS NULL

  UNION ALL

  SELECT e.id, e.name, t.level + 1,
         t.path || ' / ' || e.name,
         t.sort_key || e.name,
         t.ids || e.id
  FROM employees e
  JOIN tree t ON e.manager_id = t.id
)
SELECT t.name,
       t.level,
       t.path,
       (SELECT count(*) FROM tree d WHERE t.id = ANY (d.ids)) - 1 AS team_size
FROM tree t
ORDER BY t.sort_key;
```

Ответ:

```
Анна | 1 | Анна | 9
Алиса | 2 | Анна / Алиса | 1
Зоя | 3 | Анна / Алиса / Зоя | 0
Борис | 2 | Анна / Борис | 6
Артём | 3 | Анна / Борис / Артём | 0
Вика | 3 | Анна / Борис / Вика | 2
Дина | 4 | Анна / Борис / Вика / Дина | 1
Егор | 5 | Анна / Борис / Вика / Дина / Егор | 0
Глеб | 3 | Анна / Борис / Глеб | 1
Илья | 4 | Анна / Борис / Глеб / Илья | 0
Кира | 1 | Кира | 1
Лев | 2 | Кира / Лев | 0
Мира | 1 | Мира | 0
```

**Рекурсия несёт с собой всё, что нужно потом.** Каждый шаг наращивает
уровень, строку пути, массив имён для сортировки и массив id предков. Корни
— все `manager_id IS NULL`, а не «сотрудник с `id = 1`»: Кира и Мира —
отдельные деревья.

**Порядок обхода в глубину — сортировка по массиву.** Массивы в Postgres
сравниваются поэлементно, поэтому `ORDER BY sort_key` ставит поддерево сразу
под его корнем, а соседей — по имени. `ORDER BY level, name` дал бы «по
этажам», а сортировка по строке `path` сломается, как только в имени
встретится символ, который меньше разделителя. В Postgres 14+ есть готовое
`SEARCH DEPTH FIRST BY name SET ord`.

**Размер поддерева — из той же CTE.** Сотрудник `d` входит в команду `t`,
если `t.id` есть среди предков `d` (`t.id = ANY (d.ids)`). Сам `t` тоже
удовлетворяет условию, отсюда `- 1`. Скалярный подзапрос к CTE — законный
приём: CTE материализуется один раз. На больших деревьях это `O(n²)`, и
тогда поддеревья считают через `path`-префикс с индексом (`ltree`) или через
отдельную таблицу замыкания.

**Что спросят дальше.** «А если в данных цикл?» — `CYCLE id SET is_cycle
USING cycle_path` или условие `e.id <> ALL (t.ids)` в рекурсивной части.
«А если нужно дерево от конкретного руководителя?» — меняется только
нерекурсивная часть.
