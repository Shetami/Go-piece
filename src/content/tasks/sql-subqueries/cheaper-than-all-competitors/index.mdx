Парсер каждый день собирает цены конкурентов. Если у конкурента товара нет в
наличии, цена сохраняется пустой. Для баннера «Дешевле, чем у других» нужны
товары, у которых наша цена **строго ниже каждой известной** цены
конкурентов.

- товар без единой известной цены конкурента в баннер не идёт — сравнивать не
  с чем;
- пустые цены конкурентов в сравнении не участвуют.

- колонки: `sku`, `price` (наша), `best_competitor` — минимальная известная
  цена конкурентов, `gap` — `best_competitor - price`;
- порядок: по `gap` по убыванию, затем по `sku`.

Что проверяют скрытые данные: товар без строк у конкурентов, товар только с
пустой ценой, товар, у которого среди цен есть пустая, и цену, ровно равную
нашей.

<Reveal>

```sql
SELECT p.sku,
       p.price,
       (SELECT min(c.price) FROM competitor_prices c WHERE c.sku = p.sku) AS best_competitor,
       (SELECT min(c.price) FROM competitor_prices c WHERE c.sku = p.sku) - p.price AS gap
FROM products p
WHERE EXISTS (
        SELECT 1 FROM competitor_prices c
        WHERE c.sku = p.sku AND c.price IS NOT NULL
      )
  AND p.price < ALL (
        SELECT c.price FROM competitor_prices c
        WHERE c.sku = p.sku AND c.price IS NOT NULL
      )
ORDER BY gap DESC, p.sku;
```

Ответ:

```
A-300 | 4990.00 | 5200.00 | 210.00
A-100 | 2490.00 | 2590.00 | 100.00
```

**`x < ALL (пусто)` — истина.** Квантор «для всех» над пустым множеством
выполняется всегда. Кофемолка `A-500`, которую конкуренты не продают, без
отдельного `EXISTS` попадает в баннер «дешевле всех» с пустым `gap`.

**`x < ALL (…, NULL, …)` — не бывает истиной.** `ALL` — это цепочка `AND`:
если все известные сравнения истинны, а одно — `UNKNOWN`, итог `UNKNOWN`, и
строка отбрасывается. Блендер `A-300` честно дешевле известных цен, но из-за
`wb` с пустой ценой пропадает. Двойник этой ловушки — `NOT IN`, который
тоже `<> ALL`.

**Строго меньше.** Тостер `A-200` стоит ровно как у `ozon` — это не «дешевле».

**Через `min` проще.** `p.price < (SELECT min(price) …)` сам решает обе
проблемы: `min` игнорирует `NULL`, а для пустого множества возвращает `NULL`,
и сравнение не проходит. Но интервьюер часто просит именно `ALL`/`ANY`, чтобы
проверить, знаете ли вы их поведение на краях. Второй вопрос вдогонку:
`= ANY (…)` эквивалентно `IN`, а `<> ANY` — вовсе не `NOT IN`.

</Reveal>
