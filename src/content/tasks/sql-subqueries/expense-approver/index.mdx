Сотрудники заводят расходы, согласовывает их руководитель. Правило:
расход согласует **ближайший** руководитель вверх по цепочке, у которого
`approval_limit >= amount`. Если у руководителя лимита нет (`NULL`), он
прав согласования не имеет, и расход идёт выше. Сам автор свой расход не
согласует, даже если его лимит позволяет. Если по всей цепочке никто не
подходит — согласующего нет.

- колонки: `id` (расхода), `employee` (автор), `approver`, `step` — сколько
  ступеней вверх от автора (1 — непосредственный руководитель); если
  согласующего нет, `approver` и `step` пустые;
- порядок: по `id`.

Что проверяют скрытые данные: сумму ровно на лимите, руководителя без прав
посередине цепочки, автора с собственным лимитом, расход первого лица
компании, расход, который никто не может согласовать.

Если запрос зациклится, через пять секунд его остановят.

<Reveal>

```sql
WITH RECURSIVE chain AS (
  SELECT x.id AS expense_id, e.manager_id AS manager_id, 1 AS step
  FROM expenses x
  JOIN employees e ON e.id = x.employee_id
  WHERE e.manager_id IS NOT NULL

  UNION ALL

  SELECT c.expense_id, e.manager_id, c.step + 1
  FROM chain c
  JOIN employees e ON e.id = c.manager_id
  WHERE e.manager_id IS NOT NULL
)
SELECT x.id,
       author.name AS employee,
       a.name      AS approver,
       a.step
FROM expenses x
JOIN employees author ON author.id = x.employee_id
LEFT JOIN LATERAL (
  SELECT m.name, c.step
  FROM chain c
  JOIN employees m ON m.id = c.manager_id
  WHERE c.expense_id = x.id
    AND m.approval_limit >= x.amount
  ORDER BY c.step
  LIMIT 1
) a ON true
ORDER BY x.id;
```

Ответ:

```
1 | Дина | Глеб | 1
2 | Дина | Глеб | 1
3 | Дина | Борис | 3
4 | Глеб | Борис | 2
5 | Зоя | Борис | 2
6 | Борис | Анна | 1
7 | Анна | NULL | NULL
8 | Дина | NULL | NULL
```

**Рекурсия снизу вверх, по одной цепочке на расход.** Стартовая часть берёт
непосредственного руководителя автора — не самого автора, поэтому Глеб со
своим лимитом `20000` не согласует собственные `10000`. Рекурсивная часть
поднимается к руководителю руководителя, пока не упрётся в `manager_id IS
NULL`. В строке несём `expense_id`, чтобы цепочки разных расходов не
смешались.

**«Ближайший подходящий» — top-1 в LATERAL.** Из всей цепочки берутся те, у
кого лимит покрывает сумму, и из них — с наименьшим `step`. `NULL`-лимит Вики
в сравнении `>=` даёт `UNKNOWN` и отсеивается сам. `LEFT JOIN` сохраняет
расходы, которые никто не может согласовать: Анне некого спросить, а на
`900000` не хватает ничьего лимита.

**Можно остановить рекурсию раньше.** Добавив в рекурсивную часть условие
«текущий руководитель ещё не подходит», мы не будем подниматься выше
согласующего — на глубоких иерархиях это заметно дешевле. Но тогда сумму
расхода придётся нести в строке CTE.

**Что спросят дальше.** «А если руководитель в отпуске и есть замещающий?»
— ещё одна таблица и `coalesce(deputy, manager)` на каждом шаге. «А если в
данных цикл?» — массив пройденных id, как в любом обходе графа.
