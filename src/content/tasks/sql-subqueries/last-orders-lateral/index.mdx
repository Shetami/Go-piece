На карточке клиента в CRM показывают его два последних заказа. Нужен отчёт
по всем клиентам сразу.

- отменённые заказы (`status = 'cancelled'`) не показываются вовсе;
- «последний» — с наибольшим `created_at`; если время совпадает, позже
  считается заказ с большим `id`;
- клиент без подходящих заказов всё равно попадает в отчёт — одной строкой,
  где `id`, `created_at` и `amount` пусты.

- колонки: `name`, `id` (заказа), `created_at`, `amount`;
- порядок: по `name`, затем `created_at` по убыванию, затем `id` по
  убыванию.

Что проверяют скрытые данные: отменённый заказ, который по времени самый
свежий; три заказа одного клиента в одну и ту же секунду; клиента, у
которого есть только отменённый заказ, и клиента без заказов.

<Reveal>

```sql
SELECT c.name, o.id, o.created_at, o.amount
FROM customers c
LEFT JOIN LATERAL (
  SELECT id, created_at, amount
  FROM orders
  WHERE customer_id = c.id
    AND status <> 'cancelled'
  ORDER BY created_at DESC, id DESC
  LIMIT 2
) o ON true
ORDER BY c.name, o.created_at DESC, o.id DESC;
```

Ответ:

```
Аня | 3 | 2024-04-07 09:00:00 | 450.00
Аня | 2 | 2024-04-05 12:00:00 | 300.00
Боря | 7 | 2024-04-02 11:00:00 | 820.00
Боря | 6 | 2024-04-02 11:00:00 | 150.00
Вера | NULL | NULL | NULL
Гоша | 9 | 2024-03-30 08:00:00 | 5000.00
Даша | NULL | NULL | NULL
```

**`LATERAL` — подзапрос во `FROM`, который видит внешнюю строку.** Для
каждого клиента выполняется маленький запрос «мои заказы, свежие сверху,
первые два». Это ровно формулировка задачи, и на индексе
`orders (customer_id, created_at DESC, id DESC)` каждый такой подзапрос
читает две строки, а не всю историю клиента.

**`LEFT JOIN LATERAL … ON true`** сохраняет клиентов, для которых подзапрос
вернул ноль строк: Веру (у неё только отменённый заказ) и Дашу. С
`CROSS JOIN LATERAL` они бы пропали.

**Тай-брейкер — в самом подзапросе.** У Бори три заказа в `11:00:00`; без
`id DESC` внутри `LIMIT 2` выбор двух из трёх зависит от физического порядка
строк, и ответ «плавает». Отмену Ани (`9900`) нужно отсечь *до* `LIMIT`, иначе
она займёт одно из двух мест.

**Альтернатива — окно.** `row_number() OVER (PARTITION BY customer_id ORDER BY
created_at DESC, id DESC)` в CTE и `rn <= 2` снаружи, плюс `LEFT JOIN` от
клиентов. Работает, но нумерует *все* заказы всех клиентов. Спросят дальше:
«когда что быстрее?» — LATERAL выигрывает, когда групп мало, а строк в группе
много и есть индекс; окно — когда нужен проход по всей таблице всё равно.

</Reveal>
