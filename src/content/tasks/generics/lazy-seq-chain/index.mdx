Допишите `Map`, `Filter` и `Take` над `iter.Seq`. Цепочка
`Take(Map(Filter(src, …), …), 3)` должна работать как ленивый конвейер:
ничего не делать, пока её не начали обходить, и брать из источника ровно
столько, сколько нужно.

Что проверяют скрытые тесты:

- построение цепочки не трогает источник и не вызывает функций;
- на бесконечном источнике `Take(…, 3)` завершается и берёт из источника
  ровно столько элементов, сколько понадобилось для трёх ответов, — ни
  одного «на всякий случай»; `f` в `Map` вызывается ровно три раза;
- `Take` с нулём и отрицательным `n` не трогает источник;
- `break` у потребителя останавливает всю цепочку без паники рантайма;
- `Take` от короткого источника отдаёт сколько есть;
- результат `Take` можно обойти дважды — и получить одно и то же.

<Reveal>

```go
func Map[T, U any](seq iter.Seq[T], f func(T) U) iter.Seq[U] {
	return func(yield func(U) bool) {
		for v := range seq {
			if !yield(f(v)) {
				return
			}
		}
	}
}

func Filter[T any](seq iter.Seq[T], keep func(T) bool) iter.Seq[T] {
	return func(yield func(T) bool) {
		for v := range seq {
			if keep(v) && !yield(v) {
				return
			}
		}
	}
}

func Take[T any](seq iter.Seq[T], n int) iter.Seq[T] {
	return func(yield func(T) bool) {
		if n <= 0 {
			return
		}
		i := 0
		for v := range seq {
			if !yield(v) {
				return
			}
			i++
			if i == n {
				return
			}
		}
	}
}
```

**Ленивость бесплатна, если вся работа внутри возвращаемой функции.**
Адаптер лишь запоминает `seq` и `f` в замыкании; источник начинают
обходить, только когда кто-то делает `range` по результату.

**`break` передаётся вверх по цепочке сам.** Когда `yield` потребителя
вернул `false`, адаптер делает `return` из тела своего `range seq` — а это
для вложенного итератора такой же `break`, и его `yield` тоже вернёт
`false`. Позвать `yield` после `false` — паника рантайма.

**Главная ловушка — `Take`, который проверяет счётчик в начале итерации.**
`for v := range seq { if i >= n { return } … }` узнаёт, что пора
остановиться, только получив `(n+1)`-й элемент. Для слайса это
незаметно, а для источника, где каждый элемент — запрос в базу или
чтение из сети, это лишняя работа, для `Filter` — ещё и прокрутка до
следующего подходящего. Проверять надо сразу после `yield`.

**Состояние — внутри обхода, а не в адаптере.** Если объявить `i` снаружи
возвращаемой функции, второй обход того же `Take` начнёт с `i == n` и не
выдаст ничего. `iter.Seq` по соглашению можно обходить повторно, если
источник это позволяет.

**Что спросят дальше:** почему нельзя написать метод `seq.Map(f)` (у
методов не бывает своих параметров типа — только функции), как сделать
`Zip` двух `Seq` (нужен `iter.Pull`) и чем ленивая цепочка лучше
`slices.Collect` на каждом шаге (нет промежуточных слайсов).
