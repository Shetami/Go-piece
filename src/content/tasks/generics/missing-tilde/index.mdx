---
title: Celsius — не float64
description: Sum работает с int и float64, но не принимает тип Celsius, хотя он и есть float64. Почините ограничение.
kind: fix
topic: generics
level: easy
order: 30
---

Программа не компилируется:

```
Celsius does not satisfy Number (possibly missing ~ for float64 in Number)
```

Почините. Ожидаемый вывод:

```
6
21.5
```

<Reveal>

**`type Celsius float64` — новый тип, а не синоним.** У него тот же базовый
тип (`float64`) и то же представление в памяти, но для системы типов это
другой тип. Ограничение `int | float64` перечисляет ровно два типа, и
`Celsius` в этот список не входит.

**Тильда расширяет элемент до всех типов с таким базовым типом:**

```go
type Number interface {
	~int | ~float64
}
```

`~float64` — это `float64`, `Celsius`, `time.Duration`... нет, `Duration` —
это `~int64`. В общем, любой тип, объявленный как `type X float64`.

Компилятор в сообщении подсказывает прямо: «possibly missing ~».

**Когда тильда не нужна.** Когда вы действительно хотите только встроенные
типы — например, потому что внутри вызываете `strconv.FormatFloat`, а для
своих типов у вас другая логика. Но обычно для ограничений на числа и
строки тильда — то, что нужно. Стандартные `cmp.Ordered` и
`constraints.Integer` написаны именно с тильдами.

</Reveal>
