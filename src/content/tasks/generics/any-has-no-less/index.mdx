description: Обобщённая функция Max с параметром типа any сравнивает элементы через >. Компилятор не пропускает. Почините.
kind: fix

`Max` должна работать для чисел и строк. Компилятор отказывается
(точная формулировка зависит от версии Go):

```
invalid operation: x > m (type parameter T cannot use operator >)
```

Почините. Ожидаемый вывод:

```
7
яблоко
2.5
```

<Reveal>

**Ограничение определяет, что можно делать со значением `T`.** `any` — это
«любой тип», включая структуры, слайсы и функции, у которых оператора `>`
нет. Компилятор проверяет тело функции один раз, для всех возможных `T`
сразу, и `x > m` для «любого» типа допустить не может.

**Нужно ограничение, в котором у всех типов есть `<` и `>`** — `cmp.Ordered`
(Go 1.21): все целые, дробные и строки, а также типы на их основе.

```go
func Max[T cmp.Ordered](first T, rest ...T) T
```

**Зачем `first` отдельно.** Так `Max()` без аргументов не скомпилируется, и
не нужно решать, что возвращать для пустого списка. Для слайса есть
`slices.Max`, он для пустого паникует. А для двух значений в Go 1.21
появились встроенные `max` и `min`.

</Reveal>
