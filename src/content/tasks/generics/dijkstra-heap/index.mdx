Допишите `Graph`, `AddEdge` и `ShortestPath`. Сценарий — маршрутизация
между дата-центрами с задержкой в `Millis`, склад с клетками-координатами
или просто города. Вершины — строки, числа или структуры, веса — целые
или дробные.

Что проверяют скрытые тесты:

- самый дешёвый путь может быть длиннее по числу рёбер;
- из параллельных рёбер берётся дешёвое, ребро веса 0 — нормальное;
  граф ориентированный; путь в себя — `[from]`, 0; недостижимая вершина и
  пустой граф — `nil, 0, false`;
- до вершины сначала находится дорогой путь, а потом всё более
  дешёвые, — ответ всё равно верный;
- сетка 150×150 с вершинами-структурами: путь непрерывный, его вес по
  рёбрам совпадает с ответом, и всё быстрее двух секунд.

```go
type item[N comparable, W Weight] struct {
	node N
	dist W
}

type pq[N comparable, W Weight] []item[N, W]

func (q pq[N, W]) Len() int           { return len(q) }
func (q pq[N, W]) Less(i, j int) bool { return q[i].dist < q[j].dist }
func (q pq[N, W]) Swap(i, j int)      { q[i], q[j] = q[j], q[i] }
func (q *pq[N, W]) Push(x any)        { *q = append(*q, x.(item[N, W])) }
func (q *pq[N, W]) Pop() any {
	old := *q
	it := old[len(old)-1]
	*q = old[:len(old)-1]
	return it
}

func (g *Graph[N, W]) ShortestPath(from, to N) ([]N, W, bool) {
	dist := map[N]W{from: 0}
	prev := map[N]N{}
	done := map[N]bool{}
	q := &pq[N, W]{{from, 0}}
	for q.Len() > 0 {
		cur := heap.Pop(q).(item[N, W])
		if done[cur.node] {
			continue
		}
		done[cur.node] = true
		if cur.node == to {
			break
		}
		for _, e := range g.adj[cur.node] {
			nd := cur.dist + e.w
			if d, seen := dist[e.to]; !seen || nd < d {
				dist[e.to] = nd
				prev[e.to] = cur.node
				heap.Push(q, item[N, W]{e.to, nd})
			}
		}
	}
	if !done[to] {
		return nil, 0, false
	}
	path := []N{to}
	for n := to; n != from; {
		n = prev[n]
		path = append(path, n)
	}
	slices.Reverse(path)
	return path, dist[to], true
}
```

**Два параметра типа с разными ограничениями.** Вершине нужно только
`comparable` — она ключ мапы. Весу нужны `+` и `<`, поэтому своё
ограничение `Weight` с тильдами. Сравнимость вершин также позволяет
написать `n != from` при восстановлении пути.

**`container/heap` дружит с дженериками.** Пакет старый и работает через
`heap.Interface` и `any`, но реализовать его может и обобщённый тип
`pq[N, W]`. Приведение `x.(item[N, W])` в `Push`/`Pop` — цена этого
интерфейса; свою типизированную кучу можно написать и без него.

**Устаревшие записи вместо decrease-key.** Когда находится путь дешевле,
мы не ищем старую запись в куче, а кладём новую. Старая всплывёт позже с
большим весом, и `done` её отбросит. Без этой проверки вершина
обработается повторно, и на больших графах это умножает работу.

**Почему не BFS и не «жадно по ближайшему соседу».** BFS находит путь с
наименьшим числом рёбер, а не с наименьшим весом. Дейкстра корректна,
пока веса неотрицательны: вершина, снятая с кучи, уже не станет дешевле,
поэтому можно выйти, как только сняли `to`.

**Что спросят дальше:** что делать с отрицательными весами
(Беллман — Форд), как ускорить поиск на карте (A* с эвристикой) и почему
`prev` хранит одного предка, хотя кратчайших путей может быть несколько.
