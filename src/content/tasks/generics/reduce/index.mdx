Напишите тело `Reduce`.

Что проверяют скрытые тесты:

- сумма чисел;
- тип аккумулятора отличается от элементов: сумма длин строк в `int`;
- порядок слева направо: `">" + "a" + "b" + "c"`;
- аккумулятор — мапа.

<Reveal>

```go
func Reduce[T, A any](xs []T, init A, f func(A, T) A) A {
	acc := init
	for _, x := range xs {
		acc = f(acc, x)
	}
	return acc
}
```

**Зачем второй параметр типа.** С одним `T` для всего получилась бы только
свёртка «числа в число». Отдельный `A` позволяет свернуть строки в число,
события в мапу, что угодно во что угодно.

**Оба выводятся сами.** `Reduce(words, 0, func(a int, s string) int {...})`
— компилятор видит `[]string` и `int` и выводит `T = string`, `A = int`.
Указывать `Reduce[string, int]` не нужно.

**Почему в Go такое пишут редко.** Цикл `for` на три строки обычно
читается лучше, чем `Reduce` с анонимной функцией, — и в стандартной
библиотеке `Reduce` нет. На собеседовании задача проверяет не
функциональный стиль, а умение обращаться с несколькими параметрами типа и
выводом типов.

</Reveal>
