Программа печатает:

```
7
0
0
```

Для `[-5 -2 -9]` ответ должен быть `-2`, для `[-0.5 -1.5]` — `-0.5`.
Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 10: `var m T`.

**Нулевое значение — не нейтральный элемент для максимума.** `var m T`
начинает с нуля. Если все элементы отрицательные, ни один не больше нуля,
`m` так и остаётся нулём — числом, которого в слайсе вообще не было.

В обычном коде с `int` написали бы `math.MinInt`. В обобщённом коде такой
константы нет: `T` может быть и `int8`, и `float64`, и `string`. Честный
способ один — начать с первого элемента:

```go
m := xs[0]
for _, x := range xs[1:] { ... }
```

**А если слайс пустой?** Тогда `xs[0]` паникует. Варианты: так и оставить,
задокументировав «непустой слайс» (так делает `slices.Max`), или вернуть
второе значение: `func Max[T cmp.Ordered](xs []T) (T, bool)`. Возвращать
нулевое значение без флага — та же ошибка, что в задаче, только спрятанная
глубже.

И не пишите свой: в стандартной библиотеке есть `slices.Max` и встроенный
`max`.

</Reveal>
