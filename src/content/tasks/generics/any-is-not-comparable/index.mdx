---
title: Сравнить через == то, что может быть чем угодно
description: Обобщённый Index сравнивает элементы через ==. Компилятор не пропускает. Почините ограничение.
kind: fix
topic: generics
level: easy
order: 20
---

Программа не компилируется:

```
incomparable types in type set
```

Почините. Ожидаемый вывод:

```
1
-1
```

<Reveal>

**Ограничение — это всё, что компилятор знает о типе.** `any` разрешает
подставить любой тип, включая слайсы, мапы и функции, у которых `==` нет.
Раз хотя бы для одного допустимого `T` выражение `x == target` не имеет
смысла, компилятор не пропускает его ни для какого.

**Как чинят** — просить ровно то, что используешь:

```go
func Index[T comparable](xs []T, target T) int
```

`comparable` — встроенное ограничение: «типы, у которых есть `==`». Теперь
`Index([][]int{...}, ...)` не скомпилируется, и это правильно: сравнивать
слайсы нечем.

**Нюанс.** С Go 1.20 `comparable` пропускает и интерфейсы, включая `any`.
`Index([]any{[]int{1}}, any([]int{1}))` скомпилируется — и запаникует в
рантайме на сравнении слайсов. Ограничение гарантирует, что `==`
существует, но не что оно не упадёт.

И не пишите свой `Index` — есть `slices.Index`, с тем же ограничением.

</Reveal>
