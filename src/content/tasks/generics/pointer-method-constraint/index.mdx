`Parse` должна создать значение и заполнить его через `Set`. Метод `Set`
объявлен на `*Config`, поэтому вызывают `Parse[*Config]`. Программа падает:

```
panic: runtime error: invalid memory address or nil pointer dereference
```

Почините так, чтобы вызов выглядел как `Parse[Config]("prod")` и
возвращал значение. Ожидаемый вывод:

```
{Env:prod}
```

<Reveal>

**`var v T` для указательного `T` — это `nil`.** `T` здесь `*Config`, и
нулевое значение указателя — `nil`. Никакой структуры `Config` никто не
создал. `v.Set(s)` вызывает метод на `nil`-указателе, и запись в `c.Env`
падает.

Хочется написать `Parse[Config]`, но `Config` не реализует `Setter`: `Set`
есть только у `*Config`. Замкнутый круг: значение не подходит под
ограничение, а указатель нечем инициализировать.

**Как чинят** — второй параметр типа, который описывает указатель на
первый:

```go
func Parse[T any, PT interface {
	*T
	Setter
}](s string) T {
	var v T
	PT(&v).Set(s)
	return v
}
```

Ограничение для `PT` говорит: «это ровно `*T`, и у него есть `Set`». Теперь
`var v T` создаёт настоящую структуру, `&v` — её адрес, а приведение к `PT`
разрешает вызвать `Set`. Вызывающий пишет `Parse[Config]("prod")`, а `PT`
компилятор выводит сам.

**Где это встречается.** Обобщённое чтение из базы или декодирование в
структуры, у которых `Scan` или `UnmarshalText` объявлены на указателе. Это
самый частый «продвинутый» шаблон дженериков в реальном коде, и о нём
любят спрашивать.

</Reveal>
