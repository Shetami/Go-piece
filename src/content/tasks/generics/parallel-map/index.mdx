Допишите `ParallelMap`. Типичное применение — сходить за профилями ста
пользователей в соседний сервис, не открывая сто соединений разом и не
дожидаясь всех, если сервис уже ответил ошибкой.

Что проверяют скрытые тесты:

- результаты стоят по индексам входа, хотя вызовы заканчиваются в
  обратном порядке;
- одновременно работает не больше `limit` вызовов `f` (и всё же больше
  одного); `limit = 0` — строго по одному;
- при ошибке одного `f` возвращается именно она, а не `context.Canceled`
  от остальных; остальные `f` получают отменённый контекст, новые почти
  не запускаются, и вызов не ждёт секундных задач;
- отмена внешнего контекста — `context.Canceled`, и новые `f` не стартуют;
- после возврата не остаётся горутин, и ничего не зависает.

<Reveal>

```go
func ParallelMap[T, U any](ctx context.Context, in []T, limit int, f func(context.Context, T) (U, error)) ([]U, error) {
	if limit <= 0 {
		limit = 1
	}
	ctx, cancel := context.WithCancel(ctx)
	defer cancel()

	out := make([]U, len(in))
	sem := make(chan struct{}, limit)
	var (
		wg       sync.WaitGroup
		once     sync.Once
		firstErr error
	)
	stopped := false
	for i, v := range in {
		select {
		case sem <- struct{}{}:
		case <-ctx.Done():
		}
		if ctx.Err() != nil {
			stopped = true
			break
		}
		wg.Add(1)
		go func() {
			defer func() { <-sem; wg.Done() }()
			u, err := f(ctx, v)
			if err != nil {
				once.Do(func() { firstErr = err; cancel() })
				return
			}
			out[i] = u
		}()
	}
	wg.Wait()

	if firstErr != nil {
		return nil, firstErr
	}
	if stopped {
		return nil, ctx.Err()
	}
	return out, nil
}
```

**Дженерики убирают `any` из конкурентного кода.** До них такой хелпер
принимал `[]any` и возвращал `[]any`, и каждый вызов обрастал
приведениями типов. Здесь `T` и `U` выводятся из `in` и `f`, и результат
сразу `[]User`.

**Порядок — через индекс, а не через канал результатов.** Каждая
горутина пишет в свой `out[i]`: разные элементы слайса — разные
переменные, гонки нет. Канал с результатами пришлось бы сортировать.

**Семафор берём до `go`, а не внутри горутины.** Тогда цикл сам ждёт
свободного слота и видит отмену: как только кто-то упал, новых вызовов
нет. Если запустить сто горутин сразу, а лимит проверять внутри, после
ошибки все сто всё равно дойдут до `f`. Перепроверка `ctx.Err()` после
`select` нужна потому, что при готовности обеих веток `select` выбирает
случайно.

**Первая ошибка — через `sync.Once` вместе с `cancel()`.** Остальные `f`
вернут `context.Canceled`, но к этому моменту первая ошибка уже
записана, и именно её получит вызывающий. `wg.Wait()` обязателен: без
него горутины переживут вызов и будут писать в слайс, который уже
отдали наружу.

**Что спросят дальше:** чем это отличается от `errgroup.WithContext` +
`SetLimit` (по сути ничем — это он и есть), как вернуть все ошибки через
`errors.Join` вместо первой и как сделать потоковую версию на `iter.Seq`,
когда вход не помещается в память.
