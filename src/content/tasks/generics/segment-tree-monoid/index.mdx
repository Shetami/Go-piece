Допишите `SegTree[T]`. Обобщать здесь нужно не только тип, но и
операцию: для метрик — минимум задержки на отрезке времени, для ленты
событий — склейка, для счётчиков — сумма.

Что проверяют скрытые тесты:

- минимум на отрезке, пустой отрезок — нейтральный элемент;
- правка исходного слайса после `NewSegTree` не влияет на дерево;
- склейка строк: для неё важен порядок, и `Query` обязан
  объединять строго слева направо;
- длины 1, 2, 13, 64, 100 и 500 случайных `Set`/`Query` на каждой
  сверяются со `strings.Join`;
- 100 000 `Set` и `Query` — быстрее секунды.

<Reveal>

```go
type SegTree[T any] struct {
	n       int
	t       []T
	id      T
	combine func(a, b T) T
}

func NewSegTree[T any](vals []T, identity T, combine func(a, b T) T) *SegTree[T] {
	n := len(vals)
	s := &SegTree[T]{n: n, t: make([]T, 2*n), id: identity, combine: combine}
	copy(s.t[n:], vals)
	for i := n - 1; i > 0; i-- {
		s.t[i] = combine(s.t[2*i], s.t[2*i+1])
	}
	return s
}

func (s *SegTree[T]) Set(i int, v T) {
	i += s.n
	s.t[i] = v
	for i >>= 1; i > 0; i >>= 1 {
		s.t[i] = s.combine(s.t[2*i], s.t[2*i+1])
	}
}

func (s *SegTree[T]) Query(l, r int) T {
	if l >= r {
		return s.id
	}
	left, right := s.id, s.id
	for l, r = l+s.n, r+s.n; l < r; l, r = l>>1, r>>1 {
		if l&1 == 1 {
			left = s.combine(left, s.t[l])
			l++
		}
		if r&1 == 1 {
			r--
			right = s.combine(s.t[r], right)
		}
	}
	return s.combine(left, right)
}
```

**Моноид вместо ограничения на тип.** Для суммы хватило бы
`Number`, но минимум и склейку ограничением не выразить. Поэтому `T any`,
а операция и её нейтральный элемент приходят аргументами. Требования к
ним — ассоциативность и `combine(id, x) == x`, — компилятор проверить не
может, их пишут в контракте.

**Нерекурсивное дерево в слайсе `2n`.** Листья лежат в `t[n:]`, родитель
узла `i` — `i/2`. Так дерево работает и для `n`, не равного степени
двойки: часть внутренних узлов склеивает конец массива с началом, но
запрос снизу вверх берёт только узлы, целиком лежащие внутри `[l, r)`,
и в такие не попадает.

**Два аккумулятора — ключ к порядку.** На каждом уровне левая граница
может забрать узел справа от себя, а правая — слева. Если складывать всё
в одну переменную, узлы правой границы приклеятся в порядке подъёма, то
есть задом наперёд. Для `min` и `+` этого не видно, склейка строк
ломается сразу.

**`copy`, а не срез `vals`.** Дерево должно владеть своими данными,
иначе вызывающий, переиспользуя буфер, тихо портит все будущие ответы.

**Что спросят дальше:** как сделать изменение на отрезке (ленивое
распространение), чем это лучше дерева Фенвика (любая ассоциативная
операция, а не только обратимая) и как найти первый элемент меньше `x`
спуском по дереву.
