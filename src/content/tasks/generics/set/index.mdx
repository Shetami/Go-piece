Допишите `Set`: конструктор, `Add`, `Has`, `Union`, `Intersect`.

Что проверяют скрытые тесты:

- `NewSet(1, 2, 2, 3)` — три элемента, `Add` и `Has` работают;
- `NewSet[string]()` без аргументов возвращает множество, в которое можно
  добавлять, а не `nil`;
- объединение и пересечение правильные, исходные множества не меняются,
  результат не делит с ними память.

<Reveal>

```go
type Set[T comparable] map[T]struct{}

func NewSet[T comparable](items ...T) Set[T] {
	s := make(Set[T], len(items))
	for _, v := range items {
		s.Add(v)
	}
	return s
}

func (s Set[T]) Add(v T) { s[v] = struct{}{} }
```

**Почему `Add` на значении работает.** Обычно меняющий метод объявляют на
указателе. Но `Set` — это мапа, а значение мапы — указатель на внутреннюю
структуру. Копия `s` в получателе указывает туда же, и запись видна всем.
Не работало бы только пересоздание мапы внутри метода (`s = make(...)`).

**`nil`-множество.** Нулевое значение `Set` — `nil`-мапа: `Has` на ней
работает (чтение безопасно), а `Add` паникует. Поэтому конструктор всегда
делает `make`, даже без аргументов, — второй тест про это.

**Пересечение от меньшего.** Обходим меньшее множество и проверяем в
большем: O(min(n, m)) вместо O(n).

**В стандартной библиотеке множества нет** — ни раньше, ни с дженериками.
`map[T]struct{}` на месте и `maps`/`slices` для операций — обычный ответ.

</Reveal>
