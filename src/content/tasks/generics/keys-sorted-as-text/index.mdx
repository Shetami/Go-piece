`SortedKeys` должна работать для любых ключей. Ключам нужно сравнение, а
у `comparable` есть только `==`, поэтому автор сравнивает текстовое
представление. Программа печатает этажи так:

```
1 ресепшн
10 директор
2 бухгалтерия
9 склад
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 14: сравнение через `fmt.Sprint`.

**Строки сравниваются посимвольно.** `"10" < "2"`, потому что
`'1' < '2'`, — дальше сравнение не идёт. Для чисел текстовый порядок совпадает с
числовым только при одинаковой длине записи. А ещё `fmt.Sprint` на
каждое сравнение — это выделения памяти и работа форматирования,
`O(n log n)` раз.

**Правильное ограничение — `cmp.Ordered`**, а не `comparable`. Оно
пропускает только типы, у которых есть `<`: числа и строки (и типы на их
основе). Тогда можно сравнивать по-настоящему:

```go
func SortedKeys[K cmp.Ordered, V any](m map[K]V) []K {
	keys := slices.Collect(maps.Keys(m))
	slices.Sort(keys)
	return keys
}
```

**Если ключ не упорядочен** (структура), честнее принять функцию
сравнения, как `slices.SortFunc`, чем выдумывать порядок через текст.

</Reveal>
