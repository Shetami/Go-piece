Допишите `Merge`. Так сливают отсортированные по времени логи с
нескольких реплик, результаты запросов к шардам с сортировкой или
отсортированные куски при внешней сортировке. Источников тысячи, и они
не помещаются в память.

Что проверяют скрытые тесты:

- обычное слияние с пустым источником и без источников вовсе;
- равные по `cmp` элементы идут в порядке номеров источников, а внутри
  источника — как были;
- три бесконечных источника: построение `Merge` ничего не читает, из
  каждого берётся не больше одного элемента впрок, после `break` все
  три источника завершены (их `defer` выполнился);
- 5000 источников по 40 элементов — порядок не нарушен, все на месте, и
  быстрее трёх секунд.

<Reveal>

```go
type head[T any] struct {
	val  T
	src  int
	next func() (T, bool)
}

type heads[T any] struct {
	items []head[T]
	cmp   func(a, b T) int
}

func (h *heads[T]) Len() int { return len(h.items) }
func (h *heads[T]) Less(i, j int) bool {
	if c := h.cmp(h.items[i].val, h.items[j].val); c != 0 {
		return c < 0
	}
	return h.items[i].src < h.items[j].src
}
func (h *heads[T]) Swap(i, j int) { h.items[i], h.items[j] = h.items[j], h.items[i] }
func (h *heads[T]) Push(x any)   { h.items = append(h.items, x.(head[T])) }
func (h *heads[T]) Pop() any {
	it := h.items[len(h.items)-1]
	h.items = h.items[:len(h.items)-1]
	return it
}

func Merge[T any](cmp func(a, b T) int, seqs ...iter.Seq[T]) iter.Seq[T] {
	return func(yield func(T) bool) {
		h := &heads[T]{cmp: cmp}
		for i, s := range seqs {
			next, stop := iter.Pull(s)
			defer stop()
			if v, ok := next(); ok {
				h.items = append(h.items, head[T]{v, i, next})
			}
		}
		heap.Init(h)
		for h.Len() > 0 {
			top := &h.items[0]
			if !yield(top.val) {
				return
			}
			if v, ok := top.next(); ok {
				top.val = v
				heap.Fix(h, 0)
			} else {
				heap.Pop(h)
			}
		}
	}
}
```

**Push-итератор нельзя «попросить следующий».** `iter.Seq` сам зовёт
`yield`, когда хочет, поэтому обходить два `Seq` попеременно через
`range` невозможно. `iter.Pull` превращает его в пару `next`/`stop`:
`next()` отдаёт по одному элементу, а источник живёт в отдельной
сопрограмме.

**`stop` — обязательная часть контракта.** Если потребитель сделал
`break`, источник так и остаётся на паузе внутри своего `yield`: его
`defer` (закрыть файл, курсор, соединение) не выполнится, а сопрограмма
висит. `defer stop()` в цикле — редкий случай, когда `defer` в цикле
уместен: все они выполнятся при выходе из `Merge`. `stop` и у
неначатого, и у закончившегося источника безопасен.

**Куча по «головам» даёт `O(N log k)`.** Перебор голов каждый раз стоит
`O(k)` на элемент, и для 5000 источников это в тысячи раз медленнее.
`heap.Fix(h, 0)` после замены вершины дешевле пары `Pop` + `Push`.

**Стабильность — через номер источника в `Less`.** Куча нестабильна,
поэтому при равных значениях порядок задаём явно. Внутри источника
порядок сохраняется сам: у источника в куче всегда один элемент.

**Что спросят дальше:** как слить без `iter.Pull` (читать источники в
каналы — дороже и сложнее отменить), как сделать дедупликацию равных
ключей при слиянии и где это применяется (компакция LSM-дерева, `ORDER BY`
по шардам).
