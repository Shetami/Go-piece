Реализуйте `Queue[T]`. Поля — на ваше усмотрение. Нулевое значение
`Queue` должно быть рабочей пустой очередью.

Что проверяют скрытые тесты:

- порядок FIFO, `Pop` на пустой — нулевое значение и `false`;
- тысяча чередующихся `Push` и `Pop`: голова обходит буфер по кругу много
  раз, буфер растёт, порядок не сбивается;
- `var q Queue[float64]` сразу готова к работе.

<Reveal>

```go
type Queue[T any] struct {
	buf  []T
	head int
	n    int
}

func (q *Queue[T]) Push(v T) {
	if q.n == len(q.buf) {
		q.grow()
	}
	q.buf[(q.head+q.n)%len(q.buf)] = v
	q.n++
}
```

**Почему не `q.items = q.items[1:]`.** Самая простая очередь на слайсе —
`append` в конец и срез с начала. Она работает, но срез не освобождает
начало массива: память под давно извлечённые элементы висит, пока
`append` не перевыделит массив. Кольцевой буфер переиспользует ячейки.

**Голова и счётчик.** Хранить `head` и `n` проще, чем `head` и `tail`: с
двумя индексами полная и пустая очереди выглядят одинаково (`head == tail`),
и нужен лишний флаг. Позиция для записи — `(head + n) % len(buf)`.

**Рост с «распрямлением».** При удвоении элементы копируются по порядку
в начало нового буфера, и `head` становится 0. Просто скопировать
массив как есть нельзя: элементы, перешедшие через конец, окажутся не на
своих местах.

**Обнуление при `Pop`.** Если `T` — указатель или содержит указатели, ячейка
продолжала бы держать объект, и сборщик мусора не смог бы его освободить.

</Reveal>
