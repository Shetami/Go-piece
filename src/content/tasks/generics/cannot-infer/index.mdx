---
title: Компилятор не угадывает тип результата
description: Обобщённый Parse возвращает int или float64. Вызов Parse("8080") не компилируется. Почините.
kind: fix
topic: generics
level: easy
order: 130
---

`Parse` умеет разбирать строку и как целое, и как дробное. Компилятор
отказывается:

```
in call to Parse, cannot infer T
```

Почините. Ожидаемый вывод:

```
8081 1.5
```

<Reveal>

**Тип выводится только из аргументов.** У `Parse` единственный аргумент —
`string`, а `T` встречается только в результате. То, куда результат потом
присвоят, для вывода не используется: `port, err := Parse("8080")` не
говорит компилятору ничего — у `port` типа ещё нет, он появится из
результата.

**Как правильно** — указать тип явно:

```go
port, err := Parse[int]("8080")
ratio, err := Parse[float64]("0.75")
```

**Где ещё так.** `Zero[T]()`, `New[T]()`, `json`-декодер вида
`Decode[T](data)` — любая функция, где параметр типа есть только в
результате, требует явного указания. Это нормально и даже читается лучше:
тип виден прямо в вызове.

</Reveal>
