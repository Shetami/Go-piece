Допишите `UnmarshalJSON`, `Get` и `Apply` у `Field[T]`. Задача из
любого REST API с `PATCH`: `{"nick": null}` значит «стереть ник», пустой
объект — «ничего не менять», а `{"age": 0}` — «возраст ноль». Указатель
`*int` в DTO различает только два состояния из трёх.

Что проверяют скрытые тесты:

- отсутствующий ключ, `null`, ноль и вложенный объект дают разные
  состояния;
- `Get` возвращает `true` только для настоящего значения;
- строка в поле `Field[int]` — ошибка разбора;
- `Apply` к колонке-указателю: отсутствующее поле не трогает её (тот же
  указатель), значение записывается новой копией — старая переменная не
  меняется, и дальнейшие правки запроса не видны в колонке; `null`
  обнуляет колонку.

<Reveal>

```go
func (f *Field[T]) UnmarshalJSON(data []byte) error {
	f.Present = true
	if bytes.Equal(data, []byte("null")) {
		f.Null = true
		var zero T
		f.Value = zero
		return nil
	}
	f.Null = false
	return json.Unmarshal(data, &f.Value)
}

func (f Field[T]) Get() (T, bool) {
	if !f.Present || f.Null {
		var zero T
		return zero, false
	}
	return f.Value, true
}

func (f Field[T]) Apply(dst **T) {
	switch {
	case !f.Present:
	case f.Null:
		*dst = nil
	default:
		v := f.Value
		*dst = &v
	}
}
```

**«Ключ был» узнаём по самому вызову.** `encoding/json` зовёт
`UnmarshalJSON` поля только тогда, когда ключ есть в объекте, в том
числе для `null`. Если ключа нет, поле остаётся нулевым, и
`Present == false` получается само.

**Бесконечная рекурсия — главная ловушка.** Хочется написать
`json.Unmarshal(data, f)`, но `*Field[T]` сам реализует `Unmarshaler`, и
пакет снова вызовет этот же метод, пока не переполнится стек. Разбирать
нужно в `&f.Value`: у `T` свой способ разбора, в том числе для вложенных
структур.

**Один тип вместо десятка.** До дженериков писали `NullableString`,
`NullableInt`, `NullableTime`, как в `database/sql` (`sql.NullString`…).
С параметром типа хватает одного `Field[T]`, а в Go 1.22 и в
`database/sql` появился обобщённый `sql.Null[T]`.

**`Apply` пишет в новую переменную.** Колонка не должна делить память ни
со старым значением (иначе `*r.Age = 31` поменяло бы переменную, на
которую она указывала), ни с запросом.

**Что спросят дальше:** как сделать `MarshalJSON`, чтобы отсутствующее
поле не попадало в ответ (в Go 1.24 появился тег `omitzero`, раньше —
только своим `MarshalJSON` у всей структуры), и как валидировать PATCH,
где часть полей запрещено обнулять.

</Reveal>
