Допишите `TopoSort`. Так определяют порядок старта компонентов сервиса,
применения миграций или сборки пакетов: каждый — после своих
зависимостей, а на цикл — ошибка, по которой сразу видно, где искать.

Что проверяют скрытые тесты:

- ответ одинаковый на каждом из двадцати запусков, хотя граф пришёл
  мапой, — из готовых узлов первым идёт наименьший;
- узлы, которые есть только в списках зависимостей, тоже в ответе;
  повторная зависимость не ломает подсчёт; свой тип `type Migration int`;
- пустой граф — пустой ответ без ошибки;
- при цикле `errors.Is(err, ErrCycle)`, а в тексте — все узлы, которые не
  удалось упорядочить, по возрастанию: и сам цикл, и то, что от него
  зависит; зависимость от самого себя — тоже цикл.

```go
func TopoSort[N cmp.Ordered](deps map[N][]N) ([]N, error) {
	indeg := map[N]int{}
	users := map[N][]N{}
	for n, ds := range deps {
		if _, ok := indeg[n]; !ok {
			indeg[n] = 0
		}
		for _, d := range ds {
			if _, ok := indeg[d]; !ok {
				indeg[d] = 0
			}
			indeg[n]++
			users[d] = append(users[d], n)
		}
	}

	var ready []N
	for n, k := range indeg {
		if k == 0 {
			ready = append(ready, n)
		}
	}
	slices.Sort(ready)

	out := make([]N, 0, len(indeg))
	for len(ready) > 0 {
		n := ready[0]
		ready = ready[1:]
		out = append(out, n)
		for _, u := range users[n] {
			indeg[u]--
			if indeg[u] == 0 {
				i, _ := slices.BinarySearch(ready, u)
				ready = slices.Insert(ready, i, u)
			}
		}
	}

	if len(out) < len(indeg) {
		var rest []N
		for n, k := range indeg {
			if k > 0 {
				rest = append(rest, n)
			}
		}
		slices.Sort(rest)
		return nil, fmt.Errorf("%w: %v", ErrCycle, rest)
	}
	return out, nil
}
```

**Алгоритм Кана.** Считаем у каждого узла число невыписанных
зависимостей. Узлы с нулём готовы; выписав узел, уменьшаем счётчик у
всех, кто от него зависит. Если готовые кончились, а выписаны не все, у
оставшихся счётчики никогда не обнулятся — это цикл или то, что от
цикла зависит.

**Детерминированность — требование, а не украшение.** Обход мапы в Go
случаен, и без правила выбора порядок миграций менялся бы от запуска к
запуску. `cmp.Ordered` нужен ровно для этого: из готовых берём наименьший,
а готовые держим отсортированными (`BinarySearch` + `Insert`). Для
больших графов здесь ставят кучу.

**Все узлы — и ключи, и значения.** `config` нигде не ключ, но от него
зависят другие; если строить `indeg` только по ключам, он пропадёт из
ответа, а его пользователи никогда не станут готовыми. Повторная
зависимость безопасна, пока каждое ребро и считается, и снимается — по
разу на вхождение.

**Ошибка через `%w`.** Вызывающий проверяет `errors.Is(err, ErrCycle)`, а
человек в логе видит, какие узлы застряли. `%v` для `[]N` печатает
слайс в квадратных скобках — для строк и чисел одинаково.

**Что спросят дальше:** как вывести именно цикл, а не всё застрявшее
(поиск в глубину с цветами), как запускать независимые узлы параллельно
(уровни Кана) и что делать, если узлы — не `cmp.Ordered`, а
`comparable` (принять функцию сравнения).
