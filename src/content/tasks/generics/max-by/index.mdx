Напишите тело `MaxBy`.

Что проверяют скрытые тесты:

- сотрудник с наибольшей зарплатой;
- ключ может быть строкой, а может быть длиной строки; из равных по
  ключу выбирается первый;
- пустой вход → нулевое значение и `false`;
- все ключи отрицательные — ответ всё равно правильный;
- `key` вызывается не больше раза на элемент.

<Reveal>

```go
func MaxBy[T any, K cmp.Ordered](s []T, key func(T) K) (T, bool) {
	if len(s) == 0 {
		var zero T
		return zero, false
	}
	best, bestKey := s[0], key(s[0])
	for _, x := range s[1:] {
		if k := key(x); k > bestKey {
			best, bestKey = x, k
		}
	}
	return best, true
}
```

**Ограничения разные у разных параметров.** Сами элементы сравнивать не
нужно — `T` может быть любым. Сравниваются ключи — им нужен
`cmp.Ordered`.

**Стартуем с первого элемента, а не с нуля.** Начальное значение `0`
сломалось бы на отрицательных ключах, а для строк его и не записать.

**Ключ лучшего запоминаем.** Сравнение `key(x) > key(best)` вызывало бы
`key` дважды на шаг — дорого, если ключ вычисляется.

**`>` вместо `>=`** оставляет первый из равных — поведение, которое легко
описать и проверить. В стандартной библиотеке ближе всего
`slices.MaxFunc` с функцией сравнения; при равенстве она тоже берёт
первый.

</Reveal>
