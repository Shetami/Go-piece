Допишите `Fenwick[T]`. Задача — выручка по минутам суток для дашборда:
значения постоянно дописываются, а запросы «сумма с 10:00 до 10:15»
приходят тысячами. Деньги хранятся в `type Cents int64`, средний чек — во
`float64`, и структура должна быть одна.

Что проверяют скрытые тесты:

- `Add(0, …)` не зависает, первый и последний элементы учитываются,
  `Sum(0)` — пустой префикс;
- `Fenwick[Cents]` со своим типом; `Set` поверх уже добавленного, `Set`
  тем же значением ничего не меняет; `RangeSum(3, 1)` — ноль;
- `float64`;
- 5000 случайных `Add`/`Set` сверяются с прямым подсчётом по слайсу;
- 200 000 операций — быстрее секунды.

```go
type Number interface {
	~int | ~int32 | ~int64 | ~float64
}

type Fenwick[T Number] struct {
	tree []T
	vals []T
}

func NewFenwick[T Number](n int) *Fenwick[T] {
	return &Fenwick[T]{tree: make([]T, n+1), vals: make([]T, n)}
}

func (f *Fenwick[T]) Add(i int, delta T) {
	f.vals[i] += delta
	for i++; i < len(f.tree); i += i & -i {
		f.tree[i] += delta
	}
}

func (f *Fenwick[T]) Set(i int, v T) {
	f.Add(i, v-f.vals[i])
}

func (f *Fenwick[T]) Sum(i int) T {
	var s T
	for ; i > 0; i -= i & -i {
		s += f.tree[i]
	}
	return s
}

func (f *Fenwick[T]) RangeSum(l, r int) T {
	if l >= r {
		return 0
	}
	return f.Sum(r) - f.Sum(l)
}
```

**Тильда в ограничении.** `int64` в объединении пускает только сам
`int64`, а `~int64` — любой тип, у которого он в основе, в том числе
`Cents`. Без тильды `NewFenwick[Cents]` не скомпилируется. `+`, `-` и
литерал `0` разрешены, потому что они есть у каждого типа из набора.

**Индексы с единицы внутри.** Ячейка `tree[i]` хранит сумму `lowbit(i)`
элементов, заканчивающихся на `i`, где `lowbit(i) = i & -i`. У нуля
младшего бита нет: `0 & -0 == 0`, и цикл `i += i & -i` с нуля стоит на
месте вечно. Отсюда `i++` на входе в `Add` и `tree` длиной `n+1`.

**`Set` требует текущего значения.** Дерево хранит только частичные
суммы, отдельный элемент из него достаётся за `O(log n)` через разность
префиксов. Проще держать `vals` рядом и превращать `Set` в
`Add(v - old)`.

**`RangeSum` — разность двух префиксов.** Это работает, потому что
сложение обратимо. Для минимума или максимума вычитать нечего, там нужно
дерево отрезков. А с `float64` разность префиксов копит ошибку
округления, поэтому деньги держат в целых копейках.

**Что спросят дальше:** что изменится, если добавить в `Number` `~uint64`
(отрицательную дельту в `Add` уже не передать, хотя внутри модульная
арифметика сойдётся), как построить дерево из готового
слайса за `O(n)` и как искать «первую позицию, где префикс ≥ x» спуском
по битам.
