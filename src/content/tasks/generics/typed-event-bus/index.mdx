Допишите `Bus`, `Subscribe` и `Publish`. Модули монолита общаются
событиями: биллинг подписан на `UserCreated`, поиск — на `UserDeleted`,
и никто не хочет писать `e.(UserCreated)` в каждом обработчике.

Что проверяют скрытые тесты:

- событие доходит только до подписчиков ровно его типа, в порядке
  подписки; тип с той же структурой, но другим именем — другое событие;
  подписчик на `any` не ловит всё подряд;
- повторный вызов отписки не снимает соседний обработчик;
- обработчик отписывается, подписывает новый и публикует другое событие
  прямо во время `Publish` — ничего не виснет, а изменения подписок
  действуют со следующего `Publish`;
- восемь горутин параллельно подписываются, публикуют и отписываются —
  чисто под `-race`.

<Reveal>

```go
type subscriber struct {
	id uint64
	fn any
}

type topic[E any] struct{}

type Bus struct {
	mu   sync.Mutex
	next uint64
	subs map[any][]subscriber
}

func Subscribe[E any](b *Bus, h func(E)) (unsubscribe func()) {
	b.mu.Lock()
	defer b.mu.Unlock()
	if b.subs == nil {
		b.subs = make(map[any][]subscriber)
	}
	b.next++
	id := b.next
	k := topic[E]{}
	b.subs[k] = append(b.subs[k], subscriber{id: id, fn: h})

	var once sync.Once
	return func() {
		once.Do(func() {
			b.mu.Lock()
			defer b.mu.Unlock()
			b.subs[k] = slices.DeleteFunc(b.subs[k], func(s subscriber) bool { return s.id == id })
		})
	}
}

func Publish[E any](b *Bus, e E) int {
	b.mu.Lock()
	hs := slices.Clone(b.subs[topic[E]{}])
	b.mu.Unlock()
	for _, s := range hs {
		s.fn.(func(E))(e)
	}
	return len(hs)
}
```

**Ключ по типу без `reflect`.** `topic[E]{}` — пустая структура, но у
каждого `E` это отдельный тип, а интерфейсы с разными динамическими
типами как ключи мапы не равны. Годится и `reflect.TypeFor[E]()`, но
пустой тип-маркер дешевле. Хранить обработчики приходится как `any` —
разнотипные `func(E)` в одну мапу иначе не положить, — зато приведение
`s.fn.(func(E))` спрятано внутри и всегда успешно.

**Методов с параметрами типа в Go нет.** `b.Subscribe[E](h)` не
скомпилируется, поэтому API — функции пакета, принимающие `*Bus`. `E`
выводится из типа обработчика и из события.

**Обработчики зовём без замка, по снимку.** Если держать `mu` во время
вызова, `Publish` изнутри обработчика повиснет — `sync.Mutex` не
реентерабельный. А если отпустить замок, но обходить живой слайс, то
отписка во время обхода сдвинет элементы, и кто-то будет пропущен
или вызван дважды. `slices.Clone` под замком решает обе проблемы.

**Отписка по id, а не по функции и не по индексу.** Функции в Go
несравнимы, а индекс устаревает после первой же чужой отписки. `sync.Once`
делает повторную отписку безвредной.

**Что спросят дальше:** как доставлять асинхронно (канал на подписчика и
что делать с медленным — backpressure или дроп), как ловить панику
одного обработчика, чтобы она не мешала остальным, и нужна ли подписка
на интерфейс (`Publish` события, реализующего `Auditable`).
