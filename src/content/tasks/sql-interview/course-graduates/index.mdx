Онлайн-школа хочет вывесить доску выпускников.

Студент **окончил курс**, если он записан на этот курс (`enrollments`) и
сдал **все обязательные** уроки курса. Урок сдан, если хотя бы одна
попытка набрала 60 баллов или больше. Попыток может быть сколько угодно,
в том числе после успешной. Необязательные уроки (`is_optional`) на
окончание не влияют — ни в плюс, ни в минус. Попытки по курсам, на которые
студент не записан, не считаются.

**Дата окончания** — день, когда был сдан последний из обязательных уроков.
Урок считается сданным в день **первой** успешной попытки: пересдачи на
более высокий балл дату не сдвигают.

Нужны только выпускники:

- колонки: `course`, `place`, `student`, `finished_on`;
- `place` — порядковый номер внутри курса по дате окончания, кто раньше —
  тот выше; при одинаковой дате — по имени. Номера без повторов: 1, 2, 3;
- порядок: `course`, `place`.

<Reveal>

```sql
WITH first_pass AS (
  SELECT student_id, lesson_id, min(submitted_at) AS passed_on
  FROM submissions
  WHERE score >= 60
  GROUP BY student_id, lesson_id
),
required AS (
  SELECT course_id, count(*) AS lessons
  FROM lessons
  WHERE NOT is_optional
  GROUP BY course_id
),
progress AS (
  SELECT e.course_id, e.student_id,
         count(*)          AS passed,
         max(fp.passed_on) AS finished_on
  FROM enrollments e
  JOIN lessons l     ON l.course_id = e.course_id AND NOT l.is_optional
  JOIN first_pass fp ON fp.student_id = e.student_id AND fp.lesson_id = l.id
  GROUP BY e.course_id, e.student_id
)
SELECT c.title AS course,
       row_number() OVER (PARTITION BY c.id ORDER BY p.finished_on, s.name) AS place,
       s.name AS student,
       p.finished_on
FROM progress p
JOIN required r ON r.course_id = p.course_id AND r.lessons = p.passed
JOIN courses c  ON c.id = p.course_id
JOIN students s ON s.id = p.student_id
ORDER BY course, place;
```

Ответ:

```
Go  | 1 | Аня  | 2024-03-06
Go  | 2 | Гоша | 2024-03-06
Go  | 3 | Вера | 2024-03-07
SQL | 1 | Вера | 2024-03-12
```

**Реляционное деление.** «Студенты, сдавшие *все* уроки курса» — классика,
для которой в SQL нет отдельного оператора. Два стандартных способа:

1. **Подсчётом** (как здесь): сколько обязательных уроков сдано — и равно ли
   это числу обязательных уроков курса. Работает, только если каждый урок
   посчитан один раз.
2. **Двойным отрицанием**: «нет такого обязательного урока, который студент
   не сдал» — `NOT EXISTS (урок курса WHERE NOT EXISTS (успешная попытка))`.
   Длиннее, но не зависит от дубликатов.

**Сначала — один урок, одна строка.** `first_pass` сворачивает все успешные
попытки в одну строку на пару «студент — урок». Боря трижды сдал «Синтаксис»
и один раз — «Бонус»: если считать попытки, у него четыре успеха при трёх
обязательных уроках, и простое `count(*) >= 3` выпустит его. После
`first_pass` у него остаётся один обязательный урок из трёх.

**Необязательные уроки исключаются с обеих сторон** — и из требуемого
количества (`required`), и из сданного (условие `NOT l.is_optional` в
соединении). Если убрать только из одной стороны, счётчики перестанут
сравниваться.

**Запись на курс.** Боря сдал оба урока SQL, но на курс не записан.
`progress` строится от `enrollments`, поэтому его попытки просто не с чем
соединить.

**Дата финиша — максимум из минимумов.** Для каждого урока — первая
успешная попытка (`min` в `first_pass`), для курса — последний из этих дней
(`max` в `progress`). У Веры «Каналы»: 59 баллов 4 марта (не сдано), 88 —
7 марта (сдано), 95 — 9 марта (пересдача). Финиш — 7 марта. `max` по всем
успешным попыткам дал бы 9-е, а «последняя попытка по уроку» — тоже 9-е.

**`JOIN required … AND r.lessons = p.passed`** — фильтр по результату
агрегации, записанный как соединение. Тот же смысл дал бы `HAVING count(*) =
(SELECT count(*) FROM lessons WHERE course_id = … AND NOT is_optional)`.

**`row_number` с полным ключом сортировки.** Аня и Гоша закончили Go в один
день — `ORDER BY finished_on, s.name` делает порядок однозначным. Без имени
в ключе `row_number` раздал бы им места 1 и 2 как попало, и проверка то
проходила бы, то нет.
