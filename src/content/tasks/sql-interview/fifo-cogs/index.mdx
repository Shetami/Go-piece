Склад ведёт учёт по методу **FIFO**: продажа списывает единицы из самой
старой партии закупки, пока та не кончится, затем из следующей. Каждая партия
закуплена по своей цене, поэтому себестоимость проданного зависит от того, из
каких партий ушли единицы.

Партии упорядочены по `bought_at`; если две партии пришли в один день —
по `id`. Порядок строк в таблице и порядок `id` с датами не совпадают.

Для **каждого товара из справочника** посчитайте на сегодня:

- `sold_qty` — продано единиц всего;
- `revenue` — выручка, `sum(qty × unit_price)` по продажам;
- `cogs` — себестоимость проданного по FIFO;
- `gross_profit` — `revenue − cogs`;
- `stock_left` — сколько единиц осталось на складе;
- `stock_value` — во сколько обошлись эти оставшиеся единицы (по ценам
  своих партий).

Товары без закупок или без продаж — с нулями, не `NULL`. Продажи никогда не
превышают остаток.

Порядок: по `product`.

<Reveal>

```sql
WITH batches AS (
  SELECT product_id, qty, unit_cost,
         sum(qty) OVER w - qty AS from_qty, -- сколько единиц лежало на складе до этой партии
         sum(qty) OVER w       AS to_qty
  FROM purchases
  WINDOW w AS (PARTITION BY product_id ORDER BY bought_at, id)
),
sold AS (
  SELECT product_id, sum(qty) AS qty, sum(qty * unit_price) AS revenue
  FROM sales
  GROUP BY product_id
),
consumed AS (
  SELECT b.product_id, b.qty, b.unit_cost,
         greatest(0, least(b.to_qty, coalesce(s.qty, 0)) - b.from_qty) AS used
  FROM batches b
  LEFT JOIN sold s ON s.product_id = b.product_id
),
cost AS (
  SELECT product_id,
         sum(used * unit_cost)          AS cogs,
         sum(qty - used)                AS stock_left,
         sum((qty - used) * unit_cost)  AS stock_value
  FROM consumed
  GROUP BY product_id
)
SELECT p.name AS product,
       coalesce(s.qty, 0)                          AS sold_qty,
       coalesce(s.revenue, 0)                      AS revenue,
       coalesce(c.cogs, 0)                         AS cogs,
       coalesce(s.revenue, 0) - coalesce(c.cogs, 0) AS gross_profit,
       coalesce(c.stock_left, 0)                   AS stock_left,
       coalesce(c.stock_value, 0)                  AS stock_value
FROM products p
LEFT JOIN sold s ON s.product_id = p.id
LEFT JOIN cost c ON c.product_id = p.id
ORDER BY p.name;
```

Ответ:

```
Какао | 0  | 0    | 0    | 0    | 8  | 1600
Кофе  | 18 | 2760 | 1720 | 1040 | 7  | 780
Сахар | 0  | 0    | 0    | 0    | 0  | 0
Чай   | 20 | 1600 | 1000 | 600  | 10 | 600
```

**Ключевое наблюдение: при FIFO не важно, какая продажа что списала.** Всё
проданное в сумме — это первые `S` единиц, пришедшие на склад, где `S` —
общее число проданных. Значит, продажи можно схлопнуть в одно число на товар,
а партии разложить на прямой.

**Партии — отрезки на оси «номер единицы».** Нарастающий итог по `qty`
в порядке прихода даёт каждой партии отрезок `[from_qty, to_qty)`:

```
Кофе, S = 18
партия        отрезок    списано из партии
01-01 @100    [0, 10)    10 = min(10, 18) − 0
01-10 @90     [10, 20)    8 = min(20, 18) − 10
01-20 @120    [20, 25)    0 → greatest(0, min(25, 18) − 20)
```

Проданное — отрезок `[0, S)`. Сколько списано из партии — длина пересечения
двух отрезков: `greatest(0, least(to_qty, S) − from_qty)`. Остаток партии —
`qty − used`. Дальше обычные суммы.

**Порядок партий — по дате, а не по `id`.** Партия 3 по 90 закуплена
10 января, раньше партии 2 по 120. Сортировка по `id` дала бы Кофе
себестоимость 10×100 + 5×120 + 3×90 = 1870 вместо 1720. `id` остаётся вторым
ключом: без него у двух партий одного дня нарастающий итог стал бы общим —
окно с `ORDER BY` по умолчанию включает всех «соседей» с тем же значением.

**Два независимых «один ко многим» не соединяются напрямую.** У Кофе три
партии и три продажи: `JOIN purchases … JOIN sales` даёт девять строк, и
каждая сумма утраивается. Поэтому продажи сначала агрегируются в `sold` — по
строке на товар — и только потом присоединяются к партиям.

**Граничные случаи:**

- Чай: продано ровно 20, первая партия закончилась в ноль — вторая целиком
  в остатке;
- Какао: продаж нет, `s.qty` после `LEFT JOIN` — `NULL`, без `coalesce`
  выражение `least(…, NULL)` вернуло бы 8 (`least` пропускает `NULL`), и Какао
  «продалось» бы целиком;
- Сахар: ни закупок, ни продаж — строку даёт только `products` во главе
  `LEFT JOIN`.

**Что спросят дальше.** «А себестоимость каждой отдельной продажи?» Тот же
приём: продажам тоже даются отрезки нарастающим итогом, партии соединяются
с продажами по условию пересечения отрезков (`b.from_qty < s.to_qty AND
s.from_qty < b.to_qty`), и списание — длина пересечения.
