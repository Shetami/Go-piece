Маркетинг сравнивает когорты пользователей по **LTV за первые 30 дней**, в
долларах.

- **Когорта** — месяц регистрации (`signup_on`), первое число месяца.
  Нужны когорты января, февраля и марта 2024 года — все три, даже пустые;
- **выручка пользователя** — оплаченные заказы (`status = 'paid'`) за
  первые 30 дней: с `signup_on` включительно по `signup_on + 30` **не**
  включительно. Заказы, оформленные раньше регистрации (гостевые, позже
  привязанные к аккаунту), в LTV не идут;
- суммы переводятся в доллары по **курсу месяца заказа** из `fx_monthly`;
  для заказов в долларах курс — 1 (в таблице его нет);
- тестовые пользователи (`is_test`) не входят ни в одну когорту.

Для каждой когорты:

- колонки: `cohort` (`date`), `users` — пользователей в когорте,
  `paying_users` — у скольких выручка за 30 дней есть, `revenue_usd` —
  выручка когорты, `round(…, 2)`, 0 для пустой когорты, `ltv30_usd` —
  выручка **на одного пользователя когорты**, включая неплатящих,
  `round(…, 2)`; `NULL`, если в когорте нет пользователей;
- порядок: по `cohort`.

<Reveal>

```sql
WITH cohorts AS (
  SELECT c::date AS cohort
  FROM generate_series(date '2024-01-01', date '2024-03-01', interval '1 month') AS c
),
members AS (
  SELECT id, signup_on, date_trunc('month', signup_on)::date AS cohort
  FROM users
  WHERE NOT is_test
),
revenue AS (
  SELECT m.id, m.cohort,
         sum(o.amount * CASE WHEN o.currency = 'USD' THEN 1 ELSE fx.rate_to_usd END) AS usd
  FROM members m
  JOIN orders o ON o.user_id = m.id
               AND o.status = 'paid'
               AND o.created_on >= m.signup_on
               AND o.created_on <  m.signup_on + 30
  LEFT JOIN fx_monthly fx ON fx.currency = o.currency
                         AND fx.month = date_trunc('month', o.created_on)::date
  GROUP BY m.id, m.cohort
)
SELECT c.cohort,
       count(m.id)                       AS users,
       count(r.id)                       AS paying_users,
       round(coalesce(sum(r.usd), 0), 2) AS revenue_usd,
       round(sum(r.usd) / nullif(count(m.id), 0), 2) AS ltv30_usd
FROM cohorts c
LEFT JOIN members m ON m.cohort = c.cohort
LEFT JOIN revenue r ON r.id = m.id
GROUP BY c.cohort
ORDER BY c.cohort;
```

Ответ:

```
2024-01-01 | 3 | 3 | 322.00 | 107.33
2024-02-01 | 2 | 1 | 218.00 | 109.00
2024-03-01 | 0 | 0 |   0.00 | NULL
```

**Окно — от личной даты, когорта — по месяцу.** Это два разных измерения:
пользователь попадает в январскую когорту по месяцу регистрации, но его
30 дней считаются от собственного `signup_on`. Вера зарегистрировалась 31
января, и её февральский заказ 15-го числа — внутри её окна. У Ани окно с
10 января по 8 февраля включительно: заказ 8-го входит, 9-го — уже нет
(`< signup_on + 30`, а не `<=`).

**Курс — месяц заказа, а не когорты.** Февральский заказ Ани в рублях
пересчитывается по февральскому курсу 0,0108, а не по январскому. Курс
присоединяется по паре «валюта + `date_trunc('month', created_on)`» — этот
ключ однозначный, размножения строк нет. Доллар в `fx_monthly` отсутствует:
внутреннее соединение с курсами молча выбросит долларовые заказы Бори.
Поэтому `LEFT JOIN` и `CASE WHEN currency = 'USD' THEN 1`. (В проде лучше
положить в справочник строку `USD = 1` и сделать соединение внутренним —
тогда неизвестная валюта всплывёт ошибкой, а не нулём.)

**Знаменатель — вся когорта.** LTV — выручка на *пользователя*, а не на
заказ и не на платящего. Поэтому выручка сначала сворачивается до одной
строки на пользователя (`revenue`), а когорта строится от `members` через
`LEFT JOIN`: Гоша без заказов увеличивает `users`, но не выручку.
`avg(o.amount)` по заказам, как в заготовке, отвечает на совсем другой
вопрос — «средний чек».

**Остальные ловушки:**

- гостевой заказ Веры 30 января — до регистрации, не входит;
- возврат Бори и тестовая Дина с заказом на 1000 евро не учитываются;
- Егор зарегистрировался 29 февраля — февральская когорта, но его заказ
  1 марта пересчитывается по мартовскому курсу;
- мартовская когорта пуста, но есть в отчёте благодаря `generate_series`;
  `nullif(count, 0)` защищает от деления на ноль.

**Что спросят дальше.** Как показать LTV за 30, 60, 90 дней в одной
таблице — условная агрегация `sum(…) FILTER (WHERE created_on < signup_on
+ 60)`, и почему у молодой когорты LTV90 ещё не наступил и его надо
выводить как `NULL`, а не как заниженное число.
