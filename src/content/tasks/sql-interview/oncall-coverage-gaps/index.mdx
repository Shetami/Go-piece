SRE-лид проверяет график on-call на неделю **с 2024-09-02 00:00 по
2024-09-09 00:00** (конец не включительно): в какие периоды у команды
**никто не дежурит**.

Смена покрывает интервал `[starts_at, ends_at)`. Смены одной команды могут
пересекаться, одна может целиком лежать внутри другой, а стык «одна
закончилась в 09:00, другая началась в 09:00» — **не** дыра.

- отменённые смены (`is_cancelled`) ничего не покрывают;
- смены, начавшиеся до недели или закончившиеся после неё, учитываются
  только своей частью внутри недели;
- дыра в начале недели (до первой смены) и в конце (после последней) —
  тоже дыры; у команды без смен вся неделя — одна дыра.

Одна дыра — одна строка:

- колонки: `team`, `gap_start`, `gap_end` (`timestamp`), `gap_hours` —
  длина в часах, `round(…, 1)`;
- порядок: `team`, затем `gap_start`.

<Reveal>

```sql
WITH params AS (
  SELECT timestamp '2024-09-02 00:00' AS week_start,
         timestamp '2024-09-09 00:00' AS week_end
),
clipped AS (
  SELECT s.team_id,
         greatest(s.starts_at, p.week_start) AS starts_at,
         least(s.ends_at, p.week_end)        AS ends_at
  FROM oncall_shifts s, params p
  WHERE NOT s.is_cancelled
    AND s.starts_at < p.week_end
    AND s.ends_at   > p.week_start
  UNION ALL
  SELECT t.id, p.week_end, p.week_end
  FROM teams t, params p
),
covered AS (
  SELECT c.*,
         max(ends_at) OVER (PARTITION BY team_id ORDER BY starts_at, ends_at
                            ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS covered_until
  FROM clipped c
)
SELECT t.name AS team,
       coalesce(c.covered_until, p.week_start) AS gap_start,
       c.starts_at AS gap_end,
       round(extract(epoch FROM c.starts_at - coalesce(c.covered_until, p.week_start)) / 3600, 1) AS gap_hours
FROM covered c
JOIN teams t ON t.id = c.team_id
CROSS JOIN params p
WHERE c.starts_at > coalesce(c.covered_until, p.week_start)
ORDER BY team, gap_start;
```

Ответ:

```
Платежи   | 2024-09-05 00:00:00 | 2024-09-05 08:00:00 |   8.0
Платежи   | 2024-09-08 20:00:00 | 2024-09-09 00:00:00 |   4.0
Платформа | 2024-09-04 09:00:00 | 2024-09-04 12:00:00 |   3.0
Платформа | 2024-09-06 09:00:00 | 2024-09-06 10:00:00 |   1.0
Поиск     | 2024-09-02 00:00:00 | 2024-09-09 00:00:00 | 168.0
```

**«Покрыто до» — бегущий максимум, а не предыдущая смена.** Для каждой
смены (в порядке начала) считаем, до какого момента команда уже покрыта
всеми **предыдущими** сменами: `max(ends_at) OVER (… ROWS BETWEEN
UNBOUNDED PRECEDING AND 1 PRECEDING)`. Если смена начинается позже этого
момента — между ними дыра. `lag(ends_at)` смотрит только на соседа и
ломается на вложенных сменах: у Платформы после длинной смены Гоши (до
6-го 09:00) идёт короткая ночная смена Дины внутри неё (до 5-го 06:00), и
`lag` для смены Бори увидел бы «покрыто до 5-го 06:00» — ложная дыра в
сутки с лишним. Та же ошибка у вложенной смены Веры 3 сентября.

**Обрезка по неделе — до поиска дыр.** Смена Ани началась 1 сентября в
20:00 и покрывает начало недели — её нельзя отбросить фильтром «начало
внутри недели», иначе появится ложная дыра с понедельника 00:00. Смена Бори
до 10 сентября обрезается по `week_end`, чтобы бегущий максимум не уходил
за неделю, а смена Иры 10-го в неделю не попадает вовсе. Отменённая
смена Ани 6–9 сентября убрана — без фильтра дыра в понедельник 6-го
исчезла бы.

**Сторожевая строка вместо трёх особых случаев.** Для каждой команды
добавлена пустая «смена» `[week_end, week_end)`. Для неё бегущий максимум
показывает, до какого момента покрыта неделя, и хвост (Платежи после 20:00
8-го) находится тем же условием `starts_at > covered_until`. У Поиска смен
нет вовсе: у сторожевой строки `covered_until` — `NULL`, `coalesce`
подставляет начало недели, и получается дыра на все 168 часов. Дыра в
начале недели для первой смены находится так же.

**Стык — не дыра.** Смена Бори начинается ровно в момент конца смены Ани;
строгое `>` не даёт нулевых дыр.

**Что спросят дальше.** Как выразить это на диапазонах PostgreSQL:
`range_agg(tsrange(starts_at, ends_at))` склеивает пересечения в
мультидиапазон, а `tsmultirange(неделя) - range_agg(…)` сразу даёт дыры.
И как запретить пересечение смен одного инженера — `EXCLUDE USING gist`.
