Продакт-менеджер хочет таблицу удержания покупателей по когортам.

**Когорта** — календарный месяц регистрации (`users.signed_up_at`). Нужны
когорты с января по апрель 2024 года — **все четыре**, даже если в каком-то
месяце никто не зарегистрировался.

Для каждой когорты:

- `users` — сколько человек зарегистрировалось в этом месяце;
- `m1_pct` — какая доля когорты сделала хотя бы одну успешную покупку в
  **следующем календарном месяце** после месяца регистрации;
- `m2_pct` — то же для второго месяца после регистрации.

«Следующий календарный месяц» понимается буквально: зарегистрировался
31 января, купил 1 февраля — это месяц 1. Зарегистрировался 3 января, купил
25 января — это месяц 0, он в отчёт не входит.

Успешная покупка — заказ со статусом `done`. Несколько покупок в одном месяце
считаются за одну. Проценты — `round(…, 1)`. У пустой когорты проценты —
`NULL`: доля от нуля человек не определена.

- колонки: `cohort` (первое число месяца, тип `date`), `users`, `m1_pct`, `m2_pct`;
- порядок: по `cohort`.

<Reveal>

```sql
WITH months AS (
  SELECT m::date AS cohort
  FROM generate_series(date '2024-01-01', date '2024-04-01', interval '1 month') AS m
),
-- Номер календарного месяца: разность двух таких номеров — «сколько месяцев прошло»
buyer_months AS (
  SELECT DISTINCT user_id,
         extract(year FROM created_at)::int * 12 + extract(month FROM created_at)::int AS ym
  FROM orders
  WHERE status = 'done'
),
cohort_users AS (
  SELECT u.id,
         date_trunc('month', u.signed_up_at)::date AS cohort,
         extract(year FROM u.signed_up_at)::int * 12 + extract(month FROM u.signed_up_at)::int AS ym
  FROM users u
),
flags AS (
  SELECT cu.id, cu.cohort,
         EXISTS (SELECT 1 FROM buyer_months b WHERE b.user_id = cu.id AND b.ym = cu.ym + 1) AS m1,
         EXISTS (SELECT 1 FROM buyer_months b WHERE b.user_id = cu.id AND b.ym = cu.ym + 2) AS m2
  FROM cohort_users cu
)
SELECT m.cohort,
       count(f.id) AS users,
       round(100.0 * count(*) FILTER (WHERE f.m1) / nullif(count(f.id), 0), 1) AS m1_pct,
       round(100.0 * count(*) FILTER (WHERE f.m2) / nullif(count(f.id), 0), 1) AS m2_pct
FROM months m
LEFT JOIN flags f ON f.cohort = m.cohort
GROUP BY m.cohort
ORDER BY m.cohort;
```

Ответ:

```
2024-01-01 | 3 | 66.7  | 33.3
2024-02-01 | 3 | 100.0 | 33.3
2024-03-01 | 0 | NULL  | NULL
2024-04-01 | 2 | 50.0  | 0.0
```

**Месяцы считаются календарно, а не интервалом.** Условие
`created_at < signed_up_at + interval '30 days'` смешивает месяц 0 и месяц 1:
Вера зарегистрировалась 31 января в 23:00 и купила 1 февраля — через час, но
это уже месяц 1. Надёжный приём — перевести дату в сквозной номер месяца
`год × 12 + месяц`. Тогда разность номеров и есть число
календарных месяцев, и переход через новый год (декабрь → январь)
обрабатывается сам. То же можно записать через
`date_trunc('month', created_at) = date_trunc('month', signed_up_at) + interval '1 month'`.

**`DISTINCT` в `buyer_months`**: Аня купила в феврале дважды, но в когорте
она один человек. Без `DISTINCT` соединение с покупками размножило бы её, и
`count` вернул бы больше людей, чем есть в когорте.

**Флаги через `EXISTS`, а не через `JOIN`.** Если присоединить покупки
напрямую, строк у пользователя станет столько, сколько у него месяцев с
покупками, и `count(f.id)` перестанет означать размер когорты. `EXISTS`
отвечает «да/нет» и строк не добавляет — один пользователь остаётся одной
строкой.

**Статусы.** Боря в феврале и марте только отменял заказы — ни в `m1`, ни в
`m2` он не попадает; апрельская покупка — это уже месяц 3. У Дины возврат в
апреле не считается, а мартовская покупка — да, поэтому февральская когорта
удержала всех в первом месяце.

**Пустая когорта — сетка месяцев плюс `LEFT JOIN`.** Март существует только
в `generate_series`. `count(f.id)` там 0, а не 1: `count(колонка)` не считает
`NULL`, которые дал `LEFT JOIN`, в отличие от `count(*)`. В числителе
`count(*) FILTER (WHERE f.m1)` безопасен: у марта `f.m1` — `NULL`, фильтр его
отбрасывает. Знаменатель `nullif(…, 0)` превращает ноль в `NULL`, и деление
даёт `NULL` вместо ошибки `division by zero`.

**Зоя и Жора** — апрельская когорта: Жора купил 1 мая (месяц 1), Зоя не
покупала вовсе. Данных за июнь нет, поэтому `m2` у апреля честно 0 — в
реальном отчёте такую ячейку лучше оставлять пустой, пока месяц не закрылся.

**Ира** зарегистрировалась в декабре 2023 — её когорта за пределами сетки и в
отчёт не попадает.
