Маркетплейс формирует выплату продавцам **на 2024-11-15**.

**Какие позиции выплачиваются сейчас:**

- заказ доставлен (`delivered_at` не `NULL`), и с даты доставки прошло
  **не меньше 14 дней**: дата доставки не позже 2024-11-01 включительно;
- позиция не возвращена (возврат — всегда позиция целиком);
- позиция ещё не выплачена раньше (`paid_items`).

Доставленные, не возвращённые и не выплаченные позиции, у которых 14 дней
ещё не прошли, — **на холде**. Заказы в пути не выплачиваются и не
холдируются.

**Комиссия** — процент категории позиции, действующий **на дату создания
заказа** (`created_on`): запись справочника с наибольшим `valid_from`, не
позже этой даты. Комиссия позиции — `price × qty × pct / 100`, округлённая
до копеек (`round(…, 2)`) **по каждой позиции**.

Для **каждого** продавца:

- колонки: `seller`, `items` — выплачиваемых позиций, `gross` — их сумма
  `price × qty`, `commission` — сумма комиссий, `payout` — `gross −
  commission`, `on_hold` — сумма `price × qty` позиций на холде; все
  отсутствующие значения — 0;
- порядок: `payout` по убыванию, затем `seller`.

```sql
WITH items AS (
  SELECT o.seller_id, i.id, i.price * i.qty AS gross,
         o.delivered_at::date <= date '2024-11-15' - 14 AS released,
         (SELECT r.pct
          FROM commission_rates r
          WHERE r.category_id = i.category_id
            AND r.valid_from <= o.created_on
          ORDER BY r.valid_from DESC
          LIMIT 1) AS pct
  FROM order_items i
  JOIN orders o ON o.id = i.order_id
  WHERE o.delivered_at IS NOT NULL
    AND NOT EXISTS (SELECT 1 FROM returns r    WHERE r.order_item_id = i.id)
    AND NOT EXISTS (SELECT 1 FROM paid_items p WHERE p.order_item_id = i.id)
),
per_seller AS (
  SELECT seller_id,
         count(*) FILTER (WHERE released)                   AS items,
         sum(gross) FILTER (WHERE released)                 AS gross,
         sum(round(gross * pct / 100, 2)) FILTER (WHERE released) AS commission,
         sum(gross) FILTER (WHERE NOT released)             AS on_hold
  FROM items
  GROUP BY seller_id
)
SELECT s.name AS seller,
       coalesce(p.items, 0)                            AS items,
       coalesce(p.gross, 0)                            AS gross,
       coalesce(p.commission, 0)                       AS commission,
       coalesce(p.gross, 0) - coalesce(p.commission, 0) AS payout,
       coalesce(p.on_hold, 0)                          AS on_hold
FROM sellers s
LEFT JOIN per_seller p ON p.seller_id = s.id
ORDER BY payout DESC, seller;
```

Ответ:

```
ТехноМир | 2 | 5000.00 | 310.00 | 4690.00 | 500.00
Модный   | 1 | 2000.00 | 300.00 | 1700.00 |      0
Новичок  | 0 |       0 |      0 |       0 |      0
```

**Комиссия «на дату» — коррелированный подзапрос с `LIMIT 1`.** В
справочнике нет `valid_to`, только начало действия. Для каждой позиции
берём запись категории с наибольшим `valid_from <= created_on`. Простое
соединение по категории, как в заготовке, размножит электронику на две
ставки и удвоит суммы. Альтернативы — `LATERAL`, или `lead(valid_from)`
для построения интервалов и соединение по диапазону.

**Дата заказа, а не доставки.** Заказ №2 создан 16 октября — уже по новой
ставке 7%, хотя №1 доставлен позже, чем изменилась ставка, — у него 5%:
комиссия фиксируется в момент покупки. `1000 × 2 × 5% + 3000 × 7% = 310`.

**Холд — граница включительно, по дате.** Заказ №2 доставлен 1 ноября в
23:00: это ровно 14 дней, позиция выплачивается. Сравнение `delivered_at <
'2024-11-01'` (как в заготовке) или по временной метке `delivered_at <=
timestamp '2024-11-01'` её потеряет — полночь 1 ноября раньше 23:00. Поэтому
сначала `::date`, потом сравнение.

**Один проход — две корзины через `FILTER`.** Позиции сначала очищаются
от возвратов, выплаченных и недоставленных, а потом одним `GROUP BY`
раскладываются на «к выплате» и «на холде» условной агрегацией. Возврат №8
оформлен уже после доставки, но холд для того и нужен — позиция не попадает
ни в выплату, ни в холд. Позиция №7 выплачена в октябре — второй раз её
платить нельзя.

**Округление по позиции.** Бухгалтерия считает комиссию документом на
каждую позицию, и сумма округлённых не обязана совпадать с округлённой
суммой. Поэтому `round` стоит внутри `sum`.

**Что спросят дальше.** Как сделать выплату идемпотентной: в одной
транзакции записать все выплаченные позиции в `paid_items` с уникальным
ключом по позиции — повторный запуск просто ничего не найдёт. И как
отражать возврат *после* выплаты — отрицательной строкой в следующей
выплате, а не правкой прошлой.
