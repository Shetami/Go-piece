CRM накопила дубли: один человек регистрировался несколько раз. Перед
миграцией нужно понять, какие аккаунты — один клиент, и сколько он на
самом деле купил.

**Два аккаунта — один клиент**, если у них совпадает **email** или
**телефон** после нормализации:

- email — без учёта регистра и пробелов по краям;
- телефон — только цифры: `+7 (900) 111-22-33` и `79001112233` — один
  номер;
- `NULL`, пустая строка и строка без цифр (для телефона) — не контакт и
  ничего не связывают.

Связь **транзитивна**: если у A с B общий email, а у B с C общий телефон,
то A, B и C — один клиент, даже если у A и C нет ничего общего.
Совпадение имён ничего не значит.

**Главный аккаунт** клиента — с наименьшим `id`. Нужны только клиенты, у
которых **больше одного** аккаунта:

- колонки: `master_id`, `master_name` — имя главного аккаунта, `accounts`
  — число аккаунтов, `orders` и `revenue` — заказы и их сумма по всем
  аккаунтам клиента;
- порядок: по `master_id`.

```sql
WITH RECURSIVE keys AS (
  -- нормализованные ключи; пустые значения ключом не являются
  SELECT id, 'e:' || lower(trim(email)) AS k
  FROM customers
  WHERE nullif(trim(email), '') IS NOT NULL
  UNION ALL
  SELECT id, 'p:' || regexp_replace(phone, '\D', '', 'g')
  FROM customers
  WHERE regexp_replace(coalesce(phone, ''), '\D', '', 'g') <> ''
),
edges AS (
  SELECT DISTINCT a.id AS src, b.id AS dst
  FROM keys a
  JOIN keys b ON b.k = a.k AND b.id <> a.id
),
reach AS (
  SELECT id AS start_id, id AS node_id FROM customers
  UNION
  SELECT r.start_id, e.dst
  FROM reach r
  JOIN edges e ON e.src = r.node_id
),
components AS (
  SELECT start_id AS id, min(node_id) AS master_id
  FROM reach
  GROUP BY start_id
),
spend AS (
  SELECT customer_id, count(*) AS orders, sum(amount) AS revenue
  FROM orders
  GROUP BY customer_id
)
SELECT c.master_id,
       m.name AS master_name,
       count(*) AS accounts,
       coalesce(sum(s.orders), 0)  AS orders,
       coalesce(sum(s.revenue), 0) AS revenue
FROM components c
JOIN customers m  ON m.id = c.master_id
LEFT JOIN spend s ON s.customer_id = c.id
GROUP BY c.master_id, m.name
HAVING count(*) > 1
ORDER BY c.master_id;
```

Ответ:

```
1 | Анна | 4 | 5 | 2700.00
8 | Вера | 2 | 1 |  250.00
```

**Это задача о компонентах связности.** Аккаунты — вершины графа, общий
контакт — ребро. `GROUP BY email` находит только прямые совпадения по
одному признаку: Анна №1 и №4 связаны телефоном, №4 и №5 — email, а у №1 и
№5 общего нет вовсе. Склеить их может только обход графа.

**Шаг 1 — ключи.** Каждый аккаунт превращается в набор строк-ключей
`'e:…'` и `'p:…'` (префикс не даёт email и телефону случайно совпасть).
Здесь же отсекаются мусорные значения: `nullif(trim(email), '')` и
«телефон без цифр». Без этого пустой телефон у Козловой (№5) и у Бориса
(№6) склеит их в одного клиента, а пустой email соединит Бориса Л. с Гошей.

**Шаг 2 — рёбра и достижимость.** Два аккаунта с общим ключом — ребро в
обе стороны. Рекурсивный `reach` от каждой вершины добавляет соседей уже
достигнутых вершин. Ключевое слово — **`UNION`, а не `UNION ALL`**: в
графе есть циклы (1 → 2 → 1), и только удаление дублей останавливает
рекурсию — когда новых пар «старт, вершина» не появляется, итерации
заканчиваются. С `UNION ALL` запрос не завершится никогда.

**Шаг 3 — метка компоненты.** Минимальный `id` среди достижимых вершин
одинаков у всех аккаунтов компоненты — это и есть `master_id`. Дальше —
обычная группировка. Заказы предварительно свёрнуты в `spend` по
аккаунту, чтобы соединение не размножало строки.

**Разбор:** №2 `' ANNA@mail.ru '` совпадает с №1 после `lower(trim(…))`;
№3 — тоже Анна, но с другим email и без телефона — отдельный клиент. Вера
№8 и №9 связаны телефоном в разном формате.

**Что спросят дальше.** Сложность: достижимость от каждой вершины —
квадрат по размеру компоненты; на миллионах аккаунтов так не делают — там
union-find в приложении или итеративная «пропагация минимальной метки»
(каждый шаг — `UPDATE` метки на минимум среди соседей, пока есть
изменения). И продуктовый вопрос: общий телефон бывает у членов семьи —
склейка по нему требует ручного подтверждения.
