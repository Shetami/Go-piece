Коммерческий директор смотрит выполнение плана продаж за **апрель — июнь 2024**.

**Структура.** Регионы образуют дерево произвольной глубины: страна →
макрорегион → город. Магазин привязан к узлу **любого** уровня — бывают
магазины прямо на макрорегионе, без города.

**План** ставится на узел и покрывает всё его поддерево, включая сам узел.
План есть не у всех узлов и не на каждый месяц. **Факт** узла за месяц —
сумма продаж всех магазинов его поддерева, у которых `sold_at` попадает в
этот месяц. Возвраты уже записаны отрицательными суммами.

Для **каждого узла, у которого есть план хотя бы на один месяц**, — строка
на **каждый** из трёх месяцев:

- колонки: `region`, `month` (первое число месяца, `date`), `plan` и
  `fact` за месяц (0, если плана или продаж нет), `plan_ytd` и `fact_ytd` —
  нарастающие итоги с апреля по этот месяц включительно, `pct_ytd` —
  `fact_ytd / plan_ytd × 100`, `round(…, 1)`; `NULL`, если `plan_ytd = 0`;
- порядок: `region`, затем `month`.

<Reveal>

```sql
WITH RECURSIVE subtree AS (
  SELECT id AS root_id, id AS node_id FROM regions
  UNION ALL
  SELECT s.root_id, r.id
  FROM subtree s
  JOIN regions r ON r.parent_id = s.node_id
),
months AS (
  SELECT m::date AS month
  FROM generate_series(date '2024-04-01', date '2024-06-01', interval '1 month') AS m
),
grid AS (
  SELECT DISTINCT p.region_id, m.month
  FROM plans p
  CROSS JOIN months m
),
fact AS (
  SELECT st.root_id AS region_id,
         date_trunc('month', s.sold_at)::date AS month,
         sum(s.amount) AS amount
  FROM sales s
  JOIN stores sh  ON sh.id = s.store_id
  JOIN subtree st ON st.node_id = sh.region_id
  GROUP BY st.root_id, date_trunc('month', s.sold_at)
),
monthly AS (
  SELECT g.region_id, g.month,
         coalesce(p.amount, 0) AS plan,
         coalesce(f.amount, 0) AS fact
  FROM grid g
  LEFT JOIN plans p ON p.region_id = g.region_id AND p.month = g.month
  LEFT JOIN fact f  ON f.region_id = g.region_id AND f.month = g.month
),
running AS (
  SELECT m.*,
         sum(plan) OVER w AS plan_ytd,
         sum(fact) OVER w AS fact_ytd
  FROM monthly m
  WINDOW w AS (PARTITION BY region_id ORDER BY month)
)
SELECT r.name AS region, x.month, x.plan, x.fact, x.plan_ytd, x.fact_ytd,
       round(100 * x.fact_ytd / nullif(x.plan_ytd, 0), 1) AS pct_ytd
FROM running x
JOIN regions r ON r.id = x.region_id
ORDER BY region, x.month;
```

**Поддерево — пары «предок — потомок» из рекурсивного CTE.** Базовая часть
кладёт каждый узел как предка самого себя, рекурсивная спускается на
уровень вниз, сохраняя `root_id`. На выходе — замыкание дерева: все пары
«узел → любой его потомок, включая себя». Дальше факт любого узла — обычный
`JOIN` магазинов по `node_id` и `GROUP BY root_id`. Соединение «регион →
его прямые дети» (как в заготовке) видит только один уровень: России
достанутся магазины Центра и Сибири, если они там есть, но не московские.

**Магазин на промежуточном узле.** «Склад-магазин Сибирь» привязан прямо к
макрорегиону. Он должен попасть и в Сибирь, и в Россию — поэтому узел входит
в собственное поддерево. Томск без магазинов ничего не ломает.

**Сетка «узел × месяц» до агрегатов.** У Сибири нет ни плана, ни продаж на
май — без сетки `grid` строка пропадёт, и нарастающий итог «перепрыгнет»
месяц. `DISTINCT` в `grid` нужен, потому что `plans` содержит несколько
строк на узел. План и факт присоединяются к сетке `LEFT JOIN` и
превращаются в нули `coalesce`.

**Нарастающий итог — `sum() OVER (PARTITION BY … ORDER BY month)`.** Рамка
по умолчанию — от начала раздела до текущей строки (точнее, до последней
строки с тем же `month`, но месяцы внутри узла уникальны). Процент считается
уже от накопленных сумм, а не как среднее помесячных процентов.

**Границы месяцев и возвраты.** Продажа 31 марта в 23:59 и продажа 1 июля в
00:00 в отчёт не входят: `date_trunc('month', …)` отнесёт их к своим
месяцам, которых нет в сетке. Возврат −50 в мае уменьшает факт Москвы, а
значит и Центра, и России.

**Что спросят дальше.** Как не пересчитывать замыкание дерева на каждый
запрос — хранить его (closure table) или путь (`ltree`, материализованный
путь `'/1/2/3/'`) и искать потомков по префиксу. И что будет, если в
дереве случайно появится цикл: рекурсия не остановится — защищаются
массивом пройденных узлов и `CYCLE`-клаузой PostgreSQL.
