Сервис аренды самокатов выставляет счета. Нужно посчитать, сколько
заплатил каждый пользователь.

**Правила тарификации:**

- поездка оплачивается **поминутно**, каждая начатая минута — полная:
  3 минуты 1 секунда — это 4 минуты;
- минуты отсчитываются от `started_at`: первая минута — `[start, start +
  1 мин)`, вторая — `[start + 1 мин, start + 2 мин)` и так далее;
- цена минуты — по тарифу, который действует **в момент начала этой
  минуты**. Тарифы заданы временем суток: `from_time` включительно,
  `to_time` не включительно; ночной тариф переходит через полночь;
- за каждую оплачиваемую поездку добавляется плата за старт
  (`settings.unlock_fee`), кроме пользователей с подпиской
  (`has_subscription`);
- поездки короче 30 секунд — фальстарт, они бесплатны и не считаются
  поездками. Ровно 30 секунд — уже платная поездка;
- незавершённые поездки (`ended_at IS NULL`) пока не тарифицируются.

Для **каждого** пользователя:

- колонки: `user_name`, `rides` — оплачиваемых поездок, `minutes` —
  оплачиваемых минут, `amount` — сумма к оплате (0, если поездок нет);
- порядок: `amount` по убыванию, затем `user_name`.

<Reveal>

```sql
WITH billable AS (
  SELECT r.id, r.user_id, r.started_at,
         ceil(extract(epoch FROM r.ended_at - r.started_at) / 60)::int AS minutes
  FROM rides r
  WHERE r.ended_at IS NOT NULL
    AND r.ended_at - r.started_at >= interval '30 seconds'
),
minute_prices AS (
  SELECT b.id, t.price_per_min
  FROM billable b
  CROSS JOIN LATERAL generate_series(0, b.minutes - 1) AS g(i)
  JOIN tariffs t ON CASE
                      WHEN t.from_time < t.to_time
                        THEN (b.started_at + g.i * interval '1 minute')::time >= t.from_time
                         AND (b.started_at + g.i * interval '1 minute')::time <  t.to_time
                      ELSE (b.started_at + g.i * interval '1 minute')::time >= t.from_time
                        OR (b.started_at + g.i * interval '1 minute')::time <  t.to_time
                    END
),
ride_cost AS (
  SELECT b.id, b.user_id, b.minutes,
         (SELECT sum(price_per_min) FROM minute_prices mp WHERE mp.id = b.id)
           + CASE WHEN u.has_subscription THEN 0 ELSE s.unlock_fee END AS cost
  FROM billable b
  JOIN users u ON u.id = b.user_id
  CROSS JOIN settings s
)
SELECT u.name AS user_name,
       count(rc.id)                 AS rides,
       coalesce(sum(rc.minutes), 0) AS minutes,
       coalesce(sum(rc.cost), 0)    AS amount
FROM users u
LEFT JOIN ride_cost rc ON rc.user_id = u.id
GROUP BY u.id, u.name
ORDER BY amount DESC, user_name;
```

Ответ:

```
Боря | 2 | 14 | 211.00
Вера | 2 |  4 | 130.00
Аня  | 2 | 13 | 108.00
Гоша | 0 |  0 |      0
```

**Поездка → минуты через `generate_series`.** Число начатых минут —
`ceil(секунды / 60)`, а `round` здесь ошибка: 3:01 он округлит до трёх.
Дальше `LATERAL generate_series(0, minutes − 1)` превращает поездку в
строки-минуты, и у каждой свой момент начала `started_at + i минут`. Это
дорого для длинных сессий, но делает правило «тариф на начало минуты»
буквальным и легко проверяемым — на интервью это хорошая стартовая точка,
а оптимизацию (пересечение интервала поездки с интервалами тарифов) можно
обсудить следом.

**Интервал через полночь.** Ночь — с 23:00 до 07:00, и наивное `t >=
from_time AND t < to_time` для неё никогда не истинно: нет такого времени,
которое одновременно `>= 23:00` и `< 07:00`. Для «перевёрнутого» интервала
условие меняется на `OR`. Это стандартная ловушка любых расписаний по
времени суток.

**Разбор поездок:**

- Боря, 22:55–23:05: пять дневных минут и пять ночных — `45 + 30 + 50`.
  Тариф по началу поездки дал бы 140 вместо 125;
- Боря, 10:00:00–10:03:01 — четыре минуты, а не три;
- Вера, 06:58:30–07:01:30: минуты начинаются в 06:58:30, 06:59:30 и
  07:00:30 — две ночные и одна дневная. Смена тарифа приходится на середину
  минуты, и считается момент её начала;
- Вера, 20 секунд — фальстарт, ровно 30 секунд — одна платная минута и
  плата за старт;
- Аня с подпиской катается через полночь (ночной тариф на обе даты) и не
  платит за старт; её незавершённая поездка в счёт не идёт;
- Гоша без поездок остаётся в отчёте с нулями.

**Что спросят дальше.** Как тарифицировать поездку в несколько часов без
размножения строк: построить интервалы тарифов на даты поездки и посчитать
длину пересечения `least(конец) − greatest(начало)` — как в задачах про
рабочие часы. И где это считать в проде — обычно не в SQL, а в биллинговом
сервисе при закрытии поездки, с сохранением расчёта рядом с поездкой.
