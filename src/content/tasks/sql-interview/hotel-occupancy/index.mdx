Отель просит отчёт по типам номеров **за март 2024 года**.

Правила:

- гость живёт ночи с `check_in` по `check_out − 1` включительно: заехал
  5-го, выехал 9-го — это ночи 5, 6, 7 и 8-го;
- бронь может начаться в феврале или закончиться в апреле — в отчёт идут
  только мартовские ночи;
- отменённые брони (`status = 'cancelled'`) не считаются;
- цена каждой ночи — по тарифу, который действует **в эту ночь** для типа
  номера (`valid_to` включительно). Тариф может смениться посреди
  проживания;
- у гостя бывает персональная скидка `discount_pct` — она уменьшает цену
  каждой ночи.

Для **каждого** типа номера, включая типы без единой брони:

- `nights` — проданные номеро-ночи в марте;
- `occupancy_pct` — загрузка: `nights` / (число номеров этого типа × 31) × 100,
  `round(…, 1)`;
- `revenue` — выручка за мартовские ночи с учётом скидок, `round(…, 2)`.

Порядок: `revenue` по убыванию, при равенстве — по `room_type`.

<Reveal>

```sql
WITH nights AS (
  SELECT r.room_type_id, g.discount_pct, d::date AS night
  FROM bookings b
  JOIN rooms r  ON r.id = b.room_id
  JOIN guests g ON g.id = b.guest_id
  CROSS JOIN LATERAL generate_series(b.check_in, b.check_out - 1, interval '1 day') AS d
  WHERE b.status = 'confirmed'
    AND d >= date '2024-03-01'
    AND d <  date '2024-04-01'
),
sold AS (
  SELECT n.room_type_id,
         count(*) AS nights,
         sum(t.price_per_night * (100 - n.discount_pct) / 100.0) AS revenue
  FROM nights n
  JOIN tariffs t ON t.room_type_id = n.room_type_id
                AND n.night BETWEEN t.valid_from AND t.valid_to
  GROUP BY n.room_type_id
),
capacity AS (
  SELECT room_type_id, count(*) AS rooms
  FROM rooms
  GROUP BY room_type_id
)
SELECT rt.name AS room_type,
       coalesce(s.nights, 0) AS nights,
       round(100.0 * coalesce(s.nights, 0) / (c.rooms * 31), 1) AS occupancy_pct,
       round(coalesce(s.revenue, 0), 2) AS revenue
FROM room_types rt
JOIN capacity c ON c.room_type_id = rt.id
LEFT JOIN sold s ON s.room_type_id = rt.id
ORDER BY revenue DESC, room_type;
```

Ответ:

```
Комфорт  | 5 | 8.1 | 27000.00
Стандарт | 8 | 8.6 | 23400.00
Люкс     | 0 | 0.0 | 0.00
```

**Бронь разворачивается в ночи.** Как только тариф может смениться посреди
проживания, «число ночей × цена» перестаёт работать: у Бори ночи 5 и 6 марта
стоят по 3000, а 7 и 8 — по 4000 (праздничный тариф). Проще всего перейти к
гранулярности «одна строка — одна ночь»: `generate_series` внутри `LATERAL`
для каждой брони выдаёт её ночи. Дальше всё становится обычным `JOIN` и
`GROUP BY`:

- ночь соединяется ровно с одним тарифом по условию `BETWEEN` — это
  соединение по диапазону, а не по равенству ключей;
- фильтр по марту отсекает февральские ночи Ани и апрельские ночи Гоши —
  брони, пересекающие границу месяца, учитываются частично;
- `count(*)` ночей — это и есть номеро-ночи.

**`check_out − 1`**: ночь выезда гость не оплачивает. `generate_series` по
датам включает обе границы, поэтому верхнюю надо сдвинуть на день. Разность
дат `check_out − check_in` дала бы число ночей верно, но только всей брони, а
не мартовской её части.

**Ёмкость — отдельно от броней.** Число номеров надо посчитать до
соединения с бронями. Если сделать `count(r.id)` после `JOIN bookings`,
получится не число номеров, а число пар «номер — бронь», и загрузка
разъедется. Отдельный CTE `capacity` — одна строка на тип, соединение с ним
не размножает строк.

**Люкс без мартовских броней** — остаётся благодаря
`room_types … LEFT JOIN sold`. `JOIN capacity` здесь внутренний: тип
номера без самих номеров дал бы деление на ноль, и в реальном отчёте это
стоило бы обсудить.

**Скидка и тип деления.** Делитель `100.0`, а не `100`: при делении целых
ночь за 3333 со скидкой 10% стоила бы `3333 * 90 / 100 = 2999` вместо 2999.70.
В этих данных все цены кратны ста, и ошибка бы не проявилась — тем она и
опасна.

**Разбор по броням:**

```
бронь                   мартовские ночи     сумма
Аня,  101, 27.02–03.03  01, 02              2 × 3000              = 6000
Боря, 102, 05.03–09.03  05, 06, 07, 08      (3000+3000+4000+4000)×0.9 = 12600
Вера, 103              — отменена
Гоша, 101, 30.03–02.04  30, 31              2 × 3000 × 0.8        = 4800
Вера, 201, 14.03–18.03  14, 15, 16, 17      5000+5000+6000+6000   = 22000
Аня,  202, 01.03–02.03  01                  5000                  = 5000
Боря, 301              — апрель
```

**Что спросят дальше.** «Как найти овербукинг — две активные брони одного
номера на одну ночь?» Та же развёртка в ночи и `GROUP BY room_id, night
HAVING count(*) > 1`. Или без развёртки: самосоединение броней по
пересечению интервалов `a.check_in < b.check_out AND b.check_in < a.check_out`
либо тип `daterange` и оператор `&&`.
