SaaS-сервис продаёт подписки. Финансовому директору нужно понять, **из чего
складывается изменение месячной выручки** (MRR — monthly recurring revenue).

**MRR клиента в месяце** — цена тарифа (`plans.monthly_price`) подписки,
которая активна **на первое число** этого месяца. Подписка активна в день
`d`, если `started_on <= d` и (`ended_on IS NULL` или `ended_on > d`). Если
на первое число подписки нет, MRR клиента в этом месяце 0. Одновременно у
клиента не больше одной активной подписки.

Изменение MRR клиента по сравнению с **предыдущим месяцем** попадает ровно в
одну из категорий:

- `new_mrr` — в прошлом месяце было 0, сейчас больше нуля (новый клиент или
  вернувшийся) — сумма текущего MRR;
- `expansion_mrr` — было и есть больше нуля, выросло — сумма прироста;
- `contraction_mrr` — было и есть больше нуля, уменьшилось — сумма
  уменьшения, положительным числом;
- `churned_mrr` — было больше нуля, стало 0 — сумма прошлого MRR;
- `total_mrr` — суммарный MRR в месяце.

Нужны строки за **февраль, март, апрель и май 2024**. Январь в отчёт не
входит, но для февраля он — «предыдущий месяц». Отсутствие движения — `0`, не
`NULL`.

Проверка себя: `total` этого месяца = `total` прошлого + `new` + `expansion`
− `contraction` − `churned`.

Порядок: по `month` (первое число месяца, тип `date`).

```sql
WITH months AS (
  SELECT m::date AS month
  FROM generate_series(date '2024-01-01', date '2024-05-01', interval '1 month') AS m
),
mrr AS (
  SELECT c.id AS customer_id, m.month,
         coalesce(sum(p.monthly_price), 0) AS mrr
  FROM customers c
  CROSS JOIN months m
  LEFT JOIN subscriptions s ON s.customer_id = c.id
                           AND s.started_on <= m.month
                           AND (s.ended_on IS NULL OR s.ended_on > m.month)
  LEFT JOIN plans p ON p.id = s.plan_id
  GROUP BY c.id, m.month
),
moves AS (
  SELECT month, mrr,
         lag(mrr) OVER (PARTITION BY customer_id ORDER BY month) AS prev
  FROM mrr
)
SELECT month,
       sum(CASE WHEN prev = 0 AND mrr > 0      THEN mrr        ELSE 0 END) AS new_mrr,
       sum(CASE WHEN prev > 0 AND mrr > prev   THEN mrr - prev ELSE 0 END) AS expansion_mrr,
       sum(CASE WHEN mrr > 0  AND mrr < prev   THEN prev - mrr ELSE 0 END) AS contraction_mrr,
       sum(CASE WHEN prev > 0 AND mrr = 0      THEN prev       ELSE 0 END) AS churned_mrr,
       sum(mrr) AS total_mrr
FROM moves
WHERE month >= date '2024-02-01'
GROUP BY month
ORDER BY month;
```

Ответ:

```
2024-02-01 | 40 | 0  | 0  | 0  | 100
2024-03-01 | 0  | 0  | 0  | 10 | 90
2024-04-01 | 50 | 20 | 40 | 30 | 90
2024-05-01 | 10 | 0  | 0  | 0  | 100
```

**Сначала полная сетка «клиент × месяц».** `LAG` сравнивает строку с
предыдущей строкой, а не с предыдущим месяцем. Если у Дельты нет строки за
март (подписка кончилась), `LAG` для апреля возьмёт февраль, а отток в марте
не будет замечен вовсе — строки, в которой он должен был появиться, нет.
Поэтому `customers CROSS JOIN months` создаёт по строке на каждого клиента в
каждом месяце, а подписки присоединяются к ней через `LEFT JOIN` — и месяц
без подписки получает явный 0.

Порядок `CROSS JOIN` и `LEFT JOIN` в одном `FROM` законен: соединения
выполняются слева направо, и к моменту `LEFT JOIN subscriptions` колонка
`m.month` уже доступна в `ON`.

**Активность на дату — полуоткрытый интервал.** Бета сменила Team на Basic
1 апреля: строка Team кончается `ended_on = '2024-04-01'`, строка Basic с
него начинается. Условие `ended_on > month` не даёт обеим быть активными
1 апреля — иначе у Беты в апреле было бы 60, а не 10. Альфа перешла на Pro
10 марта — на 1 марта она ещё на Basic, апгрейд виден только в апреле.

Дельта — тонкий случай: подписка жила с 1 по 20 февраля. На 1 февраля она
активна, на 1 марта — нет: в феврале `new`, в марте `churn`.

**Фильтр по месяцам — после `LAG`.** Оконные функции считаются после
`WHERE` того же уровня. Если написать `WHERE month >= '2024-02-01'` рядом с
`lag(...)`, январь исчезнет раньше, чем окно его увидит, и у февраля `prev`
станет `NULL` — все февральские клиенты окажутся ни в одной категории.
Отсюда отдельный CTE `moves` и фильтр снаружи.

**`NULL` в `prev` у января** не страшен: январь всё равно отфильтрован. А если
бы строки января были нужны, пригодилось бы `lag(mrr, 1, 0)` — третий
аргумент задаёт значение по умолчанию.

**Условная агрегация.** Каждый `CASE` — «сумма по подмножеству клиентов»,
а `ELSE 0` гарантирует ноль вместо `NULL`, когда подмножество пусто. То же
можно записать через `coalesce(sum(mrr - prev) FILTER (WHERE …), 0)`.

**Апрель — все категории разом:**

```
клиент    март → апрель   категория
Альфа     10 → 30         expansion   +20
Бета      50 → 10         contraction  40
Гамма     30 → 0          churned      30
Эпсилон    0 → 50         new          50
итого 90 + 50 + 20 − 40 − 30 = 90
```
