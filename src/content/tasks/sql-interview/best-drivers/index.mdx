Сервис такси выбирает **лучшего водителя мая 2024 года в каждом городе**.

Поездка относится к маю, если водитель принял заказ (`accepted_at`) в мае.

Для водителя считаются:

- `done_rides` — число завершённых поездок (`status = 'done'`);
- `median_pickup_min` — **медиана** времени подачи в минутах
  (`arrived_at − accepted_at`) по завершённым поездкам. Медиана — как у
  `percentile_cont(0.5)`: при чётном числе значений — среднее двух
  центральных. `round(…, 1)`;
- `driver_cancel_pct` — доля поездок, отменённых **водителем**, среди всех
  его майских поездок любого статуса, в процентах, `round(…, 1)`;
- `avg_stars` — средняя оценка по поездкам, где оценку поставили,
  `round(…, 2)`.

К конкурсу допускаются водители с **не меньше чем тремя** завершёнными
поездками в мае. Победитель города — у кого медиана подачи меньше; при
равенстве медиан — у кого выше средняя оценка (водитель без оценок в этом
случае проигрывает); дальше — по имени. От каждого города — ровно один
победитель; город без допущенных водителей в отчёт не попадает.

- колонки: `city`, `driver`, `done_rides`, `median_pickup_min`,
  `driver_cancel_pct`, `avg_stars`;
- порядок: по `city`.

<Reveal>

```sql
WITH may AS (
  SELECT *
  FROM rides
  WHERE accepted_at >= '2024-05-01' AND accepted_at < '2024-06-01'
),
stats AS (
  SELECT d.id, d.name, d.city_id,
         count(*) FILTER (WHERE m.status = 'done') AS done_rides,
         percentile_cont(0.5) WITHIN GROUP (
           ORDER BY extract(epoch FROM m.arrived_at - m.accepted_at) / 60
         ) FILTER (WHERE m.status = 'done') AS median_pickup,
         100.0 * count(*) FILTER (WHERE m.status = 'cancelled_by_driver') / count(*) AS driver_cancel_pct,
         avg(r.stars) AS avg_stars
  FROM drivers d
  JOIN may m          ON m.driver_id = d.id
  LEFT JOIN ratings r ON r.ride_id = m.id
  GROUP BY d.id, d.name, d.city_id
  HAVING count(*) FILTER (WHERE m.status = 'done') >= 3
),
ranked AS (
  SELECT *,
         row_number() OVER (PARTITION BY city_id
                            ORDER BY median_pickup, avg_stars DESC NULLS LAST, name) AS rn
  FROM stats
)
SELECT c.name AS city,
       r.name AS driver,
       r.done_rides,
       round(r.median_pickup::numeric, 1) AS median_pickup_min,
       round(r.driver_cancel_pct, 1)      AS driver_cancel_pct,
       round(r.avg_stars, 2)              AS avg_stars
FROM ranked r
JOIN cities c ON c.id = r.city_id
WHERE r.rn = 1
ORDER BY city;
```

Ответ:

```
Казань | Глеб  | 4 | 10.5 | 28.6 | 3.50
Москва | Борис | 3 | 6.0  | 0.0  | 5.00
```

**Медиана — упорядоченный агрегат.** В Postgres нет функции `median`,
вместо неё `percentile_cont(0.5) WITHIN GROUP (ORDER BY …)`. У Глеба подачи
8, 9, 12 и 15 минут — медиана `(9 + 12) / 2 = 10.5`. Родственник
`percentile_disc(0.5)` вернул бы реальное значение из набора — 9. Среднее
(`avg`) у Глеба 11, у Даны 10.67 — по среднему победила бы Дана, по медиане
побеждает Глеб. На собеседовании часто спрашивают, чем медиана лучше для
времени подачи: она не реагирует на одну поездку с пробкой на час.

`percentile_cont` принимает `double precision`, а `round(x, 1)` с числом знаков
определён только для `numeric` — отсюда `::numeric` при выводе.

**Одна группировка, разные подмножества — `FILTER`.** В строках водителя
лежат и завершённые, и отменённые поездки. Число завершённых, медиана по
завершённым и доля отмен среди всех считаются в одном проходе: у каждого
агрегата свой `FILTER`. Отфильтровать `WHERE status = 'done'` заранее
нельзя — тогда отмены пропадут из знаменателя и числителя доли. `FILTER`
работает и с упорядоченными агрегатами: он пишется после `WITHIN GROUP`.

**Порог — в `HAVING`, по тому же `FILTER`.** «Три завершённые поездки», а не
«три поездки»: у Глеба семь поездок, у Артёма четыре, но считаются только
`done`.

**Май — по времени принятия заказа.** Валя: три поездки, медиана 1 минута —
лучший результат в Москве. Но одна поездка принята 30 апреля в 23:50, и в мае
остаётся две — Валя не допущена. Без фильтра по месяцу она бы выиграла.

**Оценки — через `LEFT JOIN`.** Оценки ставят не всегда. Внутренний `JOIN
ratings` выбросил бы неоценённые поездки из всех метрик сразу — и из числа
поездок, и из медианы, и из доли отмен (у отменённых оценок нет вовсе).
`avg(r.stars)` сам пропускает `NULL`, то есть считает среднее только по
оценённым. Размножения здесь нет: у поездки не больше одной оценки
(`ride_id` — первичный ключ).

**Победитель — `row_number` с полным ключом.** Артём и Борис в Москве —
медиана 6 у обоих. Второй ключ — оценка по убыванию: 4.50 против 5.00,
побеждает Борис. `NULLS LAST` нужен явно: при `DESC` Postgres ставит `NULL`
первыми, и водитель без единой оценки обошёл бы всех. Имя — последний ключ,
чтобы победитель был определён всегда. `rank() = 1` при полной ничьей вернул
бы двух победителей, а условие требует одного.

**Сочи**: у Евы две поездки — город без допущенных водителей, строки нет.
