Источник выдаёт событие раз в 300 мс, всего пять. Слушать их надо не
дольше секунды — значит, успеем три события, потом таймаут. Программа
печатает:

```
событие 1
событие 2
событие 3
событие 4
событие 5
источник закрылся
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 27: `case <-time.After(time.Second):` внутри цикла.

**`time.After` создаёт новый таймер при каждом вычислении.** Выражения в
ветках `select` вычисляются каждый раз, когда исполнение доходит до
`select`. Значит, на каждой итерации заводится новый таймер на секунду.
Событие приходит через 300 мс, итерация заканчивается, и следующая
начинает отсчёт заново. Пока события идут чаще раза в секунду, таймаут не
наступит никогда.

Такой код правилен для другой задачи — «таймаут *простоя*»: если событий
не было секунду, сдаёмся. Для общего ограничения он не подходит.

**Как правильно** — завести таймер один раз:

```go
timeout := time.After(time.Second)
for {
	select {
	case e, ok := <-events: ...
	case <-timeout: ...
	}
}
```

Или `ctx, cancel := context.WithTimeout(...)` и `case <-ctx.Done()` — тот же
смысл, плюс отмену можно передать дальше.

**Про память.** До Go 1.23 каждый `time.After` в горячем цикле держал таймер
до его срабатывания, и это была ещё и утечка памяти. Сейчас таймеры, на
которые никто не ссылается, собираются сразу, но логическая ошибка осталась.

</Reveal>
