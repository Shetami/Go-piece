Внешний API разрешает не больше двух одновременных запросов. Горутины
занимают место в семафоре-канале перед запросом и освобождают после.
Замер пика:

```
одновременно: 10 лимит: 2
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 14: `sem := make(chan struct{}, len(urls))`.

**Семафор на канале ограничивает ровно на ёмкость буфера.** Отправка
`sem <- struct{}{}` — «занять место» — блокируется, только когда буфер
полон. Буфер на десять мест при десяти горутинах не заполнится никогда, и
ограничения нет.

**Как правильно** — `make(chan struct{}, limit)`.

**Почему так легко ошибиться.** Буфер «по числу задач» — обычный приём для
канала *результатов*: тогда ни один воркер не заблокируется на отправке,
даже если результаты читают позже. Для семафора та же привычка ломает весь
смысл. Готовый вариант с понятным именем — `golang.org/x/sync/semaphore`
или `errgroup.Group.SetLimit`.

</Reveal>
