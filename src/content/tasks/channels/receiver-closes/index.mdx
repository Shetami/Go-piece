Производитель бесконечно шлёт числа. Получатель, дойдя до тройки, хочет
его остановить. Программа печатает

```
1
2
производитель остановился
panic: send on closed channel
```

и падает целиком, до `готово` дело не доходит. Отметьте строку, в которой
заложена поломка.

<Reveal>

Сломано в строке 20: `close(ch)` на стороне получателя.

**Закрывать канал должен отправитель.** Закрытие — это сообщение «значений
больше не будет», и дать такое обещание может только тот, кто их шлёт.
Производитель же продолжает писать: следующая отправка в закрытый канал —
паника. Паника в любой горутине роняет всю программу, `defer` успевает
напечатать своё, и всё.

**Как правильно остановить отправителя** — отдельным сигналом в обратную
сторону:

```go
done := make(chan struct{})

// производитель
select {
case ch <- i:
case <-done:
	return
}

// получатель
close(done)
```

`done` закрывает получатель — и это законно: в `done` никто не пишет, его
только читают. На практике вместо `done` передают `context.Context` и
отменяют его: это тот же канал `Done()`, но с деревом отмены и причиной.

</Reveal>
