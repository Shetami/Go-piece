Напишите `Take`: новый канал, в который попадают первые `n` значений из
`in`, после чего он закрывается.

Что проверяют скрытые тесты:

- из бесконечного потока — ровно `n` значений, затем закрытие;
- `in` закрылся раньше — выход закрывается, отдав то, что было;
- `ctx` отменён, а в `in` никто не пишет — выход всё равно закрывается;
- `n = 0` — выход закрывается сразу.

<Reveal>

```go
func Take(ctx context.Context, in <-chan int, n int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for range n {
			var v int
			var ok bool
			select {
			case v, ok = <-in:
				if !ok {
					return
				}
			case <-ctx.Done():
				return
			}
			select {
			case out <- v:
			case <-ctx.Done():
				return
			}
		}
	}()
	return out
}
```

**`defer close(out)` первой строкой.** У горутины три выхода: набрали
`n`, вход закончился, отменили. Закрыть выход надо в каждом — `defer`
делает это в одном месте.

**Отмена на обоих ожиданиях.** Горутина может застрять в двух местах: ждёт
значение из `in` (а писатель уснул) и ждёт, пока кто-то прочитает `out` (а
потребитель ушёл). Каждое ожидание — `select` с `ctx.Done()`. Пропустите
любое — и получите утечку горутины на отменённом запросе.

**`for range n`** (Go 1.22) — цикл на `n` итераций без переменной.

Готовые стадии вроде `Take`, `OrDone`, `Tee`, `Batch` в стандартной
библиотеке отсутствуют сознательно — их пишут под задачу. В Go 1.23+ многие
из них естественнее сделать итераторами без горутин вовсе.
