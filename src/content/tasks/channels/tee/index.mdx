Напишите `Tee`: два выходных канала, в каждый попадает каждое значение из
`in`. Оба закрываются после закрытия `in`.

Что проверяют скрытые тесты:

- оба потребителя получают все значения в исходном порядке, выходы
  закрываются;
- если сначала читают второй выход, а первый пока нет, значение всё равно
  доходит до второго — Tee не требует определённого порядка чтения.

<Reveal>

```go
for v := range in {
	o1, o2 := out1, out2
	for range 2 {
		select {
		case o1 <- v:
			o1 = nil
		case o2 <- v:
			o2 = nil
		}
	}
}
```

**Почему не две отправки подряд.** `out1 <- v; out2 <- v` работает, только
пока первым читают `out1`. Если потребитель второго выхода готов, а первого
— занят, Tee стоит на первой отправке, и второй ждёт зря. Второй тест
ровно про это.

**Приём с `nil`.** Локальные копии `o1`, `o2` отправляются через `select` —
кто первым готов. Отправившему присваивается `nil`: отправка в `nil`-канал
никогда не готова, и ветка выключается. Вторая итерация отдаёт значение
оставшемуся. Сами `out1` и `out2` не трогаем — в следующей итерации нужны
оба.

**Цена синхронности.** Tee без буферов движется со скоростью самого
медленного потребителя: следующее значение не начнёт раздаваться, пока оба
не забрали текущее. Если потребители сильно разные по скорости, нужны
буферы — с осознанным решением, что делать при их переполнении.

</Reveal>
