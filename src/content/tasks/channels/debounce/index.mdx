Напишите `Debounce`. Пользователь печатает в поиске — запрос уходит,
когда он замолчал на 300 мс. Файл сохраняется десять раз подряд —
пересборка запускается один раз. Но если события идут непрерывно (лог
пишется без пауз), чистый debounce не сработает никогда, поэтому нужен
потолок `maxWait` — как в `lodash.debounce`.

Что проверяют скрытые тесты:

- серия `1 2 3` без пауз — наружу уходит только `3`, и больше ничего;
  следующая серия начинается заново;
- вход закрыли, пока событие ждёт тишины длиной в час, — оно уходит
  сразу, потом выход закрывается;
- события идут каждые 10 мс в течение 400 мс, `wait` 40 мс, `maxWait`
  100 мс — наружу уходит хотя бы два события ещё до конца потока, а
  последним — самое последнее;
- при отмене выход закрывается, ожидающее событие не отправляется.

```go
func Debounce[T any](ctx context.Context, in <-chan T, wait, maxWait time.Duration) <-chan T {
	out := make(chan T)
	go func() {
		defer close(out)
		var (
			last     T
			pending  bool
			quiet    <-chan time.Time
			deadline <-chan time.Time
		)
		emit := func() bool {
			pending, quiet, deadline = false, nil, nil
			select {
			case out <- last:
				return true
			case <-ctx.Done():
				return false
			}
		}
		for {
			select {
			case v, ok := <-in:
				if !ok {
					if pending {
						emit()
					}
					return
				}
				last = v
				if !pending && maxWait > 0 {
					deadline = time.After(maxWait)
				}
				pending = true
				quiet = time.After(wait)
			case <-quiet:
				if !emit() {
					return
				}
			case <-deadline:
				if !emit() {
					return
				}
			case <-ctx.Done():
				return
			}
		}
	}()
	return out
}
```

**Два таймера с разной логикой перезапуска.** `quiet` перезаводится на
каждое событие — это и есть «тишина wait». `deadline` заводится только на
первом событии серии и не сдвигается — иначе он стал бы ещё одним `quiet`
и потолок не работал бы.

**`nil`-канал выключает ветку.** Пока серии нет, оба канала `nil`, и
`select` на них никогда не срабатывает. После отправки оба обнуляются —
старые таймеры просто забываются (с Go 1.23 их соберёт GC, даже
несработавшие). Без обнуления сработавший позже `deadline` отправил бы
пустое или повторное событие.

**Хвост при закрытии.** Если на `!ok` просто выйти, последнее событие
серии пропадёт — а это обычно самое важное (финальное сохранение файла).
Здесь его отправляют сразу, не дожидаясь `wait`.

**Что спросят дальше:** чем debounce отличается от throttle (throttle
пропускает первое событие и глушит остальные на интервал — «не чаще»,
а не «после паузы»), и как сделать leading-вариант, который отправляет
первое событие серии сразу.
