В обоих каналах по десять сообщений. Срочные должны обрабатываться первыми.
Запустите несколько раз — порядок каждый раз разный, например:

```
обычно-1
срочно-1
срочно-2
обычно-2
...
```

Почините. Ожидаемый вывод:

```
срочно-1
срочно-2
срочно-3
срочно-4
срочно-5
срочно-6
срочно-7
срочно-8
срочно-9
срочно-10
обычно-1
обычно-2
обычно-3
обычно-4
обычно-5
обычно-6
обычно-7
обычно-8
обычно-9
обычно-10
```

<Reveal>

**У `select` нет приоритетов.** Если готовы несколько веток, он выбирает
одну *случайно* и равновероятно — это сделано нарочно, чтобы ни один канал
не голодал. Порядок веток в коде ничего не значит.

**Приоритет делают двумя `select`.** Первый — только срочный канал и
`default`: если срочное есть, берём его, если нет — не ждём. Второй —
обычное ожидание обоих каналов, на случай когда срочного сейчас нет:

```go
if high != nil {
	select {
	case m, ok := <-high:
		...
		continue
	default:
	}
}
select {
case m, ok := <-high: ...
case m, ok := <-low: ...
}
```

Во втором `select` срочный канал оставлен нарочно: пока мы ждём, первым
может прийти и срочное.

**Приоритет не строгий.** Если срочное пришло, пока мы обрабатываем
обычное, оно подождёт конца этой обработки. Для большинства задач этого
достаточно.

</Reveal>
