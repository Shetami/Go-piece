kind: fix

Очередь метрик рассчитана на три значения, читателя пока нет. `report` не
должна блокировать работу: не влезло — выбросили. Программа падает:

```
fatal error: all goroutines are asleep - deadlock!
```

Почините `report`. Ожидаемый вывод:

```
отправлено: 3 выброшено: 2
```

<Reveal>

**Отправка в полный буфер блокирует.** Три метрики легли в буфер, на
четвёртой отправка ждёт, пока кто-нибудь освободит место. Читателя нет,
`main` стоит — дедлок. В настоящем сервисе с живыми горутинами дедлока бы
не было: просто основная работа встала бы, пока сборщик метрик тормозит.

**Как чинят** — `select` с `default`:

```go
select {
case metrics <- m:
	return true
default:
	return false
}
```

Если отправка может пройти прямо сейчас — она проходит. Если нет —
выполняется `default`, и функция возвращается мгновенно.

**Когда выбрасывать — правильно.** Метрики, логи отладки, сэмплы трассировки:
потерять часть лучше, чем замедлить основной путь. Для данных, которые
терять нельзя, нужен другой ответ — обратное давление (подождать),
отказ с ошибкой или отправка с таймаутом через `select` с `time.After` или
`ctx.Done()`.

</Reveal>
