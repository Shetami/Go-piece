Напишите `MergeSorted`. Так сливают логи с нескольких серверов по времени,
отсортированные куски при внешней сортировке, события из партиций в общий
порядок. Обычный fan-in здесь не подходит: он отдаёт значения в порядке
прихода, а нужен порядок по ключу.

Что проверяют скрытые тесты:

- `[0 4 9]`, `[]`, `[0 1 2 3 10 11]`, `[5]` → `0 0 1 2 3 4 5 9 10 11`:
  нули — законные данные, пустой вход не мешает;
- события с равным временем идут в порядке индексов входов;
- быстрый вход уже отдал `2`, а медленный пришлёт `1` только через 30 мс —
  первым всё равно должен выйти `1`;
- без входов выход сразу закрыт; при отмене, пока один вход молчит, выход
  закрывается и горутины не висят.

```go
func MergeSorted[T any](ctx context.Context, cmp func(a, b T) int, ins ...<-chan T) <-chan T {
	out := make(chan T)
	go func() {
		defer close(out)
		heads := make([]T, len(ins))
		has := make([]bool, len(ins))
		fill := func(i int) bool {
			select {
			case v, ok := <-ins[i]:
				if ok {
					heads[i], has[i] = v, true
				}
				return true
			case <-ctx.Done():
				return false
			}
		}
		for i := range ins {
			if !fill(i) {
				return
			}
		}
		for {
			best := -1
			for i := range ins {
				if has[i] && (best < 0 || cmp(heads[i], heads[best]) < 0) {
					best = i
				}
			}
			if best < 0 {
				return
			}
			select {
			case out <- heads[best]:
			case <-ctx.Done():
				return
			}
			has[best] = false
			if !fill(best) {
				return
			}
		}
	}()
	return out
}
```

**Выбирать минимум можно, только когда известны головы всех живых
входов.** Отсюда блокирующее чтение: пока медленный вход молчит, слияние
ждёт. Соблазн «взять то, что уже пришло» через `select` ломает порядок —
третий тест именно про это. Цена — слияние идёт со скоростью самого
медленного входа.

**Флаг `has`, а не «нулевое значение = пусто».** Для `int` ноль — обычное
число, для структуры — обычная запись. Закрытый вход — это `ok == false`,
его голова больше не появится.

**Стабильность — строгое `<`.** При равенстве остаётся ранее найденный,
то есть меньший индекс. С `<=` победил бы последний, и порядок равных
событий зависел бы от нумерации входов наоборот.

**Линейный поиск или куча.** Для k входов каждый шаг — O(k); при сотнях
входов лучше `container/heap` по головам, тогда O(log k). Каждое ожидание —
чтение головы и отправка — в `select` с `ctx.Done()`, иначе отмена
застанет горутину на молчащем входе. Что спросят дальше: как сливать
потоки, которые могут молчать вечно (watermark — «с этого входа меньше T
уже не придёт»), — так делают системы потоковой обработки.
