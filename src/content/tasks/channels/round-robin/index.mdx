Напишите тело `Split`.

Что проверяют скрытые тесты:

- `0..9` на три выхода → `[0 3 6 9]`, `[1 4 7]`, `[2 5 8]`;
- один выход получает всё по порядку;
- пустой вход → все выходы закрываются;
- `n <= 0` — паника.

<Reveal>

```go
func Split[T any](in <-chan T, n int) []<-chan T {
	if n <= 0 {
		panic("Split: n должно быть больше нуля")
	}
	outs := make([]chan T, n)
	ro := make([]<-chan T, n)
	for i := range outs {
		outs[i] = make(chan T)
		ro[i] = outs[i]
	}
	go func() {
		defer func() {
			for _, ch := range outs {
				close(ch)
			}
		}()
		i := 0
		for v := range in {
			outs[i] <- v
			i = (i + 1) % n
		}
	}()
	return ro
}
```

**Одна горутина — один писатель для всех выходов.** Раз она единственная
пишет, она же и закрывает: после конца `range in` писать больше некому.

**`[]chan T` нельзя вернуть как `[]<-chan T`.** Слайсы разных типов друг в
друга не превращаются, даже если элементы превращаются. Поэтому второй
слайс — копия с каналами на чтение. Получатель не сможет ни написать в
выход, ни закрыть его.

**Строгий круг — это связка.** Выходы без буфера, и пока нулевой выход
никто не читает, значение для него ждёт, а с ним и все остальные.
Это цена строгого порядка раздачи. Если важнее не простаивать — несколько
воркеров просто читают *один* канал, и значения достаются тому, кто
свободен.

</Reveal>
