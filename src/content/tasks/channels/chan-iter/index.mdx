Напишите `Values` и `Stream`. С Go 1.23 у нас два способа отдавать
последовательности: каналы (для конкурентных конвейеров) и итераторы
`iter.Seq` (для обычного `for range` без горутин). На стыке этих миров
легко получить панику или утёкшую горутину.

Что проверяют скрытые тесты:

- `break` в `for range Values(ctx, ch)` не вызывает паники, а из канала
  не прочитано ни одного лишнего значения — следующий `range` продолжает
  с того места;
- канал никогда не закроется, контекст отменён — `range` по `Values`
  заканчивается;
- `Stream(slices.Values(...))` отдаёт все значения (включая пустую
  строку) и закрывает канал;
- `Stream` бесконечного генератора: взяли три числа и отменили контекст —
  генератор останавливается, горутина завершается, хотя выход больше
  никто не читает.

<Reveal>

```go
func Values[T any](ctx context.Context, ch <-chan T) iter.Seq[T] {
	return func(yield func(T) bool) {
		for {
			select {
			case v, ok := <-ch:
				if !ok {
					return
				}
				if !yield(v) {
					return
				}
			case <-ctx.Done():
				return
			}
		}
	}
}

func Stream[T any](ctx context.Context, seq iter.Seq[T]) <-chan T {
	out := make(chan T)
	go func() {
		defer close(out)
		for v := range seq {
			select {
			case out <- v:
			case <-ctx.Done():
				return
			}
		}
	}()
	return out
}
```

**`yield` вернул `false` — остановиться немедленно.** Для range-over-func
компилятор превращает тело цикла в функцию `yield`; `break` и `return`
заставляют её вернуть `false`. Если итератор проигнорирует это и позовёт
`yield` снова, рантайм паникует: «range function continued iteration
after function for loop body returned false».

**Проверять `yield` до следующего чтения.** Итератор, который сначала
читает значение из канала, а потом смотрит, не было ли `break`, теряет
одно значение — оно уже вынуто из канала, а отдать его некому. Первый
тест проверяет, что после `break` канал продолжается с нужного места.

**В `Stream` `return` внутри `range seq` и есть остановка генератора.**
Выход из тела цикла делает `yield` равным `false`, правильный генератор
возвращается, срабатывает его `defer`. Без `select` с `ctx.Done()` на
отправке горутина навсегда зависла бы на `out <- v`, а вместе с ней и
бесконечный генератор.

**Когда что выбирать.** Итератор — вытягивание (pull) в той же горутине,
без синхронизации и аллокаций канала; канал — проталкивание (push) между
горутинами с буфером и `select`. Что спросят дальше: чем `iter.Pull`
отличается от `Stream` (он тоже превращает push в pull, но на корутинах
без настоящей горутины и требует вызвать `stop`).
