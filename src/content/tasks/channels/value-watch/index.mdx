Напишите `Var[T]`. Такое нужно для горячей перезагрузки конфига, для
«текущего лидера» в кластере, для статуса соединения: десятки горутин
хотят узнать об изменении сразу, а не опрашивать раз в секунду. Отправка
в канал разбудит одного — нужен broadcast, и не одноразовый.

Что проверяют скрытые тесты:

- десять горутин ждут на канале из `Get` — после `Set` просыпаются все;
  канал, полученный после `Set`, ещё открыт, а второй `Set` его закрывает
  (и не паникует);
- `WaitFor(n >= 50)`, пока другая горутина пишет `1..100`, дожидается
  подходящего значения; уже подходящее текущее значение возвращается сразу;
- `Set` сразу после запуска `WaitFor` не теряется — триста раз подряд;
- по таймауту `WaitFor` возвращает текущее значение и
  `DeadlineExceeded`.

<Reveal>

```go
type Var[T any] struct {
	mu      sync.Mutex
	val     T
	changed chan struct{}
}

func NewVar[T any](v T) *Var[T] {
	return &Var[T]{val: v, changed: make(chan struct{})}
}

func (x *Var[T]) Get() (T, <-chan struct{}) {
	x.mu.Lock()
	defer x.mu.Unlock()
	return x.val, x.changed
}

func (x *Var[T]) Set(v T) {
	x.mu.Lock()
	defer x.mu.Unlock()
	x.val = v
	close(x.changed)
	x.changed = make(chan struct{})
}

func (x *Var[T]) WaitFor(ctx context.Context, pred func(T) bool) (T, error) {
	for {
		v, ch := x.Get()
		if pred(v) {
			return v, nil
		}
		select {
		case <-ch:
		case <-ctx.Done():
			v, _ = x.Get()
			return v, ctx.Err()
		}
	}
}
```

**Многоразовый broadcast — закрыть и заменить.** Закрытый канал будит
всех, но закрыть его можно один раз. Поэтому `Set` закрывает текущий
канал и тут же ставит новый: кто взял старый — проснулся, кто придёт
позже — ждёт следующего изменения.

**Значение и канал — атомарно.** Если взять значение, отпустить замок и
потом взять канал, `Set` может вклиниться между ними: значение старое, а
канал уже новый, и изменение, случившееся «между», никто не заметит.
Это классическое потерянное пробуждение — ровно то, от чего в `sync.Cond`
спасает `Wait`, отпускающий мьютекс атомарно.

**Почему не `sync.Cond`.** `Cond.Wait` нельзя совместить с контекстом или
таймаутом — только сторонней горутиной с `Broadcast`. Канал встаёт в
`select` рядом с `ctx.Done()` бесплатно.

**Промежуточные значения можно пропустить** — и это нормально: читатель
видит последнее состояние, а не каждое изменение. Что спросят дальше:
как сделать, чтобы не терялось ни одно изменение (тогда это уже очередь
или pub/sub с буфером на подписчика) и как добавить номер версии, чтобы
`WaitFor` отличал «то же значение» от «новое, но равное».
