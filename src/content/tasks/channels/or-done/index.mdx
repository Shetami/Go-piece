`for v := range ch` не слышит отмену контекста: если `ch` не закроют, цикл
висит вечно. Напишите `OrDone`, чтобы можно было писать
`for v := range OrDone(ctx, ch)`.

Что проверяют скрытые тесты:

- значения пересылаются, выход закрывается вслед за входом;
- при отмене `ctx` выход закрывается, даже если `in` никто не закроет;
- если горутина взяла значение, а выход никто не читает, отмена её
  отпускает — утечки нет.

<Reveal>

```go
go func() {
	defer close(out)
	for {
		select {
		case <-ctx.Done():
			return
		case v, ok := <-in:
			if !ok {
				return
			}
			select {
			case out <- v:
			case <-ctx.Done():
				return
			}
		}
	}
}()
```

**Вложенный `select` на отправке.** Первый `select` ждёт значение или
отмену. Но, получив значение, горутина снова может застрять — на отправке в
`out`, если потребитель ушёл. Второй `select` закрывает эту дыру. Третий
тест проверяет именно её: значение взято, читателя нет, отмена должна
освободить горутину.

**Почему заготовка `return in` не работает.** Это тот же канал без
всякой связи с контекстом — ровно то, от чего задача и спасает.

Шаблон из книги «Concurrency in Go» Кэтрин Кокс-Будэй. Его стоит знать
наизусть: из таких кирпичей собираются все конвейеры.

</Reveal>
