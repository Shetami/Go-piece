Напишите `Dispatch`. Обычный пул воркеров, читающих один канал, ломает
порядок: «заказ создан» и «заказ оплачен» могут обработаться наоборот.
Один воркер на всё — медленно. Решение, как у партиций в Kafka: у каждого
воркера свой канал, а ключ задачи однозначно выбирает воркера.

Что проверяют скрытые тесты:

- 10 ключей по 50 задач, 4 воркера — у каждого ключа задачи идут строго
  по возрастанию, одновременно работает не больше четырёх `handle` (и всё
  же больше одного), а к возврату обработано всё;
- вход не закрывается, контекст отменён — `context.Canceled`, горутины
  воркеров не остаются висеть;
- отмена посреди долгого `handle` — `Dispatch` ждёт, пока он закончится.

<Reveal>

```go
func Dispatch(ctx context.Context, in <-chan Task, n int, handle func(Task)) error {
	shards := make([]chan Task, n)
	var wg sync.WaitGroup
	for i := range shards {
		shards[i] = make(chan Task, 16)
		wg.Add(1)
		go func(ch <-chan Task) {
			defer wg.Done()
			for t := range ch {
				if ctx.Err() != nil {
					continue
				}
				handle(t)
			}
		}(shards[i])
	}
	route := func() error {
		for {
			select {
			case <-ctx.Done():
				return ctx.Err()
			case t, ok := <-in:
				if !ok {
					return nil
				}
				h := fnv.New32a()
				h.Write([]byte(t.Key))
				select {
				case shards[h.Sum32()%uint32(n)] <- t:
				case <-ctx.Done():
					return ctx.Err()
				}
			}
		}
	}
	err := route()
	for _, ch := range shards {
		close(ch)
	}
	wg.Wait()
	if err == nil {
		err = ctx.Err()
	}
	return err
}
```

**Порядок даёт единственный читатель шарда.** Один ключ — один хеш — один
канал — одна горутина, которая читает его по очереди. Больше никакой
синхронизации не нужно. Хеш должен быть стабильным: `fnv` подходит, а
итерация по мапе или случайный выбор — нет.

**Писатель закрывает.** Роутер — единственный, кто пишет в шарды, поэтому
закрывает их он, когда вход кончился или пришла отмена. Воркеры выходят
из `range`, `wg.Wait()` дожидается хвоста — функция не возвращается,
пока кто-то ещё работает.

**После отмены воркеры дочитывают, а не выходят сразу.** Если воркер
просто вернётся по `ctx.Done()`, роутер может успеть заблокироваться на
отправке в его шард. Здесь отправка тоже в `select` с отменой, но
«дочитать без обработки» делает завершение простым и предсказуемым.

**Цена — head-of-line blocking.** Медленная задача одного ключа держит все
ключи своего шарда. Что спросят дальше: как это смягчить (больше шардов,
чем воркеров; или горутина на активный ключ с мапой очередей) и что
будет с порядком при изменении n — ключи переедут, как при ребалансе
партиций.
