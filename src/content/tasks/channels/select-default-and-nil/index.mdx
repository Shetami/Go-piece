`nilCh` объявлен, но не создан. `ready` — канал с буфером на одно значение.
Четыре `select` подряд: с `default`, без него и два раза отправка с
`default`.

Напишите весь вывод программы.

<Reveal>

**Операции с `nil`-каналом блокируются навсегда.** В `select` это значит,
что ветка никогда не будет выбрана — как будто её нет.

1. Первый `select`: из `nilCh` прочитать нельзя, других готовых веток нет,
   срабатывает `default`.
2. Второй: в `ready` лежит 7, ветка чтения готова. `nilCh` не мешает —
   `ready 7`. Без готовой ветки и без `default` здесь был бы дедлок.
3. Отправка `1`: буфер пуст (7 уже вычитали) — `отправили 1`.
4. Отправка `2`: буфер занят единицей, отправка заблокировала бы — берём
   `default`.

Итого:

```
default
ready 7
отправили 1
буфер полон 2
```

**Зачем это нужно.** `select` с `default` — неблокирующая попытка:
«отправь, если есть место, иначе выброси» (так делают сэмплирование логов и
метрик). А `nil`-канал — способ выключить ветку `select` на ходу: присвоили
переменной `nil` — ветка больше не срабатывает, не нужно переписывать сам
`select`.

</Reveal>
