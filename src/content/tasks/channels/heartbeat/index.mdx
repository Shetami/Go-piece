Напишите `Work`. Пульс нужен супервизору: воркер, который молчит дольше
пары интервалов, считается зависшим, и его перезапускают. Поэтому пульс
должен идти, *пока воркер жив*, — а жив он и когда ждёт задач, и когда
ждёт, пока кто-нибудь заберёт готовый результат. А если супервизора нет
вовсе, пульс не должен ничего блокировать.

Что проверяют скрытые тесты:

- пять задач, heartbeat никто не читает — все результаты приходят по
  порядку, потом оба канала закрываются;
- задач нет — пульс всё равно идёт; после отмены оба канала закрыты;
- результат готов, но его не забирают — пульс продолжается, а результат
  потом приходит.

<Reveal>

```go
func Work(ctx context.Context, pulse time.Duration, jobs <-chan int, f func(int) int) (<-chan struct{}, <-chan int) {
	hb := make(chan struct{}, 1)
	out := make(chan int)
	go func() {
		defer close(hb)
		defer close(out)
		ticker := time.NewTicker(pulse)
		defer ticker.Stop()
		beat := func() {
			select {
			case hb <- struct{}{}:
			default:
			}
		}
		for {
			select {
			case <-ctx.Done():
				return
			case <-ticker.C:
				beat()
			case j, ok := <-jobs:
				if !ok {
					return
				}
				r := f(j)
				for sent := false; !sent; {
					select {
					case out <- r:
						sent = true
					case <-ticker.C:
						beat()
					case <-ctx.Done():
						return
					}
				}
			}
		}
	}()
	return hb, out
}
```

**Пульс — неблокирующая отправка.** Обычное `hb <- struct{}{}` без
читателя остановит воркер на первом же тике: сигнал «я жив» сам убьёт
воркер. `select` с `default` выбрасывает сигнал, если его некому принять,
а буфер на один сохраняет последний для того, кто придёт позже.

**Каждое ожидание — в `select` с тикером.** Если отправлять результат
простым `out <- r`, пульс замрёт ровно тогда, когда потребитель тормозит,
и супервизор убьёт здоровый воркер. Поэтому отправка — отдельный цикл с
теми же ветками, что и основной.

**Пульс не доказывает, что работа идёт.** Он говорит «горутина не
зависла», но если `f` сама висит на сети, тикер тоже стоит. Поэтому в
проде рядом с пульсом нужен таймаут на саму операцию. Приём описан в
«Concurrency in Go» как heartbeats; что спросят дальше — как написать
супервизор, который перезапускает воркер по молчанию пульса.
