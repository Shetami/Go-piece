Напишите `Snapshot` — хелпер для тестов в духе `go.uber.org/goleak`:

```go
check := Snapshot()
defer func() {
	if err := check(time.Second); err != nil {
		t.Fatal(err)
	}
}()
```

Утечка горутин — одна из самых частых проблем Go-сервисов в проде:
забыли отменить контекст, не дочитали канал, и за сутки горутин
становятся сотни тысяч. Ловить такое лучше в тестах, и сразу со
стеками, по которым видно, где именно горутины повисли.

Что проверяют скрытые тесты:

- завершившиеся горутины утечкой не считаются;
- горутины, которые завершаются через 30 мс, при `timeout` в 2 с тоже не
  утечка;
- 800 горутин, повисших на канале, дают ошибку с префиксом
  `goroutine leak`, и в ней **все 800** стеков, а не первые 64 КБ;
- `check(50ms)` возвращается вовремя;
- двадцать вызовов `check` не оставляют после себя горутин.

<Reveal>

```go
func Snapshot() (check func(timeout time.Duration) error) {
	base := runtime.NumGoroutine()
	return func(timeout time.Duration) error {
		deadline := time.Now().Add(timeout)
		for {
			n := runtime.NumGoroutine()
			if n <= base {
				return nil
			}
			if !time.Now().Before(deadline) {
				return fmt.Errorf("goroutine leak: было %d, стало %d\n%s", base, n, allStacks())
			}
			time.Sleep(5 * time.Millisecond)
		}
	}
}

func allStacks() []byte {
	buf := make([]byte, 64<<10)
	for {
		n := runtime.Stack(buf, true)
		if n < len(buf) {
			return buf[:n]
		}
		buf = make([]byte, 2*len(buf))
	}
}
```

**Ждать, а не проверять сразу.** После `wg.Wait()` или `cancel()` горутина
может быть ещё жива: она выполняет `defer` или стоит в очереди
планировщика. Однократное сравнение `NumGoroutine` в тестах мигает. Опрос
с паузой до дедлайна убирает ложные срабатывания, но не прячет настоящую
утечку.

**`runtime.Stack` обрезает молча.** Функция пишет не больше `len(buf)`
байт и возвращает, сколько записала. Никакой ошибки нет, и дамп, влезший
ровно в буфер, от обрезанного не отличить. Поэтому буфер растим, пока
`n < len(buf)`. Так же устроен `debug.Stack`, но он даёт стек только
текущей горутины.

**Сравнение только по числу грубое.** Чужая горутина (например, от HTTP
keep-alive), которая завершилась, пока висит наша, скроет утечку.
Поэтому goleak сравнивает не числа, а множество стеков и игнорирует
известные системные горутины. Это хороший вопрос для продолжения
разговора: как отфильтровать горутины, которые были на момент
`Snapshot`?

**Сама проверка не должна течь.** `time.After` в цикле или вспомогательная
горутина с таймером ловятся тем же детектором. Простой цикл со
`time.Sleep` ничего после себя не оставляет.
