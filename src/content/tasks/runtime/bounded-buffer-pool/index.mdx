Допишите `BufferPool`. Такой пул стоит почти в каждом HTTP-сервисе: ответ
сериализуют в буфер из пула, пишут в сокет и возвращают буфер обратно —
без новой аллокации на каждый запрос.

Но у наивного пула две проблемы. Буфер возвращается с данными прошлого
запроса. А если однажды пришёл ответ на 50 МБ, буфер такого размера
вернётся в пул и дальше будет обслуживать ответы по 200 байт — и держать
50 МБ.

Что проверяют скрытые тесты:

- `Get` на пустом пуле возвращает новый буфер, а не `nil`;
- буфер из `Get` всегда пустой, даже если перед `Put` в него писали;
- пул действительно переиспользует буферы;
- после `Put` буфера с `Cap()` больше `maxCap` такой буфер из `Get` не
  возвращается;
- `Put(nil)` безопасен, пул работает из нескольких горутин.

<Reveal>

```go
type BufferPool struct {
	pool   sync.Pool
	maxCap int
}

func NewBufferPool(maxCap int) *BufferPool {
	p := &BufferPool{maxCap: maxCap}
	p.pool.New = func() any { return new(bytes.Buffer) }
	return p
}

func (p *BufferPool) Get() *bytes.Buffer {
	return p.pool.Get().(*bytes.Buffer)
}

func (p *BufferPool) Put(b *bytes.Buffer) {
	if b == nil || b.Cap() > p.maxCap {
		return
	}
	b.Reset()
	p.pool.Put(b)
}
```

**`New` в `sync.Pool`.** Без него `Get` на пустом пуле возвращает `nil`, и
каждый вызывающий должен сам это проверять. С `New` пул сам создаёт буфер.

**`Reset` при возврате.** Сбрасываем в `Put`, а не в `Get`, потому что
только здесь известно, что буфер больше никому не нужен. `Reset` обнуляет
длину, но оставляет выделенную память, ради которой пул и нужен.

**Ограничение по `Cap()`.** В пул нельзя возвращать всё подряд. Размер
объекта в пуле определяется самым большим запросом, который через него
прошёл. `sync.Pool` очищается сборщиком мусора (за два цикла благодаря
victim-кэшу), но под постоянной нагрузкой гигантский буфер будет
возвращаться снова и снова. Этот случай разобран в issue golang/go#23199,
и в `fmt` стоит такая же проверка: буферы больше 64 КБ в пул не
возвращаются.

**Что спросят дальше.** Почему `sync.Pool` хранит `any`, и чем плохо
класть туда `[]byte`, а не `*[]byte`: слайс при упаковке в интерфейс
копируется в кучу, и на каждом `Put` появляется лишняя аллокация. И
почему нельзя полагаться на то, что `Get` вернёт именно тот объект,
который только что положили: пул может выбросить его в любой момент.

</Reveal>
