Допишите `Interner`. Пригождается, когда в памяти миллионы записей с
небольшим набором повторяющихся строк — имена хостов, коды стран, названия
метрик: вместо миллиона копий `"ru-central1"` — одна.

Что проверяют скрытые тесты:

- две равные строки, собранные отдельно, возвращаются с **одними и теми
  же** байтами в памяти; разные строки — с разными;
- если передали подстроку мегабайтной строки, сохранённая строка не
  указывает в этот мегабайт;
- нулевой `Interner` готов к работе;
- повторный `Intern` уже сохранённой строки не выделяет память.

<Reveal>

```go
type Interner struct {
	m map[string]string
}

func (in *Interner) Intern(s string) string {
	if v, ok := in.m[s]; ok {
		return v
	}
	if in.m == nil {
		in.m = make(map[string]string)
	}
	c := strings.Clone(s)
	in.m[c] = c
	return c
}
```

**Мапа из строки в саму себя.** Ключ ищет по содержимому, значение отдаёт
*тот самый* экземпляр, который сохранили первым. Все дальнейшие равные
строки заменяются им, а их собственные байты становятся мусором.

**`strings.Clone` перед сохранением.** Строки часто приходят подстроками
больших буферов — строки лога, тела ответа. Сохранить подстроку — значит
навсегда удержать весь буфер: сборщик не освобождает часть объекта.

**Чтение отсутствующего ключа из `nil`-мапы допустимо**, поэтому ленивое
создание мапы можно делать только перед записью.

**Повторный вызов не выделяет:** поиск в мапе по строке ничего не копирует.

**В стандартной библиотеке** с Go 1.23 есть пакет `unique`:
`unique.Make(s)` возвращает `Handle`, который сравнивается за одну
операцию и не мешает сборщику освободить строку, когда на неё не осталось
ссылок. Наш `Interner` держит строки вечно.

</Reveal>
