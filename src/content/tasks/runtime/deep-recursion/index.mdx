`sum` считает сумму рекурсивно. Стек горутины ограничен мегабайтом через
`debug.SetMaxStack`. Программа падает:

```
runtime: goroutine stack exceeds 1048576-byte limit
fatal error: stack overflow
```

Почините, не трогая ограничение. Ожидаемый вывод:

```
500000500000
```

<Reveal>

**Каждый вызов занимает кадр на стеке.** Миллион вложенных вызовов — это
миллион кадров, даже если каждый всего в пару десятков байт. Стек горутины
в Go растёт сам — начинается с 8 КБ и удваивается по мере надобности, — но
не бесконечно: по умолчанию до гигабайта на 64-битных системах, здесь — до
мегабайта.

**Хвостовую рекурсию Go не оптимизирует.** В некоторых языках
`return n + sum(n-1)`, переписанный в хвостовую форму, превратился бы в
цикл. В Go — нет, каждый вызов остаётся на стеке.

**Как правильно** — цикл:

```go
total := 0
for i := 1; i <= n; i++ {
	total += i
}
```

Или формула `n * (n + 1) / 2`. Для обхода деревьев и графов, где рекурсия
естественна, но глубина зависит от данных, — явный стек на слайсе вместо
стека вызовов.

**Почему это не паника.** Переполнение стека — `fatal error`, его нельзя
перехватить через `recover`: программа завершается сразу.

</Reveal>
