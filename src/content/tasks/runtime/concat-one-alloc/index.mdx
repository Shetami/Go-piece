Заготовка работает, но на 50 строках выделяет память около сотни раз.
Перепишите `Concat` так, чтобы выделение было одно.

Что проверяют скрытые тесты:

- результат правильный, в том числе для `nil` и одного элемента;
- `testing.AllocsPerRun` на 50 строках — не больше одной аллокации на
  вызов.

<Reveal>

```go
func Concat(parts []string, sep string) string {
	if len(parts) == 0 {
		return ""
	}
	n := len(sep) * (len(parts) - 1)
	for _, p := range parts {
		n += len(p)
	}
	var b strings.Builder
	b.Grow(n)
	for i, p := range parts {
		if i > 0 {
			b.WriteString(sep)
		}
		b.WriteString(p)
	}
	return b.String()
}
```

**Почему `+=` дорого.** Строки неизменяемы. `s += p` выделяет новую строку
длиной `len(s) + len(p)` и копирует обе части. На n кусках это n аллокаций
и O(n²) копирования в сумме.

**`Builder` без `Grow`** уже намного лучше: его буфер растёт удвоением, это
O(log n) аллокаций. Но условие просит одну — значит, длину надо посчитать
заранее. `Grow(n)` выделяет ровно столько, и дальше `WriteString` только
копирует.

**`String()` не копирует.** `strings.Builder` отдаёт строку поверх своего
буфера через `unsafe`. Это безопасно, потому что `Builder` никогда не
переписывает уже записанные байты, а только дописывает новые, — и ради
этой гарантии запрещает копировать себя.
Поэтому аллокация одна, а не две.

**В стандартной библиотеке так и сделано:** `strings.Join` считает длину и
вызывает `Grow` ровно так же. На собеседовании ответ «`strings.Join`» тоже
засчитают — если вы объясните, почему он быстрый.

</Reveal>
