Допишите `Buf` — упрощённый `strings.Builder`. Ради `String()` без копии
и без аллокации буфер отдаёт строку, которая смотрит в его собственный
массив. Это накладывает ограничения. Во-первых, уже отданные байты нельзя
менять: строки в Go неизменяемы, и на этом держатся ключи карт. Во-вторых,
две копии `Buf` делят один массив, и запись в одну портит другую, поэтому
копирование нужно ловить.

Что проверяют скрытые тесты:

- `Write`, `WriteString`, `String`, `Len` работают на нулевом значении;
- строки, полученные до следующих записей **и до `Reset`**, не меняются;
- `String` не выделяет память (`testing.AllocsPerRun`);
- запись в копию непустого `Buf` вызывает панику, а запись в оригинал —
  нет; `Len`/`String` на копии работают;
- копию нулевого `Buf` и копию после `Reset` можно использовать.

<Reveal>

```go
type Buf struct {
	addr *Buf
	buf  []byte
}

func (b *Buf) copyCheck() {
	if b.addr == nil {
		b.addr = b
	} else if b.addr != b {
		panic("Buf: запись в копию непустого Buf")
	}
}

func (b *Buf) Write(p []byte) (int, error) {
	b.copyCheck()
	b.buf = append(b.buf, p...)
	return len(p), nil
}

func (b *Buf) WriteString(s string) {
	b.copyCheck()
	b.buf = append(b.buf, s...)
}

func (b *Buf) String() string {
	return unsafe.String(unsafe.SliceData(b.buf), len(b.buf))
}

func (b *Buf) Len() int { return len(b.buf) }

func (b *Buf) Reset() {
	b.addr = nil
	b.buf = nil
}
```

**Указатель на себя ловит копию.** При первой записи `Buf` запоминает
свой адрес. Копия получает то же значение поля, но живёт по другому
адресу, и `b.addr != b` выдаёт её. Нулевой `Buf` ещё ничего не запомнил,
поэтому его копировать можно. Ровно так сделан `strings.Builder`.
`go vet` копирование не поймает: проверка `copylocks` срабатывает только
на типах с методом `Lock`.

**`Reset` бросает массив, а не обрезает.** `b.buf = b.buf[:0]` выглядит
экономнее, но следующая запись положит новые байты туда, куда смотрят
уже отданные строки, и «неизменяемая» строка поменяется. Это хуже
паники: сломается, например, поиск в карте по такому ключу. `append` за
пределами `len` безопасен: отданные строки этих байт не видят.

**`unsafe.String(unsafe.SliceData(b), len(b))`** — официальный с Go 1.20
способ сделать строку из байт без копии. Для пустого `nil`-слайса он
вернёт пустую строку. Обычное `string(b.buf)` на каждом вызове выделяет
память и копирует данные.

**Цена `addr`: буфер уходит в кучу.** Присваивание `b.addr = b`
заставляет escape-анализ считать, что `b` утекает, и `var b Buf` на
стеке становится аллокацией в куче. В `strings.Builder` это обходят
внутренней функцией `abi.NoEscape`, которая прячет указатель от
анализатора. Можно проверить на `go build -gcflags=-m`: без трюка там
будет `moved to heap: b`.

**Что спросят дальше.** Почему `bytes.Buffer` может отдавать `Bytes()`
без копии, но не `String()`: байты в буфере меняются, а строка обязана
быть неизменной. И почему `strings.Builder.Grow` так важен для горячего
пути: одна аллокация вместо цепочки ростов.
