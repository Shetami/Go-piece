Строку кладут ключом в мапу, потом буфер переписывают под новое сообщение.
Программа печатает:

```
пока!!т
false
```

Строка поменялась, а ключ `"привет"` в мапе больше не находится. Почините.
Ожидаемый вывод:

```
привет
true
```

<Reveal>

**`unsafe.String` не копирует — строка смотрит в тот же массив, что и
слайс.** Язык обещает, что строки неизменяемы, и на этом обещании держится
многое: строки можно делить между горутинами без синхронизации, класть
ключами в мапы, отдавать наружу без копии. `unsafe.String` снимает с
компилятора ответственность и перекладывает её на вас: пока строка жива,
байты под ней менять нельзя.

Здесь их поменяли. `s` теперь видит новые байты. А мапа хранила ключ,
посчитав хеш от «привет»; байты ключа поменялись, хеш — нет. Поиск по
«привет» находит нужный бакет, сравнивает байты — не совпадают. Поиск по
«пока!!т» ищет в другом бакете. Элемент стал недостижим.

**Как чинят** — обычная конверсия `string(b)`: она копирует байты, и строка
становится независимой от буфера.

**Когда `unsafe.String` законен.** Когда вы можете доказать, что байты
больше никогда не изменятся — например, буфер создан здесь же и никуда не
уходит. Компилятор и сам убирает копирование в безопасных случаях:
`m[string(b)]` при поиске в мапе и `string(b) == "..."` не выделяют память.
Прежде чем лезть в `unsafe`, посмотрите в профиль — скорее всего, копия не
то место, где теряется время.

</Reveal>
