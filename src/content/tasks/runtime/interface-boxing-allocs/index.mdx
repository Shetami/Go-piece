Четыре значения — 7, 1000, строку и указатель — по очереди кладут в
глобальную `sink any`. Значения вычисляются от `len(os.Args)`, который в
песочнице равен 1: так компилятор не может заранее превратить их в
константы.
`testing.AllocsPerRun` запускает функцию 100 раз и возвращает среднее число
выделений памяти в куче на запуск.

Напишите весь вывод программы.

<Reveal>

**Интерфейс хранит два слова: тип и указатель на данные.** Значение, которое
само не указатель, надо куда-то положить, чтобы на него сослаться. Раз
`sink` глобальная, данные переживут функцию — значит, в кучу.

**Но у рантайма есть оптимизации.**

- **Маленькие числа не выделяются.** Для значений от 0 до 255 у рантайма
  есть готовая таблица `staticuint64s` — интерфейс просто указывает в неё.
  `7` — ноль выделений.
- **`1000` в таблицу не попадает** — одно выделение на 8 байт.
- **Строка — это заголовок из двух слов** (указатель и длина). Его надо
  скопировать в кучу — одно выделение. Сами байты строки не копируются.
- **Указатель кладётся в интерфейс как есть** — он уже слово. Ноль.
- **Константы не стоят ничего.** Напишите `sink = 1000` или `sink = "го"` —
  и компилятор положит данные в секцию только для чтения ещё при сборке.
  Поэтому в задаче значения и получены через `len(os.Args)`.

Итого:

```
int 7: 0
int 1000: 1
string: 1
указатель: 0
```

**Где это видно.** `fmt.Println(x)`, логгер с `...any`, `sort.Slice` со
сравнением через интерфейс — каждое значение, упакованное в `any`, может
стоить выделения. В горячем коде это заметно в профиле аллокаций, а
лечится типизированными функциями и дженериками вместо `any`.

</Reveal>
