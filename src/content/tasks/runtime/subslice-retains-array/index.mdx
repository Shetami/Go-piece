Полезных данных — 20 заголовков по 16 байт. После `runtime.GC()` программа
печатает:

```
заголовков: 20
в куче больше 10 МБ: true
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 14: `headers = append(headers, file[:16])`.

**Подслайс держит весь массив.** `file[:16]` — это указатель на начало
мегабайтного массива, длина 16 и вместимость 1 МБ. Сборщик мусора не умеет
освобождать «хвост» массива: объект в куче либо жив целиком, либо мёртв.
Пока на массив есть хотя бы один указатель, живы все его мегабайт. 20
заголовков держат 20 МБ.

**Как правильно** — скопировать нужное в отдельный маленький массив:

```go
headers = append(headers, bytes.Clone(file[:16]))
```

Теперь на мегабайтные массивы никто не ссылается, и первая же сборка их
освобождает.

**Где это встречается.** Кэш, в который кладут кусок большого ответа.
Строки из разобранного файла: `s[a:b]` для строк работает так же — держит
всю исходную строку. Для строк есть `strings.Clone`. В профиле памяти такая
утечка видна как огромное выделение в функции *чтения*, хотя данные давно
«выброшены».

</Reveal>
