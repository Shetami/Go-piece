Из каждой огромной строки лога сохраняется только уровень — `"ERROR"`.
Сами строки больше не нужны. После `runtime.GC()`:

```
слов: 20, первое: ERROR, в куче: 20 МБ
```

Отметьте строку, из-за которой память не освобождается.

<Reveal>

Сломано в строке 15: `return s[:i]`.

**Подстрока не копирует байты.** Строка в Go — указатель и длина. `s[:i]`
— новый заголовок с тем же указателем и длиной 5. Эти пять байт лежат в
начале мегабайтного массива, и пока жива подстрока, сборщик не может
освободить массив: он не умеет освобождать часть объекта.

Двадцать сохранённых слов по пять байт держат двадцать мегабайт.

**Как правильно** — скопировать то, что сохраняете надолго:
`strings.Clone(s[:i])` (Go 1.20). Копия — пять байт в своём маленьком
объекте, а мегабайтная строка становится мусором.

**Когда об этом думать.** Когда маленький кусок большой строки или слайса
уходит в долгоживущую структуру: кэш, мапу, глобальный список. Для
подстроки, которая живёт до конца функции, копия не нужна — это лишнее
выделение. То же самое со слайсами: `bytes.Clone`, `slices.Clone`.

</Reveal>
