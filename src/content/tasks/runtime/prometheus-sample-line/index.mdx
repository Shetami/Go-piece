Сервис отдаёт на `/metrics` 50 000 серий, Prometheus забирает их раз в
15 секунд с трёх реплик. В CPU-профиле видно, что сериализация метрик
выделяет сотни мегабайт в минуту. Напишите `AppendSample` — одну строку
текстового формата, дописанную в переиспользуемый буфер без единой
аллокации.

Что проверяют скрытые тесты:

- без меток — `m 42`; метки **отсортированы по имени**; числа `0.5`,
  `1e+06`, `-1`, `NaN`, `+Inf`, `-Inf`;
- экранирование `\`, `"` и перевода строки в значении метки;
- метки с пустым значением пропускаются, и если меток не осталось, то
  без `{}`; кириллица в именах и значениях проходит как есть;
- **входной слайс меток не меняется**, строка дописывается к `dst`;
- 5 меток (одна пустая, одна с кавычками) при буфере на 512 байт —
  **ноль** аллокаций.

<Reveal>

```go
func AppendSample(dst []byte, name string, labels []Label, value float64) []byte {
	var tmp [16]Label
	ls := tmp[:0]
	for _, l := range labels {
		if l.Value == "" {
			continue
		}
		ls = append(ls, l)
		for i := len(ls) - 1; i > 0 && ls[i].Name < ls[i-1].Name; i-- {
			ls[i], ls[i-1] = ls[i-1], ls[i]
		}
	}

	dst = append(dst, name...)
	if len(ls) > 0 {
		dst = append(dst, '{')
		for i, l := range ls {
			if i > 0 {
				dst = append(dst, ',')
			}
			dst = append(dst, l.Name...)
			dst = append(dst, '=', '"')
			dst = appendEscaped(dst, l.Value)
			dst = append(dst, '"')
		}
		dst = append(dst, '}')
	}
	dst = append(dst, ' ')
	dst = strconv.AppendFloat(dst, value, 'g', -1, 64)
	return append(dst, '\n')
}

func appendEscaped(dst []byte, s string) []byte {
	for i := 0; i < len(s); i++ {
		switch c := s[i]; c {
		case '\\':
			dst = append(dst, '\\', '\\')
		case '"':
			dst = append(dst, '\\', '"')
		case '\n':
			dst = append(dst, '\\', 'n')
		default:
			dst = append(dst, c)
		}
	}
	return dst
}
```

**Сортировать нужно, а трогать вход нельзя.** `slices.SortFunc(labels, …)`
на слайсе вызывающего — гонка данных, если те же метки пишут из
нескольких горутин, и сюрприз для кода, который полагался на порядок.
Копия через `slices.Clone` стоит аллокацию на каждую строку. Выход —
массив `[16]Label` на стеке. Пока ссылка на него не покидает функцию,
escape-анализ оставляет его в кадре стека, и `append` в `tmp[:0]` до
16 элементов памяти не выделяет. Проверить можно так:
`go build -gcflags=-m` не должен написать `moved to heap: tmp`.

**Вставкой, а не общей сортировкой.** Меток обычно 2–6, и сортировка
вставками на таком размере быстрее всего остального. Есть и тонкость
про escape-анализ: чем меньше `ls` передаётся в чужие функции (особенно
через замыкания и интерфейсы), тем надёжнее компилятор докажет, что
он не утекает.

**Пустое значение — не пустая строка в выводе.** В модели данных
Prometheus метка с пустым значением эквивалентна отсутствию метки.
`{a=""}` создаёт ту же серию, что и без метки, но выглядит как другая
при сравнении строк. Клиентские библиотеки выбрасывают такие метки при
сериализации.

**`strconv.AppendFloat(…, 'g', -1, 64)`** даёт кратчайшее представление,
которое читается обратно без потерь, и сам пишет `NaN`, `+Inf`, `-Inf`
именно так, как ждёт формат. `fmt.Sprintf("%v")` дал бы тот же текст, но
с аллокацией и упаковкой аргумента в интерфейс.

**Что спросят дальше.** Почему в проде такие строки кэшируют: имя и
метки серии не меняются, и префикс `name{…} ` можно собрать один раз,
а на каждом сборе дописывать только число. И почему кардинальность
меток (`user_id` в метке) опаснее любой аллокации: каждая уникальная
комбинация — отдельная серия в TSDB.
