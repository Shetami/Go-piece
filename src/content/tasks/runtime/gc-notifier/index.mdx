Адаптивному кэшу нужно знать, когда прошла сборка мусора, чтобы
посмотреть на `HeapAlloc` и подрезать себя под давлением памяти.
Подписки на GC в стандартной библиотеке нет. Зато есть известный приём:
объект-сторож, на который никто не ссылается. Его финализатор
срабатывает после сборки и заводит сторожа снова. Так давно делают
библиотеки кэшей и пулов, которым нужно реагировать на сборку мусора.

Допишите `OnGC`.

Что проверяют скрытые тесты:

- пять подряд вызовов `runtime.GC()` (с ожиданием между ними) дают по
  вызову `f` **после каждого**, а не один раз;
- после `stop` вызовы прекращаются;
- два уведомителя независимы: остановка одного не ломает другой.

<Reveal>

```go
type gcState struct {
	f       func()
	stopped atomic.Bool
}

type sentinel struct {
	st *gcState
}

func OnGC(f func()) (stop func()) {
	st := &gcState{f: f}
	runtime.SetFinalizer(&sentinel{st: st}, onSentinel)
	return func() { st.stopped.Store(true) }
}

func onSentinel(s *sentinel) {
	if s.st.stopped.Load() {
		return
	}
	s.st.f()
	runtime.SetFinalizer(s, onSentinel)
}
```

**Сторож срабатывает, потому что недостижим.** После `OnGC` ссылок на
`sentinel` нет ни у кого. Ближайший цикл GC находит его мёртвым, видит
финализатор и вместо освобождения ставит его в очередь финализаторов.
Финализатор получает объект и на время своей работы делает его снова
живым.

**Перевзвести на себе.** Документация `runtime.SetFinalizer` прямо
разрешает финализатору заново вызвать `SetFinalizer` на том же объекте.
После возврата сторож опять недостижим, и следующий цикл повторяет всё.
Если не перевзводить, сработает только первый раз. Одна аллокация на
всё время жизни уведомителя.

**Главная ловушка — замыкание.** `runtime.SetFinalizer(s, func(*sentinel)
{ …s… })` или финализатор-замыкание, которое держит сторожа через
состояние, делают сторожа достижимым из собственного финализатора: он
зарегистрирован в рантайме и является корнем сборки мусора. Тогда
уведомитель молча не срабатывает никогда. Состояние должно ссылаться
«вниз» (`sentinel → gcState`), но не «вверх» на сторожа.

**Поле-указатель в стороже.** Объекты без указателей меньше 16 байт
tiny-аллокатор упаковывает по несколько в один блок, а блок
освобождается только целиком. Финализатор такого объекта может не
вызваться никогда, и документация об этом предупреждает. Указатель
в структуре выводит её из tiny-аллокатора.

**Что спросят дальше.** Почему `f` должна быть быстрой: все финализаторы
выполняются в одной горутине, и медленный колбэк задерживает закрытие
файлов по всей программе. Почему уведомление может прийти с опозданием
на цикл. И что вместо этого предлагает Go: `runtime/metrics`
(`/gc/cycles/total:gc-cycles`) для опроса и `debug.SetMemoryLimit` для
случаев, где цель — не превысить память.
