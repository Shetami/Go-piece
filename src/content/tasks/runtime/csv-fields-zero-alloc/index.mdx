Импорт выгрузки на сто миллионов строк. `encoding/csv` на каждую строку
создаёт новые строки полей, и профиль показывает, что половина времени
уходит на `mallocgc` и сборку мусора. Напишите `AppendFields`: поля — это
подстроки исходной строки, память не выделяется, если в строке нет
экранированных кавычек.

Что проверяют скрытые тесты:

- обычные поля, пустая строка (одно пустое поле), пустые поля в конце,
  запятые в кавычках, `""` внутри кавычек, поле `""""` (одна кавычка),
  кириллица;
- ошибки: незакрытая кавычка, символы после закрывающей кавычки
  (включая пробел), кавычка посреди поля без кавычек. При ошибке `dst`
  возвращается **без частично добавленных полей**;
- поля дописываются к `dst`, а не заменяют его;
- строка без `""` при `dst` на 16 элементов — **ноль** аллокаций, строка с
  одним экранированным полем — не больше одной.

<Reveal>

```go
func AppendFields(dst []string, line string) ([]string, error) {
	orig := len(dst)
	for {
		if !strings.HasPrefix(line, `"`) {
			end := strings.IndexByte(line, ',')
			field := line
			if end >= 0 {
				field = line[:end]
			}
			if strings.IndexByte(field, '"') >= 0 {
				return dst[:orig], ErrSyntax
			}
			dst = append(dst, field)
			if end < 0 {
				return dst, nil
			}
			line = line[end+1:]
			continue
		}

		body := line[1:]
		i, escaped := 0, false
		for {
			j := strings.IndexByte(body[i:], '"')
			if j < 0 {
				return dst[:orig], ErrSyntax
			}
			i += j
			if i+1 < len(body) && body[i+1] == '"' {
				escaped = true
				i += 2
				continue
			}
			break
		}
		raw := body[:i]
		if escaped {
			var b strings.Builder
			b.Grow(len(raw) - strings.Count(raw, `""`))
			for k := 0; k < len(raw); k++ {
				b.WriteByte(raw[k])
				if raw[k] == '"' {
					k++
				}
			}
			raw = b.String()
		}
		dst = append(dst, raw)

		rest := body[i+1:]
		switch {
		case rest == "":
			return dst, nil
		case rest[0] == ',':
			line = rest[1:]
		default:
			return dst[:orig], ErrSyntax
		}
	}
}
```

**Подстрока — это просто новый заголовок строки.** `line[a:b]` создаёт
пару «указатель + длина» на те же байты, без копирования и без
аллокации. Заголовки ложатся в `dst`, у которого уже есть вместимость.
Цена в том, что каждое поле удерживает в памяти всю `line`. Если поле
нужно хранить долго (ключ в кэше), его стоит отцепить через
`strings.Clone`, иначе появится утечка того же сорта, что с подслайсами.

**`""` требует копии, и ровно одной.** Удалить символы из середины без
нового буфера нельзя. `strings.Builder` с `Grow` на точный итоговый
размер выделяет память один раз, а `String()` отдаёт её без повторного
копирования. Вариант `[]byte` + `string(b)` стоит две аллокации,
`strings.ReplaceAll` — одну, но требует выделения подстроки заранее и
второго прохода по данным.

**`dst[:orig]` при ошибке.** Вызывающий переиспользует `dst` между
строками. Если вернуть половину полей плохой строки, при следующем
вызове они окажутся мусором в начале. Откатить длину ничего не стоит.

**Строгость против терпимости.** `"a" ,b` (пробел после кавычки) и
`a"b` — ошибки по RFC 4180. У `encoding/csv` есть `LazyQuotes` для
выгрузок из Excel, но по умолчанию он строгий, и мы тоже.

**Что спросят дальше.** Как разбирать `[]byte` из `bufio.Reader` без
копирования в строку (`unsafe.String`, пока буфер не переиспользован, и
почему после следующего `ReadSlice` такие строки портятся). И как
проверить, что поле действительно подстрока: сравнить
`unsafe.StringData` с диапазоном адресов `line`.
