У слайса `s` длина 3 и вместимость 5. От него делают два `append` — сначала
с единицей, потом с двойкой — и печатают оба результата.

Напишите весь вывод программы.

<Reveal>

**`append` пишет в старый массив, если там есть место.** У `s` длина 3,
вместимость 5, значит ячейки с индексами 3 и 4 уже выделены, просто не входят
в длину. Первый `append` кладёт `1` в ячейку 3 и возвращает слайс длиной 4
поверх *того же* массива.

Второй `append` начинает с того же `s` — длина 3, — и тоже пишет в ячейку 3.
Туда, где уже лежит единица. Теперь там двойка, и `a`, и `b` видят её, потому
что смотрят в один массив:

```
массив: [0 | 0 | 0 | 2 | _]
s:       len 3
a:       len 4   ← та же память
b:       len 4   ← та же память
```

Сам `s` не меняется: `append` возвращает новый заголовок слайса, а старый
остаётся с длиной 3.

Итого:

```
[0 0 0 2] [0 0 0 2]
3 5
4 5
```

**Правило.** Результат `append` присваивают той же переменной:
`s = append(s, x)`. Как только от одного слайса растут две ветки, они
начинают затирать друг друга, пока хватает вместимости, и расходятся, когда
её перестаёт хватать. Такие баги видно только при определённых длинах.
Если нужны две независимые ветки, сначала копируйте: `slices.Clone(s)`.

</Reveal>
