`chunk` режет слайс на куски по `size` элементов, последний может быть
короче. На `[1 2 3 4 5]` пятёрка пропадает, а `[1]` превращается в `[]`.

Почините. Ожидаемый вывод:

```
[[1 2] [3 4] [5]]
[[1 2] [3 4]]
[[1]]
```

<Reveal>

**Условие цикла требует целый кусок.** `i+size <= len(xs)` пускает в цикл,
только если от `i` до конца есть `size` элементов. Неполный последний кусок
не проходит проверку и теряется.

**Как чинят** — идти, пока остался хоть один элемент, а конец куска
ограничивать длиной:

```go
for i := 0; i < len(xs); i += size {
	end := min(i+size, len(xs))
	out = append(out, xs[i:end:end])
}
```

Встроенная `min` — с Go 1.21.

**Зачем третье число `xs[i:end:end]`.** Куски — это окна в исходный массив.
Без ограничения вместимости `append` к первому куску записал бы в начало
второго. С полной формой среза `append` будет вынужден копировать.

**Готовое решение.** С Go 1.23 есть `slices.Chunk(xs, size)` — итератор,
который отдаёт куски по одному, с той же защитой вместимости.

</Reveal>
