Напишите тело `Upsert`. Отсортированный слайс — хороший индекс в памяти
(двоичный поиск, плотные данные, быстрый обход), пока его не начинают
менять. Изменения приходят пачками — из очереди, из WAL, из батча
запросов, — и вливать их надо целиком, а не по одной строке. Так же
устроена запись memtable в SST-файл в LSM-дереве.

Что проверяют скрытые тесты:

- новые строки встают на свои места, существующие — заменяются;
- повторы ID в `batch` — побеждает последнее вхождение;
- `batch` не меняется; пустые `rows` и пустой `batch`;
- если вместимости `rows` хватает, результат лежит в том же массиве;
- 20 000 новых строк в таблицу на 200 000 — быстро; вставка по одной со
  сдвигом хвоста — это миллиарды копирований.

<Reveal>

```go
func Upsert(rows, batch []Row) []Row {
	b := slices.Clone(batch)
	slices.SortStableFunc(b, func(x, y Row) int { return cmp.Compare(x.ID, y.ID) })
	w := 0
	for i := range b {
		if i+1 < len(b) && b[i+1].ID == b[i].ID {
			continue
		}
		b[w] = b[i]
		w++
	}
	b = b[:w]

	fresh := 0
	i := 0
	for _, r := range b {
		for i < len(rows) && rows[i].ID < r.ID {
			i++
		}
		if i < len(rows) && rows[i].ID == r.ID {
			rows[i] = r
		} else {
			b[fresh] = r
			fresh++
		}
	}
	b = b[:fresh]

	n := len(rows)
	rows = slices.Grow(rows, fresh)[:n+fresh]
	i, j := n-1, fresh-1
	for k := n + fresh - 1; j >= 0; k-- {
		if i >= 0 && rows[i].ID > b[j].ID {
			rows[k] = rows[i]
			i--
		} else {
			rows[k] = b[j]
			j--
		}
	}
	return rows
}
```

**Сначала привести пачку в порядок.** Копия (вход чужой), стабильная
сортировка по ID и сжатие повторов, где выживает **последний** в серии.
Стабильность здесь обязательна: только она гарантирует, что последний в
серии — это последний во входе. `slices.CompactFunc` не подходит — он
оставляет первого.

**Обновления — на месте, новые — в отдельный список.** Один проход двумя
указателями по двум отсортированным спискам: совпал ID — заменили строку
в `rows`, не совпал — это новая строка. Теперь точно известно, на
сколько вырастет результат.

**Слияние с конца.** `slices.Grow` один раз расширяет `rows` (или ничего
не выделяет, если места хватает). Дальше сливаем с конца: самый большой
из оставшихся элементов идёт в самую дальнюю свободную ячейку. Пишущий
индекс `k` всегда не левее читающего `i`, поэтому ничего непрочитанного
не затирается, — тот же приём, что в «слиянии двух массивов в первый».
Слияние с начала на месте невозможно без буфера: вставка затёрла бы
строки, которые ещё не сдвинуты.

**Почему не `slices.Insert` в цикле.** Каждая вставка сдвигает хвост —
O(n) на строку, O(n·m) на пачку. Для 20 000 строк в таблицу на 200 000 —
это два миллиарда перемещений. Слияние делает O(n + m log m).

**Что спросят дальше.** Удаления в той же пачке (tombstone — отдельный
флаг в строке); как сделать то же без изменения `rows`, для читателей без
блокировок (новый слайс и атомарная замена указателя); когда пора
переходить от слайса к B-дереву.
