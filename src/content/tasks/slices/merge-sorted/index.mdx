Напишите тело `MergeSorted`: оба входа отсортированы по возрастанию,
результат — тоже.

Что проверяют скрытые тесты:

- обычное слияние и дубликаты (они сохраняются);
- пустые и `nil`-входы;
- входные слайсы не меняются — **в том числе их свободная вместимость**;
- результат совпадает с «склеить и отсортировать».

<Reveal>

```go
func MergeSorted(a, b []int) []int {
	out := make([]int, 0, len(a)+len(b))
	i, j := 0, 0
	for i < len(a) && j < len(b) {
		if a[i] <= b[j] {
			out = append(out, a[i])
			i++
		} else {
			out = append(out, b[j])
			j++
		}
	}
	out = append(out, a[i:]...)
	out = append(out, b[j:]...)
	return out
}
```

**Два указателя.** На каждом шаге сравниваем головы и забираем меньшую.
Когда один вход кончился, хвост второго уже отсортирован и дописывается
целиком. O(n + m) по времени.

**`<=`, а не `<`,** делает слияние *стабильным*: при равенстве первым идёт
элемент из `a`. Для чисел не видно, для структур с ключом — важно.

**Про вместимость.** Короткий путь `out := append(a, b...)` и сортировка
испортит вызывающему память: если у `a` есть свободная вместимость,
`append` запишет туда. Один из тестов именно это и ловит. Своя память под
результат — `make` с нужной вместимостью — решает вопрос и заодно
избавляет от перевыделений.

</Reveal>
