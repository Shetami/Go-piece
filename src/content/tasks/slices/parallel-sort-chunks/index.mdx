Напишите тело `ParallelSortFunc`. Сортировка большого слайса — одна из
немногих задач, где параллелизм даётся почти бесплатно: куски не
пересекаются, и горутинам нечего делить.

Что проверяют скрытые тесты:

- результат совпадает со `slices.SortStableFunc`, включая порядок равных
  ключей, — при разном числе горутин, в том числе `workers` больше длины,
  длина не делится на `workers`, пустой и одноэлементный вход;
- `cmp` не выполняется одновременно больше чем в `workers` горутинах;
- после возврата `cmp` больше не вызывается — все горутины дождались;
- `workers <= 0` — паника.

<Reveal>

```go
func ParallelSortFunc[T any](s []T, workers int, cmp func(a, b T) int) {
	if workers <= 0 {
		panic("ParallelSortFunc: workers должно быть больше нуля")
	}
	parts := min(workers, len(s))
	if parts <= 1 {
		slices.SortStableFunc(s, cmp)
		return
	}
	bounds := make([]int, parts+1)
	for i := range bounds {
		bounds[i] = i * len(s) / parts
	}
	var wg sync.WaitGroup
	for i := range parts {
		wg.Add(1)
		go func(part []T) {
			defer wg.Done()
			slices.SortStableFunc(part, cmp)
		}(s[bounds[i]:bounds[i+1]])
	}
	wg.Wait()

	buf := make([]T, len(s))
	for len(bounds) > 2 {
		next := bounds[:1]
		for i := 0; i+1 < len(bounds); i += 2 {
			if i+2 >= len(bounds) {
				next = append(next, bounds[i+1])
				break
			}
			lo, mid, hi := bounds[i], bounds[i+1], bounds[i+2]
			mergeStable(buf[lo:hi], s[lo:mid], s[mid:hi], cmp)
			copy(s[lo:hi], buf[lo:hi])
			next = append(next, hi)
		}
		bounds = next
	}
}

func mergeStable[T any](dst, a, b []T, cmp func(x, y T) int) {
	i, j, k := 0, 0, 0
	for i < len(a) && j < len(b) {
		if cmp(b[j], a[i]) < 0 {
			dst[k] = b[j]
			j++
		} else {
			dst[k] = a[i]
			i++
		}
		k++
	}
	k += copy(dst[k:], a[i:])
	copy(dst[k:], b[j:])
}
```

**Непересекающиеся подслайсы — гонки нет.** Все горутины пишут в один
массив, но каждая — только в свой отрезок `s[lo:hi]`. Гонка — это
конкурентный доступ к одной ячейке памяти, а не к одному массиву, так что
`-race` молчит. Границы `i*len/parts` дают куски, отличающиеся максимум
на один элемент, и не теряют хвост, когда длина не делится нацело.

**Стабильность ломается в двух местах.** Первое — сортировка куска:
`slices.SortFunc` (pdqsort) нестабилен, нужен `SortStableFunc`. Второе —
слияние: при равенстве надо брать из **левого** куска, поэтому условие
`cmp(b[j], a[i]) < 0`, а не `<= 0`. Каждая ошибка по отдельности видна
только на входе с большим числом равных ключей.

**Слияние через один буфер.** Сливать на месте без памяти можно, но
сложно и медленно. Буфер длины `len(s)` выделяется один раз; каждый раунд
сливает соседние пары и копирует результат обратно, непарный последний
кусок ждёт следующего раунда. Раундов — `log₂(workers)`.

**`wg.Wait()` до слияния и до возврата.** Без него слияние прочитает
недосортированные куски, а горутины продолжат звать `cmp` после того, как
функция вернулась.

**Что спросят дальше.** Слияние тоже можно распараллелить — раунды
независимы по парам; при каком размере входа горутины перестают окупаться
(порог, ниже которого сортируем в одной); почему `GOMAXPROCS`, а не
«побольше», — хорошее значение по умолчанию для `workers`.
