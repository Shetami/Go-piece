Напишите тело `Diff`. Это сердце любого reconcile-цикла: контроллер
Kubernetes сверяет желаемые поды с реальными, синхронизатор прав — роли
из конфига с ролями в базе, DNS-оператор — записи. Мапа здесь не
поможет: `T` — любой тип, а равенство задаёт компаратор (например, без
учёта регистра).

Что проверяют скрытые тесты:

- `add` и `remove` отсортированы и без повторов; входы не меняются;
- пустой `want`, пустой `have`, одинаковые множества с разными повторами;
- равенство по `cmp`, а не по `==`: `"alpha"` и `"ALPHA"` — один элемент;
- из равных по `cmp` в ответ попадает первый по порядку во входе — на
  двухстах элементах с десятью ключами;
- два входа по сто тысяч — быстро.

<Reveal>

```go
func Diff[T any](want, have []T, cmp func(a, b T) int) (add, remove []T) {
	w, h := sortedUnique(want, cmp), sortedUnique(have, cmp)
	i, j := 0, 0
	for i < len(w) && j < len(h) {
		switch c := cmp(w[i], h[j]); {
		case c < 0:
			add = append(add, w[i])
			i++
		case c > 0:
			remove = append(remove, h[j])
			j++
		default:
			i++
			j++
		}
	}
	add = append(add, w[i:]...)
	remove = append(remove, h[j:]...)
	return add, remove
}

func sortedUnique[T any](s []T, cmp func(a, b T) int) []T {
	c := slices.Clone(s)
	slices.SortStableFunc(c, cmp)
	return slices.CompactFunc(c, func(a, b T) bool { return cmp(a, b) == 0 })
}
```

**Нормализация: Clone → SortStable → Compact.** После неё каждый вход —
отсортированный список уникальных элементов, и разность множеств
считается одним проходом. Сортировать сами `want` и `have` нельзя — это
чужие слайсы.

**Стабильность решает, какой из равных выживет.** `CompactFunc` оставляет
первый элемент в каждой серии равных. Но «первый в серии» — это первый во
входе, только если сортировка стабильна. `slices.SortFunc` (pdqsort) на
больших сериях равных перемешивает их, и в ответ попадёт случайный
`"ALPHA"` вместо `"alpha"`.

**Два указателя.** Меньший из `w[i]` и `h[j]` точно отсутствует в другом
списке — всё, что там осталось, не меньше текущего. Равные — есть в
обоих, пропускаем оба. Хвосты целиком уходят в ответ. Это O(n+m) после
сортировки; наивное «для каждого из want проверить `slices.ContainsFunc`
по have» — O(n·m), на ста тысячах — десять миллиардов сравнений.

**Когда хватит мапы.** Если `T` сравним через `==` и порядок ответа не
важен, мапа даёт O(n+m) без сортировки. Компаратор в контракте — ровно
тот случай, когда её нет.

**Что спросят дальше.** Третий выход — «есть в обоих, но отличается»
(сверка по ключу и сравнение значения); применять изменения пачками и
идемпотентно; почему reconcile вообще сравнивает состояния, а не
применяет события.
