Напишите `Board`: поля, конструктор и методы. Так устроены таблицы лидеров,
«топ-10 самых медленных запросов», «топ продавцов дня» — когда N
небольшое, отсортированный слайс быстрее и проще дерева или кучи.

Что проверяют скрытые тесты:

- при равном счёте выше тот, кто набрал его раньше; результат, равный
  последнему в полной таблице, в неё не попадает;
- худший результат игрока игнорируется, лучший — переносит его запись, и
  дубля не появляется;
- вылетевший с последнего места игрок забывается и может вернуться с
  любым счётом;
- `Top` отдаёт копию;
- три тысячи случайных `Submit` сверяются с медленной эталонной моделью.

<Reveal>

```go
type Board struct {
	n       int
	entries []Entry
	score   map[string]int
}

func NewBoard(n int) *Board {
	if n <= 0 {
		panic("NewBoard: n должно быть больше нуля")
	}
	return &Board{n: n, entries: make([]Entry, 0, n+1), score: make(map[string]int)}
}

func (b *Board) Submit(name string, score int) {
	if old, ok := b.score[name]; ok {
		if score <= old {
			return
		}
		i := sort.Search(len(b.entries), func(k int) bool { return b.entries[k].Score <= old })
		for b.entries[i].Name != name {
			i++
		}
		b.entries = slices.Delete(b.entries, i, i+1)
		delete(b.score, name)
	}
	i := sort.Search(len(b.entries), func(k int) bool { return b.entries[k].Score < score })
	if i >= b.n {
		return
	}
	b.entries = slices.Insert(b.entries, i, Entry{name, score})
	b.score[name] = score
	if len(b.entries) > b.n {
		last := b.entries[b.n]
		delete(b.score, last.Name)
		b.entries = slices.Delete(b.entries, b.n, b.n+1)
	}
}

func (b *Board) Top() []Entry {
	return slices.Clone(b.entries)
}
```

**Слайс отвечает за порядок, мапа — за «кто уже есть».** Без мапы
проверка «есть ли игрок» — линейный проход. Но две структуры надо держать
в согласии: **каждый выход из слайса — `delete` из мапы**. Самая частая
ошибка — забыть это при вылете с последнего места: игрок остаётся в мапе,
и его следующие результаты сравниваются с записью, которой в таблице уже
нет.

**Ничьи решает выбор границы поиска.** Новичок встаёт перед первым
элементом со счётом **строго меньше** — то есть после всех равных. Так
«раньше набрал — выше» получается само, без меток времени. Поиск по
`<= score` поставил бы новичка перед равными — это другая, тоже
разумная, политика, но не та, что в условии.

**Удаление старой записи — поиск блока, потом имя.** Двоичный поиск
находит начало блока с прежним счётом, дальше идём по равным до нужного
имени. Блок равных обычно короткий.

**`Insert` и `Delete` сдвигают хвост — O(n).** Для топ-100 это
микросекунды и работа в кэше. Если N — миллионы, нужен skip list или
дерево (так устроен `ZADD` в Redis). Вместимость `n+1` сразу — вставка
перед вылетом не перевыделит массив.

**Что спросят дальше.** Ранг игрока, которого нет в топе; потокобезопасность
и снапшоты для чтения без блокировки; как хранить топ за скользящее окно
времени.
