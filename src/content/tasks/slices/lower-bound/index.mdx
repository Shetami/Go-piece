Напишите тело `LowerBound` без `sort` и `slices`.

Что проверяют скрытые тесты:

- в `[1 3 3 3 7 9]`: для `3` — индекс `1` (первая тройка), для `4` —
  `4`, для `10` — `6` (длина слайса), для `0` — `0`;
- пустой слайс → `0`;
- сверка с линейным поиском на слайсе с повторами;
- сто тысяч поисков в слайсе на миллион элементов укладываются в пару
  секунд — линейный поиск не пройдёт.

<Reveal>

```go
func LowerBound(s []int, x int) int {
	lo, hi := 0, len(s)
	for lo < hi {
		mid := int(uint(lo+hi) >> 1)
		if s[mid] < x {
			lo = mid + 1
		} else {
			hi = mid
		}
	}
	return lo
}
```

**Держитесь инварианта, а не интуиции.** Всё левее `lo` — точно меньше
`x`, всё начиная с `hi` — точно не меньше. Каждый шаг сужает `[lo, hi)`,
когда он пуст — `lo` и есть ответ. Отсюда полуоткрытый интервал,
`hi = len(s)` (ответ может быть «за концом») и `hi = mid`, а не
`mid - 1`: `mid` сам может оказаться ответом.

**Почему не «нашли — вернули».** С дубликатами первое попавшееся `3` —
не обязательно первое в слайсе. Нижняя граница продолжает сужаться влево.

**`uint(lo+hi) >> 1`** — так же считает `sort.Search`: сумма в `uint` не
переполнится даже для индексов около `MaxInt`.

**В стандартной библиотеке** это `sort.SearchInts` и `slices.BinarySearch`
— второй заодно говорит, найден ли сам `x`.

</Reveal>
