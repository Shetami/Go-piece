Напишите тело `Rotate`. Сдвиг влево на `k` позиций, на месте — без
выделения второго слайса того же размера.

Что проверяют скрытые тесты:

- `[1 2 3 4 5]`, `k=2` → `[3 4 5 1 2]`; `k=0` ничего не меняет;
- `k` больше длины: `[1 2 3]`, `k=7` — то же, что `k=1`;
- отрицательный `k` — сдвиг вправо: `k=-1` → `[5 1 2 3 4]`;
- пустой и `nil`-слайс — без паники (в том числе без деления на ноль).

<Reveal>

```go
func Rotate(xs []int, k int) {
	n := len(xs)
	if n == 0 {
		return
	}
	k = ((k % n) + n) % n
	slices.Reverse(xs[:k])
	slices.Reverse(xs[k:])
	slices.Reverse(xs)
}
```

**Три разворота.** Разверните по отдельности первые `k` элементов и
остальные, потом весь слайс — и получится сдвиг:

```
[1 2 | 3 4 5]  → [2 1 | 5 4 3]  → [3 4 5 1 2]
```

O(n) по времени, O(1) по памяти. Это стандартный ответ на «сделайте на
месте».

**Нормализация `k`.** В Go остаток от деления сохраняет знак делимого:
`-1 % 5 == -1`. Отсюда `((k % n) + n) % n` — приводит любое `k` к
диапазону `[0, n)`. Проверка `n == 0` нужна раньше, иначе `k % 0` —
паника деления на ноль.

**Если память не жалко** — `copy` через временный слайс:
`tmp := append(xs[k:], xs[:k]...)` и `copy(xs, tmp)`. Проще, но это ровно
то, что условие просит не делать. Осторожно с этой строкой: `append` к
`xs[k:]` пишет в хвост того же массива, если там есть вместимость, —
поэтому `tmp` надо заводить через `slices.Concat` или `make`.

</Reveal>
