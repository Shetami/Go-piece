Напишите `NewLimiter` и `Allow`. Sliding log — самый точный из простых
лимитеров: в отличие от фиксированных окон он не пропускает двойную
пачку на стыке минут. Его цена — журнал отметок, и вся задача в том,
чтобы этот журнал не тёк и не мусорил в куче.

Что проверяют скрытые тесты:

- ровно `limit` событий за окно; событие ровно `window` назад уже не
  считается;
- отказанные события не записываются и не продлевают блокировку;
- после долгой паузы все старые записи уходят разом;
- `len(times)` никогда не больше `limit`;
- двадцать тысяч вызовов в установившемся режиме — практически без
  аллокаций, а вместимость журнала не разрастается;
- неверные параметры — паника.

<Reveal>

```go
func NewLimiter(limit int, window time.Duration) *Limiter {
	if limit <= 0 || window <= 0 {
		panic("NewLimiter: limit и window должны быть положительными")
	}
	return &Limiter{limit: limit, window: window, times: make([]time.Time, 0, limit)}
}

func (l *Limiter) Allow(now time.Time) bool {
	cut := now.Add(-l.window)
	i := sort.Search(len(l.times), func(k int) bool { return l.times[k].After(cut) })
	if i > 0 {
		n := copy(l.times, l.times[i:])
		l.times = l.times[:n]
	}
	if len(l.times) >= l.limit {
		return false
	}
	l.times = append(l.times, now)
	return true
}
```

**`l.times = l.times[i:]` — незаметная ловушка.** Срез с начала сдвигает
указатель на массив и **уменьшает вместимость**. Каждый вызов откусывает
голову, `append` дописывает в хвост — и через `cap−len` вызовов место
кончается: `append` выделяет новый массив, копирует, и всё повторяется.
Утечки нет, но лимитер, который стоит на каждом запросе, постоянно
мусорит. `copy` в начало того же массива сохраняет вместимость — и
`append` больше никогда не выделяет память.

**Вместимость `limit` сразу.** Больше `limit` записей в журнале не бывает
— отказы не пишутся. Значит, массив можно выделить один раз в
конструкторе.

**Граница окна: `After(cut)`.** Окно — `(now-window, now]`. Запись ровно
`window` назад должна выпасть, иначе лимитер на секунду строже
заявленного. Журнал отсортирован (время не убывает), поэтому первую
живую запись находит `sort.Search` за O(log n), а не перебор.

**Цена `copy`.** Сдвиг — O(limit) на вызов с удалением. Для лимитов в
тысячи это дёшево; для больших — кольцевой буфер на `limit` ячеек, где
голова просто двигается по кругу. Журнал хранит O(limit) памяти на ключ —
поэтому для миллионов ключей берут приближения (sliding window counter,
token bucket).

**Что спросят дальше.** Потокобезопасность (мьютекс вокруг `Allow`); лимит
на пользователя — мапа лимитеров и их вычистка; почему `time.Time` в
журнале лучше хранить как `int64` наносекунд (меньше памяти, нет
указателя на `Location`).
