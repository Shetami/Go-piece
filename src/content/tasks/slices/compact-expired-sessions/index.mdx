Напишите тело `DropExpired`. Такую чистку крутят по таймеру в хранилище
сессий: слайс большой, живёт долго, и лишняя копия на каждом проходе ни к
чему.

Что проверяют скрытые тесты:

- порядок оставшихся сессий сохраняется; сессия с `Expires == now` уже
  истекла; `nil` в слайсе выбрасывается;
- результат лежит в начале того же массива;
- после вызова в ячейках массива за длиной результата нет указателей на
  выброшенные сессии;
- все сессии истекли и `nil` на входе — пустой результат без паники;
- вызов не выделяет память.

<Reveal>

```go
func DropExpired(sessions []*Session, now time.Time) []*Session {
	kept := sessions[:0]
	for _, s := range sessions {
		if s != nil && s.Expires.After(now) {
			kept = append(kept, s)
		}
	}
	clear(sessions[len(kept):])
	return kept
}
```

**Фильтр на месте — `s[:0]` и `append`.** `kept` делит массив с
`sessions`, и его вместимости хватает на всё, так что `append` не выделяет
память, а просто пишет в тот же массив. Это безопасно: пишущий индекс
никогда не обгоняет читающий, и `range` успевает прочитать элемент раньше,
чем его место займут.

**Хвост — главная ловушка.** После фильтра массив выглядит как
`[b d | c d e]`: за длиной результата лежат старые указатели, в том числе
на выброшенные сессии. Их не видно через `kept`, но массив жив, пока жив
`kept`, — значит, и сессии живы. Для слайса указателей (и структур с
указателями, строками, слайсами) это утечка. **`clear(sessions[len(kept):])`**
обнуляет хвост; с Go 1.22 то же делают `slices.DeleteFunc` и
`slices.Compact`.

**`After`, а не `!Before`.** `Expires == now` — сессия уже истекла, поэтому
живыми считаются только те, что истекают строго позже `now`.

**Что спросят дальше.** Почему для `[]int` обнулять хвост необязательно
(держать нечего); как то же сделать через `slices.DeleteFunc`; что будет,
если кто-то снаружи держит исходный `sessions` и ждёт в нём старые данные —
фильтр на месте им всё перепишет.
