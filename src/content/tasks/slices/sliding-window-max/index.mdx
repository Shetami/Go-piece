Напишите тело `WindowMax`. На практике это пик нагрузки за последние N
минут на графике, максимальная задержка в скользящем окне для алерта,
«лучшая цена за последние k тиков». На собеседовании — классическая
задача на монотонную очередь.

Что проверяют скрытые тесты:

- пример `[1 3 -1 -3 5 3 6 7]`, `k=3` → `[3 3 5 5 6 7]`;
- повторы максимумов (`[4 4 4 1]`, чередование `5 1 5 1`), отрицательные
  числа, `k=1`, `k=len`, окно длиннее входа;
- сверка с перебором на сотнях случайных входов с повторами;
- убывающий вход длиной 300 000 с окном 150 000 — за линейное время;
- `k <= 0` — паника.

<Reveal>

```go
func WindowMax(xs []int, k int) []int {
	if k <= 0 {
		panic("WindowMax: k должно быть больше нуля")
	}
	if len(xs) < k {
		return []int{}
	}
	out := make([]int, 0, len(xs)-k+1)
	dq := make([]int, 0, k)
	for i, x := range xs {
		for len(dq) > 0 && xs[dq[len(dq)-1]] <= x {
			dq = dq[:len(dq)-1]
		}
		dq = append(dq, i)
		if dq[0] <= i-k {
			dq = dq[1:]
		}
		if i >= k-1 {
			out = append(out, xs[dq[0]])
		}
	}
	return out
}
```

**Инвариант дека: значения по индексам строго убывают.** Когда приходит
`x`, все элементы в хвосте, не большие `x`, выбрасываются: они левее `x`,
значит, выпадут из окна раньше него, и пока `x` в окне, они не станут
максимумом. Поэтому максимум текущего окна — всегда голова дека.

**В деке — индексы, а не значения.** По значению нельзя понять, выпал ли
элемент из окна: при повторах `[4 4 4 1]` непонятно, какую из четвёрок
выкидывать. По индексу проверка тривиальна: `dq[0] <= i-k`.

**Почему это O(n).** Каждый индекс один раз попадает в дек и максимум
один раз из него удаляется — с хвоста или с головы. Внутренний `for`
может быть длинным, но суммарно за весь проход он сделает не больше n
итераций. Перебор окна — O(n·k), и на убывающем входе с большим окном
это десятки миллиардов сравнений.

**Дек на слайсе.** Хвост — `dq[:len-1]`, голова — `dq[1:]`. Сдвиг головы
теряет начало массива, но `append` при нехватке места перевыделит
массив и скопирует только живую часть — память остаётся O(k), время —
амортизированно O(1). Кольцевой буфер ёмкости k экономит эти
перевыделения.

**Что спросят дальше.** Минимум (знак сравнения наоборот); максимум по
потоку, где окно задано временем, а не количеством; почему куча здесь
тоже работает, но за O(n log k) и с «ленивым» удалением.
