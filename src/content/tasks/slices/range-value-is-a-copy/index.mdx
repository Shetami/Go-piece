`Discount` должна снизить цену каждой позиции на 10. Программа отрабатывает
без ошибок и печатает:

```
[{книга 100} {кофе 50}]
```

Цены не изменились. Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 12: `for _, item := range items`.

**`range` отдаёт копию элемента, а не сам элемент.** На каждой итерации `item`
— это новая структура `Item`, в которую скопированы поля. `item.Price -= 10`
честно меняет эту копию, а в следующей итерации копию перезаписывают
следующей. Слайс при этом никто не трогал.

Обратите внимание, что дело **не** в передаче слайса в функцию: слайс — это
заголовок с указателем на массив, и `Discount` прекрасно может менять элементы.
Проблема только в том, что до элементов она не добирается.

**Как чинят.** Обращаться по индексу:

```go
for i := range items {
	items[i].Price -= 10
}
```

`items[i]` — это сам элемент массива, а не его копия.

**Почему это так легко пропустить.** С указателями всё «работает само»:

```go
for _, item := range items {   // items []*Item
	item.Price -= 10            // копируется указатель, но объект-то один
}
```

Скопировали указатель — но он показывает на ту же структуру, и правка видна
снаружи. Поэтому один и тот же код ведёт себя по-разному в зависимости от того,
`[]Item` там или `[]*Item`. Ни компилятор, ни `go vet` об этом не скажут.

**Что спросят следом.** Скорее всего, про цену копирования: если `Item` — это
жирная структура на полсотни полей, `range` по значению копирует её на каждой
итерации. Отсюда привычка писать `for i := range items` даже там, где менять
ничего не надо. А с Go 1.22 появилась и обратная тонкость: переменная `item`
теперь создаётся заново на каждой итерации, так что взять `&item` и сохранить
куда-то стало безопасно — раньше все указатели показывали бы на одну ячейку.

</Reveal>
