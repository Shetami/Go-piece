Первый `copy` копирует слайс сам в себя со сдвигом на один элемент вправо,
второй — со сдвигом на два влево. Области источника и приёмника
перекрываются.

Напишите весь вывод программы.

<Reveal>

**`copy` копирует `min(len(dst), len(src))` элементов и возвращает это
число.** В первом случае приёмник `s[1:]` короче источника: 4 против 5 —
скопируется 4. Во втором источник `t[2:]` короче: скопируется 3.

**Перекрытие обрабатывается правильно.** `copy` устроен как `memmove`, а не
как наивный цикл «слева направо». Наивный цикл при сдвиге вправо размножил
бы первый элемент: `s[1] = s[0]`, потом `s[2] = s[1]` — а там уже `1`. Но
`copy` ведёт себя так, будто сначала целиком прочитал источник, и лишь потом
записал.

Итого:

```
4 [1 1 2 3 4]
3 [3 4 5 4 5]
```

**Где это встречается.** Именно так вставляют элемент в середину слайса без
лишнего выделения памяти:

```go
s = append(s, 0)     // место под ещё один элемент
copy(s[i+1:], s[i:]) // сдвинуть хвост вправо
s[i] = v
```

Сейчас для этого есть `slices.Insert`, но внутри он делает то же самое.

</Reveal>
