Напишите тело `Partition`: вернуть элементы, для которых `pred` истинна, и
все остальные.

Что проверяют скрытые тесты:

- числа и строки;
- порядок внутри каждой части — как во входе;
- исходный слайс не меняется;
- «все подходят», «ничего нет» и `nil` — без паники.

<Reveal>

```go
func Partition[T any](xs []T, pred func(T) bool) (yes, no []T) {
	for _, x := range xs {
		if pred(x) {
			yes = append(yes, x)
		} else {
			no = append(no, x)
		}
	}
	return yes, no
}
```

**Именованные результаты** здесь по делу: они сразу объявлены как
`nil`-слайсы, и `append` к ним работает. Возвращать `nil` для пустой части
нормально — тесты проверяют длину.

**На месте — можно, но осторожно.** Классический алгоритм partition из
quicksort переставляет элементы внутри `xs` и возвращает индекс границы —
без выделений памяти. Но он *нестабилен*: порядок внутри частей теряется.
Стабильный partition на месте тоже существует, но стоит O(n log n). Для
утилиты, которая не должна трогать вход, два новых слайса — правильный
ответ.

**Предвыделение.** Можно сделать `make([]T, 0, len(xs))` для обеих частей —
тогда никаких перевыделений, но памяти вдвое больше нужного. Без него —
несколько перевыделений на рост. Оба варианта приемлемы, выбор зависит от
размеров.

</Reveal>
