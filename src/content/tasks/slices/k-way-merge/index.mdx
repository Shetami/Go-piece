Напишите тело `MergeK` (вспомогательные типы — какие угодно). Это шаг
внешней сортировки, слияние SST-файлов в LSM-дереве, объединение
отсортированных ответов с шардов.

Что проверяют скрытые тесты:

- `nil` и пустые списки среди прочих; все пустые; один список с повторами;
- стабильность: равные ключи — сначала из списка с меньшим номером, внутри
  списка — в исходном порядке;
- списки не меняются;
- при `k = 256` сравнений — O(log k) на элемент: выбор минимума перебором
  (~k на элемент) и последовательное слияние по одному списку не проходят;
- при `k = 4` и длинных списках сравнений меньше, чем у «склеить всё и
  отсортировать» (~log N на элемент).

<Reveal>

```go
type cursor struct{ list, pos int }

type cursorHeap[T any] struct {
	cur   []cursor
	lists [][]T
	cmp   func(a, b T) int
}

func (h *cursorHeap[T]) Len() int { return len(h.cur) }
func (h *cursorHeap[T]) Less(i, j int) bool {
	a, b := h.cur[i], h.cur[j]
	if c := h.cmp(h.lists[a.list][a.pos], h.lists[b.list][b.pos]); c != 0 {
		return c < 0
	}
	return a.list < b.list
}
func (h *cursorHeap[T]) Swap(i, j int) { h.cur[i], h.cur[j] = h.cur[j], h.cur[i] }
func (h *cursorHeap[T]) Push(x any)   { h.cur = append(h.cur, x.(cursor)) }
func (h *cursorHeap[T]) Pop() any {
	x := h.cur[len(h.cur)-1]
	h.cur = h.cur[:len(h.cur)-1]
	return x
}

func MergeK[T any](lists [][]T, cmp func(a, b T) int) []T {
	h := &cursorHeap[T]{lists: lists, cmp: cmp}
	total := 0
	for i, l := range lists {
		total += len(l)
		if len(l) > 0 {
			h.cur = append(h.cur, cursor{i, 0})
		}
	}
	heap.Init(h)
	out := make([]T, 0, total)
	for h.Len() > 0 {
		top := &h.cur[0]
		out = append(out, lists[top.list][top.pos])
		top.pos++
		if top.pos < len(lists[top.list]) {
			heap.Fix(h, 0)
		} else {
			heap.Pop(h)
		}
	}
	return out
}
```

**В куче — курсоры, а не элементы.** Куча размера k держит «голову»
каждого непустого списка. Минимум всех голов — вершина кучи. Забрали его —
сдвинули курсор этого списка и просеяли вершину вниз: `heap.Fix(h, 0)`
стоит O(log k) сравнений. Это дешевле, чем `Pop` + `Push` (два просеивания).
Кончился список — `heap.Pop`.

**Стабильность — второй ключ в `Less`.** Куча сама по себе не стабильна:
из двух равных голов наверху может оказаться любая. Сравнение номеров
списков при равенстве `cmp` делает порядок однозначным, а внутри списка
порядок сохраняется сам — курсор идёт только вперёд.

**Почему не «склеить и отсортировать».** Это O(N log N) и выбрасывает
то, что списки уже отсортированы. При малом k разница в разы: log 4 = 2
против log 64 000 ≈ 16. А линейный поиск минимума среди k голов — O(N·k),
при сотнях списков это катастрофа. Слияние парами «по турниру» тоже даёт
O(N log k) и честно проходит тесты.

**Интерфейс `heap.Interface` с дженериками.** `Push` и `Pop` принимают
`any` — это цена пакета `container/heap`; с дженерик-типом кучи
приведение `x.(cursor)` безопасно. `Push`/`Pop` работают с концом слайса:
«снять вершину» делает сам пакет, переставив её в конец.

**Что спросят дальше.** Слияние потоков, а не слайсов (курсор хранит
`iter.Pull` или канал), и зачем тогда k-way merge не держит всё в памяти;
выдача результата итератором; удаление дублей при слиянии.
