Напишите тело `Latest`. Типичное место — пачка изменений из очереди или
CDC: одна и та же запись приходит несколько раз, в базу нужно записать
только последнее состояние, но порядок строк в пачке важен (например, для
предсказуемых блокировок).

Что проверяют скрытые тесты:

- `[{a 1} {b 1} {a 2} {c 1} {b 2} {a 3}]` → `[{a 3} {b 2} {c 1}]`;
- вход не меняется; изменение или `append` результата не задевает вход;
- `key` вызывается ровно один раз на элемент (она может быть дорогой);
- `nil` на входе — пустой результат;
- двести тысяч уникальных ключей обрабатываются за линейное время.

<Reveal>

```go
func Latest[T any, K comparable](s []T, key func(T) K) []T {
	pos := make(map[K]int, len(s))
	out := make([]T, 0, len(s))
	for _, v := range s {
		k := key(v)
		if i, ok := pos[k]; ok {
			out[i] = v
			continue
		}
		pos[k] = len(out)
		out = append(out, v)
	}
	return out
}
```

**Мапа хранит не значение, а индекс.** Два требования — «место по первому
вхождению» и «значение по последнему» — тянут в разные стороны. Если
класть в мапу сами элементы, порядок потеряется: обход мапы случаен. Если
только проверять «уже видели», останется первое значение. Индекс в `out`
решает оба: первое вхождение занимает место, следующие перезаписывают
ячейку.

**Отдельный `out`, а не фильтр на месте.** Приём `s[:0]` здесь не годится:
вход обещано не трогать, а результат не должен делить с ним массив —
иначе правка результата незаметно поменяет чужие данные.

**`key` — один раз.** Решение в два прохода (сначала найти последнее
вхождение каждого ключа, потом собрать) честно линейно, но зовёт `key`
дважды. Для ключа, который, скажем, хэширует тело сообщения, это двойная
работа.

**Линейность.** Поиск ключа перебором по `out` — O(n²): на двухстах
тысячах уникальных ключей это десятки миллиардов сравнений. Мапа даёт
O(1) на элемент.

**Что спросят дальше.** Как вернуть память, если дублей было много
(`slices.Clip(out)`); как сделать то же для отсортированного по ключу входа
без мапы (`slices.CompactFunc` оставляет первый, а нужен последний —
придётся идти с конца); что делать, если порядок нужен по последнему
вхождению.
