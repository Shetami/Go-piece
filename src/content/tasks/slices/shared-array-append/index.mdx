`Split` возвращает первый элемент и всё остальное. Дальше к голове дописывают
`"!"` — и хвост, которого никто не трогал, приезжает испорченным:

```
head: [go !]
tail: [! fun]
```

Отметьте строку, в которой заложена поломка. Клик по номеру строки в
редакторе — выбор, потом «Проверить».

<Reveal>

Сломано в строке 7: `head = parts[:1]`.

**Слайс — это три числа: указатель на массив, длина и вместимость.** Операция
`parts[:1]` меняет только длину. Указатель остаётся тем же, а вместимость
считается до конца исходного массива:

```
parts: ptr → [ "go" | "is" | "fun" ]   len 3  cap 3
head:  ptr → [ "go" | "is" | "fun" ]   len 1  cap 3   ← тот же массив
tail:      ptr+1 → [ "is" | "fun" ]    len 2  cap 2
```

У `head` длина 1, но вместимость 3 — то есть в массиве есть куда писать.
Поэтому `append(head, "!")` **не** заводит новый массив: он кладёт `"!"` в
ячейку с индексом 1 того же массива. А на эту ячейку смотрит нулевой элемент
`tail`. Отсюда `[! fun]`.

Обратите внимание, что `tail = parts[1:]` (строка 8) ни при чём: этот слайс
никто не дополняет, он просто оказался в зоне поражения.

**Как чинят.** Третьим числом в срезе — оно ограничивает вместимость:

```go
head = parts[:1:1] // len 1, cap 1
```

Теперь вместимости не хватает, `append` выделяет новый массив и копирует туда
данные, а `parts` остаётся нетронутым. Это тот же приём, что в стандартной
библиотеке зовут «full slice expression».

**Правило, которое стоит унести с собой.** Функция, которая возвращает срез
чужого слайса, отдаёт наружу доступ к чужой памяти. Либо ограничивайте
вместимость, либо копируйте (`slices.Clone`), либо пишите в документации, что
возвращённый слайс делит массив с аргументом, — как это делает `bytes.Split`.

</Reveal>
