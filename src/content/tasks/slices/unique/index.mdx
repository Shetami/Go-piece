Напишите тело `Unique`: элементы без повторов, в порядке первого появления.

Что проверяют скрытые тесты:

- `[3 1 3 2 1 3]` → `[3 1 2]` — порядок первого появления, а не сортировка;
- работает для строк;
- исходный слайс не меняется;
- на `nil` и на слайсе из одинаковых элементов — без паники.

<Reveal>

```go
func Unique[T comparable](xs []T) []T {
	seen := make(map[T]struct{}, len(xs))
	out := make([]T, 0, len(xs))
	for _, x := range xs {
		if _, ok := seen[x]; ok {
			continue
		}
		seen[x] = struct{}{}
		out = append(out, x)
	}
	return out
}
```

**Мапа как множество.** `map[T]struct{}` — идиоматичное множество в Go:
пустая структура занимает ноль байт, так что память уходит только на
ключи. `map[T]bool` тоже работает и читается проще (`if seen[x]`), разница
в памяти небольшая.

**Ограничение `comparable`** нужно ровно из-за мапы: ключом может быть
только сравнимый тип.

**Сложность** — O(n) по времени и памяти. Частый встречный вопрос: «а без
дополнительной памяти?» Тогда сортировка и `slices.Compact` — O(n log n) и
на месте, но порядок первого появления теряется. В стандартной библиотеке
есть только этот второй вариант: `slices.Compact` убирает *соседние*
повторы.

</Reveal>
