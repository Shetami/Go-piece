Напишите `Life`: поля, конструктор и методы. Игра «Жизнь» — любимая
задача для live-coding: правила помещаются в две строки, а ошибки —
классические ошибки работы с двумерными данными. Двойная буферизация,
которая здесь нужна, встречается и в симуляциях, и в рендеринге, и в
кольцевых метриках.

Что проверяют скрытые тесты:

- мигалка: все клетки меняются одновременно — по состоянию до шага;
- края склеены: мигалка через верхнюю границу и левый край ведёт себя
  как в середине поля;
- планер на торе 8×8 за 32 шага возвращается на исходное место;
- `Step` не выделяет память;
- поле меньше 3×3 — паника.

<Reveal>

```go
type Life struct {
	h, w      int
	cur, next [][]bool
}

func newGrid(h, w int) [][]bool {
	cells := make([]bool, h*w)
	g := make([][]bool, h)
	for r := range g {
		g[r] = cells[r*w : (r+1)*w : (r+1)*w]
	}
	return g
}

func NewLife(h, w int) *Life {
	if h < 3 || w < 3 {
		panic("NewLife: поле должно быть не меньше 3×3")
	}
	return &Life{h: h, w: w, cur: newGrid(h, w), next: newGrid(h, w)}
}

func (l *Life) Set(r, c int, alive bool) { l.cur[r][c] = alive }
func (l *Life) Alive(r, c int) bool      { return l.cur[r][c] }

func (l *Life) Step() {
	for r := range l.h {
		up, down := (r-1+l.h)%l.h, (r+1)%l.h
		for c := range l.w {
			left, right := (c-1+l.w)%l.w, (c+1)%l.w
			n := 0
			for _, rr := range [3]int{up, r, down} {
				for _, cc := range [3]int{left, c, right} {
					if (rr != r || cc != c) && l.cur[rr][cc] {
						n++
					}
				}
			}
			l.next[r][c] = n == 3 || (n == 2 && l.cur[r][c])
		}
	}
	l.cur, l.next = l.next, l.cur
}
```

**Обновлять на месте нельзя.** Если писать новое состояние прямо в
`cur`, соседи справа и снизу считают уже изменённые клетки — мигалка
превращается в мусор. Нужны два поля: читаем из одного, пишем в другое.

**Обмен, а не копирование и не новое поле.** Выделять `next` на каждом
шаге — аллокация на шаг и работа сборщику мусора. Копировать `next` в
`cur` — лишний проход. Достаточно поменять местами **заголовки**
слайсов: `l.cur, l.next = l.next, l.cur` — это обмен пары указателей, и
старое поле становится черновиком для следующего шага. Перезаписывать его
начисто не нужно: `Step` пишет каждую клетку.

**Остаток от деления в Go сохраняет знак.** `(0-1) % h == -1`, и индекс
`-1` — паника. Отсюда `(r-1+h) % h`. Соседи считаются заранее для
строки и столбца, а не восемью `if` на границах. Поле от 3×3 гарантирует,
что восемь соседей — разные клетки.

**Двумерный слайс в одном массиве.** `newGrid` выделяет все клетки одним
`make` и режет его на строки — две аллокации вместо `h+1`, и строки лежат
в памяти подряд, что хорошо для кэша. Третий индекс на всякий случай не
даёт `append` к строке залезть в следующую.

**Что спросят дальше.** Бесконечное поле (мапа живых клеток); ускорение —
считать соседей только вокруг живых клеток; распараллелить шаг по
полосам строк — они независимы, пока читают `cur` и пишут в свои строки
`next`.
