Напишите тело `Page`. Так устроена keyset-пагинация в API: клиент
присылает ID последнего увиденного элемента, а не номер страницы, и не
видит дублей и пропусков, если между запросами что-то добавили или
удалили.

Что проверяют скрытые тесты:

- обход «страница за страницей» по `next` выдаёт каждый элемент ровно один
  раз и заканчивается;
- если страница дошла до конца каталога, `next` пустой — клиент не должен
  делать лишний запрос за пустой страницей;
- курсор указывает на ID, которого в каталоге уже нет;
- `append` к полученной странице не меняет каталог;
- пятьдесят тысяч страниц из каталога на двести тысяч элементов — быстро.

<Reveal>

```go
func Page(items []Item, after string, limit int) (page []Item, next string) {
	if limit <= 0 {
		return nil, ""
	}
	start := sort.Search(len(items), func(i int) bool { return items[i].ID > after })
	end := min(start+limit, len(items))
	page = items[start:end:end]
	if end < len(items) {
		next = items[end-1].ID
	}
	return page, next
}
```

**Искать не курсор, а первое «больше курсора».** Если искать сам `after`
(`slices.Index` или `BinarySearch` с проверкой «нашли»), удалённый между
запросами элемент ломает пагинацию: курсора нет — непонятно, откуда
продолжать. Условие `ID > after` для `sort.Search` отвечает сразу на оба
случая. Заодно `after == ""` не нужно обрабатывать отдельно: пустая
строка меньше любого непустого ID.

**Двоичный поиск, потому что вход отсортирован.** Линейный поиск позиции
на глубоких страницах — O(n) на запрос. Это ровно та проблема `OFFSET`,
от которой keyset-пагинация и спасает.

**`next` пустой на последней странице.** Наивное «`next` — ID последнего
элемента страницы» заставит клиента сделать ещё один запрос и получить
пустую страницу. Проверка `end < len(items)` это убирает.

**Страница — окно в каталог с обрезанной вместимостью.** `items[start:end]`
отдаёт данные без копирования, но `append` к такому слайсу запишет прямо
в `items[end]`. Третий индекс `items[start:end:end]` заставит `append`
скопировать. Если страницу отдают наружу и каталог меняется конкурентно,
надёжнее `slices.Clone`.

**Что спросят дальше.** Сортировка по неуникальному полю (цене) — курсор
становится парой `(price, id)` и сравнение лексикографическим; пагинация
назад; почему курсор обычно кодируют в непрозрачную строку.

</Reveal>
