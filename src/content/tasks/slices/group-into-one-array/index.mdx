Напишите тело `GroupBy`. Обычный `map[K][]T` с `append` отдаёт группы в
случайном порядке, а каждый слайс группы растёт сам по себе — десятки
перевыделений на группу. Когда группировка сидит в горячем пути (отчёт,
раскладка событий по партициям), это видно в профиле аллокаций. Здесь
нужна раскладка «как в сортировке подсчётом»: сначала посчитать, потом
разложить в один массив.

Что проверяют скрытые тесты:

- группы — в порядке первого появления ключа, элементы — в исходном;
- `key` вызывается ровно один раз на элемент; вход не меняется;
- `append` к одной группе не затирает соседнюю;
- элементы групп лежат подряд в одном массиве;
- 3000 элементов по 4 группам — не больше полутора десятков аллокаций.

<Reveal>

```go
func GroupBy[T any, K comparable](s []T, key func(T) K) []Group[K, T] {
	gi := make([]int, len(s))
	pos := make(map[K]int)
	var keys []K
	var counts []int
	for i, v := range s {
		k := key(v)
		g, ok := pos[k]
		if !ok {
			g = len(keys)
			pos[k] = g
			keys = append(keys, k)
			counts = append(counts, 0)
		}
		gi[i] = g
		counts[g]++
	}

	backing := make([]T, len(s))
	groups := make([]Group[K, T], len(keys))
	off := 0
	for g, k := range keys {
		groups[g] = Group[K, T]{Key: k, Items: backing[off:off:off+counts[g]]}
		off += counts[g]
	}

	for i, v := range s {
		groups[gi[i]].Items = append(groups[gi[i]].Items, v)
	}
	return groups
}
```

**Два прохода вместо одного.** Первый узнаёт размер каждой группы, второй
раскладывает. Размеры известны — значит, память под все элементы можно
выделить одним `make` и нарезать. Это та же идея, что у сортировки
подсчётом и у формата CSR для разреженных матриц.

**`key` не зовём второй раз.** Номер группы каждого элемента запоминаем
в `gi`. Это `len(s)` интов памяти, зато дорогой ключ (хэш, разбор строки)
считается один раз.

**Порядок групп — из слайса `keys`, а не из мапы.** Мапа отвечает только
на «какой номер у ключа». Порядок первого появления хранит слайс — обход
мапы в Go намеренно случаен.

**Нарезка с полным срезом `backing[off:off:off+n]`.** Длина 0 — чтобы
раскладывать через `append`; вместимость ровно `n` — чтобы `append` во
втором проходе не перевыделял, а `append` снаружи, после возврата, не
залез в соседнюю группу, а ушёл в новый массив.

**Цена.** Все группы держат один массив: пока жива хоть одна маленькая
группа, живёт весь массив. Для короткоживущего результата это выгодно, для
кэша — повод скопировать.

**Что спросят дальше.** Как сделать то же без мапы, если ключи —
небольшие целые (массив счётчиков вместо мапы); как устойчиво
отсортировать по ключу через те же два прохода; почему `append` к
`nil`-слайсу в каждой группе даёт O(log n) перевыделений на группу.
