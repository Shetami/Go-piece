Авиакомпания подбирает пассажирам стыковки. Пассажир из `transfers`
прилетает рейсом `inbound_flight_id` и летит дальше в `final_dest`.
Нужен **ближайший подходящий** стыковочный рейс:

- вылетает из того же аэропорта, куда прилетел входящий рейс, и летит в
  `final_dest`;
- не отменён (`status = 'scheduled'`);
- минимальное время пересадки — **50 минут** включительно: `dep_at >= arr_at +
  50 минут`;
- ждать больше **12 часов** включительно пассажир не будет;
- из нескольких подходящих — самый ранний по `dep_at`, при равенстве — с
  меньшим `flight_no` (сравнение строк).

- колонки: `passenger`, `inbound` — номер входящего рейса, `connection` —
  номер стыковки, `wait_minutes` — минут между прилётом и вылетом, целым
  числом;
- нет подходящей стыковки — `connection` и `wait_minutes` равны `NULL`, но
  пассажир в отчёте есть;
- порядок: по `transfers.id`.

Что проверяют скрытые данные: рейс, на который не успеть, и рейс ровно
через 50 минут; два рейса в одно время; отменённый рейс; ожидание ровно 12
часов, в том числе через полночь, и на минуту дольше; рейс нужного
направления из соседнего аэропорта того же города.

<Reveal>

```sql
SELECT t.passenger,
       i.flight_no AS inbound,
       c.flight_no AS connection,
       (extract(epoch FROM c.dep_at - i.arr_at) / 60)::int AS wait_minutes
FROM transfers t
JOIN flights i ON i.id = t.inbound_flight_id
LEFT JOIN LATERAL (
  SELECT f.flight_no, f.dep_at
  FROM flights f
  WHERE f.origin = i.dest
    AND f.dest = t.final_dest
    AND f.status = 'scheduled'
    AND f.dep_at >= i.arr_at + interval '50 minutes'
    AND f.dep_at <= i.arr_at + interval '12 hours'
  ORDER BY f.dep_at, f.flight_no
  LIMIT 1
) c ON true
ORDER BY t.id;
```

Ответ:

```
Анна | SU100 | SU502 | 50
Борис | SU100 | SU603 | 720
Вера | SU200 | SU801 | 720
Глеб | SU300 | NULL | NULL
Дина | SU100 | NULL | NULL
```

**«Ближайший подходящий» — это top-1 на строку, и `LATERAL` здесь самый
прямой инструмент.** Подзапрос видит и заявку `t`, и входящий рейс `i` и
выбирает для них одну строку по полному порядку. Вариант с `GROUP BY` и
`min(dep_at)` / `min(flight_no)` из заготовки берёт минимумы *независимо*:
время от одного рейса, номер — от другого, и в ответе оказывается рейс,
который в это время не летит.

**Соединение по окну времени.** Обе границы включены: Анна успевает на рейс
через 50 минут, а на рейс через 40 — нет. Борис и Вера ждут ровно 12 часов —
Вера через полночь, и рейс на минуту позже уже не подходит. Интервалы
прибавляются к `timestamp`, поэтому переход через сутки никаких
особых случаев не требует.

**Ничья решается явно.** SU502 и SU503 вылетают в 10:20; `ORDER BY dep_at,
flight_no` выбирает SU502. Без второго ключа `LIMIT 1` вернёт любой из двух
— и тест будет то проходить, то падать.

**Аэропорт — часть ключа.** Глеб прилетел во Внуково, а рейсы в Новосибирск
идут и из Шереметьево; без `f.origin = i.dest` он получил бы стыковку, на
которую физически не попадёт. Из Внуково же единственный рейс уходит через
30 минут — поэтому `NULL`. У Дины подходящий рейс есть, но пересадка
слишком короткая; отменённый SU601 не спасает Бориса — ему ждать вечернего.

**`LEFT JOIN LATERAL … ON true`, а не `CROSS JOIN LATERAL`:** пассажир без
стыковки должен остаться в отчёте — именно ему нужна помощь оператора.

**Что спросят дальше.** «Какой индекс нужен?» — `(origin, dest, dep_at)`
(можно частичный `WHERE status = 'scheduled'`): каждый `LATERAL` становится
одним коротким проходом по индексу до первой подходящей строки. И «а если
допустимы две пересадки?» — рекурсивный CTE или ещё один `LATERAL` поверх
первого.

</Reveal>
