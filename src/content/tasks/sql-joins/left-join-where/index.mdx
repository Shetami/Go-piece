Нужен список всех клиентов и число их заказов за 2024 год. Клиенты, которые
в 2024-м ничего не заказывали, тоже нужны — с нулём. Запрос с `LEFT JOIN`
теряет Борю и Веру.

Почините. Ожидается:

```
Аня  | 2
Боря | 0
Вера | 0
Гоша | 1
```

<Reveal>

**Условие на правую таблицу в `WHERE` отменяет `LEFT JOIN`.** У клиента без
подходящих заказов `LEFT JOIN` даёт строку, где все колонки `o.*` — `NULL`.
Дальше `WHERE o.created_at >= ...` — сравнение с `NULL`, то есть `UNKNOWN`, и
строка выбрасывается. Итог — ровно `INNER JOIN`.

**Условие переезжает в `ON`:**

```sql
LEFT JOIN orders o
  ON o.customer_id = c.id
 AND o.created_at >= '2024-01-01' AND o.created_at < '2025-01-01'
```

Теперь фильтр решает, какие заказы присоединить, а не какие клиенты
останутся. Клиент без подходящих заказов остаётся со строкой из `NULL`.

**`count(o.id)`, а не `count(*)`**: `NULL` в `o.id` даёт ноль, а `count(*)`
посчитал бы саму строку-заглушку — и у Бори с Верой было бы по единице.

**Правило:** в `LEFT JOIN` условия на левую таблицу — в `WHERE`, на правую —
в `ON`. Исключение — проверка `WHERE o.id IS NULL`: это анти-соединение, и
оно нарочно ищет строки-заглушки.

</Reveal>
