Сеть пунктов выдачи проверяет график на **5 августа 2024 года**. Рабочий
день — с 08:00 до 20:00, он делится на часовые слоты `[08:00, 09:00)`, …,
`[19:00, 20:00)`. Нужны слоты, где людей **меньше норматива**.

**Норматив** — в `coverage_rules`: правило действует для часов
`hour_from <= час < hour_to`. У правила по умолчанию `point_id` пуст; если у
пункта есть собственное правило на этот час, оно **заменяет** правило по
умолчанию (не складывается с ним).

**Кто закрывает слот.** Сотрудник засчитывается в слот, только если его
смена покрывает час **целиком**: началась не позже начала слота и
закончилась не раньше его конца. Выгрузка графика иногда содержит одну и ту
же смену дважды — человек от этого не раздваивается.

Закрытые пункты (`is_active = false`) не проверяются.

- колонки: `point`, `slot` — начало часа в виде `'HH24:MI'`, `staffed` —
  сколько разных сотрудников закрывают слот, `required`;
- в отчёт идут только слоты с `staffed < required`, включая слоты, где нет
  никого;
- порядок: по `point`, затем по времени слота.

Что проверяют скрытые данные: смена, заканчивающаяся ровно в начале слота,
и смена, начинающаяся посреди часа; продублированные смены, которые
маскируют нехватку; собственное правило пункта поверх общего; пустые часы
без единой смены; смена в другой день; закрытый пункт.

```sql
WITH slots AS (
  SELECT h, date '2024-08-05' + h * interval '1 hour' AS slot_start
  FROM generate_series(8, 19) AS h
),
grid AS (
  SELECT p.id AS point_id, p.name, s.h, s.slot_start,
         coalesce(own.required, dflt.required) AS required
  FROM points p
  CROSS JOIN slots s
  LEFT JOIN coverage_rules own
    ON own.point_id = p.id AND s.h >= own.hour_from AND s.h < own.hour_to
  LEFT JOIN coverage_rules dflt
    ON dflt.point_id IS NULL AND s.h >= dflt.hour_from AND s.h < dflt.hour_to
  WHERE p.is_active
),
staffed AS (
  SELECT g.point_id, g.name, g.slot_start, g.required,
         count(DISTINCT sh.employee_id) AS staffed
  FROM grid g
  LEFT JOIN shifts sh
    ON sh.point_id = g.point_id
   AND sh.starts_at <= g.slot_start
   AND sh.ends_at >= g.slot_start + interval '1 hour'
  GROUP BY g.point_id, g.name, g.slot_start, g.required
)
SELECT name AS point, to_char(slot_start, 'HH24:MI') AS slot, staffed, required
FROM staffed
WHERE staffed < required
ORDER BY name, slot_start;
```

**Отчёт о *нехватке* строится от сетки, а не от смен.** Смены знают только
о часах, где кто-то есть. Час, где нет никого, — самый важный в отчёте — из
таблицы смен не получить: Парк в 8, 9 и 19 часов. Сначала `CROSS JOIN`
«активные пункты × слоты», потом к сетке `LEFT JOIN` всего остального.

**Правило с переопределением — два `LEFT JOIN` и `coalesce`.** Одно
соединение ищет собственное правило пункта, другое — общее, `coalesce`
берёт первое найденное. Соединение с `point_id = p.id OR point_id IS NULL`
дало бы на Вокзал в 12–14 часов *две* строки норматива и удвоило бы
сетку. Порядок в `coalesce` и есть приоритет.

**Покрытие слота — соединение по диапазону «смена содержит слот».**
Сотрудник 5 на Вокзале вышел в 12:30 — час 12:00 он не закрывает, а 13:00 —
закрывает. Смена 08:00–12:00 в Центре кончается ровно в начале слота 12:00
и в нём не участвует. Условие «пересекается» (как для броней) здесь было бы
неверным: полчаса присутствия — не закрытый час.

**`count(DISTINCT employee_id)`, а не `count(*)`.** Дубль смены сотрудника 2
в Центре превращает одного человека в двоих, и нехватка в 17:00 пропадает;
на Вокзале дубль сотрудника 4 маскирует нехватку в 13:00. После `LEFT
JOIN` `count(DISTINCT sh.employee_id)` к тому же даёт 0 для пустого слота —
`NULL` не считается.

**Что спросят дальше.** «А если слоты по 15 минут и пунктов тысячи?» — сетка
растёт как произведение, но остаётся линейной по каждому измерению;
соединение по диапазону выигрывает от индекса `(point_id, starts_at)` или
GiST по `tsrange`. И «как показать *интервалы* нехватки, а не часы?» — те же
острова и промежутки поверх результата.
