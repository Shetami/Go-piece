Для витрины маркетплейса нужны **два самых продаваемых товара** каждой
категории за **май 2024 года**. Продажи — это штуки (`qty`) в доставленных
заказах (`status = 'delivered'`), созданных в мае.

- колонки: `category`, `rank` (1 или 2), `product`, `units` — штук за май;
- при равенстве штук выше товар с меньшим `id`;
- если в категории продан только один товар — одна строка; если ни одного —
  тоже одна строка, с `NULL` в `rank`, `product` и `units`;
- порядок: по `category`, затем по `rank`.

Решите через `LATERAL`: для каждой категории — свой подзапрос с `LIMIT`.

Что проверяют скрытые данные: товар в нескольких заказах, крупная отменённая
покупка, заказы на границах мая, ничья за второе и за первое место,
категории без продаж вовсе и с продажами только вне мая.

<Reveal>

```sql
SELECT c.name AS category, t.rank, t.product, t.units
FROM categories c
LEFT JOIN LATERAL (
  SELECT row_number() OVER (ORDER BY sum(i.qty) DESC, p.id) AS rank,
         p.name     AS product,
         sum(i.qty) AS units
  FROM products p
  JOIN order_items i ON i.product_id = p.id
  JOIN orders o      ON o.id = i.order_id
  WHERE p.category_id = c.id
    AND o.status = 'delivered'
    AND o.created_at >= '2024-05-01' AND o.created_at < '2024-06-01'
  GROUP BY p.id, p.name
  ORDER BY units DESC, p.id
  LIMIT 2
) t ON true
ORDER BY c.name, t.rank;
```

Ответ:

```
Зонты | 1 | Зонт складной | 3
Зонты | 2 | Зонт-трость | 2
Перчатки | NULL | NULL | NULL
Сумки | 1 | Шопер | 3
Сумки | 2 | Клатч | 3
Шарфы | NULL | NULL | NULL
```

**`LATERAL` — это «для каждой строки слева выполни подзапрос».** Подзапрос
справа видит `c.id` из внешней таблицы, как коррелированный подзапрос, но
возвращает не одно значение, а целую таблицу — здесь до двух строк. Обычный
подзапрос в `FROM` так не умеет: он вычисляется один раз и про `c` ничего не
знает.

**`LEFT JOIN LATERAL … ON true` сохраняет категории без продаж.** С `CROSS
JOIN LATERAL` (или просто запятой) категория, для которой подзапрос вернул
ноль строк, исчезает — как при внутреннем соединении. `ON true`
обязателен синтаксически: условие соединения уже внутри подзапроса.

**Ничьи — только с тай-брейкером.** У «Зонта-трости» и «Зонта детского» по
две штуки, у «Шопера» и «Клатча» по три. Без `p.id` в `ORDER BY` запрос
вернёт какой-то из двух — и в следующий раз, может быть, другой.
`row_number()` поверх той же сортировки даёт номер места; оконные функции
вычисляются после `GROUP BY`, поэтому `sum(i.qty)` в окне допустим.

**Фильтры — внутри подзапроса.** Отменённая покупка десяти детских зонтов и
апрельские пять рюкзаков сделали бы их лидерами. «Перчатки» проданы 1 июня
в 00:00 — это уже не май.

**Что спросят дальше.** «Чем это лучше `row_number() OVER (PARTITION BY
category)` и `WHERE rn <= 2`?» — Результат тот же. Окно считает ранги для
*всех* товаров, а потом отбрасывает лишние; `LATERAL` с `LIMIT` при индексе
вида `(category_id, …)` умеет прочитать только первые строки каждой группы —
выигрыш, когда групп мало, а строк в них много. Здесь продажи всё равно
агрегируются, так что разница — скорее в читаемости.

</Reveal>
