Магазин кофейных товаров хочет блок «С этим покупают». Для начала — список
пар товаров, которые встречались **вместе в одном оплаченном заказе**
(`status = 'paid'`) хотя бы **в двух** разных заказах.

- колонки: `product_a`, `product_b` — названия, у первого `id` меньше, чем
  у второго; `orders_together` — в скольких разных оплаченных заказах пара
  встретилась;
- каждая пара — одной строкой;
- порядок: `orders_together` по убыванию, затем `id` первого товара, затем
  `id` второго.

Один товар может занимать в заказе несколько строк (разные акции, разные
фасовки). Строки с пустым `product_id` — подарочная упаковка, это не товар.

Что проверяют скрытые данные: товар дважды в одном заказе, отменённый заказ
с популярной парой, заказ из одного товара с упаковкой, пары, которые
набирают порог только если считать строки, а не заказы.

<Reveal>

```sql
WITH lines AS (
  SELECT DISTINCT i.order_id, i.product_id
  FROM order_items i
  JOIN orders o ON o.id = i.order_id
  WHERE o.status = 'paid'
    AND i.product_id IS NOT NULL
)
SELECT pa.name AS product_a,
       pb.name AS product_b,
       count(*) AS orders_together
FROM lines a
JOIN lines b     ON b.order_id = a.order_id AND a.product_id < b.product_id
JOIN products pa ON pa.id = a.product_id
JOIN products pb ON pb.id = b.product_id
GROUP BY a.product_id, b.product_id, pa.name, pb.name
HAVING count(*) >= 2
ORDER BY orders_together DESC, a.product_id, b.product_id;
```

Ответ:

```
Кофемолка | Кофе в зёрнах | 2
Кофе в зёрнах | Турка | 2
Кофе в зёрнах | Фильтры | 2
```

**Пары внутри группы — самосоединение по ключу группы.** Каждая позиция
заказа соединяется с каждой другой позицией того же заказа. Условие
`a.product_id < b.product_id` делает сразу три дела: убирает пару товара с
самим собой, убирает зеркальный дубль (B, A) и фиксирует, кто в паре
«первый».

**Сначала — одна строка на «заказ × товар».** В заказе 106 кофе записан
дважды. Если соединять сырые строки, пара «кофе + весы» получит в этом
заказе две строки и пройдёт порог в 2, хотя встретилась в одном заказе; а
пара «кофемолка + кофе» из заказа 100 насчитает 3. Самосоединение умножает
дубли квадратично: `k` строк одного товара дают `k × m` пар. `DISTINCT` в
CTE до соединения — дешевле и честнее, чем `count(DISTINCT order_id)`
после.

**Фильтры — до самосоединения.** Отменённый заказ 103 добавил бы паре
«кофе + турка» третий заказ. Упаковка с `NULL` в пары не попадает и так
(`NULL < x` — не истина), но фильтр в CTE делает намерение явным.

**Взрыв строк.** Заказ из `n` разных товаров даёт `n(n−1)/2` пар. На
корзинах из сотни позиций это пять тысяч строк на заказ — в проде такие
счётчики считают инкрементально или ограничивают размер корзины.

**Что спросят дальше.** «Как ранжировать рекомендации честнее, чем по
частоте?» — поделить на популярность товаров: *lift* =
`P(A и B) / (P(A) · P(B))`. Иначе кофе в зёрнах будет «сопутствующим» для
всего подряд просто потому, что его покупают все.
