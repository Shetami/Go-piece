Сеть магазинов строит дневной отчёт за **1–5 марта 2024 года**. Для каждого
дня нужна строка по каждому магазину, который в этот день **работал**, —
даже если продаж не было.

Магазин работает в день `day`, если `opened_on <= day` и `closed_on` пуст
или `day < closed_on` (`closed_on` — первый день, когда магазин уже закрыт).

- колонки: `day` (дата), `store` (название), `checks` — число чеков,
  `revenue` — их сумма; возврат — это тоже чек, с отрицательной суммой;
- день без продаж — `0` и `0`;
- порядок: по `day`, затем по `store`.

Чек относится к дню по `sold_at`. Чеки интернет-кассы без магазина в отчёт
не идут.

Что проверяют скрытые данные: чек в последнюю секунду периода и ровно в
полночь после него, магазин, открывшийся посреди периода, закрывшийся
магазин, магазин, который откроется только в апреле, магазин без единой
продажи.

<Reveal>

```sql
WITH days AS (
  SELECT d::date AS day
  FROM generate_series(date '2024-03-01', date '2024-03-05', interval '1 day') AS d
),
daily AS (
  SELECT store_id, sold_at::date AS day, count(*) AS checks, sum(amount) AS revenue
  FROM sales
  WHERE sold_at >= '2024-03-01' AND sold_at < '2024-03-06'
  GROUP BY store_id, sold_at::date
)
SELECT d.day, s.name AS store,
       coalesce(x.checks, 0)  AS checks,
       coalesce(x.revenue, 0) AS revenue
FROM days d
CROSS JOIN stores s
LEFT JOIN daily x ON x.store_id = s.id AND x.day = d.day
WHERE s.opened_on <= d.day
  AND (s.closed_on IS NULL OR d.day < s.closed_on)
ORDER BY d.day, s.name;
```

```
2024-03-01 | Волхонка | 0 | 0
2024-03-01 | Горки | 0 | 0
2024-03-02 | Арбат | 0 | 0
2024-03-02 | Волхонка | 2 | 100
2024-03-02 | Горки | 0 | 0
2024-03-03 | Арбат | 1 | 150
2024-03-03 | Беговая | 1 | 500
2024-03-03 | Волхонка | 0 | 0
2024-03-03 | Горки | 0 | 0
2024-03-04 | Арбат | 1 | 50
2024-03-04 | Беговая | 1 | 250
2024-03-04 | Горки | 0 | 0
2024-03-05 | Арбат | 1 | 100
2024-03-05 | Беговая | 0 | 0
2024-03-05 | Горки | 0 | 0
```

**Отчёт с нулями строится от сетки, а не от фактов.** `GROUP BY` по продажам
не придумает строку, для которой продаж нет. Сначала декартово произведение
«все дни × все магазины» (`CROSS JOIN`), затем к нему `LEFT JOIN` фактов.
Горки не продали ничего за весь период — и всё равно занимают пять строк.

**Сетку режут по сроку работы магазина.** Беговая открылась 3 марта,
Волхонка закрылась 4-го, Дмитровка ещё не открылась. Это условие на *левую*
часть соединения — сетку, — поэтому ему место в `WHERE`: оно выбрасывает
лишние клетки, а не присоединённые продажи.

**Продажи сворачиваются до соединения.** Можно присоединить сырые чеки и
группировать по `(day, store)`, но тогда `count(*)` у пустой клетки даст 1 —
строку из `NULL`, а не 0; придётся помнить про `count(x.id)`. Предагрегация
до зерна сетки снимает вопрос: к каждой клетке присоединяется не больше
одной строки.

**Границы периода — полуоткрытые.** `BETWEEN '2024-03-01' AND '2024-03-06'`
захватит чек ровно в полночь 6 марта (999 ₽ у Арбата), а `BETWEEN … AND
'2024-03-05'` потеряет всё, что после полуночи 5-го, включая чек в
23:59:59. `sold_at >= начало AND sold_at < начало_следующего_дня` не ошибается
ни с какой точностью времени.

**Что спросят дальше.** «Где взять календарь в проде?» — `generate_series`
хорош для отчёта; в хранилищах держат таблицу-календарь с праздниками и
рабочими днями — к ней соединяются так же.
