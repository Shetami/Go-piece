`sync.Once` запоминает, что функция **была вызвана**, а не что она
**удалась**: если инициализация клиента упала на сетевой ошибке или
запаниковала, сервис навсегда остаётся без клиента. Реализуйте `Lazy[T]`,
который кэширует только успешный результат.

Что проверяют скрытые тесты:

- после успеха `init` больше не вызывается;
- после ошибки следующий `Get` вызывает `init` снова;
- паника `init` долетает до вызывающего `Get`, и **так дважды подряд** —
  а третий `Get` получает значение, не зависнув;
- 50 горутин одновременно: `init` никогда не выполняется параллельно,
  первая паникует, вторая вычисляет значение, остальные 48 получают его
  без вызова `init`;
- всё чисто под `-race`.

<Reveal>

```go
type Lazy[T any] struct {
	init func() (T, error)
	mu   sync.Mutex
	done atomic.Bool
	val  T
}

func (l *Lazy[T]) Get() (T, error) {
	if l.done.Load() {
		return l.val, nil
	}
	l.mu.Lock()
	defer l.mu.Unlock()
	if l.done.Load() {
		return l.val, nil
	}
	v, err := l.init()
	if err != nil {
		var zero T
		return zero, err
	}
	l.val = v
	l.done.Store(true)
	return v, nil
}
```

**`defer l.mu.Unlock()` — не для красоты.** Если отпускать мьютекс
вручную после `init`, паника пролетит мимо `Unlock`, и все следующие `Get`
навсегда повиснут на `Lock`. Именно так выглядит «сервис завис после
одного сбоя».

**Флаг — только после успеха.** Порядок «сначала `val`, потом
`done.Store(true)`» даёт happens-before для быстрого пути: кто увидел
`true`, тот увидит и значение. Ошибка и паника флаг не трогают — поэтому
следующая попытка возможна.

**Двойная проверка.** Пока горутина ждала мьютекс, другая могла
вычислить значение. Без второй проверки под блокировкой `init` вызовется
лишний раз.

**Почему не `sync.OnceValues`.** Он кэширует и ошибку, а при панике
перебрасывает её **на каждом** вызове — повторить нельзя. Это правильное
поведение для настоящих констант, но не для подключения к внешнему
сервису.

**Что спросят следом.** Как добавить `context` в `Get`, чтобы ожидающие
могли уйти по таймауту (мьютекс не отменяется — нужен канал или
`singleflight`), и как ограничить частоту повторов после ошибки.
