`safely` должна превратить любую панику в `error`. Первый вызов работает, а
на втором программа падает:

```
panic: просто строка [recovered
```

Почините. Ожидаемый вывод:

```
ошибка-значение
паника: просто строка
assignment to entry in nil map
```

<Reveal>

**`recover` возвращает `any`, а не `error`.** В `panic` можно передать что
угодно: строку, число, структуру. `r.(error)` — приведение без проверки. Для
строки оно паникует — прямо внутри отложенной функции, во время обработки
первой паники. Новая паника раскручивает стек дальше, `recover` больше
нет, программа падает. В сообщении видно обе: исходную с пометкой
`[recovered]` и новую про `interface conversion`.

**Как чинят** — разобрать, что пришло:

```go
switch r := recover().(type) {
case nil:
case error:
	err = r
default:
	err = fmt.Errorf("паника: %v", r)
}
```

Паники рантайма (`nil`-мапа, выход за границы, деление на ноль) —
значения типа `runtime.Error`, это интерфейс, встраивающий `error`. Поэтому
третий вызов попадает в ветку `error` и печатается как есть.

**`case nil` обязателен.** Без него при обычном завершении `f` (паники не
было, `recover` вернул `nil`) сработала бы ветка `default` и превратила
«всё хорошо» в `паника: <nil>`.

</Reveal>
