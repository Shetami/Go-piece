`defer` привязан к функции. Когда ресурсы открываются в конструкторе, а
закрываются в `Close`, нужен свой стек очистки. Реализуйте `Cleanup`.

Что проверяют скрытые тесты:

- функции выполняются в порядке, обратном добавлению — как `defer`;
- ошибка одной не мешает выполниться остальным, `Run` возвращает все
  ошибки (`errors.Is` находит каждую);
- паника в одной очистке становится ошибкой с её текстом, остальные тоже
  выполняются;
- повторный `Run` ничего не делает.

<Reveal>

```go
func (c *Cleanup) Run() error {
	var errs []error
	for i := len(c.fns) - 1; i >= 0; i-- {
		errs = append(errs, runOne(c.fns[i]))
	}
	c.fns = nil
	return errors.Join(errs...)
}

func runOne(f func() error) (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("паника в очистке: %v", r)
		}
	}()
	return f()
}
```

**Обратный порядок** — потому что ресурсы зависят друг от друга: сначала
открыли соединение, потом транзакцию в нём. Закрывать надо наоборот.

**`recover` на каждую функцию, а не один на весь `Run`.** Один `recover`
вокруг цикла остановит панику, но и цикл тоже: оставшиеся очистки не
выполнятся. Отдельная функция `runOne` со своим `defer` изолирует каждую.

**`errors.Join`** отбрасывает `nil` и возвращает `nil`, если ошибок не было
вовсе, — удобно копить всё подряд.

**`c.fns = nil`** делает `Run` идемпотентным: двойное закрытие — частая
история, когда `Close` вызывают и в `defer`, и явно.

Похожий механизм есть в стандартной библиотеке: `t.Cleanup` в тестах —
ровно такой стек, выполняемый после теста.

</Reveal>
