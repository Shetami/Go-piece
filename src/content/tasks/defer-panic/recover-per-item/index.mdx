`processAll` защищена от паники: `recover` в отложенной функции. Второй
элемент — ноль, деление на него паникует. Программа печатает:

```
5 → 20
сбой: runtime error: integer divide by zero
конец
```

Третий элемент так и не обработан. Почините: сбой одного элемента должен
пропускать только его. Ожидаемый вывод:

```
5 → 20
сбой на 0 - runtime error: integer divide by zero
20 → 5
конец
```

<Reveal>

**`recover` не продолжает выполнение с места паники.** Паника раскручивает
стек до функции, в которой отложен `recover`, и эта функция **завершается**
— штатно, но завершается. Цикл внутри неё прерван навсегда.

**Граница перехвата — функция.** Чтобы пережить сбой одного элемента,
каждому элементу нужен свой вызов функции со своим `defer`:

```go
func safeHandle(x int) (res int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("%v", r)
		}
	}()
	return handle(x), nil
}
```

Именованный результат `err` нужен, чтобы отложенная функция могла
положить в него ошибку, — без имени результат уже зафиксирован как
`(0, nil)`.

**Так устроен `net/http`:** паника в обработчике одного запроса
перехватывается на уровне этого запроса, соединение закрывается, а
сервер продолжает принимать остальные.

</Reveal>
