`process` должна держать не больше одного соединения за раз. Программа
печатает:

```
открыто соединений: 1
открыто соединений: 2
открыто соединений: 3
открыто соединений: 4
после: 0
```

В конце всё закрыто, но по дороге соединения копились. Отметьте строку, в
которой заложена поломка.

<Reveal>

Сломано в строке 21: `defer c.Close()` внутри цикла.

**`defer` привязан к функции, а не к блоку.** Отложенный вызов сработает при
выходе из `process`, а не в конце итерации. Цикл из четырёх итераций
откладывает четыре `Close`, и все они исполнятся разом, когда цикл уже
закончится.

На четырёх элементах это незаметно. На тысяче файлов — `too many open
files`. На тысяче строк из базы — исчерпанный пул соединений.

**Как правильно** — вынести тело итерации в функцию:

```go
for _, id := range ids {
	handle(id) // внутри: c := dial(id); defer c.Close(); ...
}
```

Или обернуть тело в анонимную функцию `func() { ... }()` — то же самое, но
хуже читается. Или закрывать явно, без `defer`, если в теле нет ранних
выходов.

**Линтеры это знают.** `staticcheck` предупреждает о `defer` в цикле
(SA9001 — для `range` по каналу), `gocritic` — правилом `deferInLoop`.

</Reveal>
