Допишите `SafeCall`. Сигнатуру можно менять, пока она принимает
`func()` и возвращает `error`.

Что проверяют скрытые тесты:

- без паники — `nil`, и `f` действительно вызвана;
- паника строкой или числом — ошибка, в тексте которой есть это значение;
- паника ошибкой — `errors.Is` находит исходную ошибку;
- паника рантайма (запись в `nil`-мапу) достаётся через
  `errors.As(err, &runtimeErr)`.

<Reveal>

```go
func SafeCall(f func()) (err error) {
	defer func() {
		switch r := recover().(type) {
		case nil:
		case error:
			err = fmt.Errorf("паника: %w", r)
		default:
			err = fmt.Errorf("паника: %v", r)
		}
	}()
	f()
	return nil
}
```

**Именованный результат** — единственный способ вернуть ошибку из
отложенной функции. В заготовке результат безымянный, и это первое, что
надо поменять.

**`%w` для ошибок, `%v` для остального.** Паника значением типа `error`
заслуживает того же обращения, что и обычная ошибка: вызывающий должен
суметь проверить её через `errors.Is` и `errors.As`. Паники рантайма — тоже
ошибки (`runtime.Error`), поэтому они попадают в ту же ветку.

**`case nil`.** `recover()` вне паники возвращает `nil`. Без этой ветки
`default` превратил бы нормальное завершение в ошибку `паника: <nil>`. С
Go 1.21 `panic(nil)` превращается в `*runtime.PanicNilError`, так что
«паника с `nil`» и «паники не было» теперь различимы.

**Где пригодится.** Обработчики задач в пулах воркеров и фоновых
горутинах: одна паника в чужом коде не должна ронять весь процесс. Но
перехватывать стоит на границе — там, где понятно, что делать дальше, — а
не в каждой функции.

</Reveal>
