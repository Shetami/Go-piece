Обработчик запускает загрузку профиля в фоне, параллельно считает
рекомендации, а потом забирает профиль. Если загрузчик запаниковал в своей
горутине, никакой `recover` в обработчике не поможет — упадёт весь сервис.
Реализуйте `Async` и `Future.Get`.

Что проверяют скрытые тесты:

- десять одновременных `Get` получают одно и то же значение, `fn`
  выполняется один раз, повторный `Get` тоже работает;
- ошибка `fn` возвращается как есть;
- паника рантайма в `fn` — `*PanicError` для **каждого** `Get`, через
  `errors.As` виден `runtime.Error`, в стеке — функция, где упало;
- `Get` с отменённым `ctx` сразу возвращает `context.Canceled`, а
  следующий `Get` дожидается настоящего результата.

<Reveal>

```go
type Future[T any] struct {
	done chan struct{}
	val  T
	err  error
}

func Async[T any](fn func() (T, error)) *Future[T] {
	f := &Future[T]{done: make(chan struct{})}
	go func() {
		defer close(f.done)
		defer func() {
			if r := recover(); r != nil {
				var zero T
				f.val, f.err = zero, &PanicError{Value: r, Stack: debug.Stack()}
			}
		}()
		f.val, f.err = fn()
	}()
	return f
}

func (f *Future[T]) Get(ctx context.Context) (T, error) {
	select {
	case <-f.done:
		return f.val, f.err
	case <-ctx.Done():
		var zero T
		return zero, ctx.Err()
	}
}
```

**Закрытие канала — широковещательный сигнал.** Значение, отправленное в
канал, получит только один читатель; второй `Get` зависнет навсегда.
Закрытый канал читается мгновенно и сколько угодно раз, поэтому результат
кладут в поля, а канал только закрывают.

**Порядок двух `defer`.** `close(f.done)` отложен первым и выполнится
последним — после того, как `recover` записал `*PanicError`. Поменяйте
местами — и читатель может проснуться раньше, чем появится ошибка, и
получить `nil`. Заодно это гонка, которую поймает `-race`.

**Без мьютекса.** Закрытие канала happens-before чтения из него: всё,
что горутина записала до `close`, видно тем, кто дождался `<-f.done`.

**Отмена `Get` не отменяет работу.** `ctx` в `Get` — это «сколько я готов
ждать», а не «остановить задачу». Если нужно отменять и `fn`, её ctx
передают в `Async` отдельно.

**Что спросят следом.** Чем это отличается от `errgroup` и
`singleflight`, как сделать `Then`/`All` поверх `Future` и почему в Go
такие обёртки редки: обычно хватает канала и `select`.
