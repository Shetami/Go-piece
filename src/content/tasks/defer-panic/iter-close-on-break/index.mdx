С Go 1.23 курсор базы или строки файла удобно отдавать как
`iter.Seq2[string, error]`, и потребитель пишет обычный `for … range`.
Но где тогда закрывать ресурс? Потребитель может выйти по `break`, а тело
цикла — запаниковать. Реализуйте `Lines`.

Что проверяют скрытые тесты:

- `open` вызывается при старте `range`, а не при вызове `Lines`; второй
  `range` открывает заново;
- полный проход — все строки и один `Close`;
- `break` после второй строки — один `Close`, лишних `Next` нет, и никакой
  паники рантайма;
- паника в теле цикла — `Close` вызван, паника пролетает наружу;
- ошибка `Next` — строки до неё, одна пара с ошибкой, один `Close`;
- ошибка `open` — одна пара с ней; ошибка `Close` после нормального конца —
  последней парой.

<Reveal>

```go
func Lines(open func() (Source, error)) iter.Seq2[string, error] {
	return func(yield func(string, error) bool) {
		src, err := open()
		if err != nil {
			yield("", err)
			return
		}

		closed := false
		defer func() {
			if !closed {
				_ = src.Close()
			}
		}()

		for {
			line, ok, err := src.Next()
			if err != nil {
				closed = true
				_ = src.Close()
				yield("", err)
				return
			}
			if !ok {
				closed = true
				if cerr := src.Close(); cerr != nil {
					yield("", cerr)
				}
				return
			}
			if !yield(line, nil) {
				return
			}
		}
	}
}
```

**Тело цикла выполняется внутри `yield`.** Компилятор превращает тело
`range` в функцию, которую итератор вызывает. Поэтому паника в теле
цикла летит **сквозь** кадр итератора, и его `defer` выполняется —
значит, `Close` в `defer` покрывает и панику, и `break`.

**После `false` от `yield` его вызывать нельзя.** Потребитель ушёл;
повторный вызов рантайм наказывает паникой «range function continued
iteration after function for loop body returned false». Отсюда правило:
ошибку `Close` после `break` отдать некому — её можно только проглотить
(или залогировать).

**Почему не просто `defer src.Close()`.** Тогда ошибку `Close` в нормальном
конце не вернуть: `defer` выполняется после выхода, а отдавать через
`yield` из отложенной функции нельзя: после паники тела цикла рантайм
ответит на такой вызов новой паникой «continued iteration after loop body
panic». Флаг `closed` разделяет «закрыли сами и сообщили» и
«закрывает страховка».

**Открытие — внутри возвращаемой функции.** Если открыть источник в
`Lines`, итератор, который так и не прошли, никогда не закроет ресурс, а
второй `range` прочтёт уже пустой.

**Что спросят следом.** Как устроен `iter.Pull` и почему с ним нужно
обязательно вызывать `stop`, и чем такая схема отличается от
`rows.Next()`/`rows.Err()`/`rows.Close()` в `database/sql`.
