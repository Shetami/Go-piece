Классика live-coding: перевод денег между счетами с помощью мьютексов.
Здесь к ней добавлен неприятный поворот — после изменения балансов
вызывается внешний `audit`, который может запаниковать. Деньги к этому
моменту уже списаны. Реализуйте `Transfer`.

Что проверяют скрытые тесты:

- обычный перевод меняет оба баланса;
- нулевая или отрицательная сумма, перевод самому себе, неизвестный счёт,
  нехватка денег — свои ошибки, балансы не меняются, и ничего не
  зависает;
- 300 одновременных переводов по кругу и навстречу друг другу — без
  дедлока, сумма денег сохраняется, чисто под `-race`;
- паника в `audit` — паника летит дальше, балансы возвращены, мьютексы
  отпущены, следующий перевод проходит.

<Reveal>

```go
func (b *Bank) Transfer(from, to, amount int) error {
	switch {
	case amount <= 0:
		return ErrBadAmount
	case from == to:
		return ErrSameAccount
	}
	src, ok1 := b.accounts[from]
	dst, ok2 := b.accounts[to]
	if !ok1 || !ok2 {
		return ErrNoAccount
	}

	first, second := src, dst
	if second.ID < first.ID {
		first, second = second, first
	}
	first.mu.Lock()
	defer first.mu.Unlock()
	second.mu.Lock()
	defer second.mu.Unlock()

	if src.balance < amount {
		return ErrInsufficient
	}
	src.balance -= amount
	dst.balance += amount

	done := false
	defer func() {
		if !done {
			src.balance += amount
			dst.balance -= amount
		}
	}()
	if b.audit != nil {
		b.audit(from, to, amount)
	}
	done = true
	return nil
}
```

**Порядок захвата — по ID.** Если первый перевод берёт `A`, потом `B`, а
встречный — `B`, потом `A`, каждый может успеть взять первый мьютекс и
вечно ждать второй. Глобальный порядок (по ID, по адресу — неважно, лишь
бы один для всех) делает цикл ожидания невозможным.

**Перевод самому себе — отдельная ветка.** `sync.Mutex` не реентерабельный:
второй `Lock` того же мьютекса в той же горутине висит вечно.

**Откат — через флаг и `defer`, без `recover`.** Паника пролетит сквозь
отложенную функцию, которая вернёт деньги, и дальше — сквозь разблокировки.
Перехватывать и перебрасывать её не нужно.

**Порядок `defer` — главное.** Отложенные вызовы выполняются в обратном
порядке: откат отложен последним и выполнится **первым**, ещё под обеими
блокировками. Если откатывать после `Unlock`, между разблокировкой и
откатом другая горутина увидит и потратит несуществующие деньги.

**Что спросят следом.** Почему вызывать внешний код под блокировкой —
плохая идея (аудит по сети держит оба счёта), как вынести его за
блокировку через outbox и как то же решается в базе: `SELECT … FOR
UPDATE` в порядке `id`.
