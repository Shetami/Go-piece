`get` запрашивает адрес и закрывает ответ. С нормальным адресом всё
работает, с пустым `get` должна вернуть ошибку. Программа печатает:

```
прочитали go.dev
закрыли go.dev
<nil>
panic: runtime error: invalid memory address or nil pointer dereference
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 21: `defer resp.Close()` — до проверки ошибки.

**При ошибке `resp` — `nil`.** Соглашение в Go: если функция вернула
ошибку, остальные результаты использовать нельзя. `fetch("")` возвращает
`nil, err`.

**`defer` вычисляет получатель сразу, но вызывает метод потом.** В момент
`defer` запоминается `resp` — нулевой указатель. Ничего не падает: вызов
метода на `nil`-указателе в Go законен. Функция возвращает ошибку, и на выходе
срабатывает `resp.Close()`. Внутри `Close` обращение к `r.Body` —
разыменование `nil`. Паника случается уже *после* `return err`, и ошибка до
вызывающего не доходит.

**Как правильно** — сначала проверка, потом `defer`:

```go
resp, err := fetch(url)
if err != nil {
	return err
}
defer resp.Close()
```

С `net/http` это классика: `defer resp.Body.Close()` до проверки `err`. Для
неё в `go vet` есть отдельная проверка `httpresponse`, но для своих типов
она не сработает.

</Reveal>
