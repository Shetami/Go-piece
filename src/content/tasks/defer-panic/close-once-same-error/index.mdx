Соединение закрывают из трёх мест сразу: `defer` в обработчике, хук
остановки, watchdog. Нужно, чтобы закрытие произошло один раз, а все,
кто просил закрыть, узнали результат. `sync.Once` кажется готовым
ответом — но у него есть ловушка с паникой. Реализуйте `Conn`.

Что проверяют скрытые тесты:

- 20 одновременных `Close` — `closeFn` вызвана один раз, **все** получают
  её ошибку, в том числе те, кто ждал; повторный `Close` — тоже;
- `Done` закрывается только после завершения `closeFn`;
- `closeFn` паникует — ни один `Close` не паникует, все получают одну и ту
  же ошибку с текстом паники (включая более поздние вызовы), `closeFn`
  вызвана один раз, `Done` закрыт.

<Reveal>

```go
type Conn struct {
	closeFn func() error
	once    sync.Once
	err     error
	done    chan struct{}
}

func NewConn(closeFn func() error) *Conn {
	return &Conn{closeFn: closeFn, done: make(chan struct{})}
}

func (c *Conn) Close() error {
	c.once.Do(func() {
		defer close(c.done)
		defer func() {
			if r := recover(); r != nil {
				c.err = fmt.Errorf("паника при закрытии: %v", r)
			}
		}()
		c.err = c.closeFn()
	})
	return c.err
}

func (c *Conn) Done() <-chan struct{} { return c.done }
```

**`sync.Once` считает паникующий вызов выполненным.** Если `closeFn`
запаникует прямо внутри `once.Do`, первый вызывающий получит панику, а
все следующие — мгновенный `nil`: `Once` «уже сделано», `c.err` так и не
записан. Для закрытия это худший исход — ошибка теряется молча. Поэтому
`recover` стоит **внутри** функции, переданной в `Do`.

**Ожидание — бесплатно.** `once.Do` блокирует одновременных вызывающих до
конца первого вызова, и после этого запись `c.err` им видна
(happens-before гарантирован `Once`). Мьютекс не нужен.

**Порядок `defer`.** `close(c.done)` отложен первым и выполнится
последним — после того, как ошибка паники записана. Кто дождался `Done`,
увидит финальную `c.err`.

**Почему не `sync.OnceValue`.** Он при панике перебрасывает её каждому
вызывающему — для `Close` это ещё хуже: паника в каждом `defer
conn.Close()`.

**Что спросят следом.** Как сделать `Close(ctx)` с таймаутом (ожидание
через `select` по `Done` и `ctx.Done()`) и почему `net.Conn.Close` на
второй вызов возвращает ошибку `use of closed network connection`, а не
ту же самую.

</Reveal>
