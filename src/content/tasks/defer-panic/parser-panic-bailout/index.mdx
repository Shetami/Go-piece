При рекурсивном спуске ошибку глубоко внутри приходится возвращать через
пять уровней вызовов, и каждый уровень обрастает `if err != nil`.
`encoding/json` и `text/template` поступают иначе: внутри — паника своего
типа, на публичной границе — `recover` и обычная ошибка. Реализуйте так
`Eval`.

Что проверяют скрытые тесты:

- приоритеты, левая ассоциативность (`10 - 4 - 3`, `100 / 7 / 2`), унарный
  минус, скобки и переменные;
- синтаксические ошибки — `*ParseError` с позицией первого неожиданного
  символа, а при обрыве — с позицией конца строки;
- деление на ноль — ошибка с позицией знака `/`, через `errors.Is`
  находится `ErrDivByZero`;
- 5000 вложенных скобок — и корректное значение, и ошибка незакрытой
  скобки;
- паника внутри `lookup` пролетает сквозь `Eval` без изменений — и строкой,
  и значением `*ParseError`.

<Reveal>

```go
type bailout struct{ err *ParseError }

func Eval(expr string, lookup func(name string) int) (v int, err error) {
	defer func() {
		if r := recover(); r != nil {
			b, ok := r.(bailout)
			if !ok {
				panic(r)
			}
			v, err = 0, b.err
		}
	}()
	p := &parser{s: expr, lookup: lookup}
	v = p.expr()
	if p.peek() != 0 {
		p.fail(p.pos, fmt.Sprintf("лишний символ %q", p.s[p.pos]), nil)
	}
	return v, nil
}

func (p *parser) fail(pos int, msg string, err error) {
	panic(bailout{&ParseError{Pos: pos, Msg: msg, Err: err}})
}

func (p *parser) term() int {
	v := p.unary()
	for {
		switch p.peek() {
		case '*':
			p.pos++
			v *= p.unary()
		case '/':
			opPos := p.pos
			p.pos++
			d := p.unary()
			if d == 0 {
				p.fail(opPos, "деление на ноль", ErrDivByZero)
			}
			v /= d
		default:
			return v
		}
	}
}

// expr, unary, primary — обычный рекурсивный спуск, полностью — в solution.go:
// expr   = term { ("+" | "-") term }
// unary  = "-" unary | primary
// primary = число | имя | "(" expr ")"
```

**Своя обёртка вместо `*ParseError` в панике.** Если паниковать самим
`*ParseError`, `Eval` проглотит такую же панику из `lookup` — а это чужой
баг, который нельзя превращать в «синтаксическую ошибку». Неэкспортируемый
`bailout` может создать только парсер.

**Чужое — `panic(r)` дальше.** Это касается и паники рантайма. Поэтому
деление на ноль проверяется **до** `v /= d`: иначе `integer divide by
zero` улетит наружу как чужая паника (или, того хуже, будет спутан со
своей, если ловить всё подряд).

**Именованные результаты.** Отложенная функция выставляет `v, err` уже
после паники — без имён результатов вернуть ошибку из `defer` нельзя.

**Позиции.** Ошибка «ожидали `)`» сообщает позицию того, что стоит на её
месте, а не открывающей скобки: пользователю важнее, **где** парсер
споткнулся. Позиция `/` для деления на ноль запоминается до разбора
делителя — после него `p.pos` уже убежит вперёд.

**Что спросят следом.** Почему паника не должна пересекать границу пакета
(вызывающий не обязан знать о вашем `recover`), чем плоха такая схема для
горячих путей (паника дороже `return err`) и как добавить функции
(`max(a, b)`) без переписывания парсера.
