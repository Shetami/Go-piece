`safeDivide` должна ловить панику от деления на ноль и отдавать её как ошибку.
`recover` на месте, `defer` на месте — но программа падает:

```
panic: runtime error: integer divide by zero
```

Почините. Ожидаемый вывод:

```
5 <nil>
0 паника: runtime error: integer divide by zero
```

<Reveal>

**`recover` работает, только если его вызвала сама отложенная функция** —
непосредственно, без промежуточных вызовов. В заготовке между `defer` и
`recover` вставлена лишняя анонимная функция:

```go
defer func() {        // ← вот эту функцию вызывает рантайм при панике
	func() {           // ← а recover зовёт вот эта, уровнем глубже
		if r := recover(); r != nil { ... }
	}()
}()
```

Для вложенной функции паники «не видно»: `recover` возвращает `nil`, паника
летит дальше и роняет программу. Убираем обёртку:

```go
defer func() {
	if r := recover(); r != nil {
		err = fmt.Errorf("паника: %v", r)
	}
}()
```

**Почему результат вообще удаётся подменить.** Потому что он именованный:
`(result int, err error)`. Отложенная функция видит `err` как обычную
переменную и может в неё записать уже после того, как `return` отработал. Будь
результаты безымянными, перехватить панику вы бы смогли, а вот сообщить о ней
наружу — нет: возвращаемое значение лежало бы в недоступной временной ячейке,
и наружу ушёл бы нулевой результат без ошибки. Это та же механика, что в
задаче [про отложенные вызовы и именованный результат](/practice/defer-panic/named-result-defer/).

**Заодно про `0` в выводе.** После перехвата `result` остаётся нулевым: до
присваивания дело не дошло, паника случилась прямо в `a / b`.

**Когда так вообще делают.** Редко и осознанно. Ловить панику уместно на
границе: в HTTP-мидлваре, чтобы один сломанный хендлер не уронил весь сервер;
в воркере пула, чтобы паника в одной задаче не убила процесс; в библиотеке,
которая внутри использует панику как быстрый выход из глубокой рекурсии
(так устроен `encoding/json`). Во всех остальных местах `recover` — это способ
спрятать ошибку, а не обработать её.

**Чего `recover` не умеет.** Перехватить панику из **другой** горутины.

```go
go func() { panic("бум") }()   // никакой defer в main это не поймает
```

Каждая горутина отвечает за себя: незаперехваченная паника в любой из них
роняет весь процесс. Поэтому у воркеров пула `defer recover()` ставят внутри
самой горутины. И отдельно: `fatal error` — не паника. `all goroutines are
asleep`, `concurrent map writes`, нехватка памяти `recover`-у не поддаются
вообще.

</Reveal>
