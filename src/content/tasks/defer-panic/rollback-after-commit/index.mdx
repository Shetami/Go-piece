---
title: Откат после успешного коммита
description: Транзакцию откатывают через defer на случай ошибки. Но откат срабатывает и после успешного коммита. Почините.
kind: fix
topic: defer-panic

---

Идиома из `database/sql`: сразу после начала транзакции —
`defer tx.Rollback()`, чтобы любой ранний выход её откатил. Контракт
`Rollback` обещает, что после `Commit` вызывать его безопасно. Но сейчас
программа печатает:

```
commit
rollback
<nil>
rollback
недостаточно средств
```

Почините `Tx` так, чтобы откат после коммита ничего не делал. Ожидаемый
вывод:

```
commit
<nil>
rollback
недостаточно средств
```

<Reveal>

**`defer` не знает, чем кончилась функция.** Он выполнится при любом
выходе — и после ошибки, и после успешного `Commit`. Поэтому идиома
работает только вместе с контрактом: `Rollback` после завершения
транзакции — пустая операция.

**Как правильно** — `Rollback` проверяет, не завершена ли транзакция:

```go
func (t *Tx) Rollback() {
	if t.done {
		return
	}
	t.done = true
	...
}
```

В `database/sql` так и устроено: `Rollback` после `Commit` возвращает
`sql.ErrTxDone` и ничего не откатывает. Ошибку отложенного `Rollback`
поэтому обычно игнорируют.

**Альтернатива без контракта** — флаг в самой функции:
`defer func() { if !committed { tx.Rollback() } }()`. Работает с любым
`Tx`, но это лишняя переменная в каждой функции с транзакцией.

</Reveal>
