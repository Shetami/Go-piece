Загрузка файла в хранилище: читаем тело запроса, пишем в объект. Оба
нужно закрыть, а у приёмника `Close` — это ещё и последний сброс буфера:
если он упал, файл не записан, хотя `io.Copy` вернул `nil`. Реализуйте
`CopyAndClose`.

Что проверяют скрытые тесты:

- успешное копирование — `nil`, все байты на месте, закрыто сначала `dst`,
  потом `src`;
- копирование прошло, а `dst.Close` вернул ошибку — она в результате,
  а `n` всё равно равен числу скопированных байт;
- упало всё сразу (запись и оба `Close`) — в ошибке все три, каждая со
  своей подписью, и оба конца закрыты;
- паника в `Write` — оба конца закрыты, паника летит дальше.

<Reveal>

```go
func CopyAndClose(dst io.WriteCloser, src io.ReadCloser) (n int64, err error) {
	defer func() {
		if cerr := src.Close(); cerr != nil {
			err = errors.Join(err, fmt.Errorf("close src: %w", cerr))
		}
	}()
	defer func() {
		if cerr := dst.Close(); cerr != nil {
			err = errors.Join(err, fmt.Errorf("close dst: %w", cerr))
		}
	}()

	n, err = io.Copy(dst, src)
	if err != nil {
		err = fmt.Errorf("copy: %w", err)
	}
	return n, err
}
```

**`defer dst.Close()` без проверки — главная ловушка.** Для чтения
игнорировать ошибку `Close` обычно можно. Для записи — нельзя: буфер
`bufio.Writer`, gzip-футер, `os.File` на NFS сообщают о провале именно на
`Close`. Проглотили — и отдали клиенту «200 OK» за файл, которого нет.

**Именованные результаты — единственный способ.** Отложенная функция
выполняется уже после `return n, err`, когда значения записаны в
результаты. Менять их она может только по имени. `n` при этом не
трогаем — скопированное остаётся скопированным.

**`errors.Join`, а не «первая ошибка побеждает».** Классический вариант
`if err == nil { err = cerr }` теряет ошибку закрытия, если копирование
тоже упало. `Join` сохраняет обе, а если ошибок нет — остаётся `nil`.

**Порядок — через порядок `defer`.** Отложенные вызовы выполняются
в обратном порядке, поэтому `src` откладывают первым. `recover` не нужен:
паника пройдёт сквозь оба `defer`, закрыв оба конца.

**Что спросят следом.** Как быть, если `Close` сам паникует, и почему при
ошибке записи в объектное хранилище нужен не `Close`, а `Abort` — иначе
закроется частично записанный объект.
