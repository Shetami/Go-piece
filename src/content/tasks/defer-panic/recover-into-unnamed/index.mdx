`safeDiv` превращает панику деления на ноль в ошибку. Программа печатает:

```
5 <nil>
0 <nil>
```

Паника поймана, а ошибка до вызывающего не дошла. Почините. Ожидаемый вывод:

```
5 <nil>
0 деление: runtime error: integer divide by zero
```

<Reveal>

**Отложенная функция пишет в локальную переменную, а не в результат.**
`err` объявлена через `var` внутри функции. Результаты функции — безымянные
ячейки, до которых из `defer` не дотянуться.

Что происходит при `b == 0`: вычисление `a / b` паникует *до* того, как
`return` что-то записал. Раскрутка вызывает `defer`, `recover` останавливает
панику, ошибка ложится в локальный `err`. Функция завершается нормально — и
возвращает то, что лежит в ячейках результата: нулевые значения, `0` и `nil`.

**Как чинят** — назвать результаты:

```go
func safeDiv(a, b int) (res int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("деление: %v", r)
		}
	}()
	return a / b, nil
}
```

Теперь `err` в `defer` — это сам результат функции.

**Практический совет.** Деление на ноль лучше проверить заранее:
`if b == 0 { return 0, ErrDivByZero }`. `recover` — для непредвиденного,
а не способ обработки ожидаемых ошибок.

</Reveal>
