Кэш перед медленным источником — одна из самых частых live-coding задач.
Наивная версия «мьютекс вокруг карты» на ней и ломается. Реализуйте
`Cache[K, V]` по контракту из заготовки. Часы подменяются через `now`,
поэтому TTL проверяется без реального ожидания.

Что проверяют скрытые тесты:

- попадание в кэш до истечения `ttl` и перезагрузка ровно на границе;
- ошибка загрузки не запоминается;
- тридцать одновременных `Get` горячего ключа — один вызов `load`;
- пока грузится медленный ключ, другой ключ отдаётся без ожидания;
- ждущий уходит по своему `ctx`, а загрузка, которую он начал, всё равно
  доезжает до кэша: следующий `Get` не вызывает `load` повторно.

<Reveal>

```go
type entry[V any] struct {
	ready   chan struct{}
	val     V
	err     error
	expires time.Time
}

func (c *Cache[K, V]) Get(ctx context.Context, key K) (V, error) {
	c.mu.Lock()
	e, ok := c.entries[key]
	if ok {
		select {
		case <-e.ready:
			if e.err == nil && c.now().Before(e.expires) {
				c.mu.Unlock()
				return e.val, nil
			}
			ok = false
		default:
		}
	}
	if !ok {
		e = &entry[V]{ready: make(chan struct{})}
		c.entries[key] = e
		go c.fill(key, e)
	}
	c.mu.Unlock()

	select {
	case <-e.ready:
		return e.val, e.err
	case <-ctx.Done():
		var zero V
		return zero, ctx.Err()
	}
}

func (c *Cache[K, V]) fill(key K, e *entry[V]) {
	v, err := c.load(key)
	c.mu.Lock()
	e.val, e.err = v, err
	e.expires = c.now().Add(c.ttl)
	if err != nil && c.entries[key] == e {
		delete(c.entries, key)
	}
	c.mu.Unlock()
	close(e.ready)
}
```

**Запись в карте — это «обещание», а не значение.** Кладём в карту
`entry` с каналом `ready` до загрузки, под мьютексом. Все, кто придёт за
ключом, найдут обещание и будут ждать канал. Так `load` вызывается один раз
на всю толпу — защита от cache stampede. А мьютекс держится микросекунды:
`load` идёт без него, и другие ключи не ждут.

**Загрузка — в отдельной горутине.** Если грузить в горутине первого
вызывающего, его отмена оборвёт загрузку для всех, кто присоединился. В
отдельной горутине каждый ждущий уходит по своему `ctx` через `select`, а
результат всё равно попадает в кэш. Цена: `load` не получает контекст —
чей передавать, если ждущих много? Обычно это отдельный контекст с
таймаутом.

**Ошибки удаляются, но аккуратно.** `c.entries[key] == e` — проверка, что
запись не заменил кто-то другой, иначе можно стереть чужую свежую
загрузку. Ждущие текущей загрузки всё равно получат ошибку: они держат
указатель на `e`.

**TTL сравнивается через подменяемые часы.** `now().Before(expires)`
проверяется только у готовой записи (канал закрыт). Читать поля записи,
пока она не готова, — гонка данных.

**Что спросят дальше.** Stale-while-revalidate: отдавать протухшее
значение и обновлять его в фоне. Вытеснение (LRU) и ограничение размера.
Negative caching: кэшировать «не найдено» на короткое время, чтобы
несуществующий ключ не пробивал базу. И почему это нельзя собрать из
`sync.Map`: нет атомарного «найти или завести обещание» вместе с проверкой
TTL.
