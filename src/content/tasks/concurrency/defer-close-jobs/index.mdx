Классический пул: воркеры читают `jobs` через `range`, `main` отправляет
десять задач и ждёт воркеров. Закрыть канал не забыли — через `defer`.
Программа падает:

```
fatal error: all goroutines are asleep - deadlock!
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 10: `defer close(jobs)`.

**`defer` выполнится при выходе из `main`, а `main` из `wg.Wait()` не
выйдет.** Воркеры сидят в `range jobs` и ждут либо новую задачу, либо
закрытия. `main` ждёт воркеров. Закрытие отложено до момента, который
никогда не наступит. Круг замкнулся, рантайм видит, что спят все, и падает.

**Как правильно** — закрывать канал сразу после последней отправки, до
`wg.Wait()`:

```go
for i := 1; i <= 10; i++ {
	jobs <- i
}
close(jobs)
wg.Wait()
```

**Правило.** `defer close(ch)` хорош в горутине-производителе, которая
только пишет и выходит, — там выход из функции и есть «больше писать
нечего». В функции, которая после отправки ещё чего-то ждёт, `defer`
закрывает слишком поздно.

</Reveal>
