Упражнение «Web Crawler» из Go Tour, доведённое до продакшен-требований.
`Crawl` получает стартовую страницу и `Fetcher` (в тестах — карта в памяти)
и обходит всё, до чего дотягивается. Контракт — в заготовке.

Что проверяют скрытые тесты:

- циклы в графе и страница, на которую ведёт много ссылок: каждая
  загружается ровно один раз; битые ссылки не прерывают обход;
- глубина считается по кратчайшему пути: если до страницы можно дойти и
  коротко, и длинно, её ссылки не должны потеряться из-за того, что первым
  нашёлся длинный путь;
- не больше `workers` одновременных загрузок, и параллельность реально
  есть;
- `fetch` зависает до отмены: после `cancel()` `Crawl` быстро возвращает
  `context.Canceled`, не начинает новых загрузок и не оставляет горутин.

```go
func Crawl(ctx context.Context, start string, maxDepth, workers int, fetch Fetcher) ([]string, error) {
	seen := map[string]bool{start: true}
	frontier := []string{start}
	var visited []string
	sem := make(chan struct{}, workers)

	for depth := 0; depth <= maxDepth && len(frontier) > 0; depth++ {
		var (
			mu   sync.Mutex
			wg   sync.WaitGroup
			next []string
		)
	dispatch:
		for _, u := range frontier {
			select {
			case sem <- struct{}{}:
			case <-ctx.Done():
				break dispatch
			}
			if ctx.Err() != nil {
				<-sem
				break
			}
			wg.Add(1)
			go func() {
				defer wg.Done()
				defer func() { <-sem }()
				links, err := fetch(ctx, u)
				if err != nil {
					return
				}
				mu.Lock()
				defer mu.Unlock()
				visited = append(visited, u)
				if depth == maxDepth {
					return
				}
				for _, l := range links {
					if !seen[l] {
						seen[l] = true
						next = append(next, l)
					}
				}
			}()
		}
		wg.Wait()
		if err := ctx.Err(); err != nil {
			slices.Sort(visited)
			return visited, err
		}
		frontier = next
	}
	slices.Sort(visited)
	return visited, nil
}
```

**Обход в ширину по уровням решает сразу две проблемы.** Первая — глубина.
Рекурсивный обход в глубину может сначала дойти до страницы длинным путём,
пометить её как посещённую — и когда короткий путь дойдёт до неё позже,
она уже «занята», а её ссылки отрезаны лимитом глубины. На уровнях страница
всегда впервые встречается на минимальной глубине. Вторая — завершение:
понятно, когда обход кончился (следующий уровень пуст). В рекурсивной
версии с горутинами это самое трудное место: нужен общий `WaitGroup`, и
`Add` должен успеть до `Wait`.

**`seen` помечаем в момент обнаружения, а не загрузки.** Если помечать
страницу, только когда её начали качать, две горутины успеют увидеть одну
ссылку непомеченной и загрузят её дважды. Проверка и пометка — одна
операция под одним мьютексом.

**Семафор ограничивает загрузки, а не горутины уровня.** Горутина
запускается только после того, как взяла слот, поэтому на уровне в миллион
ссылок живых горутин всё равно не больше `workers`.

**Отмена: `select` плюс повторная проверка.** Когда свободен слот и
отменён контекст, `select` выбирает ветку случайно — без второй проверки
`ctx.Err()` загрузки продолжали бы стартовать после отмены. А `wg.Wait()`
перед возвратом гарантирует, что ни одна горутина не переживёт `Crawl`.

**Цена и что спросят дальше.** Барьер между уровнями: один медленный
ответ держит весь следующий уровень. Альтернатива — пул воркеров с общей
очередью и счётчиком незавершённых задач, где глубина едет вместе с URL, а
`seen` хранит минимальную глубину. Ещё вопросы: нормализация URL перед
дедупликацией, ограничение по хостам (вежливость к сайту) и повторы с
backoff.
