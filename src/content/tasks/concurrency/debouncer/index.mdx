Файловый вотчер присылает десять событий на одно сохранение файла.
Пересобирать конфиг десять раз незачем — достаточно одного раза, когда
события затихли. Реализуйте `Debouncer[T]` по контракту из заготовки.

Что проверяют скрытые тесты:

- серия событий с паузами меньше `wait` даёт ровно один вызов с последним
  значением, и не раньше, чем через `wait` после последнего события;
- новая серия после паузы даёт новый вызов;
- `Flush` вызывает `fn` сразу и отменяет отложенный вызов; `Flush` без
  отложенного значения ничего не делает;
- после `Stop` ничего не вызывается;
- восемь горутин шлют события, а `fn` медленная: вызовы не перекрываются,
  значения приходят по возрастанию, последнее значение не теряется.

<Reveal>

```go
func (d *Debouncer[T]) Trigger(v T) {
	d.mu.Lock()
	defer d.mu.Unlock()
	if d.stopped {
		return
	}
	d.val, d.pending = v, true
	if d.timer == nil {
		d.timer = time.AfterFunc(d.wait, d.fire)
	} else {
		d.timer.Reset(d.wait)
	}
}

func (d *Debouncer[T]) fire() {
	d.callMu.Lock()
	defer d.callMu.Unlock()
	d.mu.Lock()
	if !d.pending || d.stopped {
		d.mu.Unlock()
		return
	}
	v := d.val
	d.pending = false
	d.mu.Unlock()
	d.fn(v)
}

func (d *Debouncer[T]) Flush() {
	d.mu.Lock()
	if d.timer != nil {
		d.timer.Stop()
	}
	d.mu.Unlock()
	d.fire()
}

func (d *Debouncer[T]) Stop() {
	d.mu.Lock()
	d.stopped = true
	d.pending = false
	if d.timer != nil {
		d.timer.Stop()
	}
	d.mu.Unlock()
	d.callMu.Lock()
	d.callMu.Unlock()
}
```

**`AfterFunc` + `Reset` — и никакой своей горутины.** Каждый `Trigger`
отодвигает срабатывание на `wait`. `AfterFunc` запускает `fire` в новой
горутине, когда таймер истёк. `Reset` на уже сработавшем таймере просто
планирует его снова — поэтому решение о вызове принимает не таймер, а флаг
`pending`: сработавший «лишний раз» `fire` увидит, что делать нечего.

**Два мьютекса с разными ролями.** `mu` защищает состояние и держится
микросекунды. `callMu` сериализует вызовы `fn`. Держать `mu` во время `fn`
нельзя: медленная `fn` заблокировала бы `Trigger`, а `fn`, которая сама
вызывает `Trigger`, получила бы дедлок.

**Порядок захвата решает порядок значений.** Если сначала прочитать
значение под `mu`, а потом ждать `callMu`, два `fire` могут прочитать `5` и
`7`, а в `fn` войти в обратном порядке — и последним применится устаревшее
значение. Поэтому `callMu` берётся первым: кто вошёл в `fn`, тот и забрал
самое свежее значение на этот момент.

**`Stop` дожидается выполняющегося `fn`** через пустой захват `callMu`.
После `Stop` владелец может спокойно освобождать ресурсы, которые
использует `fn`.

**Что спросят дальше.** Чем debounce отличается от throttle (не чаще раза в
T, но во время серии тоже). Опция `maxWait`: при непрерывном потоке событий
debounce не сработает никогда, и нужен предел, как в lodash. И как
тестировать это без реального времени — подменяемые часы вместо
`time.AfterFunc`.
