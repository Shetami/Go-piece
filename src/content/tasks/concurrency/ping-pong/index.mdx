`main` шлёт слово в `ping`, горутина печатает «получил», отвечает в `pong`,
`main` печатает «ответ». Так два раза. Потом `ping` закрывают и ещё раз
читают из `pong`.

Напишите весь вывод программы.

<Reveal>

**Небуферизованный канал упорядочивает события.** Печатают две горутины, и
обычно это значит «порядок не гарантирован». Но здесь каждая печать зажата
между операциями с каналами:

1. `main` отправляет `"a"` в `ping` и не может ничего напечатать, пока не
   получит ответ из `pong`.
2. Горутина печатает `получил a` **до** того, как отправит в `pong`.
3. Значит, `ответ a!` в `main` случается строго после `получил a`.

Со вторым словом — то же самое. Отношение happens-before выстраивает все
четыре строки в одну цепочку.

**Закрытие по цепочке.** `close(ping)` завершает `range` в горутине, она
закрывает `pong`. Чтение из закрытого пустого канала сразу возвращает нулевое
значение и `ok == false`.

Итого:

```
получил a
ответ a!
получил b
ответ b!
false
```

**Проверьте себя.** Если сделать `pong` буферизованным на одно значение,
порядок останется тем же: `main` всё равно ждёт ответа. А вот если
горутина будет печатать `получил` *после* отправки в `pong`, строки
`получил b` и `ответ a!` могут поменяться местами.

</Reveal>
