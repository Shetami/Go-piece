Типичная история: клиент к внешнему сервису создаётся лениво через
`sync.Once`. В момент первого запроса сервис лежал — `Once` запомнил ошибку,
и до рестарта все запросы получают её. Нужен `Lazy[T]` с другим поведением —
контракт в заготовке.

Что проверяют скрытые тесты:

- ошибка не запоминается, а успешное значение — запоминается навсегда;
- полсотни одновременных `Get` вызывают `init` ровно один раз;
- даже если `init` всё время падает, два его вызова никогда не работают
  одновременно;
- паника в `init` доходит до вызывающего и не ломает `Lazy`: следующий
  `Get` не зависает.

<Reveal>

```go
type Lazy[T any] struct {
	init func() (T, error)
	mu   sync.Mutex
	done atomic.Bool
	val  T
}

func (l *Lazy[T]) Get() (T, error) {
	if l.done.Load() {
		return l.val, nil
	}
	l.mu.Lock()
	defer l.mu.Unlock()
	if l.done.Load() {
		return l.val, nil
	}
	v, err := l.init()
	if err != nil {
		var zero T
		return zero, err
	}
	l.val = v
	l.done.Store(true)
	return v, nil
}
```

**Это double-checked locking, и в Go он корректен только с атомиком.**
Быстрый путь читает `done` без мьютекса. Если бы `done` был обычным `bool`,
это гонка данных: другая горутина могла бы увидеть `done == true`, но ещё
старое `val`. `atomic.Bool` даёт happens-before: всё, что записано до
`Store(true)`, видно после `Load() == true`. Ровно так устроен и сам
`sync.Once`.

**Вторая проверка под мьютексом обязательна.** Пятьдесят горутин одновременно
увидят `done == false` и встанут в очередь на мьютекс. Без повторной
проверки каждая из них вызовет `init` заново.

**`defer Unlock`, а не `Unlock` в конце.** Если `init` паникует, код после
него не выполнится, мьютекс останется занятым, и все следующие `Get` зависнут
навсегда. `defer` отработает и при панике.

**Почему не `sync.OnceValues`.** Он запоминает первый результат, включая
ошибку, — ровно то поведение, от которого мы уходим. А «пересоздать
`sync.Once` после ошибки» — гонка: чужая горутина может как раз сидеть внутри
старого `Once.Do`.

**Что спросят дальше.** Ожидающие после неудачи идут в `init` по одному —
при лежащем сервисе это цепочка медленных попыток. Улучшения: отдавать всем
ждущим ошибку текущей попытки (как `singleflight`) и не повторять чаще, чем раз
в N секунд (backoff). И нужен ли `ctx` в `Get`, чтобы не ждать бесконечно.
