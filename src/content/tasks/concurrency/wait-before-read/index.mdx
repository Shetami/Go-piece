title: Wait перед чтением
description: Горутины пишут результаты в канал, main ждёт их через WaitGroup, закрывает канал и читает. Программа зависает. Почините.
kind: fix
topic: concurrency
level: easy

Программа падает:

```
fatal error: all goroutines are asleep - deadlock!
```

Почините. Ожидаемый вывод:

```
сумма: 60
```

<Reveal>

**Все ждут друг друга.** Канал `results` небуферизованный: отправка
завершается, только когда кто-то читает. Горутины встают на
`results <- i * 10` и ждут читателя. `main` стоит на `wg.Wait()` и ждёт,
пока горутины закончат. А читать `main` начнёт только после `Wait`.
Круг замкнулся.

**Как чинят** — читать и ждать одновременно. Ожидание с закрытием уезжает
в отдельную горутину:

```go
go func() {
	wg.Wait()
	close(results)
}()
for r := range results { ... }
```

`main` сразу читает, горутины отдают результаты и завершаются, `Wait`
возвращается, канал закрывается, `range` заканчивается.

**Почему не буфер.** `make(chan int, 3)` тоже починит, но только пока
горутин не больше трёх. Шаблон «закрыть после `Wait` в своей горутине»
работает при любом их числе — это стандартная сборка результатов в
fan-in.

</Reveal>
