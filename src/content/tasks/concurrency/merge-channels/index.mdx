Напишите тело `Merge`. Она принимает произвольное число каналов и возвращает
один, в котором оказываются все их значения.

Что проверяют скрытые тесты:

- **ничего не теряется** — все значения со всех входов доходят до выхода;
- **выход закрывается** ровно тогда, когда закрылись все входы (в том числе
  когда входов не передали вовсе — тогда выход должен закрыться сразу);
- **значения идут потоком** — `Merge` не имеет права сначала вычитать всё в
  слайс, а потом отдавать: на небуферизованном входе это сразу дедлок.

Порядок значений не проверяется: каналы читаются одновременно, и порядок там
не определён по построению.

Кнопка «Запустить» соберёт ваш код с пустым `main` — так видно ошибки
компиляции и замечания `vet`, не тратя попытку. «Проверить» допишет тесты.

<Reveal>

Схема стандартная и стоит того, чтобы помнить её наизусть: **горутина на
каждый вход плюс отдельная горутина-закрывашка**.

```go
func Merge(chans ...<-chan int) <-chan int {
	out := make(chan int)

	var wg sync.WaitGroup
	wg.Add(len(chans))

	for _, ch := range chans {
		go func(ch <-chan int) {
			defer wg.Done()
			for v := range ch {
				out <- v
			}
		}(ch)
	}

	go func() {
		wg.Wait()
		close(out)
	}()

	return out
}
```

Три места, где здесь ошибаются.

**Закрывать `out` внутри перекладывающей горутины.** Тогда его закроет первая
же дочитавшая свой вход, а остальные упадут с `send on closed channel`.
Закрывать канал должен тот, кто точно знает, что писателей больше нет, — здесь
это отдельная горутина после `Wait`.

**Звать `wg.Wait()` прямо в `Merge`, без горутины.** Выглядит логично и
намертво вешает программу: отправители блокируются на `out <- v`, потому что
читать из `out` начнут только после возврата из `Merge`, а возврата не будет,
пока не отработает `Wait`. Классический дедлок.

**Собрать всё в слайс и отдать потом.** На буферизованных входах тесты это
даже пропустили бы, поэтому среди них есть отдельный — с небуферизованным
каналом, который отдаёт значения по одному. Кроме того, такая «реализация»
теряет весь смысл: `Merge` должна работать на бесконечных потоках.

**Что спросят дальше.** Скорее всего — про отмену: «а если читатель передумал
и перестал читать `out`?» Тогда отправители навсегда зависнут на `out <- v` —
это утечка горутин. Лечится вторым аргументом `done <-chan struct{}` или
`context.Context` и `select` на отправке:

```go
select {
case out <- v:
case <-ctx.Done():
	return
}
```

Ещё могут попросить дженерик-версию — `func Merge[T any](chans ...<-chan T) <-chan T`.
Тело не меняется ни на строчку.
