Функция `step` вызывает `runtime.Goexit` — завершение текущей горутины.
В `step` есть `defer` с `recover`, в самой горутине — ещё два `defer`, один
из которых закрывает канал, которого ждёт `main`.

Напишите весь вывод программы.

<Reveal>

**`Goexit` завершает горутину, но честно выполняет все отложенные вызовы**
— по всему стеку, от самого глубокого к внешнему. Поэтому печатаются оба
`defer` из `step`, потом `defer` горутины, и закрывается `done`.

**Это не паника.** `recover` возвращает `nil`: ловить нечего, и остановить
`Goexit` через `recover` нельзя.

**Кода после `Goexit` не будет** — ни в `step`, ни в горутине после вызова
`step`. `main` ждёт закрытия канала, получает его и печатает своё.

Итого:

```
recover: <nil>
defer step
defer горутины
main дождался
```

**Где это встречается.** Главный пользователь `Goexit` — `testing`:
`t.FailNow()` и `t.Fatal` вызывают именно его. Поэтому `t.Fatal` из
горутины, которую запустил тест, ведёт себя странно: завершается эта
горутина, а не тест. Из `main` же `Goexit` лучше не звать — когда все
остальные горутины кончатся, программа упадёт с deadlock.

</Reveal>
