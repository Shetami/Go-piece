Напишите `ForEachLimit`: вызвать `f` для каждого элемента параллельно, но
чтобы одновременно работало не больше `limit` вызовов. Функция
возвращается, когда все вызовы закончились.

Что проверяют скрытые тесты:

- все сто элементов обработаны к моменту возврата;
- одновременно работает не больше `limit` вызовов — и параллельность
  действительно есть: при `limit = 3` пик ровно 3;
- пустой вход — `f` не вызывается.

<Reveal>

```go
func ForEachLimit(items []int, limit int, f func(int)) {
	sem := make(chan struct{}, limit)
	var wg sync.WaitGroup
	for _, it := range items {
		sem <- struct{}{}
		wg.Go(func() {
			defer func() { <-sem }()
			f(it)
		})
	}
	wg.Wait()
}
```

**Буферизованный канал как семафор.** В буфере `limit` мест. Отправка
занимает место и блокируется, когда мест нет; чтение освобождает. Значения
не нужны, поэтому `struct{}`.

**Захват до `go`, а не внутри горутины.** Если занимать место внутри
горутины, их запустится сразу сто, и девяносто семь будут стоять в очереди
на семафор. Лимит на *работу* соблюдается, но горутины (и их стеки)
создаются все сразу. Захват в цикле держит и число горутин в пределах
лимита — цикл сам ждёт, пока освободится место.

**Альтернатива — пул воркеров:** `limit` горутин читают элементы из канала.
Горутин ровно `limit` за всё время, что лучше для миллионов элементов. Для
сотен — семафор проще.

**Готовое.** `errgroup.Group` с `SetLimit(n)` делает то же, плюс собирает
первую ошибку и отменяет контекст.

</Reveal>
