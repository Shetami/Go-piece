Реализуйте обобщённый конвейер `Run[T]`: значения идут из `src` через все
этапы, каждый этап — отдельная горутина. Контракт — в заготовке.

Что проверяют скрытые тесты:

- порядок результатов и крайний случай без этапов;
- этапы действительно работают одновременно: три медленных этапа на восьми
  значениях заметно быстрее последовательного прохода;
- ошибка на третьем значении из тысячи: наружу выходит именно она, хотя
  соседний этап после отмены честно возвращает `ctx.Err()`; первый этап
  почти сразу перестаёт брать новые значения;
- внешняя отмена: `Run` быстро возвращает `context.Canceled`;
- после ошибки и после отмены не остаётся ни одной горутины.

```go
func Run[T any](ctx context.Context, src []T, stages ...Stage[T]) ([]T, error) {
	ctx, cancel := context.WithCancelCause(ctx)
	defer cancel(nil)

	var wg sync.WaitGroup
	source := make(chan T)
	wg.Add(1)
	go func() {
		defer wg.Done()
		defer close(source)
		for _, v := range src {
			select {
			case source <- v:
			case <-ctx.Done():
				return
			}
		}
	}()

	var in <-chan T = source
	for _, st := range stages {
		out := make(chan T)
		wg.Add(1)
		go func(in <-chan T) {
			defer wg.Done()
			defer close(out)
			for v := range in {
				r, err := st(ctx, v)
				if err != nil {
					cancel(err)
					return
				}
				select {
				case out <- r:
				case <-ctx.Done():
					return
				}
			}
		}(in)
		in = out
	}

	res := make([]T, 0, len(src))
	for v := range in {
		res = append(res, v)
	}
	wg.Wait()
	if err := context.Cause(ctx); err != nil {
		return nil, err
	}
	return res, nil
}
```

**Каждый канал закрывает тот, кто в него пишет.** Источник закрывает
`source`, этап — свой `out`. Закрытие идёт по цепочке вниз: когда этап
выходит (данные кончились, ошибка или отмена), его `out` закрывается,
следующий этап дочитывает и выходит тоже. Последний канал читает сама
`Run` — её `range` и есть сигнал «конвейер опустел».

**Отмена нужна в каждой отправке.** Сигналы в конвейере идут в две
стороны: данные и закрытие — вниз, «хватит» — вверх. Если этап 2 упал и
перестал читать, этап 1 навсегда застрянет на `out <- r`, а источник — на
`source <- v`. Это утечка. `select` с `ctx.Done()` на каждой отправке
и `cancel(err)` при ошибке будят всех выше по течению.

**`WithCancelCause` вместо `WithCancel` и переменной с ошибкой.** После
`cancel(err)` другие этапы видят отмену и могут вернуть `ctx.Err()`, то есть
`context.Canceled`. Если сохранять «последнюю ошибку», наружу уйдёт
бесполезный `Canceled` вместо настоящей причины. `context.Cause` запоминает
первую причину, остальные вызовы `cancel` её не перезаписывают. При внешней
отмене `Cause` вернёт причину родителя — `context.Canceled`.

**`wg.Wait()` после чтения, а не вместо.** Сначала дочитываем выход, чтобы
последний этап смог завершиться, потом ждём всех. Наоборот — дедлок:
`Wait` ждёт этап, а этап ждёт, пока его прочитают.

**Что спросят дальше.** Как распараллелить один медленный этап (fan-out на
N воркеров с восстановлением порядка), зачем буферы между этапами
(сгладить неровную скорость, но не ускорить узкое место) и когда конвейер не
нужен: если этапы быстрые, передача через каналы стоит дороже самой работы.
