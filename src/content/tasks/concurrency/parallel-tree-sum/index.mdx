Каталог товаров, дерево файлов, оргструктура — в каждом узле нужно
сделать медленную операцию (посчитать размер, сходить в сервис) и сложить
результаты. Нужна параллельность, но ограниченная. Реализуйте `Sum` по
контракту из заготовки.

Что проверяют скрытые тесты:

- правильная сумма, пустое дерево, `limit = 1`;
- одновременно работает не больше `limit` вызовов `weight`, и параллельность
  реально есть;
- цепочка из пяти тысяч узлов не зависает;
- у корня пять тысяч детей — горутины не создаются по одной на
  каждый узел.

<Reveal>

```go
func Sum(root *Node, limit int, weight func(*Node) int) int {
	if root == nil {
		return 0
	}
	var total atomic.Int64
	var wg sync.WaitGroup
	sem := make(chan struct{}, limit-1)

	var walk func(n *Node)
	walk = func(n *Node) {
		total.Add(int64(weight(n)))
		for _, c := range n.Children {
			select {
			case sem <- struct{}{}:
				wg.Add(1)
				go func() {
					defer wg.Done()
					defer func() { <-sem }()
					walk(c)
				}()
			default:
				walk(c)
			}
		}
	}
	walk(root)
	wg.Wait()
	return int(total.Load())
}
```

**Почему не работает «семафор как обычно».** Привычный шаблон: взять слот
(`sem <- struct{}{}`), запустить горутину, отдать слот в конце. В рекурсии
горутина держит слот, пока обходит всё своё поддерево, а внутри хочет
взять ещё слоты для детей. На глубокой цепочке все `limit` слотов
разбирают предки, каждый ждёт слот для ребёнка, и никто не отпустит свой —
дедлок. Проявляется не сразу, а на достаточно глубоком дереве.

**Решение — «есть свободный слот — отдай, нет — делай сам».**
Неблокирующий `select` с `default`: если слот свободен, поддерево уходит в
новую горутину, иначе текущая горутина обходит его сама. Ожидания нет
вообще, значит, и дедлока нет. Параллельность при этом не теряется: как
только кто-то освобождает слот, следующий найденный ребёнок уходит в новую
горутину.

**Работающих горутин — не больше `limit`.** Новая горутина запускается,
только когда взяла слот (завершающиеся могут ненадолго пережить свой слот). Наивное «горутина на каждого ребёнка + семафор внутри неё»
ограничивает одновременную работу, но не число горутин: на пять тысяч
детей — пять тысяч спящих горутин с их стеками.

**Сумма — через атомик, `wg.Add` — до `go`.** Все горутины добавляют в
один счётчик, `atomic.Int64` дешевле мьютекса. `Wait` в корне ждёт все
горутины, потому что каждый `Add` происходит внутри уже учтённой горутины
(или в самой `Sum`) раньше, чем её `Done`.

**Что спросят дальше.** Пул воркеров с общей очередью узлов (и как тогда
понять, что обход закончен — счётчик незавершённых узлов). Work stealing,
как в планировщике Go: у каждого воркера своя очередь, а свободные воруют
у занятых. И как вернуть не сумму, а ошибку первого упавшего узла с
отменой остальных.
