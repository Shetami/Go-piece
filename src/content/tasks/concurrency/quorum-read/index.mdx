Так читают Cassandra и Dynamo-подобные хранилища: запрос уходит на все
реплики, ответ готов, когда ответили `k` из `N`, а из ответов берётся
самая свежая версия. Если `R + W > N`, среди `R` прочитанных точно есть
последняя запись. Реализуйте `QuorumRead` по контракту из заготовки.

Что проверяют скрытые тесты:

- кворум 2 из 3 собран — ответ возвращается, не дожидаясь зависшей
  реплики, и это самая свежая версия, а не первая пришедшая; зависшая
  получает отмену;
- две из трёх упали — ошибка возвращается сразу, не дожидаясь третьей, в
  ней есть и `ErrNoQuorum`, и обе причины;
- одна упавшая из трёх кворуму 2 не мешает;
- `k` больше числа реплик — ошибка без единого запроса;
- таймаут внешнего контекста: возврат по дедлайну, и реплики, которые
  ответят позже, не оставят висящих горутин.

```go
func QuorumRead(ctx context.Context, replicas []Replica, k int) (Reply, error) {
	if k > len(replicas) {
		return Reply{}, ErrNoQuorum
	}
	ctx, cancel := context.WithCancel(ctx)
	defer cancel()

	type result struct {
		r   Reply
		err error
	}
	results := make(chan result, len(replicas))
	for _, rep := range replicas {
		go func() {
			r, err := rep(ctx)
			results <- result{r, err}
		}()
	}

	var best Reply
	oks := 0
	var errs []error
	allowedFailures := len(replicas) - k
	for oks < k {
		select {
		case res := <-results:
			if res.err != nil {
				errs = append(errs, res.err)
				if len(errs) > allowedFailures {
					return Reply{}, fmt.Errorf("%w: %w", ErrNoQuorum, errors.Join(errs...))
				}
				continue
			}
			if oks == 0 || res.r.Version > best.Version {
				best = res.r
			}
			oks++
		case <-ctx.Done():
			return Reply{}, ctx.Err()
		}
	}
	return best, nil
}
```

**Ранний выход в обе стороны.** Наивная версия ждёт все `N` ответов и
потом считает — и медленная реплика определяет задержку всего запроса,
хотя смысл кворума как раз в том, чтобы её не ждать. Успех — как только
набралось `k`. Провал — как только упавших стало больше `N − k`: даже если
остальные ответят, кворума не будет.

**Самая свежая, а не самая быстрая.** Первый ответ легко может прийти от
отстающей реплики со старой версией. Среди `k` ответов выбирается
максимальная `Version`. В настоящих системах после этого ещё идёт
read repair: отстающим репликам в фоне дописывают свежее значение.

**Буфер на все ответы + отмена = нет утечек.** Возвращаемся рано, и
результаты оставшихся реплик никто не прочитает. Канал с буфером `N`
позволяет им отправить и завершиться. `defer cancel()` просит их не
тратить время, но от утечки защищает именно буфер: реплика может контекст
и не слушать.

**Две обёртки в одной ошибке.** `fmt.Errorf("%w: %w", …)` (Go 1.20+)
оборачивает и `ErrNoQuorum`, и `errors.Join` причин. Вызывающий может
проверить и «это отказ кворума», и «среди причин есть таймаут».

**Что спросят дальше.** Что делать, если версии равны, а значения разные
(конфликт — векторные часы или last-write-wins по времени). Почему `R + W
> N` даёт чтение последней записи, а `R + W ≤ N` — только eventual
consistency. И как сюда добавить страховочные запросы: опрашивать сначала
ровно `k` реплик, а остальные — только если кто-то тормозит.
