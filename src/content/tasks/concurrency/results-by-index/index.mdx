title: Каждая горутина пишет в свою ячейку
description: Горутины параллельно считают длины слов и записывают их в общий слайс по индексу. Есть ли здесь гонка и что напечатается?
kind: output

Для каждого слова запускается горутина, которая пишет длину слова в
`lens[i]`. Мьютекса нет. `main` ждёт всех через `WaitGroup` и печатает
результат.

Напишите весь вывод программы.

<Reveal>

**Гонки нет.** Гонка — это два доступа к *одной* ячейке памяти, хотя бы один
из которых — запись, без синхронизации. Здесь каждая горутина пишет в свой
элемент слайса, ячейки разные. Сам заголовок слайса только читается.
`go run -race` промолчит.

**Порядок завершения не важен.** Горутины могут закончить в любом порядке,
но каждая кладёт результат на своё место. После `wg.Wait()` все записи
видны `main`: `Done` и `Wait` дают нужное happens-before.

**`len` считает байты.** «го» — две кириллические буквы, по два байта:
длина 4.

**Переменные цикла.** С Go 1.22 у каждой итерации свои `i` и `w`, поэтому
замыкание можно писать без `i, w := i, w`. На старом Go все горутины видели
бы общие переменные и, скорее всего, писали бы в последнюю ячейку.

Итого:

```
[4 4 1]
```

**Приём стоит запомнить.** «Заранее выделить слайс под результаты и писать по
индексу» — самый простой способ собрать результаты параллельной работы
в исходном порядке. Никаких каналов, мьютексов и сортировок.

</Reveal>
