Буферизованный канал на два места ограничивает параллельность. Каждая
третья задача завершается с ошибкой. Программа падает:

```
fatal error: all goroutines are asleep - deadlock!
```

Почините. Ожидаемый вывод:

```
успешно: 14 с ошибкой: 6
```

<Reveal>

**Ранний `return` не освобождает слот.** Задача занимает место в
семафоре (`sem <- struct{}{}`) и освобождает его (`<-sem`) только в конце
успешной ветки. Задача с ошибкой выходит раньше и уносит слот с собой.
Две такие задачи — и семафор занят навсегда. Все остальные горутины стоят
на `sem <- struct{}{}`, `wg.Wait()` не дождётся — дедлок.

**Как чинят** — освобождать через `defer` сразу после захвата:

```go
sem <- struct{}{}
defer func() { <-sem }()
```

Это тот же шаблон, что `mu.Lock(); defer mu.Unlock()`: захватили — тут же
отложили освобождение. Сколько бы выходов ни было у функции, включая
панику, слот вернётся.

**Готовые варианты.** `golang.org/x/sync/semaphore` — взвешенный семафор с
поддержкой контекста. А `errgroup.Group` с `SetLimit(n)` решает всю задачу
целиком: ограничение параллельности, ожидание и первая ошибка.

</Reveal>
