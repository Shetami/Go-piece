Три горутины ждут `<-start`. `main` ничего в `start` не отправляет, а только
закрывает его и ждёт всех. Потом ещё раз читает из `start`.

Напишите весь вывод программы.

<Reveal>

**Отправка будит одного получателя, закрытие — всех.** Если бы `main` сделал
`start <- struct{}{}`, проснулась бы одна горутина, а две остальные ждали бы
вечно — и `wg.Wait()` повис бы с дедлоком. `close` работает иначе: все, кто
ждёт чтения, получают нулевое значение сразу, и все будущие чтения тоже.

Поэтому все три горутины проходят дальше и добавляют свой номер. Порядок
случайный, но слайс отсортирован.

**Чтение из закрытого канала не блокирует.** `<-start` возвращает нулевое
значение `struct{}{}` — оно печатается как `{}` — и `ok == false`.

Итого:

```
[0 1 2] 3
{} false
```

**Это стандартный приём.** Так устроен `ctx.Done()`: отмена контекста —
это `close` канала, и её видят все горутины, которые его слушают, сколько бы
их ни было. Канал `chan struct{}` для сигнала — идиома: значение не несёт
данных и не занимает памяти.

Важно только, чтобы закрывал ровно один: второй `close` — паника.

</Reveal>
