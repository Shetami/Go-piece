Кэш протух, и сотня запросов одновременно идёт за одним ключом в базу —
классический cache stampede. `singleflight` из `golang.org/x/sync` склеивает
их в один вызов. Напишите свою `Group[K, V]` по контракту из заготовки.

Что проверяют скрытые тесты:

- десять одновременных `Do` с одним ключом — один вызов `fn`, у всех один
  результат и `shared = true`;
- результат не кэшируется: последовательные вызовы каждый раз запускают
  `fn`, `shared = false`;
- ошибка тоже общая для всех участников;
- пока идёт медленный вызов по одному ключу, вызовы по другому ключу не ждут;
- `fn` паникует: паника доходит до той горутины, которая запускала `fn`,
  ждущий получает `ErrPanicked` и не висит, а ключ снова свободен.

<Reveal>

```go
type Group[K comparable, V any] struct {
	mu    sync.Mutex
	calls map[K]*call[V]
}

type call[V any] struct {
	done   chan struct{}
	val    V
	err    error
	shared bool
}

func (g *Group[K, V]) Do(key K, fn func() (V, error)) (v V, err error, shared bool) {
	g.mu.Lock()
	if g.calls == nil {
		g.calls = make(map[K]*call[V])
	}
	if c, ok := g.calls[key]; ok {
		c.shared = true
		g.mu.Unlock()
		<-c.done
		return c.val, c.err, true
	}
	c := &call[V]{done: make(chan struct{})}
	c.err = ErrPanicked
	g.calls[key] = c
	g.mu.Unlock()

	defer func() {
		g.mu.Lock()
		delete(g.calls, key)
		shared = c.shared
		g.mu.Unlock()
		close(c.done)
	}()
	c.val, c.err = fn()
	return c.val, c.err, false
}
```

**Мьютекс — только на карту, `fn` работает без него.** Держать общий
мьютекс на время `fn` — значит склеить не одинаковые запросы, а вообще все:
медленный ключ `a` остановит ключ `b`. Под мьютексом только «найти или
завести запись». Ждут на канале `done` конкретного вызова.

**Закрытие канала — широковещательный сигнал.** Сколько бы горутин ни
ждали `<-c.done`, один `close` будит всех. Запись `val`/`err` до `close`
видна всем после `<-done`: это happens-before, мьютекс для чтения результата
не нужен.

**Удаление ключа и `close` — в `defer`.** Если `fn` запаникует, обычный код
после неё не выполнится: ключ навсегда останется в карте, а ждущие навсегда
зависнут на `done`. Поэтому `c.err` заранее выставлен в `ErrPanicked`, а
очистка стоит в `defer` — она выполнится и при панике, и паника пойдёт дальше
к своему владельцу. Настоящий `singleflight` делает похоже, но паникует и в
ждущих горутинах.

**Порядок в `defer` важен:** сначала `delete`, потом `close`. Наоборот —
проснувшийся ждущий может сразу вызвать `Do` снова и присоединиться к уже
завершённому вызову.

**Что спросят дальше.** `DoChan` — чтобы ждущий мог уйти по `ctx.Done()`.
`Forget(key)`. И главное: `singleflight` склеивает только одновременные
вызовы — это не кэш. Кэш с загрузкой строят поверх него, и там уже
появляются TTL и вопрос, чей контекст передавать в загрузку.
