Напишите `FirstOf`. Так делают «хеджированные» запросы: спрашивают
несколько реплик и берут того, кто ответил первым.

Что проверяют скрытые тесты:

- быстрый успешный ответ возвращается, а медленная функция получает отмену
  своего контекста;
- неудачи пропускаются, пока кто-то ещё может ответить успешно;
- если упали все — ошибка, из которой `errors.Is` достаёт каждую.

<Reveal>

```go
func FirstOf(ctx context.Context, fns ...func(context.Context) (string, error)) (string, error) {
	ctx, cancel := context.WithCancel(ctx)
	defer cancel()

	type result struct {
		val string
		err error
	}
	results := make(chan result, len(fns))
	for _, fn := range fns {
		go func() {
			v, err := fn(ctx)
			results <- result{v, err}
		}()
	}

	var errs []error
	for range fns {
		r := <-results
		if r.err == nil {
			return r.val, nil
		}
		errs = append(errs, r.err)
	}
	return "", errors.Join(errs...)
}
```

**Отмена через `defer cancel()`.** Когда функция возвращает первый успех,
`cancel` закрывает `Done()` у общего дочернего контекста, и все
оставшиеся функции (если они уважают контекст) бросают работу. Родительский
`ctx` при этом не трогается.

**Буфер размером `len(fns)` — защита от утечки.** Проигравшие горутины
всё равно попытаются отправить результат. Без буфера они застрянут на
отправке навсегда: читать больше некому. С буфером — положат результат и
завершатся.

**Структура для результата.** Два значения в канале передают одной
структурой. Отдельные каналы для ошибок и значений только усложняют
`select`.

**Что спросят следом.** Как не перегружать реплики: отправлять второй
запрос не сразу, а если первый не ответил за p95 задержки — это и есть
hedged request в статье «The Tail at Scale».
