Сервисы, пакеты, миграции, шаги пайплайна — у каждого свой список «что
должно быть готово до меня». Напишите `BuildOrder`: порядок, в котором всё
можно собрать, или ошибку, если зависимости зациклены. Типы ошибок уже
объявлены в заготовке, правила — в doc-комментарии.

Что проверяют скрытые тесты:

- обычный граф: порядок один и тот же на каждом запуске, хотя входные
  данные — мапа;
- вершина, которая есть только в чьём-то списке зависимостей, тоже
  собирается; повтор зависимости не ломает подсчёт;
- при выборе следующей вершины учитываются все готовые, а не только те, что
  были готовы в самом начале;
- цикл из трёх вершин плюс вершина, зависящая от цикла, плюс независимая
  ветка: `errors.Is(err, ErrCycle)`, а `errors.As` достаёт `*CycleError` с
  точным списком вершин;
- петля `a → a`.

```go
func BuildOrder(deps map[string][]string) ([]string, error) {
	indeg := make(map[string]int)
	users := make(map[string][]string)
	seen := make(map[[2]string]bool)
	for x, ds := range deps {
		if _, ok := indeg[x]; !ok {
			indeg[x] = 0
		}
		for _, d := range ds {
			if _, ok := indeg[d]; !ok {
				indeg[d] = 0
			}
			if seen[[2]string{x, d}] {
				continue
			}
			seen[[2]string{x, d}] = true
			indeg[x]++
			users[d] = append(users[d], x)
		}
	}

	var ready strHeap
	for x, n := range indeg {
		if n == 0 {
			ready = append(ready, x)
		}
	}
	heap.Init(&ready)

	order := make([]string, 0, len(indeg))
	for ready.Len() > 0 {
		x := heap.Pop(&ready).(string)
		order = append(order, x)
		for _, u := range users[x] {
			indeg[u]--
			if indeg[u] == 0 {
				heap.Push(&ready, u)
			}
		}
	}

	if len(order) < len(indeg) {
		var rest []string
		for x, n := range indeg {
			if n > 0 {
				rest = append(rest, x)
			}
		}
		slices.Sort(rest)
		return nil, &CycleError{Nodes: rest}
	}
	return order, nil
}
```

(`strHeap` — минимальная куча строк на `container/heap`, в эталонном
решении.)

**Алгоритм Кана на трёх мапах.** `indeg` — сколько зависимостей у вершины
ещё не собрано, `users` — обратные рёбра «кого разблокирует сборка `d`».
Собрали вершину — уменьшаем счётчики её пользователей, обнулившиеся
становятся готовыми. Это O(V + E) плюс log на кучу.

**Все вершины — ключи `indeg`.** Вершина `log`, которая встречается только
в списках, иначе не попадёт ни в стартовый набор, ни в ответ. А проверка
«собрали всё?» (`len(order) < len(indeg)`) без неё посчитает цикл там, где
его нет, или пропустит.

**Повторы рёбер — отдельной мапой.** `"z": {"b", "b"}` без дедупликации
даст `indeg[z] = 2` и два `z` в `users[b]` — это как раз сходится. Но стоит
дедуплицировать только одну сторону — и `z` либо не соберётся никогда
(ложный цикл), либо попадёт в ответ дважды. Проще убрать повторы на входе.

**Однозначный порядок — куча, а не сортировка стартового списка.** Порядок
обхода мапы случаен, поэтому готовые вершины надо выбирать по правилу.
Отсортировать только стартовый набор мало: вершина, которая освободится по
ходу, должна встать в общую очередь по алфавиту. Тест `b → a, c, d` это
ловит: после `a` готова `b`, и она идёт раньше `c`.

**Цикл — это «кто-то остался».** Если очередь опустела, а ненулевые
счётчики остались, эти вершины лежат на цикле или за ним. `Unwrap`,
возвращающий `ErrCycle`, делает ошибку проверяемой через `errors.Is`, а
`errors.As` отдаёт подробности. Спросят следом: как вернуть сам цикл, а не
всех «застрявших», — DFS с тремя цветами и восстановлением пути по стеку.
