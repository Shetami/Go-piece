Каждый текст обрабатывается в своей горутине тысячу раз, слова
складываются в общую мапу `counts`. Программа падает с

```
fatal error: concurrent map writes
```

Почините. Ожидаемый вывод:

```
fast 1000
fun 3000
go 2000
is 3000
```

<Reveal>

**Мапа в Go не потокобезопасна.** Запись может перестраивать внутреннюю
таблицу, и две одновременные записи портят её. Рантайм проверяет это
дёшево и вероятностно: при каждой записи ставит флаг «идёт запись», и если
другая горутина его видит — `fatal error`. Это не паника, `recover` её не
поймает: программа завершается целиком.

**Как чинят.** Самое прямое — мьютекс вокруг `counts[w]++`. Работает, но
все горутины 9000 раз толкаются за один мьютекс, и параллельность
пропадает.

В решении — приём лучше: каждая горутина считает в свою локальную мапу, а
в общую сливает один раз в конце. Синхронизации почти нет, и никакой
гонки: локальную мапу видит только её горутина.

**Про `sync.Map`.** Она здесь не подходит: `counts[w]++` — это «прочитать и
записать», а `sync.Map` даёт атомарными только отдельные операции. Пришлось
бы класть в неё `*atomic.Int64` и следить за созданием через `LoadOrStore`.
`sync.Map` хороша для кэшей, куда пишут редко, а читают много.

</Reveal>
