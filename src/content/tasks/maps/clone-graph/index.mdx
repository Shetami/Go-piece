Граф зависимостей, дерево меню со ссылками «см. также», документ с
перекрёстными ссылками — перед правкой их копируют, чтобы не испортить
оригинал. Напишите `Clone` (вариант LeetCode 133, но граф ориентированный,
имена не уникальны, а рёбра повторяются). Точный контракт — в заготовке.

Что проверяют скрытые тесты:

- «ромб»: две вершины ссылаются на одну — в копии тоже одна, а не две;
  повторное ребро на ту же вершину сохраняется;
- цикл и петля — обход заканчивается, а рёбра ведут обратно в копии;
- две разные вершины с одинаковым именем не склеиваются; `nil` в рёбрах;
- `Clone(nil)`; правка копии не трогает оригинал;
- цепочка из 100 000 вершин с обратными рёбрами в корень.

<Reveal>

```go
func Clone(root *Node) *Node {
	if root == nil {
		return nil
	}
	copies := map[*Node]*Node{root: {Name: root.Name}}
	stack := []*Node{root}
	for len(stack) > 0 {
		orig := stack[len(stack)-1]
		stack = stack[:len(stack)-1]
		cp := copies[orig]
		cp.Edges = make([]*Node, len(orig.Edges))
		for i, next := range orig.Edges {
			if next == nil {
				continue
			}
			c, ok := copies[next]
			if !ok {
				c = &Node{Name: next.Name}
				copies[next] = c
				stack = append(stack, next)
			}
			cp.Edges[i] = c
		}
	}
	return copies[root]
}
```

**Мапа «оригинал → копия» решает сразу три проблемы.** Цикл: вершина, к
которой вернулись, уже в мапе — второй раз её не обходим, и обход
конечен. Общие вершины: «ромб» получает одну копию `d`, а не две. Повторные
рёбра: обе ссылки находят одну и ту же копию.

**Ключ — указатель, не имя.** `map[string]*Node` по `Name` выглядит
естественно, но склеит две разные вершины `x` в одну. Идентичность вершины —
её адрес; указатели сравнимы и годятся в ключи мапы.

**Регистрация до обхода рёбер.** Копию кладём в мапу **в момент создания**,
а не после того, как обработали её соседей. Иначе в петле `a → a` при
обходе рёбер `a` мапа ещё пуста — и рекурсия создаёт новую копию `a`
бесконечно.

**Явный стек вместо рекурсии.** Рекурсивный DFS тоже корректен, и горутинный
стек в Go растёт динамически — 100 000 уровней он переживёт, хотя и займёт
десятки мегабайт. Стек-слайс дешевле и не упрётся в лимит стека в 1 ГБ на
действительно глубоких графах.

**`make([]*Node, len(orig.Edges))` — новый слайс.** Скопировать вершину
через `*cp = *orig` и поправить рёбра на месте — значит писать в тот же
массив, на который смотрит оригинал. Слайс рёбер тоже надо создавать заново.
