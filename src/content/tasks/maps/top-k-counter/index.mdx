Реализуйте `Counter[K]` — счётчик событий по ключам (эндпоинты, ошибки,
товары) с выборкой топа. Приращение бывает отрицательным: отмена заказа,
откат метрики. Поля и конструктор — на ваше усмотрение, контракт — в
заготовке.

`TopK` должен работать за O(u log k): ключей может быть миллион, а нужны
десять лучших. Держите кучу на `k` элементов, на вершине которой — худший из
отобранных.

Что проверяют скрытые тесты:

- обычный топ; повторный вызов `TopK` даёт то же самое и не портит счётчики;
- ничьи — по возрастанию ключа, и так каждый раз, а не как повезёт с обходом
  мапы;
- ключ, чей счётчик ушёл в ноль или в минус, исчезает: не попадает в топ и в
  `Len`, а после нового `Add` считается с нуля;
- пустой счётчик, `k = 0`, отрицательный `k`, `k` больше числа ключей;
- две тысячи ключей с кучей ничьих на верхнем значении.

<Reveal>

```go
func (c *Counter[K]) Add(key K, delta int) {
	n := c.counts[key] + delta
	if n <= 0 {
		delete(c.counts, key)
		return
	}
	c.counts[key] = n
}

func better[K cmp.Ordered](a, b Entry[K]) bool {
	if a.Count != b.Count {
		return a.Count > b.Count
	}
	return a.Key < b.Key
}

type worstHeap[K cmp.Ordered] []Entry[K]

func (h worstHeap[K]) Less(i, j int) bool { return better(h[j], h[i]) }
// Len, Swap, Push, Pop — стандартные

func (c *Counter[K]) TopK(k int) []Entry[K] {
	if k <= 0 {
		return nil
	}
	h := make(worstHeap[K], 0, min(k, len(c.counts)))
	for key, n := range c.counts {
		e := Entry[K]{key, n}
		if h.Len() < k {
			heap.Push(&h, e)
		} else if better(e, h[0]) {
			h[0] = e
			heap.Fix(&h, 0)
		}
	}
	res := []Entry[K](h)
	slices.SortFunc(res, func(a, b Entry[K]) int {
		if better(a, b) {
			return -1
		}
		if better(b, a) {
			return 1
		}
		return 0
	})
	return res
}
```

**Куча «наоборот».** Для топа лучших нужна куча, у которой на вершине
**худший** из отобранных: каждый новый ключ сравниваем с ним и, если новый
лучше, заменяем вершину и чиним кучу (`heap.Fix`) за O(log k). Куча с лучшим
на вершине — частая ошибка: тогда отбирать приходится все u элементов.

**Ничья — часть порядка, а не случайность.** Сравнение в куче и финальная
сортировка должны использовать **один и тот же** полный порядок: счётчик,
затем ключ. Если в куче сравнивать только счётчики, то при ничьей на границе
топа в результат попадёт ключ, который раньше встретился при обходе мапы, —
а порядок обхода случаен. Тест со счётчиками по 100 у двадцати ключей это
ловит.

**Удаление при ≤ 0.** Иначе в мапе копятся нули, `Len` врёт, а на отрицательных
значениях `TopK(100)` честно вернёт ключ со счётчиком −4. Кроме того,
удаление — это ограничение кардинальности: счётчик по пользовательскому вводу
без удаления растёт бесконечно.

**Результат — k элементов из кучи, досортированных.** Куча упорядочена
только частично; сортировка k элементов — O(k log k), что в пределах
O(u log k). Можно и вынимать через `heap.Pop` в обратном порядке.

**Что спросят дальше.** Потоковый топ по бесконечному потоку, где все
ключи не помещаются в память: Count-Min Sketch плюс куча, или алгоритм
Space-Saving. И как сделать `Counter` конкурентным — шардировать по ключу.
