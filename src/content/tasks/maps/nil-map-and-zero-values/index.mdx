`m` объявлена, но не создана. Дальше — обычная мапа и мапа указателей.

Напишите весь вывод программы.

<Reveal>

```
true 0 0
0 false
2 0
1
```

**Из нулевой мапы можно читать.** `var m map[string]int` — это `nil`, но
чтение из неё не паникует: `len` даёт `0`, любой ключ возвращает нулевое
значение типа. Так задумано, чтобы нулевая мапа была пригодна для чтения без
инициализации.

**А вот писать — нельзя.** `m["a"] = 1` в нулевую мапу роняет программу с
`assignment to entry in nil map`. Это, пожалуй, единственная реальная ловушка
нулевой мапы, и ловится она только на исполнении.

**Отсутствующий ключ не отличить от нулевого значения** — и ровно для этого
есть форма с двумя результатами:

```go
v, ok := m["нет такого"]   // 0, false
```

Без `ok` вы не отличите «ключа нет» от «по ключу лежит 0». Для
`map[string]bool` это особенно важно: `false` — совершенно законное значение.

**`counts["a"]++` работает на пустой мапе**, потому что разворачивается в
`counts["a"] = counts["a"] + 1`, а чтение даёт `0`. Мапу при этом создать
всё-таки надо: `map[string]int{}` здесь есть.

**Последняя строка — про то, почему в мапе держат указатели.** Элемент мапы
неадресуемый: `stats["x"].Hits++` со значением `Counter` (а не `*Counter`) не
скомпилируется — `cannot assign to struct field`. С указателем всё работает,
потому что меняется не элемент мапы, а то, на что он показывает.

**Что спросят следом.** Порядок обхода: он намеренно случайный, рандомизация
добавлена в рантайм специально, чтобы на него не закладывались. Нужен
стабильный порядок — собирайте ключи в слайс и сортируйте. И про
конкурентность: одновременная запись в мапу из двух горутин роняет программу с
`concurrent map writes` — рантайм проверяет это сам, без `-race`. Лечится
`sync.Mutex` или `sync.Map`.

</Reveal>
