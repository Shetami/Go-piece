Реализуйте `MultiMap[K, V]`: подписки пользователя на темы, теги статьи,
роли сотрудника. На один ключ — много значений, повтор пары не добавляется,
значения идут в порядке первого добавления. Поля и конструктор — на ваше
усмотрение; контракт каждого метода — в заготовке.

Что проверяют скрытые тесты:

- порядок значений и отказ добавить пару повторно;
- `Len` (ключи) и `Size` (пары) сходятся после любых операций;
- ключ, у которого удалили последнее значение, исчезает: `Has` — `false`,
  `Len` его не считает;
- результат `Get` можно менять и дописывать — мапа этого не замечает, в том
  числе когда во внутреннем слайсе остался запас ёмкости;
- `RemoveAll` существующего и отсутствующего ключа.

<Reveal>

```go
type MultiMap[K, V comparable] struct {
	buckets map[K]*bucket[V]
	size    int
}

type bucket[V comparable] struct {
	order []V
	set   map[V]struct{}
}

func (m *MultiMap[K, V]) Remove(k K, v V) bool {
	b := m.buckets[k]
	if b == nil {
		return false
	}
	if _, ok := b.set[v]; !ok {
		return false
	}
	delete(b.set, v)
	b.order = slices.DeleteFunc(b.order, func(x V) bool { return x == v })
	m.size--
	if len(b.set) == 0 {
		delete(m.buckets, k)
	}
	return true
}

func (m *MultiMap[K, V]) Get(k K) []V {
	b := m.buckets[k]
	if b == nil {
		return nil
	}
	return slices.Clone(b.order)
}
```

(`Add`, `RemoveAll` и счётчики — в эталонном решении.)

**Слайс для порядка, мапа для «уже есть?».** `map[K][]V` с
`slices.Contains` работает, но проверка на дубль стоит O(n) на каждый `Add`.
Мапа-множество внутри бакета даёт O(1), слайс сохраняет порядок. Цена —
удаление за O(n) из слайса; если удалений много, порядок держат двусвязным
списком, как в LRU.

**Пустой ключ — это утечка и враньё.** Если после удаления последнего
значения оставить `buckets[k]` пустым, `Has` скажет «есть», `Len` посчитает
лишний ключ, а в долгоживущем сервисе мапа будет только расти. Удалять ключ
надо явно — Go за вас этого не сделает.

**Наружу — копия.** Вернуть `b.order` как есть — значит отдать вызывающему
право писать во внутреннее состояние: `got[0] = …` меняет мапу, а `append`
при запасе ёмкости молча перетирает следующий элемент после очередного
`Add`. `slices.Clone` стоит одной аллокации и закрывает весь класс ошибок.

**`Size` как отдельный счётчик.** Пересчитывать пары обходом всех бакетов —
O(ключей) на каждый вызов. Счётчик надо менять во всех трёх местах: `Add`,
`Remove`, `RemoveAll` — на собеседовании часто забывают последнее.
