Цена товара на момент заказа, курс валюты на дату платежа, конфиг,
действовавший во время инцидента, — везде нужно «значение ключа на момент
t». Реализуйте `TimeMap` (вариант LeetCode 981, но честнее: моменты
приходят не по порядку). Поля и конструктор — на ваше усмотрение, контракт —
в заготовке.

Что проверяют скрытые тесты:

- чтение ровно в момент записи, между записями, после последней и до первой;
- записи, пришедшие в перемешанном порядке;
- повторная запись на тот же момент заменяет значение, а не добавляет
  вторую версию; пустая строка — обычное значение;
- нулевые и отрицательные моменты;
- тысяча записей по порядку и тысяча — догрузкой с конца.

<Reveal>

```go
type TimeMap struct {
	hist map[string][]version
}

type version struct {
	ts    int
	value string
}

func (m *TimeMap) Set(key, value string, ts int) {
	vs := m.hist[key]
	i := sort.Search(len(vs), func(i int) bool { return vs[i].ts >= ts })
	if i < len(vs) && vs[i].ts == ts {
		vs[i].value = value
		return
	}
	m.hist[key] = slices.Insert(vs, i, version{ts, value})
}

func (m *TimeMap) Get(key string, ts int) (string, bool) {
	vs := m.hist[key]
	i := sort.Search(len(vs), func(i int) bool { return vs[i].ts > ts })
	if i == 0 {
		return "", false
	}
	return vs[i-1].value, true
}
```

**Мапа — по ключу, двоичный поиск — по времени.** Искать «наибольший
`ts' <= ts`» перебором — O(n) на запрос. Если история каждого ключа
отсортирована, это `sort.Search` за O(log n): находим первую версию
**строго позже** `ts`, нужная стоит перед ней.

**Сортированность надо поддерживать.** Исходная задача обещает растущие
моменты, и решение «просто `append`» проходит её тесты. Здесь записи
приходят вперемешку, а двоичный поиск по неотсортированному слайсу молча
возвращает неверную версию — без паники и без ошибки. Поэтому вставка идёт
на своё место через `slices.Insert`: в типичном случае это конец, и
сдвига нет.

**Граница поиска: `>=` в `Set`, `>` в `Get`.** В `Set` ищем место, где
могла бы лежать версия с тем же `ts`, чтобы заменить её, а не дублировать.
В `Get` ищем первую версию позже `ts` — так запрос ровно в момент записи
видит эту запись. Перепутать знаки — самая частая ошибка на
off-by-one.

**`i == 0` — «ещё ничего не было».** Отсутствующий ключ даёт `nil`-слайс,
`sort.Search` по нему возвращает 0 — оба случая обрабатываются одной
проверкой. `ok` нужен, потому что пустая строка — законное значение.

**Что спросят дальше.** Удаление («значения нет с момента t» — версия-
надгробие), ограничение истории по давности, и как это устроено в MVCC
базы данных: версии строки с интервалами видимости вместо одного `ts`.
