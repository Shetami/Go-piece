Реализуйте `Index` — маленький полнотекстовый поиск, как в основе
Elasticsearch или GIN-индекса Postgres: для каждого слова хранится множество
документов, где оно встречается. Поиск по нескольким словам — пересечение
множеств. Поля и конструктор — на ваше усмотрение, контракт — в заготовке.

Что проверяют скрытые тесты:

- регистр, пунктуация, кириллица; повтор слова в запросе ничего не меняет;
- слово, которого нет ни в одном документе, делает результат пустым, а не
  игнорируется;
- запрос из одной пунктуации и пустой запрос — пусто, без паники;
- повторный `Add` того же документа: по словам старого текста он больше не
  находится;
- после `Remove` и замены текста в индексе не остаётся слов без документов;
- результат можно испортить — индекс этого не заметит;
- 300 документов: результат полный и отсортирован.

<Reveal>

```go
type Index struct {
	postings map[string]map[int]struct{}
	docs     map[int][]string
}

func (ix *Index) Add(id int, text string) {
	ix.Remove(id)
	ws := terms(text)
	for _, w := range ws {
		set := ix.postings[w]
		if set == nil {
			set = make(map[int]struct{})
			ix.postings[w] = set
		}
		set[id] = struct{}{}
	}
	ix.docs[id] = ws
}

func (ix *Index) Remove(id int) {
	ws, ok := ix.docs[id]
	if !ok {
		return
	}
	delete(ix.docs, id)
	for _, w := range ws {
		set := ix.postings[w]
		delete(set, id)
		if len(set) == 0 {
			delete(ix.postings, w)
		}
	}
}

func (ix *Index) Search(query string) []int {
	qs := terms(query)
	if len(qs) == 0 {
		return nil
	}
	sets := make([]map[int]struct{}, 0, len(qs))
	for _, w := range qs {
		set, ok := ix.postings[w]
		if !ok {
			return nil
		}
		sets = append(sets, set)
	}
	slices.SortFunc(sets, func(a, b map[int]struct{}) int { return len(a) - len(b) })
	var res []int
	for id := range sets[0] {
		inAll := true
		for _, s := range sets[1:] {
			if _, ok := s[id]; !ok {
				inAll = false
				break
			}
		}
		if inAll {
			res = append(res, id)
		}
	}
	slices.Sort(res)
	return res
}
```

(`terms` — `FieldsFunc` по не-буквам, `ToLower`, `Sort` + `Compact`; целиком
в эталонном решении.)

**Прямой индекс рядом с обратным.** Чтобы переиндексировать или удалить
документ, нужно знать, в каких списках он лежит. Без `docs` пришлось бы
обходить весь словарь; с ним `Remove` стоит O(слов документа). Наивный
повторный `Add`, который просто дописывает новые слова, оставляет документ
в старых списках — он находится по тексту, которого в нём уже нет.

**Пустые списки удаляем.** Иначе словарь только растёт: в сервисе, где
документы живут недолго (объявления, сессии чата), это утечка памяти.
`Words()` в тестах именно это и проверяет.

**Пересечение — с самого короткого.** Перебираем документы самого редкого
слова и проверяем их по остальным мапам за O(1). Стоимость — O(min · k), а не
O(max). Отсутствующее слово даёт пустой результат сразу — тут частая ошибка:
`continue` вместо `return nil` превращает AND в «AND по известным словам».

**Уникальные слова и в документе, и в запросе.** `Sort` + `Compact`
убирает повторы: в документе они раздували бы `docs`, в запросе — заставляли
пересекать множество с самим собой.

**Что спросят дальше.** Ранжирование (TF-IDF, BM25 — нужны уже не множества,
а счётчики вхождений), OR-запросы как объединение, хранение списков
отсортированными слайсами с пересечением слиянием — так делают настоящие
движки, это компактнее мап и дружелюбнее к кэшу.
