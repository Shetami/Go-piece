Реализуйте `LFU[K, V]` — кэш, который при переполнении выбрасывает запись,
к которой обращались реже всех; при ничьей — ту, к которой дольше всего не
обращались. Так работает политика `allkeys-lfu` в Redis. `Get` и `Put` — за
O(1): никаких сортировок и обходов всех записей. Поля и конструктор — на
ваше усмотрение, точные правила подсчёта частоты — в заготовке.

Что проверяют скрытые тесты:

- классическая последовательность из задачи LeetCode 460;
- ничья по частоте решается по давности обращения, а не по порядку вставки;
- `Put` существующего ключа — тоже обращение;
- ключ, который вытеснили и вставили снова, начинает с частоты 1, а сразу
  после вставки нового ключа самой редкой становится именно она — даже если
  у всех остальных частота 6;
- `capacity = 0` — кэш ничего не хранит и не паникует.

```go
type LFU[K comparable, V any] struct {
	capacity int
	items    map[K]*list.Element
	buckets  map[int]*list.List
	minFreq  int
}

func (c *LFU[K, V]) touch(el *list.Element) {
	e := el.Value.(*lfuEntry[K, V])
	old := c.buckets[e.freq]
	old.Remove(el)
	if old.Len() == 0 {
		delete(c.buckets, e.freq)
		if c.minFreq == e.freq {
			c.minFreq++
		}
	}
	e.freq++
	c.items[e.key] = c.bucket(e.freq).PushFront(e)
}

func (c *LFU[K, V]) Put(k K, v V) {
	if c.capacity <= 0 {
		return
	}
	if el, ok := c.items[k]; ok {
		el.Value.(*lfuEntry[K, V]).val = v
		c.touch(el)
		return
	}
	if len(c.items) >= c.capacity {
		l := c.buckets[c.minFreq]
		victim := l.Back()
		l.Remove(victim)
		if l.Len() == 0 {
			delete(c.buckets, c.minFreq)
		}
		delete(c.items, victim.Value.(*lfuEntry[K, V]).key)
	}
	c.items[k] = c.bucket(1).PushFront(&lfuEntry[K, V]{key: k, val: v, freq: 1})
	c.minFreq = 1
}
```

(`Get`, `bucket` и `Len` — в эталонном решении.)

**Мапа списков по частотам.** Для каждой частоты — свой двусвязный список,
внутри него порядок как в LRU: спереди свежие, сзади давние. Кандидат на
вытеснение — хвост списка минимальной частоты. Обращение переносит узел из
списка `f` в список `f+1` — O(1).

**`minFreq` без перебора.** Минимальная частота меняется всего двумя
способами. При вставке нового ключа она становится 1 — всегда. При обращении
к записи с минимальной частотой она растёт на единицу, но только если список
`minFreq` опустел: запись переехала на `minFreq+1`, и это новый минимум.
Искать минимум по всем ключам мапы `buckets` — O(число частот) и частая
ошибка на собеседовании.

**Ловушки сброса.** Забыть `minFreq = 1` при вставке — и следующая эвикция
полезет в список старого минимума: он либо пуст (`nil`-паника на `Back()`),
либо в нём живут часто используемые записи, а свежая редкая выживет. Хранить
частоты вытесненных ключей «на будущее» — другая ошибка: по контракту
вернувшийся ключ начинает с нуля.

**Пустые списки удаляем.** Иначе мапа `buckets` со временем хранит тысячи
пустых списков для частот, которых уже ни у кого нет.

**Что спросят дальше.** Недостаток чистого LFU — «старые чемпионы»: запись,
которую вчера читали миллион раз, не вытесняется никогда. Поэтому на
практике частоту старят (делят со временем), как делает Redis, или
используют W-TinyLFU, как Caffeine и Ristretto.
