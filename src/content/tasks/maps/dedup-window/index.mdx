Очередь сообщений гарантирует доставку «хотя бы один раз»: при ретраях
продюсера и ребалансах консьюмеров одно событие приходит дважды. Защита —
помнить недавние id и отбрасывать повторы. Помнить вечно нельзя: память.
Реализуйте `Dedup` с окном; правила — в заготовке.

Время передаётся в `Seen` явно — так логику легко проверить, а в проде туда
отдают время события или `time.Now()`.

Что проверяют скрытые тесты:

- повтор внутри окна и новое событие ровно на границе окна;
- поток повторов каждые 3 секунды при окне 10 — на десятой секунде событие
  снова принимается;
- id принят, окно истекло, id принят заново — чистка старой записи не должна
  удалить свежую;
- 20 000 уникальных id по 100 в секунду при окне в 1 секунду — хранится
  около сотни, а не двадцать тысяч.

<Reveal>

```go
type Dedup struct {
	window   time.Duration
	accepted map[string]time.Time
	queue    []dedupRec
}

func (d *Dedup) evict(now time.Time) {
	i := 0
	for ; i < len(d.queue) && now.Sub(d.queue[i].at) >= d.window; i++ {
		r := d.queue[i]
		if t, ok := d.accepted[r.id]; ok && t.Equal(r.at) {
			delete(d.accepted, r.id)
		}
	}
	d.queue = d.queue[i:]
	if cap(d.queue) > 64 && len(d.queue) < cap(d.queue)/2 {
		d.queue = append([]dedupRec(nil), d.queue...)
	}
}

func (d *Dedup) Seen(id string, at time.Time) bool {
	d.evict(at)
	if t, ok := d.accepted[id]; ok && at.Sub(t) < d.window {
		return true
	}
	d.accepted[id] = at
	d.queue = append(d.queue, dedupRec{id, at})
	return false
}
```

**Мапа отвечает «было ли», очередь — «что пора забыть».** Время не
убывает, поэтому принятые события лежат в очереди по порядку, и истёкшие
всегда в её начале. Чистка снимает их с головы, пока не встретит живое, —
амортизированно O(1) на вызов. Обход всей мапы на каждом `Seen` — O(n), и
при высоком потоке он съедает всё время.

**Устаревшая отметка.** Если id приняли заново, в очереди лежат две записи
о нём. Когда истекает первая, удалять `accepted[id]` нельзя — там уже новое
время. Сверяем время из очереди с временем в мапе, как с номером поколения в
TTL-кэше.

**Повторы не продлевают окно.** Если обновлять время на каждом повторе, то
событие, которое ретраится чаще окна, будет отбрасываться вечно — а
продюсер, возможно, как раз хочет доставить новое событие с тем же ключом.
Что из двух нужно — вопрос к бизнесу, но в контракте это должно быть
записано, и тест это различает.

**Хвост слайса держит память.** `d.queue[i:]` не освобождает начало
массива: он живёт, пока жив срез. Периодическое копирование в новый слайс
возвращает память; альтернатива — кольцевой буфер.

**Что спросят дальше.** Как дедуплицировать между несколькими репликами
консьюмера (Redis `SET NX EX`, уникальный индекс в базе,
идемпотентные обработчики) и почему идемпотентность обработчика надёжнее
любого окна.
