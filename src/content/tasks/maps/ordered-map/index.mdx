Реализуйте `OrderedMap[K, V]` — мапу, которая помнит порядок вставки, как
`LinkedHashMap` в Java или `dict` в Python. Нужна для детерминированного
вывода: заголовки HTTP, поля JSON, шаги конфигурации. Поля и конструктор — на
ваше усмотрение, контракт — в заготовке.

Самое интересное — обход `All()`: это `iter.Seq2`, по нему ходят
`for k, v := range m.All()`, и внутри тела цикла разрешено удалять ключи.

Что проверяют скрытые тесты:

- порядок вставки; обновление значения не двигает ключ, а удалённый и
  вставленный заново ключ уходит в конец;
- `break` в цикле по `All()` — итератор должен это заметить;
- `Delete` текущего ключа на каждой итерации — обход доходит до конца;
- в середине обхода удаляют несколько следующих ключей, меняют значение
  ещё не пройденного и добавляют новые — что выдаётся, а что нет.

<Reveal>

```go
type OrderedMap[K comparable, V any] struct {
	items      map[K]*omNode[K, V]
	head, tail *omNode[K, V]
	seq        uint64
}

type omNode[K comparable, V any] struct {
	key        K
	val        V
	prev, next *omNode[K, V]
	seq        uint64
	removed    bool
}

func (m *OrderedMap[K, V]) Delete(k K) bool {
	n, ok := m.items[k]
	if !ok {
		return false
	}
	delete(m.items, k)
	if n.prev != nil {
		n.prev.next = n.next
	} else {
		m.head = n.next
	}
	if n.next != nil {
		n.next.prev = n.prev
	} else {
		m.tail = n.prev
	}
	n.removed = true
	return true
}

func (m *OrderedMap[K, V]) All() iter.Seq2[K, V] {
	return func(yield func(K, V) bool) {
		limit := m.seq
		for n := m.head; n != nil && n.seq <= limit; n = n.next {
			if n.removed {
				continue
			}
			if !yield(n.key, n.val) {
				return
			}
		}
	}
}
```

(`Set`, `Get`, `Len` — в эталонном решении.)

**Мапа находит, список помнит порядок.** Мапа хранит указатель на узел
списка, поэтому `Delete` — O(1): нашли узел, перешили соседей. Слайс ключей
вместо списка даёт O(n) на удаление — на собеседовании это первое, о чём
спросят.

**Ловушка `container/list`.** Естественный код —
`for e := l.Front(); e != nil; e = e.Next()`. Но `list.Remove` обнуляет у
удалённого элемента `next`, и если тело цикла удалило текущий ключ,
`e.Next()` вернёт `nil` — обход тихо оборвётся после первого элемента.
Поэтому здесь свой список: удалённый узел **сохраняет** указатель вперёд и
получает флаг `removed`. Цепочка из удалённых узлов всё равно приводит к
живым: между удалённым узлом и его прежним соседом новые узлы появиться не
могут — вставка бывает только в хвост.

**Граница по номеру вставки.** Каждый узел получает растущий `seq`, а обход
запоминает `limit` в начале. Узлы, добавленные позже, в том числе ключ,
удалённый и вставленный заново, имеют больший номер — так выполняется правило
«новые ключи в этот обход не попадают», и цикл не становится бесконечным,
если тело всё время что-то добавляет.

**`if !yield(...) { return }` обязателен.** После `break` рантайм запрещает
звать `yield` снова — это паника
`range function continued iteration after function for loop body returned false`.

**Что спросят дальше.** Альтернатива попроще — снимок ключей в начале обхода
и проверка `items[k]` на каждом шаге: корректно, но O(n) памяти на каждый
обход. И вопрос про мусор: удалённые узлы держат ссылки на соседей, но
недостижимы из мапы и головы списка, так что GC их соберёт, как только
закончатся обходы.
