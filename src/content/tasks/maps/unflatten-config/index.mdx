Плоские пути `db.host=x` приходят из переменных окружения, флагов, etcd —
а коду нужен вложенный документ. Напишите `Unflatten`; правила и ошибки —
в заготовке.

Входная мапа обходится в случайном порядке, а ответ обязан от него не
зависеть: одни и те же данные — всегда одна и та же ошибка или один и тот
же документ.

Что проверяют скрытые тесты:

- обычная сборка на три уровня, `nil` как значение, пустой вход;
- `"a"` и `"a.b"` в любом порядке, лист `nil`, конфликт на глубине —
  по 30 запусков, ни одной паники и ни одного «последний победил»;
- значение `"a"` — само `map[string]any`, а рядом путь `"a.b"`: ошибка, и
  мапа из входа не тронута; пустая мапа-значение — обычный лист;
- пустые сегменты пути.

```go
func Unflatten(flat map[string]any) (map[string]any, error) {
	paths := make([]string, 0, len(flat))
	for p := range flat {
		paths = append(paths, p)
	}
	slices.Sort(paths)

	root := make(map[string]any)
	ours := map[string]bool{"": true}

	for _, p := range paths {
		segs := strings.Split(p, ".")
		if slices.Contains(segs, "") {
			return nil, fmt.Errorf("%w: %q", ErrBadPath, p)
		}
		node, prefix := root, ""
		for _, s := range segs[:len(segs)-1] {
			if prefix == "" {
				prefix = s
			} else {
				prefix += "." + s
			}
			next, exists := node[s]
			if !exists {
				m := make(map[string]any)
				node[s] = m
				ours[prefix] = true
				node = m
				continue
			}
			if !ours[prefix] {
				return nil, fmt.Errorf("%w: %q и %q", ErrConflict, prefix, p)
			}
			node = next.(map[string]any)
		}
		last := segs[len(segs)-1]
		if _, exists := node[last]; exists {
			return nil, fmt.Errorf("%w: %q", ErrConflict, p)
		}
		node[last] = flat[p]
	}
	return root, nil
}
```

**Порядок обхода решает всё.** Наивный цикл по `flat`: если первым пришёл
`a.b`, создаём узел `a`, а потом `"a": 1` его молча перезаписывает — ошибки
нет, `b` потерян. Если первым пришёл `a`, то на `a.b` приведение
`node["a"].(map[string]any)` паникует. Один вход — два разных исхода.
Сортировка путей делает обход детерминированным, а проверки на обоих концах
(«промежуточный узел — лист?» и «на месте листа уже узел?») ловят конфликт в
любом порядке.

**Чьё это `map[string]any`?** Проверить тип промежуточного узла мало:
значение из входа тоже может быть `map[string]any`. Если спуститься в него и
дописать `b`, мы, во-первых, смешаем лист с узлом, во-вторых, изменим мапу,
которой владеет вызывающий, — её ссылка лежит во входе. Поэтому храним
множество путей узлов, **созданных нами**, и спускаемся только в них.

**`_, exists := node[k]`, а не `node[k] != nil`.** Лист `nil` — законное
значение (`"debug": null`), и сравнение с `nil` не заметит, что место
занято.

**Пустые сегменты — отдельная ошибка.** `strings.Split("a..b", ".")` даёт
`["a", "", "b"]`, и без проверки в документе появится ключ `""`. Такие пути
почти всегда опечатка в имени переменной окружения — лучше упасть при старте.
