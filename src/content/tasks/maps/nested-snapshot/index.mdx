Реализуйте `Registry` — реестр настроек «раздел → ключ → значение», из
которого другие части сервиса берут снимки, например чтобы отдать в
`/debug/config` или сравнить с новой версией. Поля и конструктор — на ваше
усмотрение, контракт — в заготовке.

Что проверяют скрытые тесты:

- обычные `Set` и `Get`, пустое значение, чтение из отсутствующего
  раздела;
- раздел исчезает вместе с последним ключом;
- снимок пустого реестра — не `nil`;
- правка **внутри раздела** снимка не видна реестру, а новая запись в реестр
  не видна старому снимку;
- восемь горутин одновременно пишут, удаляют и обходят снимки.

<Reveal>

```go
type Registry struct {
	mu   sync.RWMutex
	data map[string]map[string]string
}

func (r *Registry) Set(section, key, value string) {
	r.mu.Lock()
	defer r.mu.Unlock()
	sec := r.data[section]
	if sec == nil {
		sec = make(map[string]string)
		r.data[section] = sec
	}
	sec[key] = value
}

func (r *Registry) Delete(section, key string) {
	r.mu.Lock()
	defer r.mu.Unlock()
	sec := r.data[section]
	delete(sec, key)
	if len(sec) == 0 {
		delete(r.data, section)
	}
}

func (r *Registry) Snapshot() map[string]map[string]string {
	r.mu.RLock()
	defer r.mu.RUnlock()
	snap := make(map[string]map[string]string, len(r.data))
	for name, sec := range r.data {
		snap[name] = maps.Clone(sec)
	}
	return snap
}
```

(`Get` — в эталонном решении.)

**`maps.Clone(r.data)` — не снимок.** Он копирует внешнюю мапу, а значения
— это мапы, то есть ссылки на те же разделы. Правка `snap["db"]["host"]`
пишет прямо в реестр, причём **без мьютекса**: одновременно с `Set` из
другой горутины это `concurrent map writes` и падение процесса. Каждый
раздел клонируется отдельно.

**Вложенная мапа создаётся явно.** `r.data[section][key] = value` для
нового раздела паникует: `r.data[section]` — это `nil`, а писать в
`nil`-мапу нельзя. Читать из неё — можно, поэтому `Get` обходится одной
строкой, а `delete` на `nil`-мапе ничего не делает.

**Пустые разделы удаляем.** Иначе снимок показывает «раздел есть, ключей
нет», а при ротации ключей мапа растёт без ограничений.

**Что спросят дальше.** Если снимки берут часто, а пишут редко, выгоднее
copy-on-write: реестр хранит неизменяемую мапу в `atomic.Pointer`, запись
строит новую копию, а снимок — просто загрузка указателя без копирования.
