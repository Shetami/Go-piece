Напишите `SubarraySum`: сколько непрерывных подотрезков имеют сумму ровно
`k` и какова длина самого длинного из них. На практике это «сколько
интервалов, где баланс изменился ровно на k», «самый длинный период с
нулевым итогом по счёту». На собеседовании — LeetCode 560 и 325 в одной
задаче.

Числа бывают отрицательными, поэтому скользящее окно из двух указателей не
работает: сумма не растёт монотонно при расширении окна.

Что проверяют скрытые тесты:

- обычные примеры, в том числе отрезок, который начинается с первого
  элемента;
- отрицательные числа и нули: у `[0 0 0]` при `k = 0` шесть отрезков;
- пустой слайс при `k = 0` — пустой отрезок не считается;
- 200 случайных массивов сверяются с перебором;
- 200 000 элементов — квадратичный перебор не укладывается во время.

<Reveal>

```go
func SubarraySum(nums []int, k int) (count, longest int) {
	seen := map[int]int{0: 1}
	first := map[int]int{0: -1}
	sum := 0
	for j, x := range nums {
		sum += x
		count += seen[sum-k]
		if i, ok := first[sum-k]; ok {
			longest = max(longest, j-i)
		}
		seen[sum]++
		if _, ok := first[sum]; !ok {
			first[sum] = j
		}
	}
	return count, longest
}
```

**Префиксные суммы.** Сумма отрезка от `i+1` до `j` — это
`prefix[j] - prefix[i]`. Значит, для каждого `j` нужно знать, сколько раз
раньше встречался префикс `prefix[j] - k`, — это ровно число отрезков,
заканчивающихся в `j`. Мапа отвечает на этот вопрос за O(1), и весь
алгоритм — один проход.

**Пустой префикс: `{0: 1}` и `{0: -1}`.** Отрезок может начинаться с
нулевого элемента — тогда вычитается сумма пустого префикса, то есть 0. Без
начальной записи `[3]` при `k = 3` даст 0 отрезков. Индекс `-1` делает
длину такого отрезка равной `j + 1`.

**Порядок строк в цикле.** Сначала ищем `sum - k`, потом кладём `sum`.
Наоборот при `k = 0` текущий префикс найдёт сам себя, и каждый элемент
посчитается как пустой отрезок.

**Для длины — только первое вхождение.** Самый длинный отрезок до `j`
начинается сразу после **самого раннего** подходящего префикса. Если
перезаписывать `first[sum] = j` каждый раз, на нулях и отрицательных
числах длина получится меньше. Поэтому мап две: одна считает вхождения,
другая помнит первое.

**Что спросят дальше.** Отрезки с суммой, кратной `k` (мапа по остатку, и
аккуратно с отрицательными остатками в Go: `-1 % 5 == -1`), и та же идея в
двумерной матрице.
