Реализуйте `TTLCache[K, V]` — кэш, у каждой записи которого свой срок
жизни: токены, ответы внешних API, сессии. Поля — на ваше усмотрение,
контракт — в заготовке.

Время берётся только из функции `now`, переданной в конструктор: так кэш
тестируется без `time.Sleep`, а в проде туда передают `time.Now`. Чистка
`Purge` не должна обходить всю мапу — держите сроки в куче
(`container/heap`), на вершине — ближайший.

Что проверяют скрытые тесты:

- запись жива через 9 с при ttl 10 с и мертва ровно в 10 с;
- `ttl` ноль и отрицательный — бессрочно;
- `Len` не считает истёкшие записи, даже если к ним никто не обращался;
- повторный `Set` с более длинным сроком: старая отметка в куче не должна
  удалить свежую запись; повторный `Set` с коротким — укорачивает;
- `Purge` возвращает точное число удалённых — без записей, которые уже
  убрал `Get`;
- восемь горутин одновременно пишут и читают.

```go
type TTLCache[K comparable, V any] struct {
	mu    sync.Mutex
	now   func() time.Time
	items map[K]*ttlItem[V]
	exp   expHeap[K] // (ключ, срок, поколение), на вершине — ближайший срок
	gen   uint64
}

func (c *TTLCache[K, V]) Set(k K, v V, ttl time.Duration) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.gen++
	it := &ttlItem[V]{val: v, gen: c.gen}
	if ttl > 0 {
		it.expires = c.now().Add(ttl)
		heap.Push(&c.exp, expEntry[K]{k, it.expires, c.gen})
	}
	c.items[k] = it
}

func (c *TTLCache[K, V]) purge() int {
	now := c.now()
	n := 0
	for len(c.exp) > 0 && !now.Before(c.exp[0].expires) {
		e := heap.Pop(&c.exp).(expEntry[K])
		if it, ok := c.items[e.key]; ok && it.gen == e.gen {
			delete(c.items, e.key)
			n++
		}
	}
	return n
}
```

(`Get`, `Len`, `Purge` и куча — в эталонном решении.)

**Устаревшие записи в куче — главная ловушка.** Из кучи нельзя дёшево
удалить произвольный элемент, поэтому при повторном `Set` старая отметка
остаётся. Если `purge` удаляет ключ, просто увидев его на вершине, то первая
отметка через секунду убьёт запись, которую только что продлили на десять.
Каждая запись получает номер поколения; отметка в куче удаляет ключ, только
если поколения совпадают. Это «ленивое удаление» — тот же приём, что в
Дейкстре на `container/heap`.

**Граница: `now.Before(expires)`.** Запись с ttl 10 с, проверенная ровно
через 10 с, мертва. `!now.After(expires)` даёт на одну наносекунду больше
жизни — мелочь, но на тестах с явными часами это видно сразу.

**Mutex, а не RWMutex.** `Get` удаляет истёкшую запись — это запись в мапу.
Под `RLock` два `Get` одновременно получат `concurrent map writes`. Можно не
удалять в `Get`, а только отвечать «промах» — тогда `RLock` допустим, а
чистку делает `Purge`.

**Явные часы.** `now func() time.Time` вместо прямого `time.Now()` —
стандартный способ сделать логику со временем детерминированной: в тесте
время двигается одной строкой. Спросят, как чистить в фоне: горутина с
`time.Ticker`, которая зовёт `Purge`, и `Close`/контекст, чтобы её
остановить, — иначе утечка горутины.
