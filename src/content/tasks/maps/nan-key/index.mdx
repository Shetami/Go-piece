Ключ мапы — `float64`, и дважды в неё пишут по ключу `math.NaN()`. Потом ищут
этот ключ, удаляют его и в конце очищают мапу встроенной `clear`.

Напишите весь вывод программы.

<Reveal>

**`NaN` не равен ничему, даже самому себе.** Так требует IEEE 754, и Go
следует стандарту: `nan == nan` — `false`.

Мапа находит ключ через хеш и сравнение на равенство. Хеш у `NaN` рантайм
намеренно делает случайным, а сравнение всегда даёт «не равно». Поэтому каждая
запись по ключу `NaN` создаёт **новый** элемент. После двух записей и
единицы в мапе три элемента.

Найти такой элемент нельзя: `m[nan]` сравнивает ключи, и ни один не
совпадёт — `ok == false`. Удалить через `delete` тоже нельзя по той же
причине, длина остаётся 3.

Единственный способ избавиться от них — `clear(m)` (Go 1.21+). Встроенная
`clear` не ищет ключи, а обнуляет мапу целиком. До её появления приходилось
пересоздавать мапу: цикл `for k := range m { delete(m, k) }` NaN-ключи не
удаляет.

Итого:

```
3
false
3
0
```

**Где встречается.** Мапы с ключом `float64` редки, но NaN легко
прилетает из деления `0/0` в статистике или из разбора `"NaN"` через
`strconv.ParseFloat`. Мапа от этого растёт и ничего не находит. Если ключ —
число с плавающей точкой, отсекайте NaN до записи.

</Reveal>
