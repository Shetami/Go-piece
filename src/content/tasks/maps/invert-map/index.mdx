Напишите тело `Invert`.

Что проверяют скрытые тесты:

- `{"один": 1, "два": 2}` → `{1: "один", 2: "два"}`;
- если два ключа дают одно значение — результат `nil` и ошибка:
  `errors.Is(err, ErrDuplicate)` истинно, и в тексте есть само значение;
- пустая мапа → пустая (не `nil`) мапа без ошибки.

<Reveal>

```go
func Invert[K, V comparable](m map[K]V) (map[V]K, error) {
	out := make(map[V]K, len(m))
	for k, v := range m {
		if _, ok := out[v]; ok {
			return nil, fmt.Errorf("%w: %v", ErrDuplicate, v)
		}
		out[v] = k
	}
	return out, nil
}
```

**Молчаливая потеря — главный риск.** Наивный вариант `out[v] = k` без
проверки работает, но при повторах один из ключей тихо исчезает — причём
какой именно, зависит от случайного порядка обхода мапы. Такой баг
невоспроизводим: при каждом запуске пропадает разное.

**Обе стороны `comparable`.** Значения исходной мапы становятся ключами
новой, поэтому ограничение нужно и на `V`.

**Ошибка с данными.** `fmt.Errorf("%w: %v", ErrDuplicate, v)` одновременно
сохраняет сентинел для `errors.Is` и добавляет контекст для человека.
Если вызывающему нужно само значение программно — тогда свой тип ошибки с
полем и `errors.As`.

**Предвыделение `make(map[V]K, len(m))`** избавляет мапу от роста по ходу
заполнения — размер известен заранее.

</Reveal>
