После слияния двух CRM у одного клиента оказалось несколько карточек.
Считаем, что карточки принадлежат одному человеку, если у них есть общий
адрес почты — хоть напрямую, хоть по цепочке. Напишите `MergeAccounts`
(вариант задачи LeetCode 721). Точные правила ответа — в заготовке.

Что проверяют скрытые тесты:

- цепочка из трёх карточек, связанных двумя разными адресами;
- «мост», который связывает уже разошедшиеся группы, стоит последним во
  входе;
- тёзки не склеиваются; повтор адреса в одной карточке; карточка без адресов;
- входные слайсы `Emails` — в том числе с запасом ёмкости — не меняются;
  пустой вход.

<Reveal>

```go
func MergeAccounts(accs []Account) []Account {
	parent := make([]int, len(accs))
	for i := range parent {
		parent[i] = i
	}
	var find func(int) int
	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}
	union := func(a, b int) {
		ra, rb := find(a), find(b)
		if ra == rb {
			return
		}
		if rb < ra {
			ra, rb = rb, ra
		}
		parent[rb] = ra
	}

	owner := make(map[string]int)
	for i, a := range accs {
		for _, e := range a.Emails {
			if j, ok := owner[e]; ok {
				union(i, j)
			} else {
				owner[e] = i
			}
		}
	}

	pos := make(map[int]int)
	var res []Account
	for i, a := range accs {
		r := find(i)
		p, ok := pos[r]
		if !ok {
			p = len(res)
			pos[r] = p
			res = append(res, Account{Name: accs[r].Name})
		}
		res[p].Emails = append(res[p].Emails, a.Emails...)
	}
	for i := range res {
		slices.Sort(res[i].Emails)
		res[i].Emails = slices.Compact(res[i].Emails)
	}
	return res
}
```

**Мапа превращает адреса в рёбра.** `owner` помнит, в какой карточке адрес
встретился впервые. Каждая следующая карточка с тем же адресом
объединяется с той — рёбер получается не больше, чем адресов, а не квадрат
от числа карточек.

**Почему не «один проход с группировкой».** Наивно: заводим мапу «адрес →
группа», новой карточке даём группу первого известного адреса. Это ломается
на мосте: карточка `{3, 2, 1}` связывает три группы, но каждую из них
надо переписать целиком — со всеми адресами, уже разложенными по другим
группам. Union-find делает это за почти O(1): меняется только корень.

**Корень — наименьший индекс.** При объединении подвешиваем больший корень
к меньшему, и корень группы автоматически оказывается её первой карточкой:
имя берём из `accs[r]`, порядок групп — по первому появлению. Без этого
пришлось бы отдельно искать минимум в каждой группе. Сжатие пути в `find`
сохраняет почти константную сложность и при таком правиле объединения.

**Не портить вход.** `res[p].Emails` начинается с `nil`, поэтому `append`
всегда пишет в новый массив. Если же стартовать с `accs[r].Emails` и
дописывать в него, при запасе ёмкости адреса чужих карточек молча лягут в
память вызывающего, а `slices.Sort` переставит его данные. Тест с `cap = 10`
именно это и проверяет.

**Что спросят дальше.** Как сделать это на потоке, где карточки приходят по
одной (тот же union-find, но инкрементально), и как объяснить, чем
union-find лучше обхода графа в ширину: обход тоже работает, но требует
сначала построить список смежности.
