`Take` списывает товар, если его хватает, и возвращает ошибку, если нет.
Первый вызов успешен, второй правильно отказывает, а на третьем:

```
fatal error: all goroutines are asleep - deadlock!
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 16: `return` с ошибкой при захваченном мьютексе.

**На этом пути `Unlock` не вызывается.** Мьютекс остаётся захваченным
навсегда. Следующий `Take` — от кого угодно, по любому товару — встаёт на
`Lock` и ждёт вечно. В программе с одной горутиной рантайм это замечает и
падает. В сервере с сотней горутин запросы просто будут копиться в
очереди на мьютекс без единой ошибки в логах.

**Как правильно** — `defer s.mu.Unlock()` сразу после `Lock`. Тогда мьютекс
освободится на любом пути выхода: после `return`, после паники, после
кода, который добавят в функцию через год.

Держать критическую секцию без `defer` имеет смысл только тогда, когда
после неё в функции есть долгая работа, которой мьютекс не нужен. Тогда
выделите секцию в отдельную функцию — и в ней уже `defer`.

</Reveal>
