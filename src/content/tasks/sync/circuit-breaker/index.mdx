Реализуйте `Breaker` — circuit breaker, как `sony/gobreaker`. Когда
зависимость лежит, выключатель перестаёт слать в неё запросы и сразу
отвечает ошибкой, а через время осторожно проверяет одним пробным
вызовом, не ожила ли она. Состояния и переходы — в doc-комментарии к
типу; время берите только из `now`.

Что проверяют скрытые тесты (с детектором гонок):

- ошибки, перемежающиеся успехом, выключатель не размыкают; ошибка,
  которая его разомкнула, возвращается как есть;
- в разомкнутом состоянии `fn` не вызывается; граница cooldown;
- неудачная проба размыкает заново — и cooldown отсчитывается от неё;
- пока проба висит, двадцать одновременных вызовов сразу получают
  `ErrOpen`, а `fn` за всё это время вызвана ровно один раз.

<Reveal>

```go
func (b *Breaker) Call(fn func() error) error {
	probe, err := b.before()
	if err != nil {
		return err
	}
	err = fn()
	b.after(probe, err)
	return err
}

func (b *Breaker) before() (bool, error) {
	b.mu.Lock()
	defer b.mu.Unlock()
	switch b.state {
	case closed:
		return false, nil
	case open:
		if b.now().Sub(b.openedAt) < b.cooldown {
			return false, ErrOpen
		}
		b.state = halfOpen
		return true, nil
	default:
		return false, ErrOpen
	}
}

func (b *Breaker) after(probe bool, err error) {
	b.mu.Lock()
	defer b.mu.Unlock()
	if probe {
		if err != nil {
			b.trip()
		} else {
			b.state = closed
			b.failures = 0
		}
		return
	}
	if b.state != closed {
		return
	}
	if err == nil {
		b.failures = 0
		return
	}
	b.failures++
	if b.failures >= b.threshold {
		b.trip()
	}
}

func (b *Breaker) trip() {
	b.state = open
	b.openedAt = b.now()
	b.failures = 0
}
```

**Вызов разбит на «до» и «после», `fn` — между ними, без мьютекса.**
Самое простое решение — `mu.Lock(); defer mu.Unlock()` на весь `Call` —
превращает выключатель в очередь: все запросы к зависимости идут по
одному, а зависшая проба держит всех (последний тест). Под мьютексом —
только решение о допуске и учёт результата.

**Ровно одна проба — благодаря переходу в `half-open` под той же
блокировкой, что и проверка cooldown.** Если сначала проверить время, а
состояние поменять позже, двадцать горутин одновременно решат, что
пробовать можно именно им, — и на едва поднявшуюся зависимость
обрушится волна запросов, которая снова её уронит.

**Опоздавшие результаты.** В `closed` идут десятки параллельных вызовов.
Выключатель разомкнулся, а часть вызовов ещё выполняется; их ошибки или
успехи не должны менять новое состояние — иначе запоздавший успех
«замкнёт» выключатель без пробы. Поэтому обычный вызов учитывается,
только если выключатель всё ещё `closed`. Пробный помечен флагом `probe`
и обрабатывается отдельно.

**Часы снаружи.** `now func() time.Time` в конструкторе — чтобы тесты
проверяли cooldown мгновенно и детерминированно, без `time.Sleep`.

**Что спросят дальше.** «Ошибки подряд» плохо работают под большим
трафиком: 1% ошибок никогда не даст пяти подряд, а 30% дадут случайно.
В проде считают долю ошибок в скользящем окне (например, за 10 секунд, с
минимальным числом запросов). И какие ошибки считать: `context.Canceled`
от клиента и 4xx — это не отказ зависимости.
