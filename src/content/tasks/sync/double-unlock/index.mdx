---
title: Отказ в списании роняет программу
description: Успешное списание работает, а при нехватке денег программа падает с fatal error про мьютекс. Почините.
kind: fix
topic: sync
level: easy
order: 30
related: [mutex]
---

Первое списание проходит, на втором денег не хватает — и вместо ошибки
программа падает:

```
fatal error: sync: unlock of unlocked mutex
```

Почините. Ожидаемый вывод:

```
<nil>
недостаточно средств
остаток: 70
```

<Reveal>

**Мьютекс разблокируется дважды.** В ветке с ошибкой стоит ручной
`a.mu.Unlock()`, а потом `return` запускает отложенный `defer a.mu.Unlock()`.
Второй `Unlock` на уже свободном мьютексе — ошибка, после которой
состояние мьютекса не восстановить. Поэтому это `fatal error`, а не паника:
`recover` её не перехватит.

Скорее всего, ручной `Unlock` остался от версии без `defer` — кто-то
добавил `defer` и забыл почистить ранние выходы.

**Как чинят** — оставить только `defer`:

```go
a.mu.Lock()
defer a.mu.Unlock()
if a.balance < n {
	return errors.New("недостаточно средств")
}
```

**Правило.** Либо `defer Unlock` сразу после `Lock` и больше никаких
`Unlock` в функции, либо только ручные `Unlock` на каждом выходе. Смешивать
нельзя. Первый вариант почти всегда лучше: он переживает и ранние `return`,
и панику.

</Reveal>
