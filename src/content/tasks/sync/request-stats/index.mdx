Реализуйте `Stats` — счётчики, которые middleware обновляет на каждый
HTTP-запрос: всего запросов, ответов 4xx, ответов 5xx и отданных байтов.
`Record` зовут сотни горутин одновременно, поэтому — `sync/atomic`, без
мьютекса. Нулевое значение `Stats` должно быть готово к работе.

Что проверяют скрытые тесты (с детектором гонок):

- коды на границах классов: 399, 400, 499, 500, 599;
- `ErrorRate` у пустой статистики;
- восемь горутин по 2000 `Record` — ни одно обновление не потеряно, а
  `ErrorRate`, прочитанный посреди записи, остаётся в пределах `[0, 1]`.

<Reveal>

```go
type Stats struct {
	requests     atomic.Int64
	clientErrors atomic.Int64
	serverErrors atomic.Int64
	bytes        atomic.Int64
}

func (s *Stats) Record(status int, bytes int) {
	s.requests.Add(1)
	s.bytes.Add(int64(bytes))
	switch {
	case status >= 500 && status <= 599:
		s.serverErrors.Add(1)
	case status >= 400 && status <= 499:
		s.clientErrors.Add(1)
	}
}

func (s *Stats) ErrorRate() float64 {
	errs := s.serverErrors.Load()
	total := s.requests.Load()
	if total == 0 {
		return 0
	}
	return float64(errs) / float64(total)
}
```

**Типы `atomic.Int64` вместо функций `atomic.AddInt64`.** Нулевое значение
готово к работе, а обратиться к полю неатомарно просто нельзя — нет такого
метода. Со старыми функциями легко где-нибудь написать `s.requests++` и
получить гонку. Заодно типы гарантируют выравнивание по 8 байт на 32-битных
платформах.

**Снимок атомарен по полям, но не целиком.** Между чтением `requests` и
`serverErrors` может прийти ещё десяток запросов. Для метрик это нормально:
в следующем снимке всё сойдётся. Если нужна строгая согласованность
нескольких чисел, нужен мьютекс (или один атомик с упакованными полями).

**Порядок чтения в `ErrorRate` не случаен.** `Record` сначала увеличивает
`requests`, потом `serverErrors`, поэтому в любой момент ошибок не больше,
чем запросов. Если прочитать ошибки *первыми*, а запросы — после, доля
гарантированно не превысит 1. В обратном порядке между чтениями могут
успеть записаться новые ошибки, и доля выйдет за единицу.

**`0/0` для `float64` — это `NaN`, а не паника.** И `NaN` потом отравит
дашборд и сравнения: `NaN > 0.05` ложно, алерт молчит. Пустую статистику
проверяют явно.
