Реализуйте `Store` — хранилище сессий с временем жизни. Чтений на
порядки больше, чем записей. Истёкшие сессии вычищает фоновая горутина,
а `Close` её останавливает. Контракт — в doc-комментариях; время берите
только из `now`.

Что проверяют скрытые тесты (с детектором гонок):

- сессия на границе срока жизни, продление через `Set`, истёкшая сессия
  при чистке раз в час (то есть чистка ещё не прошла);
- при частой чистке истёкшие сессии пропадают из `Len`, а живые остаются;
- двадцать раз `NewStore` + двойной `Close` — число горутин не растёт и
  ничего не паникует;
- восемь горутин одновременно пишут и читают.

```go
type Store struct {
	ttl time.Duration
	now func() time.Time

	mu       sync.RWMutex
	sessions map[string]session

	stop      chan struct{}
	done      chan struct{}
	closeOnce sync.Once
}

func (s *Store) janitor(every time.Duration) {
	defer close(s.done)
	t := time.NewTicker(every)
	defer t.Stop()
	for {
		select {
		case <-t.C:
			s.cleanup()
		case <-s.stop:
			return
		}
	}
}

func (s *Store) Get(id string) (string, bool) {
	now := s.now()
	s.mu.RLock()
	ss, ok := s.sessions[id]
	s.mu.RUnlock()
	if !ok || !now.Before(ss.expires) {
		return "", false
	}
	return ss.user, true
}

func (s *Store) Close() {
	s.closeOnce.Do(func() { close(s.stop) })
	<-s.done
}
```

**Чистка — оптимизация памяти, а не часть логики.** Уборщик просыпается
раз в `cleanupEvery`, и между проходами истёкшие сессии ещё лежат в мапе.
Если `Get` вернёт такую, пользователь с протухшей сессией пройдёт
авторизацию. Поэтому срок проверяется при каждом чтении, а уборщик лишь
не даёт мапе расти бесконечно.

**Граница: `now < expires`, а не `<=`.** Ровно в момент истечения сессия
уже мертва. В контракте это записано явно — на собеседовании такие вещи
стоит проговаривать, а не угадывать.

**`RWMutex` оправдан:** `Get` на каждый запрос, `Set` при логине. Читатели
не блокируют друг друга, но заметьте: `now()` вызывается до `RLock` —
под блокировкой только обращение к мапе.

**`Close` без утечек.** Горутина-уборщик живёт, пока её не остановят;
забытый `Close` в тестах или при пересоздании хранилища — классическая
утечка горутины (и тикера). `sync.Once` защищает от паники на повторном
`close(stop)`, а канал `done` даёт дождаться реального выхода горутины —
после `Close` уборщик гарантированно не трогает мапу.

**Что спросят дальше.** Проход по всей мапе под `Lock` на миллионе
сессий — заметная пауза для всех `Get`. Решения: шардировать мапу, чистить
порциями, или держать мин-кучу по времени истечения (`container/heap`) и
удалять только то, что на вершине. А на нескольких инстансах сервиса
сессии вообще живут в Redis с `EXPIRE`.
