Блокирующая очередь: `Pop` ждёт на `sync.Cond`, пока появится элемент,
`Push` кладёт элемент и будит ожидающих. Три потребителя уже ждут, в
очередь кладут первый элемент:

```
panic: runtime error: index out of range [0] with length 0
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 32: `if` вместо `for` вокруг `cond.Wait()`.

**Проснуться — не значит, что условие выполнено.** `Broadcast` будит всех
трёх. Каждый по очереди захватывает мьютекс и выходит из `Wait`. Первый
забирает элемент. Второй и третий, проснувшись, условие не перепроверяют —
`if` уже пройден — и лезут в пустой слайс.

**`Wait` всегда вызывают в цикле:**

```go
for len(q.items) == 0 {
	q.cond.Wait()
}
```

Это требование прямо записано в документации `sync.Cond`. Даже с
`Signal`, который будит одного, `if` не спасает: между сигналом и
моментом, когда проснувшийся захватит мьютекс, элемент может забрать
кто-то, кто пришёл в `Pop` только что и вообще не ждал.

**На практике** блокирующую очередь проще сделать на буферизованном
канале. `sync.Cond` нужен, когда условие сложнее «есть элемент» и каналом
не выражается.

</Reveal>
