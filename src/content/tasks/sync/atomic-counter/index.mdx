`atomic.Int64` увеличивают из 50 горутин по 100 раз. `wg.Go` (Go 1.25+)
запускает горутину и сам делает `Add` и `Done`. Потом — `Swap` и два
`CompareAndSwap`.

Напишите весь вывод программы.

<Reveal>

**`Add` атомарен — потерь нет.** `n++` на обычной переменной — это три
шага: прочитать, прибавить, записать. Две горутины могут прочитать одно и то
же значение, и одна прибавка потеряется. `n.Add(1)` делает все три шага
одной процессорной инструкцией (`LOCK XADD` на amd64). Итог ровно
`50 × 100 = 5000`.

**`Swap` записывает новое значение и возвращает старое.** Было 5000, стало
0.

**`CompareAndSwap(old, new)` пишет, только если текущее значение равно
`old`.** Сейчас 0, мы ждём 1 — не совпало, `false`, значение не тронуто.
Второй раз ждём 0 — совпало, записали 5, `true`.

Итого:

```
5000
5000 0
false 0
true 5
```

**Когда атомики, а когда мьютекс.** Атомик защищает одно слово. Как только
надо согласованно поменять два значения — счётчик и сумму, указатель и длину,
— нужен мьютекс. На CAS строят циклы «прочитал — посчитал — попробовал
записать, иначе заново», но это оправдано только на действительно горячем
пути.

</Reveal>
