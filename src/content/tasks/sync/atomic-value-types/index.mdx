`atomic.Value` хранит конфигурацию. Сначала её читают до всякой записи,
потом пробуют положить строку, число и `nil`. Паники перехватываются и
печатаются.

Напишите весь вывод программы.

<Reveal>

**До первой записи `Load` возвращает `nil`.** Проверять на это надо всегда,
иначе приведение `cfg.Load().(string)` упадёт.

**Первый `Store` фиксирует тип навсегда.** Строка записалась, и дальше
`Value` принимает только строки. `Store(42)` паникует с сообщением
`sync/atomic: store of inconsistently typed value into Value`.

**`nil` класть нельзя вообще** — `nil` означает «ещё не записано», и
отличить одно от другого было бы невозможно.

**`Swap` (Go 1.17) записывает и возвращает старое значение** атомарно.

Итого:

```
<nil>
строка ок
число паника: sync/atomic: store of inconsistently typed value into Value
nil паника: sync/atomic: store of nil value into Value
конфиг v1 → конфиг v2
```

**Что лучше сейчас.** С Go 1.19 есть `atomic.Pointer[T]` — типизированный,
без приведения типа и без паник: `var cfg atomic.Pointer[Config]`,
`cfg.Store(&c)`, `cfg.Load()` возвращает `*Config`. Для горячей замены
конфигурации это обычный выбор.

</Reveal>
