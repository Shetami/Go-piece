Реализуйте `Histogram` — гистограмму латентностей, как `prometheus.Histogram`:
фиксированные верхние границы бакетов, счётчик в каждом, общее число
наблюдений и их сумма. `Observe` вызывается на каждый запрос из всех
горутин, поэтому мьютекса в нём быть не должно — только `sync/atomic`.

Что проверяют скрытые тесты (с детектором гонок):

- значения ровно на границах бакетов, значения больше последней границы,
  кумулятивные счётчики в снимке;
- вызывающий меняет свой слайс границ после конструктора, а потом —
  полученный снимок;
- восемь горутин по 1000 `Observe`: счётчики сошлись, и сумма — тоже.

```go
type Histogram struct {
	bounds  []float64
	buckets []atomic.Uint64
	count   atomic.Uint64
	sumBits atomic.Uint64
}

func (h *Histogram) Observe(v float64) {
	h.buckets[sort.SearchFloat64s(h.bounds, v)].Add(1)
	for {
		old := h.sumBits.Load()
		next := math.Float64bits(math.Float64frombits(old) + v)
		if h.sumBits.CompareAndSwap(old, next) {
			break
		}
	}
	h.count.Add(1)
}

func (h *Histogram) Snapshot() HistogramSnapshot {
	s := HistogramSnapshot{
		Bounds: slices.Clone(h.bounds),
		Counts: make([]uint64, len(h.buckets)),
		Count:  h.count.Load(),
		Sum:    math.Float64frombits(h.sumBits.Load()),
	}
	var acc uint64
	for i := range h.buckets {
		acc += h.buckets[i].Load()
		s.Counts[i] = acc
	}
	return s
}
```

**Атомарного `float64` в Go нет — но есть его биты.** `math.Float64bits`
превращает число в `uint64` без потерь, и над ним работает CAS: прочитать
старое, посчитать новое, записать, только если за это время никто не
успел поменять. Проиграли гонку — повторяем. «`Load`, прибавить, `Store`»
теряет прибавления конкурентов (последний тест). Ровно так сделан
`Histogram` в `client_golang`.

**Храним некумулятивно, отдаём кумулятивно.** Если в `Observe` прибавлять
единицу ко всем бакетам с границей `>= v`, запись стоит O(число бакетов)
атомарных операций, и каждая — возможная борьба за кэш-линию. Один
`Add` в свой бакет, а сумму префиксов считаем в редком `Snapshot`.

**Граница включительна.** В Prometheus бакет называется `le` — «меньше
или равно». `sort.SearchFloat64s` возвращает первый индекс, где
`bounds[i] >= v`, — ровно то, что нужно, и за O(log n). Значения больше
всех границ получают индекс `len(bounds)` — это и есть бакет `+Inf`.

**Копии на входе и выходе.** Границы — часть состояния: если хранить
слайс вызывающего, он может поменять их на лету, и `SearchFloat64s`
будет искать в неотсортированном массиве. Снимок — тоже копия, иначе
получатель испортит гистограмму.

**Что спросят дальше.** Снимок не атомарен: между чтением `count` и
бакетов приходят новые наблюдения. `client_golang` решает это двумя
половинками счётчиков и «горячим» индексом, переключаемым атомарно при
чтении. И почему гистограмма, а не перцентили в процессе: бакеты можно
складывать между подами, перцентили — нельзя.
