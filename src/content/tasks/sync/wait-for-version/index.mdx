Реализуйте `Version`: монотонный номер версии и `WaitFor` — ожидание,
пока версия догонит нужную. Так делают read-your-writes на репликах:
клиент знает версию своей записи и ждёт, пока реплика её применит.
Ожидание должно уважать контекст запроса. Контракт — в doc-комментариях.

Что проверяют скрытые тесты:

- трое ждут версий 3, 5 и 10; `Set(5)` будит ровно двоих, `Set(10)` —
  третьего; `Set` меньшего значения не уменьшает версию;
- отмена контекста будит ждущего с `context.Canceled`; уже достигнутая
  версия — `nil` даже при отменённом контексте;
- двести успешных `WaitFor` с неотменённым контекстом не оставляют после
  себя горутин.

```go
type Version struct {
	mu   sync.Mutex
	cond *sync.Cond
	n    int64
}

func (v *Version) Set(n int64) {
	v.mu.Lock()
	defer v.mu.Unlock()
	if n <= v.n {
		return
	}
	v.n = n
	v.cond.Broadcast()
}

func (v *Version) WaitFor(ctx context.Context, n int64) error {
	stop := context.AfterFunc(ctx, func() {
		v.mu.Lock()
		v.cond.Broadcast()
		v.mu.Unlock()
	})
	defer stop()

	v.mu.Lock()
	defer v.mu.Unlock()
	for v.n < n {
		if err := ctx.Err(); err != nil {
			return err
		}
		v.cond.Wait()
	}
	return nil
}
```

**`Broadcast`, а не `Signal`.** Ждущие ждут *разных* условий: `Signal`
разбудит одного случайного — например, ждущего версии 10, он проверит
условие и снова уснёт, а ждущий версии 3 так и не узнает, что дождался.
Когда условия разные, — только `Broadcast`, и каждый перепроверяет своё в
цикле `for`.

**`sync.Cond` не знает про контекст — `context.AfterFunc` (Go 1.21)
это исправляет.** При отмене он запускает функцию, которая будит всех
ждущих; проснувшийся видит `ctx.Err()` и выходит. Остальные перепроверяют
условие и засыпают снова — лишнее пробуждение безопасно.

**Почему `Broadcast` в `AfterFunc` — под мьютексом.** Без него возможна
потерянная побудка: ждущий проверил `ctx.Err()` (ещё `nil`), и в этот
момент контекст отменили и отправили `Broadcast` — до того, как ждущий
дошёл до `Wait`. Сигнал ушёл в пустоту, ждущий спит вечно. Мьютекс не даёт
`Broadcast` вклиниться между проверкой и `Wait`: `Wait` отпускает мьютекс
атомарно вместе с засыпанием.

**`defer stop()` — против утечки.** Контекст запроса может жить долго
(или быть `Background`), а зарегистрированная функция живёт до его
отмены. Двести успешных ожиданий без `stop` — двести висящих регистраций.
Самодельный вариант — `go func() { <-ctx.Done(); ... }()` на каждый
вызов — течёт ещё нагляднее: двести горутин, их и ловит последний тест.

**Альтернатива без `Cond`:** канал, который закрывается и пересоздаётся
на каждый `Set`; ждущий делает `select` по этому каналу и `ctx.Done()`.
Это тоже широковещательный сигнал и вполне идиоматично.
