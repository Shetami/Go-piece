Реализуйте `Group.Do`: пока `fn` для ключа выполняется, другие вызовы с
тем же ключом ждут её результата вместо того, чтобы запускать свою.

Что проверяют скрытые тесты:

- десять одновременных вызовов с одним ключом — `fn` вызвана один раз, все
  получили результат;
- это не кэш: вызов после завершения выполняет `fn` снова;
- вызов с другим ключом не ждёт медленный вызов;
- ошибка `fn` возвращается.

<Reveal>

```go
func (g *Group) Do(key string, fn func() (int, error)) (int, error) {
	g.mu.Lock()
	if g.calls == nil {
		g.calls = make(map[string]*call)
	}
	if c, ok := g.calls[key]; ok {
		g.mu.Unlock()
		c.wg.Wait()
		return c.val, c.err
	}
	c := &call{}
	c.wg.Add(1)
	g.calls[key] = c
	g.mu.Unlock()

	c.val, c.err = fn()
	c.wg.Done()

	g.mu.Lock()
	delete(g.calls, key)
	g.mu.Unlock()
	return c.val, c.err
}
```

**Мьютекс защищает только мапу вызовов.** `fn` выполняется без него —
иначе все ключи ждали бы друг друга (третий тест).

**`WaitGroup` на каждый вызов** — механизм ожидания для опоздавших. `Add(1)`
делается под мьютексом, до того как вызов стал виден в мапе, поэтому
опоздавший никогда не позовёт `Wait` раньше `Add`.

**Почему чтение `c.val` без мьютекса безопасно.** Запись идёт до
`wg.Done()`, чтение — после `wg.Wait()`. Эта пара даёт happens-before.

**Зачем это нужно.** Кэш истёк, и в ту же миллисекунду пришла тысяча
запросов — без склейки все пойдут в базу (cache stampede). С singleflight в
базу пойдёт один. Настоящий пакет — `golang.org/x/sync/singleflight`: он ещё
сообщает, был ли результат общим, и умеет `Forget`, чтобы следующий вызов
не ждал зависший.

</Reveal>
