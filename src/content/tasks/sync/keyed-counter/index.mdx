Реализуйте `Counter`. Поля и конструктор — на ваше усмотрение.

Что проверяют скрытые тесты (с детектором гонок):

- 90 горутин по 100 инкрементов на три ключа — ровно 3000 на каждом;
- `Snapshot` — копия: её изменения не видны счётчику, и наоборот;
- `Snapshot` можно обходить, пока другие горутины пишут, — без гонки.

<Reveal>

```go
type Counter struct {
	mu sync.Mutex
	m  map[string]int
}

func (c *Counter) Snapshot() map[string]int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return maps.Clone(c.m)
}
```

**Главная ловушка — вернуть `c.m`.** Мапа — ссылочный тип. Вернув её,
вы отдаёте вызывающему доступ к внутренностям без мьютекса: он будет
читать её, пока другие горутины пишут, — и получит `concurrent map read
and map write`. Третий тест именно это и делает. Копия под мьютексом —
единственный безопасный способ.

**Мьютекс и данные рядом.** Поле `mu` стоит прямо над полем, которое
защищает. Это соглашение в Go-коде: всё, что ниже мьютекса и до пустой
строки, — под ним.

**`Counter` нельзя копировать.** В нём мьютекс, поэтому все методы — на
указателе, а конструктор возвращает `*Counter`. `go vet` (проверка
`copylocks`) предупредит, если кто-то передаст `Counter` по значению.

**Когда мьютекс станет узким местом**, счётчики шардируют: N мап с N
мьютексами, ключ выбирает шард по хешу.

</Reveal>
