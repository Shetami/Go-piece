description: Конфиг собирается через sync.Once при первом обращении. Программа зависает на первом же вызове. Почините.
kind: fix

`Config` собирает настройки один раз через `sync.Once`. Внутри сборки нужен
уже известный `host`, и его берут через `Get`. Программа падает:

```
fatal error: all goroutines are asleep - deadlock!
```

Почините. Ожидаемый вывод:

```
localhost:8080
```

<Reveal>

**`once.Do` не реентерабелен.** Пока функция внутри `Do` выполняется, все
остальные вызовы `Do` ждут её завершения — так `Once` гарантирует, что после
`Do` инициализация *закончена*, а не просто начата. Здесь функция внутри
`Do` вызывает `Get`, та — `Config`, та — снова `once.Do`. Второй вызов ждёт,
пока закончится первый, а первый ждёт второй. Та же горутина, тот же
мьютекс внутри `Once` — взаимная блокировка.

Документация так и пишет: «if f calls Do, it will deadlock».

**Как чинят** — внутри инициализации не ходить через публичный API, который
сам зависит от инициализации:

```go
once.Do(func() {
	c := map[string]string{"host": "localhost"}
	c["addr"] = c["host"] + ":8080"
	cfg = c
})
```

Заодно `cfg` присваивается один раз в конце, уже собранной мапой.

**Где это случается в жизни.** Ленивая инициализация клиента, который при
создании логирует, а логгер берёт настройки из того же клиента. Цепочка
вызовов длинная, и самоссылку видно только в трассировке стека: обе
записи про `sync.(*Once).doSlow` в одной горутине.

</Reveal>
