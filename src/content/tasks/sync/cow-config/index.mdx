Реализуйте `Holder` — хранилище конфига, который читают на каждый
запрос, а меняют редко (админка, перезагрузка по сигналу). Чтение — без
блокировок, конфиг из `Load` — неизменяемый снимок. Контракт — в
doc-комментариях.

Что проверяют скрытые тесты (с детектором гонок):

- вызывающий меняет свою мапу после `NewHolder`; старый снимок
  сравнивают с ожидаемым после `Update`;
- пятьдесят горутин одновременно делают `Update`, каждая добавляет свой
  ключ, а читатели в это время проверяют, что снимок цельный: в итоге
  версия 50 и все 50 ключей;
- пока `fn` внутри `Update` висит, `Load` из другой горутины возвращает
  старый конфиг сразу.

<Reveal>

```go
type Holder struct {
	cur atomic.Pointer[Config]
}

func (c *Config) clone() *Config {
	cp := *c
	cp.Limits = maps.Clone(c.Limits)
	if cp.Limits == nil {
		cp.Limits = map[string]int{}
	}
	return &cp
}

func (h *Holder) Load() *Config { return h.cur.Load() }

func (h *Holder) Update(fn func(c *Config)) {
	for {
		old := h.cur.Load()
		next := old.clone()
		fn(next)
		next.Version = old.Version + 1
		if h.cur.CompareAndSwap(old, next) {
			return
		}
	}
}
```

**Copy-on-write: снимки никогда не меняются.** Читатель получил
указатель — и может спокойно читать по нему сколько угодно, без
блокировок: никто этот объект больше не тронет. Писатель строит новый
конфиг рядом и одной атомарной операцией переключает указатель.

**Главная ловушка — мелкая копия.** `cp := *old` копирует структуру, но
мапа в ней — та же самая. Изменения «копии» видны в старом снимке (первый
тест), а читатели в этот момент читают мапу — `concurrent map read and
map write`. Все ссылочные поля (мапы, слайсы, указатели) копируются явно.

**Вторая ловушка — «`Load`, поменять, `Store`».** Две горутины взяли одну
и ту же версию, каждая добавила свой ключ, вторая `Store` затёрла первую.
Потерянное обновление. `CompareAndSwap(old, next)` публикует, только если
текущий указатель всё ещё тот, от которого мы строили; иначе повторяем
от свежей версии. Поэтому `fn` может вызваться несколько раз и не должна
иметь побочных эффектов.

**Писательский мьютекс — тоже правильно.** Вместо цикла CAS:
`mu.Lock(); old := Load(); ...; Store(next); mu.Unlock()`. Читатели по-прежнему
без блокировок, а писатели идут строго по очереди, и `fn` вызывается ровно
раз. Когда писателей много и `fn` дорогая, мьютекс даже лучше: цикл CAS под
конкуренцией выбрасывает работу. А вот `RWMutex` на весь конфиг не подходит —
читатели будут ждать медленную `fn` (третий тест).

**Что спросят дальше.** Почему `atomic.Pointer[T]`, а не `atomic.Value`:
типобезопасность и нет паники при смене типа. И как не дать вызывающему
испортить снимок: вернуть копию (дорого на каждом запросе) или спрятать
мапу за методом `Limit(name) int`.
