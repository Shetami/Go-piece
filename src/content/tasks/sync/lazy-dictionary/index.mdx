Реализуйте `Directory`: справочник «код → название», который грузится из
базы не при старте сервиса, а при первом `Lookup`. Контракт — в
doc-комментарии к типу.

Что проверяют скрытые тесты:

- до первого `Lookup` загрузчик не вызывается, после 50 одновременных —
  вызван ровно один раз, и все получили ответ;
- неизвестный код — `ErrUnknownCode`, ошибка загрузки видна через
  `errors.Is` в каждом `Lookup`, а сама загрузка не повторяется;
- загрузчик возвращает мапу, которую потом меняет у себя.

<Reveal>

```go
type Directory struct {
	get func() (map[string]string, error)
}

func NewDirectory(load func() (map[string]string, error)) *Directory {
	return &Directory{
		get: sync.OnceValues(func() (map[string]string, error) {
			m, err := load()
			if err != nil {
				return nil, fmt.Errorf("загрузка справочника: %w", err)
			}
			return maps.Clone(m), nil
		}),
	}
}

func (d *Directory) Lookup(code string) (string, error) {
	m, err := d.get()
	if err != nil {
		return "", err
	}
	name, ok := m[code]
	if !ok {
		return "", fmt.Errorf("%q: %w", code, ErrUnknownCode)
	}
	return name, nil
}
```

**`sync.OnceValues` (Go 1.21) — `Once` плюс запомненный результат.**
Раньше писали `once sync.Once` + поля `m` и `err` + `once.Do(...)` в
каждом методе. `OnceValues` делает то же: первый вызов выполняет функцию,
одновременные вызовы ждут его, последующие сразу возвращают сохранённые
значения.

**Мапа читается без мьютекса — и это безопасно.** Запись мапы происходит
внутри `Once`, а завершение `Once` happens-before возврата из любого
другого вызова. После этого мапа только читается, а конкурентное чтение
мапы в Go разрешено.

**Своя копия.** Если сохранить мапу загрузчика как есть, он может поменять
её позже — и справочник изменится без всякой синхронизации, то есть с
гонкой. `maps.Clone` делает справочник по-настоящему неизменяемым.

**Ошибка запоминается навсегда — осознанное решение.** Для справочника это
может быть плохо: база моргнула при старте — сервис без справочника до
перезапуска. Об этом спросят следующим вопросом: тогда нужен `Lazy`,
повторяющий неудачи (соседняя задача), или периодическая перезагрузка.
