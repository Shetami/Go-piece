Реализуйте `Semaphore`: не больше `n` одновременных владельцев. `Acquire`
ждёт свободного места, но прекращает ждать при отмене контекста.

Что проверяют скрытые тесты:

- десять горутин через семафор на два места: одновременно работают ровно
  двое;
- места нет, контекст истёк — `Acquire` возвращает `DeadlineExceeded`;
- после `Release` место снова можно занять.

<Reveal>

```go
type Semaphore struct {
	slots chan struct{}
}

func (s *Semaphore) Acquire(ctx context.Context) error {
	select {
	case s.slots <- struct{}{}:
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

func (s *Semaphore) Release() { <-s.slots }
```

**Почему канал, а не мьютекс со счётчиком.** Ожидание «пока не освободится
место или не отменят» на мьютексе пришлось бы строить через `sync.Cond`, а
`Cond` не умеет ждать контекст. Канал умеет всё сразу: `select` ждёт и
свободное место, и отмену.

**Тонкость с `select`.** Если место свободно *и* контекст уже отменён,
`select` выберет случайную готовую ветку — может и занять место. Если это
важно, проверяют `ctx.Err()` до `select`.

**`Release` без `Acquire`** здесь заблокируется навсегда (читать из пустого
канала). Во взвешенном семафоре `golang.org/x/sync/semaphore` такое —
паника. Оба варианта лучше, чем молча испортить счётчик.

**Готовое.** `golang.org/x/sync/semaphore.Weighted` — то же, но с весами:
одна задача может занять сразу несколько мест (например, по объёму памяти).

</Reveal>
