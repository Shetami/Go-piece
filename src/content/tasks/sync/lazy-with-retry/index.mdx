`sync.Once` считает вызов состоявшимся, даже если инициализация упала. Для
подключения к базе это плохо: одна неудача при старте — и сервис навсегда
без базы. Реализуйте `Lazy`, который повторяет неудачные попытки.

Что проверяют скрытые тесты:

- две неудачи — две ошибки, третья попытка успешна, после неё `init` не
  вызывается;
- 50 горутин одновременно зовут `Get`: `init` вызвана ровно один раз и
  никогда не выполнялась параллельно, все получили значение.

<Reveal>

```go
type Lazy[T any] struct {
	mu    sync.Mutex
	done  bool
	value T
}

func (l *Lazy[T]) Get(init func() (T, error)) (T, error) {
	l.mu.Lock()
	defer l.mu.Unlock()
	if l.done {
		return l.value, nil
	}
	v, err := init()
	if err != nil {
		var zero T
		return zero, err
	}
	l.value, l.done = v, true
	return v, nil
}
```

**Флаг ставится только при успехе.** В этом вся разница с `sync.Once`: у
`Once` флаг ставится в `defer` и переживает и ошибку, и панику.

**Мьютекс на время `init`.** Горутины, пришедшие во время инициализации,
ждут на мьютексе и потом видят `done == true`. Без этого все 50 запустили
бы свою инициализацию — 50 подключений к базе вместо одного.

**Цена.** Каждый `Get` берёт мьютекс, даже когда значение давно готово.
`sync.Once` оптимизирован: быстрый путь — один атомарный `Load` флага. Можно
сделать так же: `atomic.Bool` для `done`, проверка до мьютекса и повторная
— после (double-checked locking). Для большинства случаев мьютекс
достаточно быстр.

**Готовое.** `sync.OnceValues` (Go 1.21) возвращает функцию, которая
вернёт значение и ошибку, — но ошибку он тоже запоминает навсегда.

</Reveal>
