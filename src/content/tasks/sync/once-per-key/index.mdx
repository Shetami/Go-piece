Реализуйте `OnceMap` — «`sync.Once` на каждый ключ». Типичное
применение: подключение к каждому шарду базы, скомпилированный шаблон
на каждое имя, клиент на каждый хост. Нулевое значение готово к работе,
контракт — в doc-комментарии к `Get`.

Что проверяют скрытые тесты (с детектором гонок):

- 60 горутин запрашивают три ключа — `init` каждого вызван ровно один
  раз, все получили свои значения;
- ошибка `init` запоминается для ключа, повторно `init` не зовётся;
- пока `init` одного ключа висит, `Get` другого ключа отвечает сразу.

<Reveal>

```go
type OnceMap[K comparable, V any] struct {
	mu sync.Mutex
	m  map[K]func() (V, error)
}

func (m *OnceMap[K, V]) Get(key K, init func(K) (V, error)) (V, error) {
	m.mu.Lock()
	if m.m == nil {
		m.m = make(map[K]func() (V, error))
	}
	get, ok := m.m[key]
	if !ok {
		get = sync.OnceValues(func() (V, error) { return init(key) })
		m.m[key] = get
	}
	m.mu.Unlock()
	return get()
}
```

**Два уровня блокировки.** Общий мьютекс защищает только мапу и держится
наносекунды: найти или положить «обещание». Долгая работа идёт внутри
`OnceValues` конкретного ключа — там ждут только те, кому нужен этот же
ключ. Вызвать `init` под общим мьютексом — значит, один медленный шард
остановит обращения ко всем остальным (третий тест).

**Почему не «проверил — отпустил — создал — положил».** Если искать
ключ под мьютексом, а создавать значение после `Unlock`, две горутины
одновременно увидят промах и обе вызовут `init` — два подключения к
базе, одно из которых утечёт. Регистрация обещания под мьютексом делает
выбор победителя атомарным.

**А `sync.Map.LoadOrStore`?** Тоже работает:
`v, _ := sm.LoadOrStore(key, sync.OnceValues(...))`. Но замыкание
`OnceValues` создаётся на каждый вызов, даже если ключ уже есть, — лишняя
аллокация на горячем пути. Лечится сначала `Load`, и только при промахе
`LoadOrStore`. `sync.Map` оправдан, когда ключи в основном читаются и
множество ключей стабильно — ровно этот случай.

**Что спросят дальше.** Ошибка запомнена навсегда — как перезапускать?
Удалять запись из мапы при ошибке (осторожно: удалить нужно именно то
обещание, которое упало, а не новое, успевшее встать на его место). И как
закрыть все созданные клиенты при остановке: обойти мапу и вызвать
`Close` у тех, что инициализировались успешно.
