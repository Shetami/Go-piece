Реализуйте обобщённый `Batcher`: элементы копятся и уходят в `flush`
пачками по `size`. `Add` зовут из многих горутин, `flush` пишет в базу и
может быть медленным. Контракт — в doc-комментарии.

Что проверяют скрытые тесты (с детектором гонок):

- `flush` сохраняет полученные пачки у себя, а потом их сравнивают с
  ожидаемыми; `Flush` без накопленного не зовёт `flush`;
- восемь горутин по 500 `Add`: каждый элемент ушёл во `flush` ровно один
  раз, пачки не пустые и не больше `size`;
- пока `flush` первой пачки висит, `Add` из другой горутины не ждёт его.

<Reveal>

```go
type Batcher[T any] struct {
	mu    sync.Mutex
	size  int
	buf   []T
	flush func([]T)
}

func (b *Batcher[T]) Add(v T) {
	b.mu.Lock()
	b.buf = append(b.buf, v)
	var batch []T
	if len(b.buf) >= b.size {
		batch = b.takeLocked()
	}
	b.mu.Unlock()
	if batch != nil {
		b.flush(batch)
	}
}

func (b *Batcher[T]) Flush() {
	b.mu.Lock()
	batch := b.takeLocked()
	b.mu.Unlock()
	if len(batch) > 0 {
		b.flush(batch)
	}
}

func (b *Batcher[T]) takeLocked() []T {
	if len(b.buf) == 0 {
		return nil
	}
	batch := b.buf
	b.buf = make([]T, 0, b.size)
	return batch
}
```

**Ловушка первая — `b.buf = b.buf[:0]`.** Выглядит как экономия
памяти, но пачка, отданная во `flush`, и новый `buf` смотрят в один и тот
же массив. Следующие `append` перезапишут элементы, которые `flush`
сохранил или ещё отправляет в базу. Под мьютексом — это тихая порча
данных, а если `flush` читает пачку в другой горутине — ещё и гонка.
Нужен новый массив на каждую пачку.

**Ловушка вторая — `flush` под мьютексом.** Проще всего написать
`defer b.mu.Unlock()` в начале `Add`, но тогда запись в базу держит всех
писателей: сервис с батчером работает медленнее, чем без него. Под
мьютексом — только «забрать пачку», отправка — после `Unlock`.

**Цена такого решения — порядок.** Две пачки могут уйти во `flush`
одновременно из разных горутин, и вторая может записаться раньше первой.
Если порядок важен (лог событий), нужен один писатель — отдельная горутина
с каналом — или второй мьютекс только на `flush`.

**Что спросят дальше.** Как не держать элементы вечно, если поток
иссяк? Добавить сброс по таймеру (`time.AfterFunc` при первом элементе
пачки) и `Close`, который сбрасывает остаток при остановке сервиса.
