`Counter` защищён мьютексом, `Inc` вызывают тысячу раз подряд — даже без
горутин. Программа печатает:

```
счётчик: 0
```

Отметьте строку, в которой заложена поломка. Запустите код: `go vet` скажет
почти то же самое, что и разбор.

<Reveal>

Сломано в строке 14: `func (c Counter) Inc()` — приёмник **по значению**.

**Метод с приёмником-значением получает копию структуры.** `c.n++` увеличивает
поле копии, копия умирает вместе с вызовом, оригинал остаётся нулём. Тысяча
вызовов — тысяча копий, и ни одна не дожила.

Заодно копируется и мьютекс. `c.mu.Lock()` блокирует замок копии, который
никому не нужен и никого не защищает. Это вторая беда, и `go vet` ругается
именно на неё:

```
Inc passes lock by value: Counter contains sync.Mutex
```

Обратите внимание: `Value` объявлен правильно, через `*Counter`, — поэтому он
читает настоящее поле и честно показывает ноль.

**Как чинят** — одним символом:

```go
func (c *Counter) Inc() {
```

**Почему вызов вообще скомпилировался.** `c` — адресуемая переменная, поэтому
Go сам подставляет `(&c).Value()` там, где метод требует указателя, и `c.Inc()`
там, где требуется значение. Эта любезность и прячет ошибку: код выглядит
одинаково в обоих случаях.

**Правило, которое стоит унести.** Если у типа есть хоть один метод с
приёмником-указателем — делайте указателями **все** его методы. Смешивать
приёмники можно, но тогда легко получить ровно эту историю. И отдельно: тип,
внутри которого лежит `sync.Mutex`, `sync.WaitGroup`, `sync.Once` или
`strings.Builder`, нельзя копировать вообще — ни в приёмнике, ни в аргументе,
ни присваиванием.

**Что спросят следом.** Почему здесь нет гонки (горутин нет — писать
одновременно некому) и что было бы, будь `Inc` правильным, а `n` — без
мьютекса: вот тогда была бы гонка, и поймал бы её `go build -race`.

</Reveal>
