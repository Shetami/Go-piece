В цепочке есть ошибка с методом `Status()`, её ищут через `errors.As` по
интерфейсу. Программа падает:

```
panic: errors: target cannot be nil
```

Почините. Ожидаемый вывод:

```
код 404
```

<Reveal>

**`errors.As` записывает найденное в цель, поэтому цель — указатель на
переменную.** `se` — переменная интерфейсного типа, и её значение сейчас
`nil`. Передав `se`, мы передали `nil`: записывать некуда. `errors.As`
проверяет цель первым делом и паникует — это ошибка программиста, а не
данных. Будь в `se` что-то ненулевое, паника была бы другой — «target must
be a non-nil pointer»: не-указатель ему тоже не годится.

```go
var se StatusError
errors.As(err, &se)
```

**Цель-интерфейс — полезный приём.** `errors.As` ищет в цепочке любую ошибку,
которая реализует `StatusError`, — не зная её конкретного типа. Так нижние
слои могут возвращать свои типы, а обработчик HTTP — вытаскивать из любого
из них код ответа.

**`go vet` ловит эту ошибку** (проверка `errorsas`: «second argument to
errors.As must be a non-nil pointer to either a type that implements error,
or to any interface type»). Кнопка «Запустить» его вызывает, так что
подсказка была прямо под кодом.

</Reveal>
