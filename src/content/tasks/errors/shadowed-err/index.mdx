`parseAll` разбирает строки и должна вернуть ошибку, если хоть одна не
разобралась. В списке есть «два». Программа печатает:

```
[1 3] <nil>
false
```

Числа собраны верно, а ошибка потерялась. Отметьте строку, в которой заложена
поломка.

<Reveal>

Сломано в строке 15: `n, err := strconv.Atoi(s)`.

**`:=` внутри цикла объявляет новую переменную, а не пишет во внешнюю.** В теле
цикла своя область видимости; раз слева от `:=` есть хотя бы одно новое имя
(`n`), оператор объявляет **оба** — и `n`, и `err`. Внутренний `err` живёт одну
итерацию и умирает, а внешний, объявленный выше через `var err error`, так и
остаётся `nil`.

Компилятор молчит: внутренний `err` используется в `if err != nil`, внешний —
в проверке после цикла. Формально всё занято делом.

**Как чинят.** Первое, что приходит в голову, — объявить `n` отдельно и
присваивать, а не объявлять:

```go
var n int
n, err = strconv.Atoi(s)
```

Но этого мало. Теперь `err` один на весь цикл, и следующая итерация его
перезаписывает: `"3"` разбирается успешно, и `err` снова `nil`. Ошибка
теряется уже не из-за затенения, а из-за `continue`. Первую ошибку надо
запомнить отдельно и больше не трогать:

```go
n, e := strconv.Atoi(s)
if e != nil {
	if err == nil {
		err = e
	}
	continue
}
```

**Как это ловят на практике.** `go vet` затенение не ищет. Есть
`go vet -vettool` с анализатором `shadow` и линтер `govet(shadow)` в
`golangci-lint` — но они шумные, потому что затенение в Go сплошь и рядом
совершенно законно. Надёжнее привычка: увидел `err :=` внутри блока, где `err`
уже есть снаружи, — остановись и посмотри.

**Заодно про вторую строку вывода.** `errors.Is(err, strconv.ErrSyntax)` даёт
`false` просто потому, что `err` здесь `nil`. Но даже почини мы затенение,
ответ был бы `true` только благодаря `%w` в `fmt.Errorf`: именно он строит
цепочку, по которой идёт `errors.Is`. С `%v` обёртка получилась бы
«плоской» — текст сохранился бы, а связь с исходной ошибкой пропала.

**Что спросят следом.** Разницу между `errors.Is` (сравнить с конкретной
ошибкой-значением) и `errors.As` (достать ошибку нужного типа), и почему
`strconv.Atoi` возвращает `*strconv.NumError`, который оборачивает
`ErrSyntax` — то есть цепочка здесь и так двухзвенная ещё до нашей обёртки.

</Reveal>
