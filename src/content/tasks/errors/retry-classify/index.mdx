Клиент внешнего API повторяет запросы. Решение «повторять или нет»
принимается не по тексту и не по конкретному типу ошибки, а по её
**поведению**: как у `net.Error`, у временных ошибок есть метод
`Temporary() bool`, а сервер, ответивший «429, приходите через секунду»,
отдаёт ошибку с `RetryAfter()`.

Напишите `Retry` по контракту в заготовке.

Что проверяют скрытые тесты:

- паузы растут `10ms, 20ms, 25ms` — удвоение с потолком;
- постоянная ошибка (без `Temporary` или с `Temporary() == false`
  глубже в цепочке) возвращается как есть — после одного вызова и без пауз;
- попытки кончились — пауз на одну меньше, чем попыток, ошибка
  оборачивает последнюю и упоминает их число;
- `RetryAfter` сервера больше `Max` — ждём, сколько сказал сервер;
- таймаут одной попытки (`context.DeadlineExceeded` из `f`) при живом
  внешнем контексте повторяется;
- отменённый контекст — `f` не вызывается; отмена во время паузы —
  ошибка, в которой видно и отмену, и последнюю ошибку `f`;
- восемьдесят попыток с базой в секунду — ни одна пауза не становится
  отрицательной.

<Reveal>

```go
func Retry(ctx context.Context, p Policy, f func(context.Context) error) error {
	if err := ctx.Err(); err != nil {
		return err
	}
	sleep := p.Sleep
	if sleep == nil {
		sleep = sleepCtx
	}
	delay := p.Base
	var last error
	for attempt := 1; ; attempt++ {
		last = f(ctx)
		if last == nil {
			return nil
		}
		if !isTemporary(last) {
			return last
		}
		if attempt >= p.Attempts {
			return fmt.Errorf("после %d попыток: %w", attempt, last)
		}
		wait := min(delay, p.Max)
		var ra interface{ RetryAfter() time.Duration }
		if errors.As(last, &ra) {
			wait = max(wait, ra.RetryAfter())
		}
		if delay < p.Max {
			delay *= 2
		}
		if err := sleep(ctx, wait); err != nil {
			return fmt.Errorf("повтор прерван: %w (последняя ошибка: %w)", err, last)
		}
		if err := ctx.Err(); err != nil {
			return fmt.Errorf("повтор прерван: %w (последняя ошибка: %w)", err, last)
		}
	}
}

func isTemporary(err error) bool {
	var t interface{ Temporary() bool }
	return errors.As(err, &t) && t.Temporary()
}
```

**`errors.As` умеет искать интерфейс.** Цель — указатель на переменную
интерфейсного типа, и `As` находит первое звено цепочки, которое этот
интерфейс реализует. Так проверяют поведение, не завязываясь на типы
чужих пакетов. Важно проверить и результат метода: звено с
`Temporary() == false` — это явное «не повторять», а не «не знаю».

**`context.DeadlineExceeded` — временная ошибка.** Её тип реализует
`Timeout()` и `Temporary()`, оба возвращают `true`. Поэтому таймаут одной
попытки повторяется «сам» — при условии, что жив *внешний* контекст. Его
проверяем отдельно: перед первой попыткой и после каждой паузы.

**Две ошибки в одной через два `%w`.** С Go 1.20 `fmt.Errorf` принимает
несколько `%w`, и результат реализует `Unwrap() []error`. Вызывающему
нужно и то, и другое: `errors.Is(err, context.Canceled)`, чтобы не
писать в лог «сбой API», и последняя ошибка — чтобы понять, что
происходило до отмены.

**Переполнение.** `Base << attempt` при `Base = 1s` уходит в минус
примерно на 34-м шаге, и `min(отрицательное, Max)` даёт отрицательную
паузу — то есть повторы без пауз, ровно в момент, когда сервис лежит.
Удваивать нужно, только пока не достигнут потолок.

**Что спросят дальше.** Джиттер (иначе все клиенты повторяют синхронно),
бюджет повторов на уровне сервиса, идемпотентность повторяемых запросов
и почему повторять надо на одном уровне стека, а не на каждом.
