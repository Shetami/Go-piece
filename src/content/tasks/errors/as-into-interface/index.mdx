Таймауты надо повторять, остальные ошибки — нет. Проверка — через
приведение к интерфейсу с методом `Timeout`, как у `net.Error`. Программа
печатает:

```
0 фатально: fetch 0: сеть недоступна
1 фатально: fetch 1: сеть недоступна
2 фатально: fetch 2: сеть недоступна
3 фатально: fetch 3: сеть недоступна
```

Почините. Ожидаемый вывод:

```
0 таймаут — повторим
1 фатально: fetch 1: сеть недоступна
2 таймаут — повторим
3 фатально: fetch 3: сеть недоступна
```

<Reveal>

**Приведение типа смотрит только на верхнее звено.** `err` — обёртка от
`fmt.Errorf`, у неё нет метода `Timeout`. Сам `*netErr` лежит уровнем
ниже, и `err.(...)` до него не дотягивается.

**`errors.As` умеет искать интерфейсы.** Целью может быть указатель на
переменную интерфейсного типа — тогда `As` ищет в цепочке первое звено,
которое этот интерфейс реализует:

```go
var t interface{ Timeout() bool }
if errors.As(err, &t) && t.Timeout() {
```

**Где это важно на практике.** `net/http` оборачивает сетевые ошибки в
`*url.Error`, свои обёртки добавляют библиотеки. Проверка `err.(net.Error)`
на реальном коде ломается от первого же `fmt.Errorf("...: %w", err)`.

</Reveal>
