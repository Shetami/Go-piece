Когда товара нет, покупателю надо предложить аналог. Программа печатает:

```
ошибка: резерв "книга": нет на складе
```

Почините. Ожидаемый вывод:

```
предложим аналог
```

<Reveal>

**`==` сравнивает только само значение ошибки.** `reserve` возвращает не
`ErrNoStock`, а обёртку над ней — новое значение типа `*fmt.wrapError`. Оно
не равно `ErrNoStock`, хотя содержит её внутри.

**`errors.Is` разворачивает цепочку:** проверяет саму ошибку, потом то, что
вернёт `Unwrap`, и так до конца. Находит `ErrNoStock` на втором звене.

```go
if errors.Is(err, ErrNoStock) { ... }
```

**Правило.** После Go 1.13 сравнивать ошибки через `==` имеет смысл только
если вы уверены, что их никто не оборачивает. А уверенным быть нельзя:
обёртку может добавить любой слой между вами и источником. Поэтому
`errors.Is` — всегда. Линтер `errorlint` ищет именно `==` и приведения типа
на ошибках.

Исключение — `io.EOF`: по соглашению его возвращают без обёрток, и
`err == io.EOF` в циклах чтения встречается повсеместно. Но и там
`errors.Is` не хуже.

</Reveal>
