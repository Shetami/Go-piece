`read` возвращает обёрнутый `TimeoutError`, и программа должна его
распознать и повторить запрос. Вместо этого:

```
сдаёмся: чтение конфига: read: таймаут
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 19: `var te *TimeoutError`.

**`errors.As` ищет ошибку ровно того типа, что у цели.** В цепочке лежит
`TimeoutError` — значение: так её создали в `read`. А цель — переменная типа
`*TimeoutError`. Для `As` это разные типы: значение нельзя присвоить
указателю. Совпадения нет, `false`.

`go vet` тут не поможет: `*TimeoutError` тоже реализует `error` (набор
методов указателя включает методы значения), так что вызов формально
корректен.

**Как правильно** — тип цели совпадает с тем, как ошибку создают:

```go
var te TimeoutError
if errors.As(err, &te) { ... }
```

**Как избегать путаницы.** Для каждого своего типа ошибки выберите один
способ — значение или указатель — и держитесь его. Самый частый вариант:
метод `Error` на указателе и возврат `&MyError{...}`. Тогда значение
`MyError` вообще не реализует `error`, и перепутать не получится: vet
поймает `As` с неправильной целью.

</Reveal>
