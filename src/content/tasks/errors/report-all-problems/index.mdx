У пользователя пустое имя, неправильный email и отрицательный возраст.
`validate` сообщает только первое:

```
пустое имя
<nil>
```

Почините. Ожидаемый вывод:

```
пустое имя
email без @
отрицательный возраст
<nil>
```

<Reveal>

**`return` на первой ошибке — это правильно для операций, но не для
валидации.** Если открыть файл не удалось, писать в него бессмысленно — надо
выходить. А проверки полей независимы, и пользователю удобнее увидеть все
сразу, чем исправлять форму в три захода.

**Как чинят** — копить ошибки и объединить через `errors.Join` (Go 1.20):

```go
var errs []error
if u.Name == "" {
	errs = append(errs, errors.New("пустое имя"))
}
...
return errors.Join(errs...)
```

`errors.Join` удобен тремя вещами:

- без ошибок возвращает `nil` — не нужно отдельно проверять `len(errs)`;
- `Error()` склеивает тексты через перевод строки;
- `errors.Is` и `errors.As` видят каждую ошибку внутри — можно проверить,
  была ли среди них конкретная.

**Если нужна структура**, а не текст — например, чтобы подсветить поля в
форме, — лучше свой тип: `type ValidationError struct{ Field, Msg string }`,
а наружу `errors.Join` таких ошибок. Клиент достанет их через `errors.As`
или обход `Unwrap() []error`.

</Reveal>
