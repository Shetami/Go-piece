В большом сервисе ошибки удобно классифицировать деревом кодов:
`db.conn.timeout`, `db.conn.refused`, `db.query.syntax`. Алерт по базе
хочет ловить всё семейство `db`, ретраер — `db.conn`, а обработчик
конкретного случая — точный код. Хочется писать это одинаково:
`errors.Is(err, Code("db"))`.

Реализуйте методы `Code` и `E` и функцию `CodeOf`.

Что проверяют скрытые тесты:

- код совпадает с собой и со всеми предками, но не с «кусками сегмента»
  (`d`, `db.co`), не с потомками и не с пустым кодом;
- голый `Code`, обёрнутый через `%w`, тоже понимает иерархию;
- текст `E` — с причиной и без;
- у внешнего и внутреннего `E` разные коды — `errors.Is` находит оба
  семейства и причину под ними;
- `CodeOf` возвращает код самого внешнего `E`.

<Reveal>

```go
func (c Code) Is(target error) bool {
	t, ok := target.(Code)
	if !ok || t == "" {
		return false
	}
	return c == t || strings.HasPrefix(string(c), string(t)+".")
}

func (e *E) Error() string {
	s := string(e.Code) + ": " + e.Msg
	if e.Err != nil {
		s += ": " + e.Err.Error()
	}
	return s
}

func (e *E) Unwrap() error { return e.Err }

func (e *E) Is(target error) bool { return e.Code.Is(target) }

func CodeOf(err error) Code {
	var e *E
	if errors.As(err, &e) {
		return e.Code
	}
	return ""
}
```

**Метод `Is` расширяет равенство.** `errors.Is` для каждого звена
сначала сравнивает `==`, а потом спрашивает `Is(target)`, если метод есть.
Сравнение `==` даст только точный код; иерархию добавляет наш метод.

**Сегменты, а не строки.** `strings.HasPrefix(c, t)` скажет, что `db` —
предок `dbx.fail`, а `db.co` — предок `db.conn`. Префикс с точкой
(`t + "."`) плюс точное совпадение — и сравнение идёт целыми сегментами.

**`Is` не должен ходить по цепочке сам.** Спуск в `e.Err` делает
`errors.Is` через `Unwrap`. Если `E.Is` ещё и вызовет `errors.Is(e.Err,
target)`, работа удвоится на каждом уровне, а при цикле — зависнет.
Метод отвечает только за своё звено.

**Метод и у `Code`, и у `E`.** Голый `Code` в цепочке — тоже звено, и без
своего `Is` он совпадёт только точно. У `E` метод свой, потому что `E` —
не `Code`, хоть и содержит его. Строковый тип удобен ещё и тем, что он
сравним: `errors.Is` не споткнётся о несравнимые значения.

**Что спросят дальше.** Почему не строка в тексте ошибки (парсить тексты
— хрупко), как отдавать код клиенту и в метрики (низкая кардинальность —
отсюда и иерархия) и где провести границу между кодом и типом ошибки.
