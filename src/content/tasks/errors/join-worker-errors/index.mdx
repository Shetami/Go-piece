Ночной импорт обрабатывает тысячи строк. Одна битая строка не должна
останавливать остальные, а в отчёте нужны **все** неудачи — и так, чтобы
их было удобно читать и проверять кодом.

Напишите `ProcessAll`: пул из `workers` горутин вызывает `f` для каждого
элемента и собирает ошибки.

Что проверяют скрытые тесты:

- всё успешно (и пустой вход) → настоящий `nil`;
- элементы завершаются в обратном порядке, а текст ошибки всё равно
  идёт по индексам: `item 1: …`, потом `item 3: …`;
- `errors.Is` и `errors.As` находят исходные ошибки `f` сквозь обёртку
  и объединение;
- одновременно работает не больше `workers` вызовов, но параллельность есть;
- ни одна ошибка не потеряна, даже если падают все двадцать;
- горутины пула не остаются висеть после возврата.

<Reveal>

```go
func ProcessAll(items []string, workers int, f func(string) error) error {
	errs := make([]error, len(items))
	jobs := make(chan int)

	var wg sync.WaitGroup
	for range min(workers, len(items)) {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for i := range jobs {
				if err := f(items[i]); err != nil {
					errs[i] = fmt.Errorf("item %d: %w", i, err)
				}
			}
		}()
	}
	for i := range items {
		jobs <- i
	}
	close(jobs)
	wg.Wait()
	return errors.Join(errs...)
}
```

**Слот на элемент вместо общего слайса.** Очевидное решение —
`errs = append(errs, err)` под мьютексом. Оно работает, но порядок ошибок
становится порядком завершения: от запуска к запуску отчёт разный, и тест
«ожидаемый текст» мигает. Слайс `errs[i]` решает обе задачи сразу: каждая
горутина пишет в свою ячейку (гонки нет — это разные переменные), а
порядок задан индексом.

**`errors.Join` пропускает `nil`.** Поэтому слайс с дырами можно отдать
целиком, а если дыры все — вернётся настоящий `nil`, а не пустая
«мультиошибка». Своя структура с `[]error` здесь опасна: вернуть
`*MultiErr(nil)` как `error` — классическая ловушка с ненулевым
интерфейсом.

**`%w`, а не `%v`.** Номер элемента нужен человеку, а исходная ошибка —
коду: `errors.Is(err, ErrBadRow)` или `errors.As(err, &numErr)` должны
пройти сквозь обе обёртки — и `fmt.Errorf`, и `Join` (у него
`Unwrap() []error`).

**`wg.Wait()` — это ещё и синхронизация памяти.** Чтение `errs` после
`Wait` видит все записи воркеров. Без `Wait` (например, «подождём
`time.Sleep`») это гонка, даже если на практике «успевает».

**Что спросят дальше.** Как остановить обработку после N ошибок (счётчик
плюс отмена контекста), как не держать в памяти миллион ошибок (хранить
первые K и счётчик остальных), и чем это отличается от `errgroup`, который
возвращает только первую ошибку.
