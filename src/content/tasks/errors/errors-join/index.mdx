`errors.Join` объединяет две ошибки и `nil` между ними. Потом то же самое
делают через `fmt.Errorf` с двумя `%w`. Проверяют `errors.Is`,
`errors.Unwrap` и объединение одних `nil`.

Напишите весь вывод программы.

<Reveal>

**`errors.Join` пропускает `nil` и склеивает тексты переводом строки.**
Поэтому первый `Println` даёт две строки: `нет диска` и `нет сети`.

**`errors.Is` видит обе.** С Go 1.20 у ошибки может быть метод
`Unwrap() []error`, и `Is` с `As` обходят такие ошибки как дерево — в глубину,
по порядку.

**А `errors.Unwrap` — нет.** Функция `errors.Unwrap` вызывает только
`Unwrap() error` — с одним результатом. У объединённой ошибки такого метода
нет, и `Unwrap` возвращает `nil`. Код, который вручную крутит цикл
`for err != nil { err = errors.Unwrap(err) }`, на таких ошибках
останавливается сразу.

**`errors.Join` из одних `nil` возвращает `nil`.** Это удобно: можно
копить ошибки и в конце вернуть `errors.Join(errs...)`, не проверяя, были ли
они.

**Два `%w` в `fmt.Errorf`** дают то же дерево: `Is` находит обе, `Unwrap` —
`nil`. Отличается только текст: тут он собран по формату, через `; `.

Итого:

```
нет диска
нет сети
true true
true
true
нет диска; нет сети true true
```

</Reveal>
