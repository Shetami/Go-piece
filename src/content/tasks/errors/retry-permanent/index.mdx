Напишите `Retry`.

Что проверяют скрытые тесты:

- успех на третьей попытке — `nil`, ровно три вызова;
- все попытки неудачны — ровно `attempts` вызовов, итоговая ошибка
  оборачивает последнюю (`errors.Is`) и упоминает число попыток;
- ошибка, обёрнутая вокруг `ErrPermanent`, возвращается сразу, после одного
  вызова.

<Reveal>

```go
func Retry(attempts int, f func() error) error {
	var err error
	for range attempts {
		err = f()
		if err == nil {
			return nil
		}
		if errors.Is(err, ErrPermanent) {
			return err
		}
	}
	return fmt.Errorf("после %d попыток: %w", attempts, err)
}
```

**Пометка через обёртку.** Постоянная ошибка не обязана *быть*
`ErrPermanent` — достаточно обернуть её: `fmt.Errorf("неверный пароль: %w",
ErrPermanent)`. `errors.Is` найдёт пометку в цепочке, а текст останется
информативным. Это удобнее отдельного типа, когда категорий немного.

**Почему важно не повторять.** Неверный пароль, 404, ошибка валидации не
исправятся от повтора. Зато повтор умножает нагрузку и задерживает ответ.
В худшем случае — блокирует учётную запись после N неверных попыток.

**Чего не хватает до боевого варианта.** Паузы между попытками с
экспоненциальным ростом и разбросом, контекста для отмены (см. задачу
«Повторы, которые не слышат таймаут») и бюджета повторов на уровне
сервиса, чтобы при сбое зависимости повторы не превратились в лавину.

</Reveal>
