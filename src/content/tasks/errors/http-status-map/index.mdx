Сервисный слой возвращает доменные ошибки, а в HTTP-обработчике их надо
превратить в статус и тело ответа. Делают это в одном месте, чтобы каждый
обработчик не изобретал свои правила.

Напишите `Respond` по таблице в заготовке.

Что проверяют скрытые тесты:

- `nil` → `200`;
- сентинелы находятся сквозь несколько слоёв `fmt.Errorf("…: %w")`;
- для `*ValidationError` в тело идёт только её текст, а не вся цепочка
  «handler: сохранить заказ: …»;
- `context.DeadlineExceeded` и `context.Canceled` — разные коды;
- в `errors.Join` из нескольких ошибок побеждает правило, которое выше в
  таблице;
- текст неизвестной ошибки (с логином к базе) наружу не попадает.

<Reveal>

```go
func Respond(err error) (int, string) {
	if err == nil {
		return 200, ""
	}
	var ve *ValidationError
	if errors.As(err, &ve) {
		return 400, ve.Error()
	}
	switch {
	case errors.Is(err, ErrNotFound):
		return 404, "не найдено"
	case errors.Is(err, ErrForbidden):
		return 403, "доступ запрещён"
	case errors.Is(err, ErrConflict):
		return 409, "конфликт"
	case errors.Is(err, context.DeadlineExceeded):
		return 504, "таймаут"
	case errors.Is(err, context.Canceled):
		return 499, "запрос отменён"
	}
	return 500, "внутренняя ошибка"
}
```

**Сравнение `==` и `switch err {}` здесь не работают.** Между сервисом и
обработчиком ошибку оборачивают два-три раза, и сравнивается уже обёртка.
`errors.Is` идёт по цепочке `Unwrap`, а для `errors.Join` — по всем
веткам.

**Тело 400 — из найденного звена.** `errors.As` отдаёт само звено
`*ValidationError`, и клиенту уходит `ve.Error()`, а не `err.Error()` с
названиями внутренних функций.

**Порядок правил — это решение, а не случайность.** Если одна ошибка
содержит и «не найдено», и «невалидно», клиенту полезнее узнать, что он
сам прислал неправильно. Порядок проверок в `switch` и есть приоритет,
поэтому его держат в одном месте.

**499 и 504.** `Canceled` означает, что клиент сам ушёл: это не наша
авария, её не надо считать в SLO как 5xx. `DeadlineExceeded` — мы не
уложились, и это наша проблема. Смешать их — значит либо пропустить
деградацию, либо будить дежурного из-за закрытых вкладок.

**Что спросят дальше.** Где логировать полную ошибку (здесь же, для
5xx), как сделать тело ответа структурным (код ошибки плюс сообщение) и
почему доменный слой не должен знать про HTTP-коды.
