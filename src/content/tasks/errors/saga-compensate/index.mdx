Оформление заказа — несколько вызовов разных сервисов: зарезервировать
товар, заблокировать деньги, списать, отправить. Общей транзакции нет,
поэтому при сбое на середине выполненные шаги отменяют компенсациями:
разблокировать деньги, снять резерв. Это сага.

Реализуйте `Run` и методы `SagaError`.

Что проверяют скрытые тесты:

- всё прошло → настоящий `nil`;
- упал шаг — выполненные шаги откатываются в обратном порядке, упавший и
  последующие не трогаются, шаги без компенсации пропускаются;
  `*SagaError` с именем шага, причиной и текстом;
- компенсация упала — остальные всё равно выполняются; ошибки
  компенсаций собраны по порядку, обёрнуты, `errors.Is` находит и их, и
  причину, текст сообщает их число;
- контекст отменили посреди саги — следующий шаг не выполняется,
  `SagaError` указывает на него с `context.Canceled`, а компенсации
  получают неотменённый контекст.

<Reveal>

```go
func (e *SagaError) Error() string {
	s := fmt.Sprintf("сага: шаг %s: %v", e.Step, e.Err)
	if n := len(e.Compensation); n > 0 {
		s += fmt.Sprintf("; компенсаций не удалось: %d", n)
	}
	return s
}

func (e *SagaError) Unwrap() []error {
	return append([]error{e.Err}, e.Compensation...)
}

func Run(ctx context.Context, steps []Step) error {
	for i, s := range steps {
		err := ctx.Err()
		if err == nil {
			err = s.Do(ctx)
		}
		if err != nil {
			return &SagaError{Step: s.Name, Err: err, Compensation: compensate(ctx, steps[:i])}
		}
	}
	return nil
}

func compensate(ctx context.Context, done []Step) []error {
	cctx := context.WithoutCancel(ctx)
	var errs []error
	for i := len(done) - 1; i >= 0; i-- {
		s := done[i]
		if s.Compensate == nil {
			continue
		}
		if err := s.Compensate(cctx); err != nil {
			errs = append(errs, fmt.Errorf("компенсация %s: %w", s.Name, err))
		}
	}
	return errs
}
```

**Одна ошибка, в которой вся история.** Вызывающему нужно знать три
вещи: где сломалось, почему и удалось ли откатиться. `SagaError` несёт
всё это, а `Unwrap() []error` делает каждую часть доступной для
`errors.Is`: код, который ждёт «карта отклонена», продолжает работать, а
алерт на «возврат не прошёл» тоже срабатывает. Неудачная компенсация —
самая опасная ситуация (деньги списаны, заказа нет), её нельзя
проглатывать.

**Откат не останавливается на первой ошибке.** Если возврат денег упал,
резерв товара всё равно нужно снять. Ошибки копятся, а не прерывают
цикл.

**`context.WithoutCancel` (Go 1.21).** Самая частая причина провала
саги — отмена: клиент закрыл вкладку, истёк дедлайн. Передав компенсациям
тот же `ctx`, мы получим мгновенный `context canceled` на каждом откате —
и полусделанную операцию навсегда. `WithoutCancel` сохраняет значения
(trace ID, пользователь), но не отмену; свой таймаут для отката лучше
добавить отдельно.

**Проверка контекста перед шагом.** Иначе отменённая сага продолжит
списывать деньги, пока какой-нибудь шаг сам не заметит отмену.
`Err = ctx.Err()` честно говорит, что шаг не выполнялся.

**Что спросят дальше.** Компенсации должны быть идемпотентными (их
повторяют после рестарта), где хранить состояние саги, чтобы пережить
падение процесса, и чем оркестрация отличается от хореографии.
