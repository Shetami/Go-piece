Ошибку-значение `ErrNotFound` оборачивают двумя способами, печатают,
проверяют через `errors.Is`, сравнивают тексты. В конце создают ещё одну
ошибку с тем же текстом и сравнивают с оригиналом.

Напишите весь вывод программы.

<Reveal>

**Текст у обёрток одинаковый.** И `%w`, и `%v` подставляют `Error()`
вложенной ошибки. Печать обеих даёт одну и ту же строку.

**Разница — в цепочке.** `%w` создаёт значение типа `*fmt.wrapError`, у
которого есть метод `Unwrap`, возвращающий `ErrNotFound`. `errors.Is` идёт по
этой цепочке и находит совпадение. С `%v` получается обычная ошибка с
текстом, `Unwrap` у неё нет, и связь с исходной ошибкой потеряна:
`errors.Is` — `false`.

**Ошибки-значения сравниваются по указателю.** `errors.New` возвращает
`*errors.errorString`, и каждый вызов — новый указатель. Два `errors.New` с
одинаковым текстом не равны. Поэтому сентинел-ошибки объявляют один раз на
уровне пакета и сравнивают именно с ними.

Итого:

```
загрузка профиля: не найдено
загрузка профиля: не найдено
true false
true
false
```

**Когда `%v` правильный выбор.** Когда вы *не хотите* делать внутреннюю
ошибку частью своего API. Обернув через `%w` ошибку драйвера базы, вы
обещаете вызывающим, что `errors.Is(err, sql.ErrNoRows)` будет работать и
дальше, — и сменить драйвер уже сложнее. Обёртка через `%v` оставляет текст
для логов, но прячет тип.

</Reveal>
