В конвейерах и пулах воркеров результат удобно передавать одним
значением: «число или ошибка». Напишите небольшой набор функций вокруг
`Result[T]`.

Что проверяют скрытые тесты:

- `Collect` без ошибок — все значения по порядку; пустой вход — пустой,
  но не `nil` слайс;
- `Collect` с ошибками — `nil` вместо значений и одна ошибка, где каждая
  исходная помечена своим индексом, а `errors.Is` находит любую;
- `Map` не вызывает функцию на ошибке и переносит ошибку без изменений;
  ошибка самой функции попадает в результат;
- `Try` превращает панику строкой и панику ошибкой в `Result` с
  `ErrPanic`; во втором случае `errors.Is` находит и исходную ошибку.

<Reveal>

```go
func Try[T any](f func() (T, error)) (r Result[T]) {
	defer func() {
		if p := recover(); p != nil {
			if e, ok := p.(error); ok {
				r = Result[T]{Err: fmt.Errorf("%w: %w", ErrPanic, e)}
			} else {
				r = Result[T]{Err: fmt.Errorf("%w: %v", ErrPanic, p)}
			}
		}
	}()
	v, err := f()
	return Result[T]{v, err}
}

func Map[T, U any](r Result[T], f func(T) (U, error)) Result[U] {
	if r.Err != nil {
		return Result[U]{Err: r.Err}
	}
	v, err := f(r.Val)
	return Result[U]{v, err}
}

func Collect[T any](rs []Result[T]) ([]T, error) {
	var errs []error
	for i, r := range rs {
		if r.Err != nil {
			errs = append(errs, fmt.Errorf("#%d: %w", i, r.Err))
		}
	}
	if len(errs) > 0 {
		return nil, errors.Join(errs...)
	}
	vals := make([]T, 0, len(rs))
	for _, r := range rs {
		vals = append(vals, r.Val)
	}
	return vals, nil
}
```

**`recover` работает только через именованный результат.** Отложенная
функция выполняется после `return`, и подменить возвращаемое значение она
может, только если у него есть имя. С безымянным результатом `Try`
вернёт нулевой `Result` без ошибки — паника «проглочена» бесследно, а это
хуже, чем упасть.

**Два `%w` в одной строке.** Паника значением-ошибкой должна оставаться
этой ошибкой: вызывающий проверяет `errors.Is(err, io.ErrUnexpectedEOF)`
и не должен знать, что по дороге была паника. `fmt.Errorf("%w: %w", …)`
(Go 1.20) даёт ошибку с `Unwrap() []error`, и `errors.Is` видит обе
метки.

**`Map` переносит ошибку как есть.** Не оборачивает, не вызывает `f` с
нулевым значением. Иначе ошибка «не число» на первом шаге превращается в
«деление на ноль» на третьем, и первопричину уже не найти.

**`[]T{}` против `nil`.** Для Go разницы почти нет, а для
`encoding/json` — есть: `nil`-слайс кодируется как `null`, и фронтенд,
ожидающий массив, падает на пустом списке.

**Что спросят дальше.** Почему в Go не прижился `Result` вместо пары
`(T, error)` (нет сопоставления с образцом и `?`-оператора, а методы не
могут иметь свои параметры типа — `Map` поэтому функция, а не метод) и
когда он всё же удобен — в каналах.
