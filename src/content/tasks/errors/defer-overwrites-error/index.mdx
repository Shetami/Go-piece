Автор не хотел терять ошибку `Close` и присваивает её именованному
результату в отложенной функции. Программа печатает:

```
закрыт ok.csv
<nil>
закрыт bad.csv
<nil>
```

Почините: ошибка обработки не должна теряться. Ожидаемый вывод:

```
закрыт ok.csv
<nil>
закрыт bad.csv
битый заголовок
```

<Reveal>

**`return errors.New(...)` присваивает `err`, потом выполняется `defer`.**
Отложенная функция безусловно пишет в `err` результат `Close` — `nil`. Та
ошибка, ради которой всё затевалось, стёрта. Хотели не потерять одну
ошибку — потеряли другую.

**Как правильно** — затирать только пустой результат:

```go
defer func() {
	if cerr := f.Close(); err == nil {
		err = cerr
	}
}()
```

Основная ошибка важнее: из-за неё, скорее всего, и `Close` мог сломаться.

**Если нужны обе** — `err = errors.Join(err, f.Close())`. `Join` выбросит
`nil` и не создаст ошибку на пустом месте, а если упали оба — сохранит
обе, и `errors.Is` найдёт любую.

</Reveal>
