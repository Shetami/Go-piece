title: Обернуть nil
description: errors.Join и fmt.Errorf с %w получают nil вместо ошибки. Один из них возвращает nil, другой — нет.

Переменная `none` — ошибка, которой нет. Её передают в `errors.Join` и
оборачивают через `fmt.Errorf` с `%w`, как будто ошибка была.

Напишите весь вывод программы.

<Reveal>

**`errors.Join` выбрасывает `nil`-аргументы.** Если после этого не осталось
ничего — возвращает `nil`. Поэтому `Join` удобно копить в цикле:
`err = errors.Join(err, step())` — пока все шаги успешны, `err` остаётся
`nil`.

**`fmt.Errorf` возвращает ошибку всегда.** Ему всё равно, что аргумент
`nil`: он форматирует строку и отдаёт непустое значение. Вместо текста
ошибки в строке окажется `%!w(<nil>)` — так `fmt` сообщает, что глаголу
досталось не то.

**Обёртка при этом ничего не оборачивает** — `Unwrap` вернёт `nil`.

Итого:

```
true
диск полон
false
загрузка: %!w(<nil>)
true
```

**Отсюда правило.** Оборачивать только после проверки:

```go
if err != nil {
	return fmt.Errorf("загрузка: %w", err)
}
return nil
```

Написать `return fmt.Errorf("загрузка: %w", err)` без `if` — значит
превратить успех в ошибку.

</Reveal>
