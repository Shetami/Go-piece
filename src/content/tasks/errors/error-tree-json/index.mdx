Строка `сохранить: нет соединения\nкэш: EOF` в логе нечитаема, а поиск по
коду ошибки в ней невозможен. Хочется видеть структуру: какая ошибка
что обернула, где объединились две причины и у какой из них какой код.

Напишите `Encode`: она превращает ошибку в дерево `Node`, которое
`encoding/json` сериализует как есть.

Что проверяют скрытые тесты:

- `nil` → `nil`;
- цепочка `fmt.Errorf("…: %w")` даёт вложенные узлы; код стоит только у
  того звена, которое само реализует `Coder`, а не у всех его предков;
- `errors.Join` и `fmt.Errorf` с двумя `%w` дают по ребёнку на каждую
  причину, в исходном порядке;
- `nil`-элементы в `Unwrap() []error` пропускаются;
- ошибка, у которой `Unwrap` возвращает её саму, не вешает сервис:
  дерево обрезается на глубине `MaxDepth`.

<Reveal>

```go
func Encode(err error) *Node {
	if err == nil {
		return nil
	}
	n := encode(err, 1)
	return &n
}

func encode(err error, depth int) Node {
	n := Node{Msg: err.Error()}
	if c, ok := err.(Coder); ok {
		n.Code = c.Code()
	}
	if depth >= MaxDepth {
		return n
	}
	switch u := err.(type) {
	case interface{ Unwrap() error }:
		if c := u.Unwrap(); c != nil {
			n.Causes = []Node{encode(c, depth+1)}
		}
	case interface{ Unwrap() []error }:
		for _, c := range u.Unwrap() {
			if c != nil {
				n.Causes = append(n.Causes, encode(c, depth+1))
			}
		}
	}
	return n
}
```

**`errors.Unwrap` видит только половину.** Он вызывает лишь
`Unwrap() error`. У `errors.Join` и у `fmt.Errorf` с несколькими `%w`
другой метод — `Unwrap() []error`, и `errors.Unwrap` для них вернёт
`nil`. Обход дерева ошибок всегда проверяет оба интерфейса — так же
делают `errors.Is` и `errors.As` внутри.

**Здесь нужен не `errors.As`.** `As` ищет по всей цепочке, и код
глубокой причины оказался бы у каждого предка — в JSON это выглядит так,
будто ошибок с кодом `db.timeout` четыре. Чтобы узнать, реализует ли
интерфейс *само звено*, достаточно утверждения типа `err.(Coder)`.

**Защита от бесконечности.** Ошибки приходят из чужого кода, и
`Unwrap`, возвращающий `self`, — не теория. Сериализатор ошибок работает
в обработчике паник и логгере: зациклившись там, он роняет сервис ровно
тогда, когда тот и так болеет. Ограничение глубины — самая простая
защита; `errors.Is` в такой ситуации, кстати, тоже зациклится.

**`omitempty` и порядок полей.** Пустой код и пустой список причин не
попадают в JSON, а порядок ключей задан порядком полей структуры —
поэтому тест может сравнивать строку целиком.

**Что спросят дальше.** Как не отдавать клиенту внутренние тексты (Msg
для клиента и для лога — разные поля), как ограничить ширину дерева, и
как это же дерево вывести через `slog.LogValuer`.
