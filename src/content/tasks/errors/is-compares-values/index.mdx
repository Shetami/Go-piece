`codeErr` — ошибка-структура с полем `code`, метод `Error` у неё на
значении. `ptrErr` — такая же, но метод на указателе. Обе оборачивают в
`fmt.Errorf` и ищут через `errors.Is` свежесозданной ошибкой с тем же кодом.

Напишите весь вывод программы.

<Reveal>

**`errors.Is` сравнивает через `==`** — каждое звено цепочки с целью (если у
звена нет своего метода `Is`). А `==` для интерфейсов сравнивает динамический
тип и значение.

- `codeErr{404}` против `codeErr{404}` — один тип, структуры равны по
  полям: `true`.
- `codeErr{404}` против `codeErr{500}` — поля разные: `false`.
- `&ptrErr{404}` против `&ptrErr{404}` — указатели, а у двух литералов
  разные адреса: `false`.
- Два `errors.New("нет")` — тоже два разных указателя: `false`. Одинаковый
  текст ничего не значит.

Итого:

```
true
false
false
false
```

**Где это пригождается.** Небольшую ошибку из сравнимых полей можно
использовать как «сентинел с параметром»: `errors.Is(err, codeErr{404})`
работает без своего метода `Is`. С указателем так не выйдет — нужен
`errors.As` и проверка поля руками.

**Где стреляет.** Добавьте в структуру слайс или мапу — и `==` на ней
перестанет компилироваться, а `errors.Is` с такой целью будет просто
возвращать `false`: он проверяет сравнимость типа перед сравнением.

</Reveal>
