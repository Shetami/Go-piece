`NotFound` — ошибка-значение (не указатель) с полем `Key`. У неё свой метод
`Is`. Ошибку оборачивают и проверяют через `errors.Is` с тремя разными
образцами, а потом достают через `errors.As`.

Напишите весь вывод программы.

<Reveal>

**Как работает `errors.Is`.** На каждом звене цепочки он делает две
проверки: сначала `err == target` (если тип сравним), потом — если у звена
есть метод `Is(error) bool` — вызывает его. Совпадение по любой из проверок
— `true`.

- `NotFound{Key: "user:1"}` — структуры равны поле за полем, `==` уже даёт
  `true`.
- `NotFound{Key: "user:2"}` — `==` даёт `false`, но наш метод `Is`
  проверяет только тип и говорит `true`.
- `NotFound{}` — то же самое. Пустой образец превращается в «любая ошибка
  этого вида». Для этого свой `Is` обычно и пишут.

**`errors.As` метод `Is` не использует.** Он ищет звено, которое можно
присвоить в цель, — `NotFound`, и копирует его: `Key` — `user:1`.

Итого:

```
true
true
true
true user:1
```

**Когда писать свой `Is`.** Когда ошибка несёт данные (ключ, код, путь), но
вызывающим важна только категория. Без `Is` им пришлось бы писать
`errors.As` с временной переменной. Так сделано в стандартной библиотеке:
`*fs.PathError` через `Unwrap` отдаёт `syscall.Errno`, а у `Errno` есть свой
`Is`, который сопоставляет `ENOENT` с `fs.ErrNotExist`. Поэтому
`errors.Is(err, fs.ErrNotExist)` работает, хотя такой ошибки в цепочке нет.

</Reveal>
