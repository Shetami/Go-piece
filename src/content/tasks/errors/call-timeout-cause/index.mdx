Сервис зовёт склад с таймаутом 300 мс. В логах — `context deadline
exceeded`, и непонятно: это склад тормозит (наш таймаут, пора крутить
circuit breaker) или у всего запроса кончился бюджет времени (виноват
кто-то раньше по цепочке)? Или сервис вообще останавливается?

Напишите `Call`: ошибка должна однозначно отвечать, чей это таймаут или
отмена, но при этом оставаться совместимой с `errors.Is(err,
context.DeadlineExceeded)`.

Что проверяют скрытые тесты:

- успех → `nil`; у контекста `f` есть дедлайн, а после возврата `Call` он
  отменён;
- обычная ошибка `f` оборачивается с `op` и не выглядит таймаутом;
- сработал наш таймаут → `*TimeoutError` с `op` и длительностью, который
  `Is(DeadlineExceeded)`; если `f` игнорировала контекст и вернула свою
  ошибку позже — она внутри;
- истёк дедлайн вызывающего при нашем таймауте в час — это не
  `*TimeoutError`, но `DeadlineExceeded` с `op` в тексте;
- вызывающего отменили с причиной (`WithCancelCause`) — видны и
  `Canceled`, и причина.

<Reveal>

```go
func Call(ctx context.Context, op string, d time.Duration, f func(context.Context) error) error {
	cctx, cancel := context.WithTimeout(ctx, d)
	defer cancel()

	err := f(cctx)
	if err == nil {
		return nil
	}
	if perr := ctx.Err(); perr != nil {
		cause := context.Cause(ctx)
		if cause == perr {
			return fmt.Errorf("%s: %w", op, perr)
		}
		return fmt.Errorf("%s: %w: %w", op, perr, cause)
	}
	if cctx.Err() != nil {
		return &TimeoutError{Op: op, After: d, Err: err}
	}
	return fmt.Errorf("%s: %w", op, err)
}
```

**По ошибке `f` не понять, чей это таймаут.** Дочерний контекст
наследует дедлайн родителя, и `f` в обоих случаях вернёт один и тот же
`context.DeadlineExceeded`. Различить можно только по состоянию
контекстов: завершён родитель — виноват он; жив родитель, но завершён
наш — сработал наш таймаут. Проверять родителя нужно первым: когда
истекли оба, наш таймаут уже ничего не решает.

**Своя ошибка, совместимая со старыми проверками.** `*TimeoutError`
несёт `op` и длительность — для логов и метрик по зависимостям. Метод
`Is(target) bool { return target == context.DeadlineExceeded }` сохраняет
весь существующий код вида «если таймаут — 504». А `Unwrap` отдаёт
ошибку `f`: если `f` не слушала контекст и вернула что-то своё, это тоже
важно.

**`context.Cause` — зачем останавливают.** `ctx.Err()` может быть только
`Canceled` или `DeadlineExceeded`. Причина из `WithCancelCause` («сервис
останавливается») добавляется вторым `%w`, и `errors.Is` видит обе.
Если причины нет, `Cause` возвращает саму `ctx.Err()` — дублировать её
в тексте незачем.

**`defer cancel()` — не формальность.** Без него контекст и таймер живут
до срабатывания `d`: при часовом таймауте и тысяче запросов в секунду это
утечка, которую `go vet` ловит (`lostcancel`), а тест — по состоянию
контекста после `Call`.

**Что спросят дальше.** Как это же сделать через
`context.WithTimeoutCause`, как распределять бюджет времени по нескольким
вызовам (дедлайн родителя минус запас) и как передавать дедлайн по сети
(gRPC делает это сам, HTTP — через заголовок).
