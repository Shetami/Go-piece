`QueryError` несёт текст запроса и исходную ошибку. Запрос не нашёл строк,
значит, ответ должен быть «не найден». Программа печатает:

```
сбой базы: SELECT user: нет строк
```

Почините тип `QueryError`, не трогая `main`. Ожидаемый вывод:

```
пользователь не найден
```

<Reveal>

**`errors.Is` не заглядывает в поля.** Он знает про цепочку только то, что
сообщают методы `Unwrap() error` или `Unwrap() []error`. Поле `Err` для него
— просто поле структуры. Метода нет — значит, цепочка обрывается на
`QueryError`, и `ErrNoRows` не найден.

**Как чинят** — добавить `Unwrap`:

```go
func (e *QueryError) Unwrap() error { return e.Err }
```

Теперь `errors.Is` и `errors.As` проходят сквозь `QueryError`.

**Когда `Unwrap` не нужен.** Когда вы сознательно прячете детали нижнего
слоя. Если `QueryError` — часть публичного API пакета, то `Unwrap`
делает ошибку драйвера частью этого API: вызывающие начнут проверять
`errors.Is(err, pq.ErrSomething)`, и сменить драйвер уже не получится.
Это то же решение, что `%w` против `%v` в `fmt.Errorf`, только для своего
типа.

</Reveal>
