Сервис ходит за курсами валют или профилями пользователей в медленный
upstream. Нужна обёртка-кэш: результат живёт `ttl`, ошибки не кэшируются,
а когда запись протухла и за ней одновременно пришла сотня запросов,
upstream получает один запрос, а не сто.

Напишите `Cached` по контракту в заготовке.

Что проверяют скрытые тесты:

- через 59 секунд при `ttl = 1m` значение берётся из кэша (даже нулевое),
  ровно через минуту — грузится заново;
- 20 одновременных вызовов одного ключа: `load` вызвана один раз, и
  ошибку этой загрузки получили все 20;
- после ошибки следующий вызов грузит заново;
- пока грузится ключ `a`, загрузка ключа `b` не ждёт его.

<Reveal>

```go
func Cached[K comparable, V any](load func(K) (V, error), ttl time.Duration, now func() time.Time) func(K) (V, error) {
	type entry struct {
		done chan struct{}
		val  V
		err  error
		at   time.Time
	}
	var (
		mu sync.Mutex
		m  = make(map[K]*entry)
	)
	return func(k K) (V, error) {
		mu.Lock()
		if e, ok := m[k]; ok {
			select {
			case <-e.done:
				if e.err == nil && now().Sub(e.at) < ttl {
					mu.Unlock()
					return e.val, nil
				}
			default:
				mu.Unlock()
				<-e.done
				return e.val, e.err
			}
		}
		e := &entry{done: make(chan struct{})}
		m[k] = e
		mu.Unlock()

		e.val, e.err = load(k)
		e.at = now()
		if e.err != nil {
			mu.Lock()
			if m[k] == e {
				delete(m, k)
			}
			mu.Unlock()
		}
		close(e.done)
		return e.val, e.err
	}
}
```

**Запись — это и значение, и «обещание».** `entry` появляется в мапе до
начала загрузки. Канал `done` показывает, готова ли она. Кто пришёл, пока
канал открыт, ждёт на нём — без замка — и получает тот же результат.
Это singleflight и кэш в одной структуре, а не два механизма, которые
надо согласовывать.

**`load` — вне мьютекса.** Самая частая ошибка — `mu.Lock()` на весь вызов.
Тогда дедупликация работает сама собой, но все ключи грузятся строго по
очереди, и один медленный ключ блокирует весь сервис. Тест с ключами `a` и
`b` ловит именно это. Под замком мы только смотрим в мапу и кладём
запись.

**Видимость без мьютекса.** `val`, `err` и `at` записываются одной
горутиной до `close(done)`. Закрытие канала происходит раньше (happens-before),
чем любое получение из него. Поэтому читатель после `<-e.done` видит
записанное, и `-race` доволен.

**Ошибки не кэшируем, но делим.** Те, кто ждал загрузку, получают её
ошибку. Иначе при недоступном upstream каждый ждущий запустил бы свою
загрузку, и стампеда вернулась бы. Саму запись удаляем, чтобы следующий
вызов попробовал снова. Проверка `m[k] == e` защищает чужую, более новую
запись.

**Что спросят дальше:** паника в `load` (сейчас ждущие зависнут навеки —
нужен `defer` с `close`), отмена по контексту для ждущих, мапа, которая
растёт без вытеснения, и stale-while-revalidate — отдавать протухшее
значение, пока новое грузится в фоне.
