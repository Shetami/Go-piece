`chain(h, auth, log, gzip)` должна сделать так, чтобы запрос сначала прошёл
`auth`, потом `log`, потом `gzip` и только потом попал в обработчик. Каждый
middleware оборачивает ответ своим именем, поэтому порядок видно. Программа
печатает:

```
gzip(log(auth(запрос)))
```

Авторизация оказалась в самой глубине. Почините. Ожидаемый вывод:

```
auth(log(gzip(запрос)))
```

<Reveal>

**Каждая обёртка становится новой внешней оболочкой.** Цикл по порядку
делает `h = auth(h)`, потом `h = log(auth(h))`, потом `h = gzip(log(auth(h)))`.
Последний обёрнутый — самый внешний, и запрос попадает в него первым.
Значит, первым в цепочке оказывается `gzip`, а `auth` видит запрос последним
— уже после того, как логирование и сжатие поработали с неавторизованным
запросом.

**Как чинят** — оборачивать с конца:

```go
for _, m := range slices.Backward(ms) {
	h = m(h)
}
```

`slices.Backward` (Go 1.23) — итератор, идущий от последнего элемента к
первому. Раньше писали `for i := len(ms) - 1; i >= 0; i--`.

**Почему это вопрос про замыкания.** Каждый middleware — функция, которая
возвращает замыкание над `next`. Цепочка — это вложенные замыкания, и
порядок вложенности определяется порядком, в котором их создавали. Ровно
так устроены middleware в `net/http`, `chi`, gRPC-интерсепторы.

</Reveal>
