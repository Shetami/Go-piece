`memo` оборачивает функцию и запоминает результаты. Аргументов всего два
разных, значит, настоящих вызовов должно быть два. Программа печатает:

```
вызовов: 5
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 15: `cache := map[int]int{}` — внутри возвращаемой
функции.

**Код внутри замыкания исполняется при каждом его вызове.** Кэш создаётся
заново на каждый вызов `sq(n)`, в него кладётся одно значение, и в конце
вызова он выбрасывается. Следующий вызов начинает с пустого кэша.

Замыкание запоминает переменные *внешней* функции. Чтобы кэш жил между
вызовами, он должен быть переменной `memo`, а не возвращённой функции:

```go
func memo(f func(int) int) func(int) int {
	cache := map[int]int{}          // один раз, при вызове memo
	return func(n int) int { ... }  // каждый раз — только это
}
```

**Что спросят следом.** Безопасна ли такая мемоизация из нескольких
горутин (нет: мапа без мьютекса), и как не посчитать одно и то же дважды,
если два запроса пришли одновременно (`singleflight`: второй ждёт результат
первого, а не запускает своё вычисление).

</Reveal>
