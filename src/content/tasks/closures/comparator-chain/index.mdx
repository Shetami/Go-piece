Типичная задача из отчётов: отсортировать сотрудников по отделу, внутри —
по убыванию зарплаты, при равной зарплате — по имени. Вместо одного
большого `func(a, b T) int` с тремя `if` соберите его из кирпичиков:

```go
slices.SortFunc(es, By(
	Key(func(e Emp) string { return e.Dept }),
	Desc(Key(func(e Emp) int { return e.Salary })),
	Key(func(e Emp) string { return e.Name }),
))
```

Напишите `By`, `Key` и `Desc`.

Что проверяют скрытые тесты:

- пример выше даёт правильный порядок из пяти сотрудников с совпадениями
  по отделу и зарплате;
- `By()` без аргументов считает все элементы равными — стабильная
  сортировка ничего не переставляет;
- `Desc` работает с любым законным компаратором — у которого важен только
  знак результата, а сам результат может быть каким угодно `int`;
- если вызывающий после сборки поменял элементы слайса, переданного как
  `cs...`, собранный компаратор этого не видит.

<Reveal>

```go
func By[T any](cmps ...func(a, b T) int) func(a, b T) int {
	cmps = append([]func(a, b T) int(nil), cmps...)
	return func(a, b T) int {
		for _, c := range cmps {
			if r := c(a, b); r != 0 {
				return r
			}
		}
		return 0
	}
}

func Key[T any, K cmp.Ordered](key func(T) K) func(a, b T) int {
	return func(a, b T) int {
		return cmp.Compare(key(a), key(b))
	}
}

func Desc[T any](c func(a, b T) int) func(a, b T) int {
	return func(a, b T) int {
		return c(b, a)
	}
}
```

**Каждая функция — фабрика замыканий.** `Key` захватывает `key`, `Desc` —
исходный компаратор, `By` — список. Сами они ничего не сравнивают, а
возвращают функцию, которая будет сравнивать, когда её позовёт сортировка.

**`Desc` — аргументы местами, а не минус.** Контракт компаратора говорит
только про знак. Компаратор вправе вернуть `math.MinInt`, а `-math.MinInt`
в Go — снова `math.MinInt`: переполнение молча оставляет знак, и «по
убыванию» превращается в «по возрастанию». `c(b, a)` от этого свободен.

**`cmp.Compare`, а не `a - b`.** Вычитание переполняется на больших
числах, а для строк и float его нет вовсе. `cmp.Compare` ещё и
определённо упорядочивает `NaN`.

**Копия вариативного параметра** — та же история, что в задаче «Композиция
функций»: при вызове `By(cs...)` параметр делит массив с вызывающим.

**Что спросят дальше:** почему для «сначала по отделу» нельзя просто дважды
вызвать `sort.Slice` (можно, но только стабильной сортировкой и в обратном
порядке ключей), и сколько раз вызывается `key` — на каждое сравнение, так
что тяжёлый ключ стоит посчитать заранее.
