В `main` большого сервиса десятки объектов: пул БД, кэш, репозитории,
сервисы, HTTP-хендлеры. Порядок их создания руками — источник ошибок.
Контейнер делает это сам: каждая фабрика получает функцию `get` и просит
у неё свои зависимости, а контейнер строит их лениво и ровно по одному
разу.

Напишите `Container` по контракту в заготовке: поля и методы.

Что проверяют скрытые тесты:

- ромб `app → users, orders`, `orders → db, users`, `users → db` — не
  цикл; `db` и `users` — одни и те же объекты у всех, каждая фабрика
  вызвана один раз, даже после повторных `Get`;
- цикл `auth → session → auth` — ошибка с `ErrCycle` и путём
  `auth -> session -> auth`; зависимость от самого себя — тоже цикл;
- нет фабрики — `ErrUnknown` с именем; после регистрации недостающей
  фабрики сервис собирается;
- фабрика упала один раз — следующий `Get` пробует снова и
  успешно.

<Reveal>

```go
type Container struct {
	factories map[string]Factory
	built     map[string]any
}

func NewContainer() *Container {
	return &Container{factories: make(map[string]Factory), built: make(map[string]any)}
}

func (c *Container) Provide(name string, f Factory) {
	c.factories[name] = f
}

func (c *Container) Get(name string) (any, error) {
	return c.get(name, nil)
}

func (c *Container) get(name string, path []string) (any, error) {
	if v, ok := c.built[name]; ok {
		return v, nil
	}
	if i := slices.Index(path, name); i >= 0 {
		loop := append(slices.Clone(path[i:]), name)
		return nil, fmt.Errorf("%w: %s", ErrCycle, strings.Join(loop, " -> "))
	}
	f, ok := c.factories[name]
	if !ok {
		return nil, fmt.Errorf("%w: %q", ErrUnknown, name)
	}
	path = append(path[:len(path):len(path)], name)
	v, err := f(func(dep string) (any, error) {
		return c.get(dep, path)
	})
	if err != nil {
		return nil, fmt.Errorf("build %s: %w", name, err)
	}
	c.built[name] = v
	return v, nil
}
```

**`get` — замыкание над путём.** Каждая фабрика получает свою функцию
`get`, которая помнит, по какой цепочке мы сюда пришли. Путь не хранится в
поле контейнера и не очищается вручную. Он живёт ровно столько, сколько
строится объект, и после ошибки не остаётся «висящих» отметок. Поэтому
падение фабрики не мешает следующей попытке — последний тест про это.

**Цикл — это «строится сейчас», а не «уже видели».** Самая частая ошибка
— общий набор `visited`. В ромбе `db` встречается дважды по разным путям,
и такой набор объявит цикл там, где его нет. Цикл — только если имя уже
есть на текущем пути вверх по стеку.

**Путь в ошибке.** Сообщение «dependency cycle» без пути в графе из
пятидесяти сервисов бесполезно. `path[i:]` — от места, где цикл
начинается, до повторного имени. `slices.Clone` нужен, чтобы `append` не
писал в массив `path`.

**`path[:len:len]`.** Две зависимости одной фабрики получают один и тот же
`path`. Если у его массива есть запас ёмкости, `append` для второй
зависимости запишет имя поверх первой. Полное выражение среза заставляет
`append` выделять новый массив. Здесь это не ломает текущие тесты, но при
ленивом `get`, вызванном позже, дало бы неверный путь.

**Что спросят дальше:** потокобезопасность (мьютекс не годится — фабрика
рекурсивно зовёт `get`; нужны singleflight-записи на имя), типизированный
`Get[T]` на дженериках, и почему в Go обычно пишут зависимости руками в
`main` или генерируют код (wire), а не держат рефлексивный контейнер.
