`Count` — итератор в стиле Go 1.23: функция, которая вызывает `yield` на
каждый элемент. Цикл хочет остановиться на тройке, а программа падает:

```
range function continued iteration after function for loop body returned false
```

Почините итератор. Ожидаемый вывод:

```
0
1
2
готово
```

<Reveal>

**Тело цикла — это замыкание `yield`, а `break` — его `return false`.**
Компилятор превращает

```go
for i := range Count(10) { ... }
```

в вызов `Count(10)(yield)`, где `yield` — замыкание с телом цикла. Если в
теле случился `break`, `return` или `goto` наружу, `yield` возвращает
`false`: «больше не зови меня».

Итератор это значение проигнорировал и вызвал `yield` снова. Тело цикла
уже закончилось, продолжать его нельзя — рантайм проверяет это и паникует.

**Как чинят** — проверять результат `yield` каждый раз:

```go
if !yield(i) {
	return
}
```

**Правило для любого итератора.** После `yield`, вернувшего `false`, —
только выход. Если итератор держит ресурсы (файл, курсор базы), закрывайте
их в `defer` внутри итератора: он сработает и при досрочном выходе, и при
обычном завершении. Проверку в рантайме при этом не отключить — и хорошо:
без неё такая ошибка молча портила бы данные.

</Reveal>
