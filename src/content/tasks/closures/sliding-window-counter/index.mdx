Сколько ошибок было за последнюю минуту? Сколько запросов сделал клиент за
10 секунд? Хранить время каждого события дорого. Стандартный приём —
кольцо из `buckets` корзин: окно режется на отрезки, в каждой корзине
только число событий. Всё состояние — кольцо и мьютекс — живёт в
замыкании, наружу отдаются `add` и `count`.

Напишите `NewWindowCounter` по контракту в заготовке. Время приходит из
`now`.

Что проверяют скрытые тесты:

- события 1, 2 и 3 в моменты 0.5 с, 3.2 с и 9.9 с при окне 10 с из десяти
  корзин: `count` в 9.9 с — 6, в 10 с — 5, в 13.1 с — 3, в 18.5 с — 3,
  в 19.95 с — 0 (точность — одна корзина);
- после 20 секунд простоя событие попадает в ту же ячейку кольца, что и
  старые, — старые не учитываются; ещё позже — ноль;
- опоздавшее событие, чья корзина ещё в окне, учитывается, а совсем
  старое, чью ячейку уже заняла новая корзина, — нет, и новую корзину не
  портит;
- 50 горутин по `add(2)` → ровно 100.

```go
func NewWindowCounter(window time.Duration, buckets int, now func() time.Time) (add func(n int), count func() int) {
	size := int64(window) / int64(buckets)
	type slot struct {
		id    int64
		n     int
		valid bool
	}
	var (
		mu   sync.Mutex
		ring = make([]slot, buckets)
	)
	bucketOf := func(t time.Time) int64 {
		ns := t.UnixNano()
		id := ns / size
		if ns%size < 0 {
			id--
		}
		return id
	}
	index := func(id int64) int {
		i := int(id % int64(buckets))
		if i < 0 {
			i += buckets
		}
		return i
	}
	add = func(n int) {
		mu.Lock()
		defer mu.Unlock()
		id := bucketOf(now())
		s := &ring[index(id)]
		if !s.valid || s.id != id {
			if s.valid && s.id > id {
				return
			}
			*s = slot{id: id, valid: true}
		}
		s.n += n
	}
	count = func() int {
		mu.Lock()
		defer mu.Unlock()
		cur := bucketOf(now())
		total := 0
		for _, s := range ring {
			if s.valid && s.id > cur-int64(buckets) && s.id <= cur {
				total += s.n
			}
		}
		return total
	}
	return add, count
}
```

**Ячейка помнит, какую корзину она хранит.** Кольцо из `buckets` ячеек
переиспользуется по кругу: корзины 1, 11, 21 попадают в ячейку 1. Наивная
версия просто прибавляет к ячейке и после простоя считает события
двадцатисекундной давности как свежие. Решение — хранить в ячейке `id`
корзины и сверять его. `add` обнуляет ячейку, если в ней чужая корзина,
`count` пропускает ячейки с корзинами вне окна. Никакой фоновой очистки не
нужно.

**Граница окна.** Окно — `buckets` последних корзин, включая текущую:
`(cur-buckets, cur]`. В 10.0 с текущая корзина — 10, и корзина 0 с
событием из 0.5 с уже вне окна. Точность счётчика — одна корзина: событие
из 3.2 с перестаёт считаться в 13.0 с, а не в 13.2 с, а событие из 9.9 с — уже в 19.0 с. Больше корзин —
точнее и дороже. Это главный компромисс, о нём спросят.

**Опоздавшие события.** Часы разных горутин и хостов расходятся, и событие
может прийти «из прошлого». Если его корзина ещё в окне, оно честно
ложится в свою ячейку. Если ячейку уже заняла более новая корзина — его
место давно вытеснено, и запись поверх уничтожила бы свежие данные.

**Помощники-замыкания.** `bucketOf` и `index` захватывают `size` и
`buckets`, поэтому `add` и `count` читаются как описание алгоритма. `floor`
и положительный остаток — для времени до 1970 года, иначе `%` в Go вернёт
отрицательный индекс.

**Что спросят дальше:** чем это отличается от фиксированного окна (скачок
вдвое на стыке окон) и от скользящего лога (точно, но память на каждое
событие), как сгладить приближение — взвешивать самую старую корзину долей
её перекрытия с окном, как в rate limiter Cloudflare, и как сделать то же
на атомиках без мьютекса.
