Дерево каталогов, категорий или меню хочется обходить обычным `for range`:

```go
for path, n := range Walk(root, skipVendor) {
	fmt.Println(strings.Join(path, "/"))
}
```

`Walk` — функция-итератор над рекурсивным обходом. Рекурсия и
range-over-func вместе дают две классические ловушки: `break`, который
не доходит до верхнего уровня, и общий массив путей. Напишите `Walk` по
контракту в заготовке.

Что проверяют скрытые тесты:

- прямой порядок и пути всех 13 узлов, *сохранённые* потребителем
  до конца обхода, остаются верными;
- `skip` отсекает узел вместе с поддеревом и не вызывается для
  потомков пропущенного; путь заканчивается именем самого узла; `nil`-корень
  — пустой обход;
- `break` на узле третьего уровня: без паники, и после него не посещается
  ни одного узла;
- цепочка глубиной 5000 обходится целиком.

<Reveal>

```go
func Walk(root *Node, skip func(*Node) bool) iter.Seq2[[]string, *Node] {
	return func(yield func([]string, *Node) bool) {
		var walk func(n *Node, parent []string) bool
		walk = func(n *Node, parent []string) bool {
			if skip != nil && skip(n) {
				return true
			}
			path := append(parent[:len(parent):len(parent)], n.Name)
			if !yield(path, n) {
				return false
			}
			for _, c := range n.Children {
				if !walk(c, path) {
					return false
				}
			}
			return true
		}
		if root != nil {
			walk(root, nil)
		}
	}
}
```

**Рекурсивный помощник возвращает `bool`.** `yield` вернул `false` —
значит, тело цикла сделало `break`. Это надо донести через все уровни
рекурсии. Если `walk` ничего не возвращает (или результат игнорируют),
родитель пойдёт к следующему ребёнку и вызовет `yield` снова. Go ловит
это паникой «range function continued iteration after function for loop
body returned false». Это рекурсивная версия задачи «Итератор, который не
слышит break».

**Общий массив путей.** Естественное `append(parent, n.Name)` у братьев
пишет в один и тот же массив, если у `parent` есть запас ёмкости. Первый
брат отдал путь `repo/cmd/api`, второй записал `worker` на то же место —
и у потребителя сохранённый путь незаметно превратился в
`repo/cmd/worker`. Выражение `parent[:len:len]` отнимает запас ёмкости,
и `append` всегда выделяет новый массив. Это стоит аллокацию на узел.
Альтернатива — явно написать в контракте «путь действителен до следующей
итерации», как делает `bufio.Scanner`.

**Замыкание, которое вызывает само себя.** `walk` объявлена через `var` до
присваивания, иначе внутри она не видна. Она захватывает `yield` и `skip`,
поэтому их не нужно протаскивать параметрами через рекурсию.

**Что спросят дальше:** обход без рекурсии (явный стек — не упрётся в
глубину и не растит стек горутины), `SkipDir`-семантика, как в
`filepath.WalkDir` (отдать узел, но не заходить в детей), и обход в
ширину — там понадобится очередь, и рекурсия уже не поможет.
