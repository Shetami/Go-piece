Upstream лежит, а сервис продолжает слать ему запросы, каждый из которых
висит до таймаута. Горутины копятся, и падает уже сам сервис. Предохранитель
после нескольких ошибок подряд перестаёт звать зависимость и сразу
возвращает ошибку. Через `cooldown` он пропускает один пробный запрос:
получилось — работаем дальше, нет — ждём снова.

Напишите `Breaker` по контракту в заготовке. Всё состояние — в замыкании.

Что проверяют скрытые тесты:

- ошибки, разбитые успехом, не размыкают; после `threshold` ошибок подряд
  — `ErrOpen`, и `call` больше не вызывается; ошибки `call` возвращаются
  как есть;
- через 59 секунд при `cooldown = 1m` — всё ещё `ErrOpen`, ровно через
  минуту — проба;
- неудачная проба размыкает заново на полный `cooldown` от момента пробы;
- удачная проба замыкает, и счётчик ошибок начинается с нуля;
- пока проба выполняется, параллельный вызов сразу получает `ErrOpen`, а
  не ждёт и не идёт в `call` вторым.

```go
func Breaker(call func() error, threshold int, cooldown time.Duration, now func() time.Time) func() error {
	var (
		mu       sync.Mutex
		fails    int
		open     bool
		openedAt time.Time
		probing  bool
	)
	return func() error {
		mu.Lock()
		if open {
			if probing || now().Sub(openedAt) < cooldown {
				mu.Unlock()
				return ErrOpen
			}
			probing = true
		}
		isProbe := probing
		mu.Unlock()

		err := call()

		mu.Lock()
		defer mu.Unlock()
		switch {
		case isProbe && err == nil:
			open, probing, fails = false, false, 0
		case isProbe:
			probing = false
			openedAt = now()
		case err == nil:
			fails = 0
		default:
			fails++
			if fails >= threshold && !open {
				open, openedAt, fails = true, now(), 0
			}
		}
		return err
	}
}
```

**Состояние в замыкании, решение в два приёма.** До вызова, под замком,
решаем, можно ли звать `call` и не проба ли это. После вызова, снова под
замком, обновляем состояние по результату. Между ними замок отпущен —
иначе один висящий запрос к upstream блокирует все остальные вызовы, даже
те, что должны мгновенно получить `ErrOpen`.

**Одна проба — флаг `probing`.** Без него после `cooldown` все запросы,
пришедшие одновременно, пойдут пробовать, и едва поднявшийся upstream
получит ту же лавину, от которой лёг. Флаг ставится до вызова и
запоминается в локальной `isProbe`: именно этот вызов потом решает судьбу
предохранителя.

**Подряд, а не всего.** Сто ошибок за сутки на миллионе запросов — не
повод размыкаться. Успех обнуляет счётчик. Счётчик обнуляется и при
размыкании, чтобы после удачной пробы начать с чистого листа.

**Поздние ответы.** Запрос, начатый ещё в замкнутом состоянии, может
вернуться, когда предохранитель уже разомкнут. Условие `!open` не даёт
такой ошибке сдвинуть `openedAt` и продлить паузу.

**Что спросят дальше:** какие ошибки считать (таймаут и 5xx — да, 404 и
отмена контекста клиентом — нет; нужен классификатор), скользящее окно с
долей ошибок вместо «подряд», и как предохранитель сочетается с retry:
retry снаружи будет упираться в `ErrOpen`, и его нужно не повторять.
