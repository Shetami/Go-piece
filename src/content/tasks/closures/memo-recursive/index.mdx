`Memoize(fib)` не делает `fib` быстрой: `fib` внутри вызывает саму себя
напрямую, и все рекурсивные вызовы идут мимо кэша. Нужно, чтобы рекурсия
шла через мемоизированную версию. Решение — передать функции её
собственную мемоизированную версию параметром:

```go
fib := MemoRec(func(self func(int) uint64, n int) uint64 {
	if n < 2 {
		return uint64(n)
	}
	return self(n-1) + self(n-2)
})
```

Так в динамическом программировании на собеседовании пишут «сверху вниз»:
рекурсия как в формуле, а сложность как у таблицы. Напишите `MemoRec`.

Что проверяют скрытые тесты:

- `fib(90)` считается мгновенно, и `f` вызвана ровно 91 раз — по разу на
  каждое `n`;
- повторные `fib(90)` и `fib(0)` не вызывают `f` ни разу — даже для
  нулевого результата;
- два `MemoRec` не делят кэш;
- ключ-структура: число путей в сетке 16×16, каждая клетка считается один
  раз.

```go
func MemoRec[K comparable, V any](f func(self func(K) V, k K) V) func(K) V {
	cache := make(map[K]V)
	var memo func(K) V
	memo = func(k K) V {
		if v, ok := cache[k]; ok {
			return v
		}
		v := f(memo, k)
		cache[k] = v
		return v
	}
	return memo
}
```

**Замыкание, которое видит само себя.** `memo := func…` не скомпилируется,
если внутри есть `memo`: переменная появляется в области видимости только
после объявления. Поэтому сначала `var memo func(K) V`, потом
присваивание. Замыкание захватывает переменную, а не её значение на
момент создания, — к моменту вызова в ней уже лежит сама функция.

**Главная ошибка — передать в `self` не то.** Если внутри `memo` вызвать
`f` с «сырой» рекурсией (например, с функцией, которая вызывает `f`
напрямую), кэш заполнится только на верхнем уровне. `fib(90)` без кэша —
это около 10¹⁹ вызовов. Вся идея в том, что `self` — это `memo`.

**`ok`, а не проверка на ноль.** `fib(0) = 0`, путей из края — `1`, а
«нет в кэше» от «в кэше ноль» отличает только второе значение из мапы.

**Кэш пишется после вычисления.** Во время `f(memo, k)` рекурсия уже
заполнила кэш для меньших ключей — мапу мы меняем между вызовами, а не во
время обхода, так что всё корректно. Это же объясняет ограничение: если
зависимость циклическая (`k` через цепочку зависит от самого себя),
получится бесконечная рекурсия — кэш ещё пуст. Спросят, как это
обнаружить: отметка «вычисляется» перед вызовом `f`.

**Что спросят дальше:** глубина рекурсии (для `fib(10⁶)` стек Go вырастет,
а не упадёт, но памяти съест много — снизу вверх лучше) и потокобезопасная
версия, где под мьютексом нельзя вызывать `f`, иначе рекурсия
заблокируется на собственном замке.
