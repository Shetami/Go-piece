Напишите `Memoize`: обёртка, которая вызывает `f` один раз на каждый
аргумент и запоминает результат.

Что проверяют скрытые тесты:

- на пяти вызовах с двумя разными аргументами `f` вызвана дважды;
- запоминаются и нулевые результаты (`false`, `0`, `""`);
- у двух мемоизированных функций свои кэши.

<Reveal>

```go
func Memoize[K comparable, V any](f func(K) V) func(K) V {
	cache := make(map[K]V)
	return func(k K) V {
		if v, ok := cache[k]; ok {
			return v
		}
		v := f(k)
		cache[k] = v
		return v
	}
}
```

**Где живёт кэш.** `cache` объявлен в `Memoize`, а не внутри возвращаемой
функции. Замыкание захватывает переменную, и она переживает вызов
`Memoize`. Каждый вызов `Memoize` заводит новую переменную — отсюда
независимые кэши. Объяви кэш внутри возвращаемой функции — и он будет
создаваться заново на каждом вызове (это разобрано в задаче «Мемоизация,
которая ничего не помнит»).

**`ok`, а не проверка на ноль.** `if v := cache[k]; v != zero` пропустит
законные нулевые результаты — второй тест про это. Да и сравнить `V` с
нулём нельзя: `V` не `comparable`.

**Не потокобезопасно.** Из нескольких горутин нужна блокировка, а чтобы
одинаковые ключи не считались параллельно дважды — `singleflight`.
И кэш без ограничения растёт вечно; в жизни нужна политика вытеснения.

</Reveal>
