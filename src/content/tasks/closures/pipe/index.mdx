Напишите `Pipe`: `Pipe(f, g, h)(x)` — это `h(g(f(x)))`.

Что проверяют скрытые тесты:

- порядок: `Pipe(inc, dbl)(3)` — `8`, `Pipe(dbl, inc)(3)` — `7`;
- `Pipe()` без аргументов — функция, возвращающая аргумент как есть (не
  `nil`);
- собранную функцию можно вызывать много раз;
- если вызывающий после сборки поменял элементы слайса, который передавал
  как `fs...`, собранная функция этого не видит.

<Reveal>

```go
func Pipe(fs ...func(int) int) func(int) int {
	fs = append([]func(int) int(nil), fs...)
	return func(x int) int {
		for _, f := range fs {
			x = f(x)
		}
		return x
	}
}
```

**Замыкание над слайсом функций.** Цикл выполняется при каждом вызове
собранной функции, а не при сборке. Пустой `fs` — цикл не делает ничего,
получается тождественная функция без особых случаев.

**Подвох с вариативным параметром.** `Pipe(fs...)` не копирует слайс:
параметр `fs` внутри — тот же массив, что у вызывающего. Замыкание
захватило бы его, и последующая запись `fs[0] = ...` снаружи поменяла бы
поведение уже собранной функции. Последний тест ловит именно это. Копия в
начале отвязывает `Pipe` от чужого массива. `Pipe(f, g)` с отдельными
аргументами такой проблемы не имеет — там компилятор создаёт новый
массив.

**Вариант с рекурсией** — `Pipe(fs[1:]...)` поверх `fs[0]` — тоже
правильный и красивый, но на каждый вызов создаёт цепочку замыканий
глубиной n. Цикл проще и дешевле.

</Reveal>
