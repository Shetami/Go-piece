Правило скидки или формула метрики приходит из конфига строкой и
вычисляется на каждом запросе. Разбирать строку каждый раз — медленно и
позорно. Классический приём — «компиляция в замыкания»: разобрать один раз
и собрать дерево функций, каждая из которых знает свой узел выражения.

Формат — обратная польская запись, чтобы не писать парсер приоритетов:
`price qty * discount -` — это `price*qty - discount`. Напишите `Compile`
по контракту в заготовке.

Что проверяют скрытые тесты:

- арифметика, отрицательные числа, переменные с `_` и цифрами, одиночное
  число; `10 4 -` — это `6`, а не `-6`;
- пустая строка, `1 +`, `1 2`, лишние операнды, неизвестный оператор,
  имя с цифры, оператор без второго операнда — `ErrSyntax` сразу из
  `Compile` и `nil` вместо `Expr`;
- нет переменной — `ErrUnknown` с её именем; деление на ноль —
  `ErrDivZero`; то же выражение на других переменных считается верно;
- вычисление готового выражения не выделяет память — значит, строка
  разбирается только в `Compile`.

```go
func Compile(src string) (Expr, error) {
	var stack []Expr
	for _, tok := range strings.Fields(src) {
		switch tok {
		case "+", "-", "*", "/":
			if len(stack) < 2 {
				return nil, fmt.Errorf("%w: %q needs two operands", ErrSyntax, tok)
			}
			l, r := stack[len(stack)-2], stack[len(stack)-1]
			stack = append(stack[:len(stack)-2], binary(tok, l, r))
			continue
		}
		if n, err := strconv.ParseFloat(tok, 64); err == nil {
			stack = append(stack, func(map[string]float64) (float64, error) { return n, nil })
			continue
		}
		if !isIdent(tok) {
			return nil, fmt.Errorf("%w: bad token %q", ErrSyntax, tok)
		}
		name := tok
		stack = append(stack, func(vars map[string]float64) (float64, error) {
			v, ok := vars[name]
			if !ok {
				return 0, fmt.Errorf("%w: %s", ErrUnknown, name)
			}
			return v, nil
		})
	}
	if len(stack) != 1 {
		return nil, fmt.Errorf("%w: %d values left on stack", ErrSyntax, len(stack))
	}
	return stack[0], nil
}

func binary(op string, l, r Expr) Expr {
	var f func(a, b float64) (float64, error)
	switch op {
	case "+":
		f = func(a, b float64) (float64, error) { return a + b, nil }
	case "-":
		f = func(a, b float64) (float64, error) { return a - b, nil }
	case "*":
		f = func(a, b float64) (float64, error) { return a * b, nil }
	case "/":
		f = func(a, b float64) (float64, error) {
			if b == 0 {
				return 0, ErrDivZero
			}
			return a / b, nil
		}
	}
	return func(vars map[string]float64) (float64, error) {
		a, err := l(vars)
		if err != nil {
			return 0, err
		}
		b, err := r(vars)
		if err != nil {
			return 0, err
		}
		return f(a, b)
	}
}

func isIdent(s string) bool {
	for i, c := range s {
		letter := c == '_' || (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')
		digit := c >= '0' && c <= '9'
		if !letter && !(digit && i > 0) {
			return false
		}
	}
	return s != ""
}
```

**Стек замыканий вместо стека чисел.** Обычный калькулятор ОПЗ кладёт на
стек числа. Здесь на стек кладутся *функции, которые вернут число*.
Константа — замыкание над `n`, переменная — над `name`, оператор — над
двумя дочерними замыканиями и выбранной операцией. В конце на стеке одно
замыкание — корень дерева. Разбор, выбор оператора и проверки выполнены
один раз, при вычислении остаются только вызовы функций и поиск в мапе.
Поэтому ноль аллокаций.

**Порядок операндов.** Верх стека — *правый* операнд. `10 4 -` снимает `4`
первым, и если назвать его левым, получится `-6`. Для `+` и `*` ошибку не
видно, поэтому её ловят только тесты с `-` и `/`.

**Ошибки структуры — во время компиляции.** Глубина стека моделируется
при разборе, поэтому `1 +` и `1 2` отлавливаются до первого вычисления, то
есть при загрузке конфига, а не на тысячном запросе. Ошибки, зависящие от
данных (нет переменной, деление на ноль), возможны только при вычислении.

**Переменные цикла в замыканиях.** С Go 1.22 у каждой итерации своя
`tok`, и `name := tok` уже не обязателен. Но так явно видно, что
захватывается. До 1.22 без копии все переменные читали бы последний
токен — классическая ошибка этой темы.

**Что спросят дальше:** инфиксная запись (алгоритм сортировочной станции
Дейкстры поверх того же компилятора), свёртка констант (`2 3 +`
превращается в одно замыкание-константу ещё при компиляции) и сравнение с
интерпретатором AST через `switch` по типу узла.
