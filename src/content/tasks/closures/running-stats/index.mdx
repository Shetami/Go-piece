Сервис считает время ответа и раз в минуту отдаёт сводку: сколько было
запросов, минимум, максимум и среднее. Хранить все значения не нужно —
достаточно нескольких переменных, спрятанных в замыканиях.

Напишите `NewStats`. Она возвращает две функции, которые делят одно
состояние: `add` добавляет значение, `snapshot` возвращает сводку.

Что проверяют скрытые тесты:

- `4, 1, 7` → `Count 3, Min 1, Max 7, Mean 4`;
- правильные минимум и максимум, когда все значения отрицательные или все
  положительные;
- пока значений нет — сводка из одних нулей, без `NaN` в среднем;
- `NaN` не учитывается;
- снятая сводка не меняется от последующих `add`, а два вызова `NewStats`
  не делят состояние.

<Reveal>

```go
func NewStats() (add func(x float64), snapshot func() Stats) {
	var (
		n      int
		sum    float64
		lo, hi float64
	)
	add = func(x float64) {
		if math.IsNaN(x) {
			return
		}
		if n == 0 || x < lo {
			lo = x
		}
		if n == 0 || x > hi {
			hi = x
		}
		n++
		sum += x
	}
	snapshot = func() Stats {
		if n == 0 {
			return Stats{}
		}
		return Stats{Count: n, Min: lo, Max: hi, Mean: sum / float64(n)}
	}
	return add, snapshot
}
```

**Две функции — одно состояние.** `n`, `sum`, `lo`, `hi` объявлены в
`NewStats`, и оба замыкания захватывают одни и те же переменные. Это
«объект без структуры»: данные закрыты, снаружи есть только два метода.
Новый вызов `NewStats` заводит новые переменные — отсюда независимость.

**Ловушка нулевого старта.** `lo` и `hi` начинаются с нуля, и если просто
сравнивать, то у отрицательных значений максимум останется `0`, а у
положительных — минимум. Первое значение должно задать обе границы.
Альтернатива — стартовать с `math.Inf(1)` и `math.Inf(-1)`, но тогда
пустую сводку всё равно придётся обрабатывать отдельно.

**Пустая сводка.** `sum / float64(0)` — это `NaN`, а не паника. Такой
`NaN` уедет в метрики и сломает графики. Поэтому `n == 0` — отдельная
ветка. Входной `NaN` тоже отравил бы сумму навсегда: любое действие с
`NaN` даёт `NaN`.

**Снимок — значение.** `snapshot` возвращает структуру по значению,
поэтому уже снятая сводка не меняется. Верни мы `*Stats` на внутреннее
состояние — вызывающий видел бы, как числа меняются у него в руках.

**Что спросят дальше:** что делать с конкурентным `add` (мьютекс на все
четыре переменные сразу — атомики по отдельности не дадут согласованного
снимка) и как считать среднее без переполнения и потери точности на
миллиардах значений — алгоритм Уэлфорда.
