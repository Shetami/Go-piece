Поиск по мере набора текста, сохранение черновика, пересборка индекса после
пачки изменений — всё это debounce: вызвать `f` один раз, когда вызовы
утихли на `wait`. Чтобы бесконечный поток не откладывал работу навсегда,
есть `maxWait`: не дольше этого с начала серии.

Таймеров нет — время сообщают `call` и `tick`, так debounce легко
тестировать (а в проде `tick` дёргает `time.Ticker`). Напишите
`NewDebouncer`.

Что проверяют скрытые тесты:

- `call(a)`, через 50 мс `call(b)` → `f(b)` ровно через `wait` после
  последнего вызова, один раз, и не раньше;
- после срабатывания новая серия работает так же;
- отложенное значение `0` — тоже значение: `f(0)` вызывается;
- вызовы каждые 50 мс при `wait = 100`, `maxWait = 250`: `f` срабатывает
  по `maxWait` на 250 мс, а потом — когда поток утих, с последним
  значением.

```go
func NewDebouncer[T any](wait, maxWait time.Duration, f func(T)) (call func(v T, now time.Time), tick func(now time.Time)) {
	var (
		pending     bool
		last        T
		first, seen time.Time
	)
	call = func(v T, now time.Time) {
		if !pending {
			pending = true
			first = now
		}
		last, seen = v, now
	}
	tick = func(now time.Time) {
		if !pending {
			return
		}
		quiet := now.Sub(seen) >= wait
		tooLong := maxWait > 0 && now.Sub(first) >= maxWait
		if !quiet && !tooLong {
			return
		}
		v := last
		pending = false
		var zero T
		last = zero
		f(v)
	}
	return call, tick
}
```

**Две функции над одной серией.** Состояние — есть ли отложенное значение,
само значение, начало серии и время последнего вызова — объявлено в
`NewDebouncer` и захвачено обеими функциями. Снаружи его не видно и не
испортить.

**Флаг `pending`, а не сравнение с нулём.** `T` — любой тип, его даже
нельзя сравнить с нулём без `comparable`. И даже для `int` ноль — законное
значение: «пользователь стёр поле, ищем пустую строку».

**`maxWait` — от начала серии.** Серия начинается первым `call` после
срабатывания, поэтому `first` пишется только при `!pending`. Если
обновлять его на каждом вызове, `maxWait` превратится во второй `wait` и
никогда не сработает. Если не сбрасывать после срабатывания — `f` начнёт
срабатывать на каждом `tick`.

**Сначала снять состояние, потом вызвать `f`.** Если `f` сама вызовет
`call` (например, запланирует следующую порцию), серия должна начаться
заново, а не затереться. Отсюда порядок: скопировать `v`, сбросить флаг,
вызвать `f`. В конкурентной версии тот же порядок нужен ещё и чтобы не
держать мьютекс во время `f`.

**Что спросят дальше:** чем debounce отличается от throttle (throttle
пропускает первый вызов сразу и ограничивает частоту, debounce ждёт
тишины) и как сделать то же на `time.AfterFunc` с `Reset`.
