Первый контекст создают с таймаутом `-1s`. Потом у родителя таймаут час, а
у дочернего — два часа. Сравнивают их дедлайны и смотрят дедлайн у
`context.Background()`.

Напишите весь вывод программы.

<Reveal>

**Дедлайн в прошлом — контекст отменён сразу.** `WithTimeout` с
отрицательной длительностью не ошибка: контекст рождается уже
просроченным, `Err()` — `context deadline exceeded`.

**`DeadlineExceeded` и `Canceled` — разные ошибки.** По ним отличают «не
успели» от «нас отменили». `errors.Is` с `DeadlineExceeded` — `true`, с
`Canceled` — `false`. Кстати, `DeadlineExceeded` реализует `Timeout() bool`,
поэтому код, проверяющий сетевые таймауты через `net.Error`, узнаёт и его.

**Ребёнок не может жить дольше родителя.** `WithTimeout(parent, 2h)` видит,
что у родителя дедлайн раньше, и просто берёт родительский. Так что
`d1.Equal(d2)` — `true`. Продлить дедлайн вниз по дереву нельзя, только
сократить.

**У `Background` дедлайна нет** — `ok == false`.

Итого:

```
context deadline exceeded
true false
true
false
```

**Практический вывод.** Если сервис даёт запросу 2 секунды, а внутри вы
ставите таймаут на поход в базу в 5 секунд, работать будет 2. Если нужно
сделать что-то *после* отмены запроса — записать аудит, отправить метрику, —
есть `context.WithoutCancel(ctx)`: значения он сохраняет, а отмену и дедлайн
отрезает.

</Reveal>
