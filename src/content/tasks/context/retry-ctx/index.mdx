Напишите тело `Retry`.

Что проверяют скрытые тесты:

- успех с третьей попытки → `nil`, ровно три вызова;
- все попытки неудачны → последняя ошибка `f`, и после последней попытки
  паузы нет;
- отмена во время часовой паузы прерывает её сразу, ошибка — с
  `context.Canceled`;
- отменённый заранее контекст → `f` не вызывается вовсе;
- `f` получает контекст вызывающего.

<Reveal>

```go
func Retry(ctx context.Context, attempts int, delay time.Duration, f func(context.Context) error) error {
	var last error
	for i := range attempts {
		if err := ctx.Err(); err != nil {
			return fmt.Errorf("retry: попытка %d: %w", i+1, err)
		}
		if last = f(ctx); last == nil {
			return nil
		}
		if i == attempts-1 {
			break
		}
		t := time.NewTimer(delay)
		select {
		case <-t.C:
		case <-ctx.Done():
			t.Stop()
			return fmt.Errorf("retry: ожидание после попытки %d: %w", i+1, ctx.Err())
		}
	}
	return last
}
```

**`time.Sleep` отмену не слышит.** Запрос отменили, клиент ушёл, а
горутина ещё час спит между попытками. Ожидание, которое должно
прерываться, — это всегда `select` с `ctx.Done()`.

**`time.NewTimer` вместо `time.After`** — чтобы при отмене остановить
таймер. С Go 1.23 неостановленный таймер больше не держит память до
срабатывания, но `Stop` по-прежнему честнее.

**Проверка `ctx.Err()` перед попыткой** не даёт начать работу, которая уже
никому не нужна.

**Пауза после последней попытки** — частая мелочь: вызывающий ждёт ещё
`delay` только для того, чтобы получить ту же ошибку.

**В реальном коде** пауза растёт от попытки к попытке и получает случайный
разброс (jitter), а повторяют не всякую ошибку, а только временные.
