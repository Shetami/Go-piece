Каждый запрос длится 100 мс, лимит на запрос — 150 мс. Все три должны
успеть. Программа печатает:

```
a.example <nil>
b.example context deadline exceeded
c.example context deadline exceeded
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 20: `context.WithTimeout(...)` до цикла.

**Дедлайн — это момент времени, а не длительность.** `WithTimeout(150ms)`
вычисляет «сейчас + 150 мс» и дальше живёт с этой отметкой. Один контекст
на три запроса — одна отметка на всех. Первый запрос тратит 100 мс, второму
остаётся 50, и он не успевает. Третьему не остаётся ничего.

Иногда это именно то, что нужно: «на всю пачку — не больше 150 мс». Но по
условию лимит на каждый запрос.

**Как правильно** — свой контекст на каждый запрос:

```go
func fetchWithTimeout(url string) error {
	ctx, cancel := context.WithTimeout(context.Background(), 150*time.Millisecond)
	defer cancel()
	return fetch(ctx, url)
}
```

Отдельная функция здесь не для красоты: `defer cancel()` прямо в цикле
отложил бы все отмены до конца `main`.

**Обычно нужны оба лимита.** Общий дедлайн запроса пользователя сверху
(родительский `ctx`) и свой таймаут на каждый поход вниз. Тогда
`WithTimeout(parentCtx, 150ms)`: запрос получит меньшее из «150 мс» и
«сколько осталось у родителя».

</Reveal>
