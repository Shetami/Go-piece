`context.AfterFunc(ctx, f)` (Go 1.21) запускает `f` после отмены `ctx` и
возвращает функцию `stop`. Первую регистрацию отменяют через `stop` до
отмены контекста. Вторую — после. Третью регистрируют, когда контекст уже
отменён.

Напишите весь вывод программы.

<Reveal>

**`stop` снимает регистрацию и отвечает, успел ли.** До отмены контекста
`stop1()` возвращает `true`: функция не запускалась и уже не запустится.
`"первый"` не печатается никогда.

**После отмены `f` запускается в своей горутине.** Поэтому `main` ждёт
`done2`, иначе порядок печати был бы случайным. `stop2()` после этого
возвращает `false`: функция уже запущена, остановить её нечего.

**Регистрация на уже отменённом контексте запускает `f` сразу** — тоже в
отдельной горутине.

Итого:

```
stop1: true
второй
stop2: false
третий
```

**Где полезно.** Разбудить то, что не умеет слушать контекст: закрыть
соединение, чтобы прервать блокирующее чтение, или сделать `cond.Broadcast`,
чтобы ожидающие на `sync.Cond` проснулись и проверили `ctx.Err()`. Раньше
для этого заводили горутину с `<-ctx.Done()`, которую ещё надо было не
забыть остановить.

</Reveal>
