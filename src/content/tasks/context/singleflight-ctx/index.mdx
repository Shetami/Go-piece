Классический singleflight (как `golang.org/x/sync/singleflight.Do`) не
знает про контекст: вызов идёт с контекстом того, кто пришёл первым.
Если первый клиент отвалился, общий запрос в базу отменяется — и падают
все, кто к нему присоединился. А если не отменять вовсе, запрос живёт,
даже когда его уже никто не ждёт. Напишите `Group.Do`, в котором у
каждого ждущего своя отмена, а общий вызов живёт, пока нужен хоть
кому-то.

Что проверяют скрытые тесты:

- десять одновременных `Do` — один вызов `fn`, все получают результат;
  после завершения следующий `Do` вызывает `fn` снова;
- первый вызывающий ушёл — он сразу получает причину своей отмены,
  контекст `fn` жив, второй получает результат, а `fn` видит значения
  первого;
- ушли все — контекст `fn` отменён, а новый `Do` запускает новый вызов,
  хотя брошенный ещё не вернулся;
- ошибка `fn` достаётся всем ждущим.

<Reveal>

```go
type call[V any] struct {
	done    chan struct{}
	val     V
	err     error
	waiters int
	cancel  context.CancelFunc
}

type Group[K comparable, V any] struct {
	mu sync.Mutex
	m  map[K]*call[V]
}

func (g *Group[K, V]) Do(ctx context.Context, key K, fn func(context.Context) (V, error)) (V, error) {
	g.mu.Lock()
	if g.m == nil {
		g.m = make(map[K]*call[V])
	}
	c, ok := g.m[key]
	if !ok {
		fctx, cancel := context.WithCancel(context.WithoutCancel(ctx))
		c = &call[V]{done: make(chan struct{}), cancel: cancel}
		g.m[key] = c
		go func() {
			v, err := fn(fctx)
			c.val, c.err = v, err
			g.mu.Lock()
			if g.m[key] == c {
				delete(g.m, key)
			}
			g.mu.Unlock()
			cancel()
			close(c.done)
		}()
	}
	c.waiters++
	g.mu.Unlock()

	select {
	case <-c.done:
		return c.val, c.err
	case <-ctx.Done():
		g.mu.Lock()
		c.waiters--
		if c.waiters == 0 {
			if g.m[key] == c {
				delete(g.m, key)
			}
			c.cancel()
		}
		g.mu.Unlock()
		var zero V
		return zero, context.Cause(ctx)
	}
}
```

**Вызов живёт в своей горутине, ждущие — в `select`.** Тогда любой
вызывающий может уйти по своему `ctx`, не трогая сам вызов. Если бы `fn`
выполнял первый пришедший прямо в своей горутине, его отмена обрывала
бы работу для всех.

**`WithoutCancel(ctx)` + свой `cancel`.** От первого вызывающего берём
значения (trace id, пользователь — для логов и прав), но не его отмену.
Отмену заменяет подсчёт ждущих: последний ушедший вызывает `cancel`, и
база перестаёт выполнять запрос, который никому не нужен.

**Брошенный вызов нужно убрать из мапы сразу.** Иначе новый запрос
придёт, найдёт отменённый вызов и присоединится к нему — получит
`context.Canceled`, которого не заслужил. Поэтому горутина вызова
удаляет ключ, только если в мапе всё ещё *её* вызов (`g.m[key] == c`):
его место мог уже занять новый.

**Результат пишется до `close(done)`.** Закрытие канала — точка
синхронизации: всё, что записано до него, видно тем, кто прочитал из
канала. Мьютекс для `val`/`err` не нужен.

**Что спросят дальше:** как совместить это с кэшем (singleflight
закрывает только одновременные промахи), что делать с паникой в `fn` (её
нужно поймать и отдать всем ждущим) и почему `x/sync/singleflight`
предлагает `DoChan` — это ровно половина этого решения.
