Три контекста с таймаутом. У первого таймаут нулевой. Второй получает час,
но его родитель уже отменён. Третий получает час, но его отменяют руками
через `cancel`.

Напишите весь вывод программы.

<Reveal>

**Нулевой (и отрицательный) таймаут — контекст, который уже истёк.**
`WithTimeout` видит, что дедлайн в прошлом, и отменяет контекст сразу, с
причиной `DeadlineExceeded`. Это не ошибка — так удобно проверять код на
реакцию на таймаут.

**Отмена родителя сильнее таймаута ребёнка.** Родитель отменён через
`cancel` — ребёнок унаследовал его отмену в момент создания, и ошибка у
него `Canceled`. До своего часа он не доживёт.

**Ручной `cancel` даёт `Canceled`**, даже у контекста с таймаутом. Ошибка
говорит, *почему* контекст закончился, а не каким конструктором его
создали. Дедлайн при этом никуда не девается: `Deadline()` по-прежнему
возвращает `ok == true`.

Итого:

```
context deadline exceeded
true
context canceled
context canceled
true
```

**Зачем различать.** `DeadlineExceeded` — «мы не успели», обычно это 504 и
метрика таймаутов. `Canceled` — «нас больше не ждут», клиент ушёл сам, и
считать это ошибкой сервиса нечестно. Проверять — через `errors.Is`: обе
ошибки часто приходят обёрнутыми.

</Reveal>
