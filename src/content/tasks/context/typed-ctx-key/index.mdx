В каждом пакете повторяется одно и то же: приватный тип ключа, функция
`WithX`, функция `XFrom` с приведением типа. Хочется один обобщённый
ключ: `var userKey = NewKey[string]("user")`, дальше `userKey.With(ctx,
…)` и `userKey.Get(ctx)`. Допишите `With`, `Get` и `MustGet`.

Что проверяют скрытые тесты:

- `With` → `Get` возвращает значение; на пустом контексте `ok == false`;
  ближайший `With` перекрывает предыдущий;
- два `NewKey[string]("id")` — два разных ключа; `Key[int]` с тем же
  именем и строковый ключ `"id"` тоже ничего не видят и ничего не
  перекрывают;
- `Key[error]`, в который положили `nil`, отвечает `(nil, true)`; так же
  для `nil`-указателя;
- `MustGet` без значения паникует с именем ключа в сообщении.

<Reveal>

```go
type box[T any] struct{ v T }

func (k *Key[T]) With(ctx context.Context, v T) context.Context {
	return context.WithValue(ctx, k, box[T]{v})
}

func (k *Key[T]) Get(ctx context.Context) (T, bool) {
	b, ok := ctx.Value(k).(box[T])
	return b.v, ok
}

func (k *Key[T]) MustGet(ctx context.Context) T {
	v, ok := k.Get(ctx)
	if !ok {
		panic(fmt.Sprintf("в контексте нет значения %q", k.name))
	}
	return v
}
```

**Ключ — сам указатель `*Key[T]`.** `ctx.Value` ищет по `==`. Если
ключом сделать `k.name`, все ключи с именем `"id"` совпадут между собой и
со строкой из чужого пакета. Если ключом сделать значение `Key[T]{name}`,
совпадут два `NewKey[string]("id")`. Указатель уникален для каждого
`NewKey` — это тот же приём, что и `type ctxKey struct{}`, только без
отдельного типа на каждый ключ.

**Зачем обёртка `box`.** Для `T = error` наивное
`ctx.Value(k).(T)` ломается: положили `nil`-ошибку — `Value` вернёт
`nil`-интерфейс `any`, а приведение `nil` к интерфейсу `error` даёт
`ok == false`. «Положили nil» становится неотличимо от «не клали».
Обёртка — всегда непустое значение конкретного типа, и `ok` честный.

**Тип значения гарантирует компилятор.** `userKey.With(ctx, 42)` не
скомпилируется, а вызывающему не нужно приведение типа и проверка `ok`
на тип — только на наличие.

**Что спросят дальше:** почему `String()` полезен (`fmt.Println(ctx)`
печатает ключи) и почему даже с удобным ключом в контекст кладут только
request-scoped данные, а не зависимости.

</Reveal>
