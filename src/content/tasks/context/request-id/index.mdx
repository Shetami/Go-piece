Напишите `WithRequestID` и `RequestID`.

Что проверяют скрытые тесты:

- положили — достали, в пустом контексте — `ok == false`;
- дочерний контекст может переопределить значение, родитель не меняется;
- значение нельзя достать строковым ключом вроде `"request_id"` — и нельзя
  подменить, положив что-то по такому ключу.

<Reveal>

```go
type requestIDKey struct{}

func WithRequestID(ctx context.Context, id string) context.Context {
	return context.WithValue(ctx, requestIDKey{}, id)
}

func RequestID(ctx context.Context) (string, bool) {
	id, ok := ctx.Value(requestIDKey{}).(string)
	return id, ok
}
```

**Ключ — свой неэкспортируемый тип.** Контекст сравнивает ключи через `==`
вместе с типом. `requestIDKey{}` может создать только этот пакет, поэтому
ни чтение, ни запись снаружи невозможны: чужой `"request_id"` — это
`string`, другой ключ. Пустая структура не занимает памяти, и все её
значения равны друг другу.

**Приведение с `ok`.** `ctx.Value` возвращает `any`, для отсутствующего
ключа — `nil`. Форма `.(string)` с `ok` превращает оба случая —
«нет значения» и «лежит не строка» — в аккуратное `"", false` без паники.

**Почему не экспортировать ключ.** Тогда любой пакет смог бы положить туда
что угодно, и `RequestID` пришлось бы защищаться от чужих типов. Пара
функций — единственная точка входа, и формат значения под контролем.

`go vet` не ругается на строковые ключи, а `staticcheck` — да (SA1029):
«should not use built-in type string as key for value».

</Reveal>
