p50 ответа хранилища — 5 мс, а p99 — 400: иногда реплика задумывается на
сборке мусора. Hedged-запрос срезает этот хвост: если реплика не ответила
за порог (обычно около p95), запрос параллельно отправляют следующей и
берут того, кто ответит первым. В отличие от «спросить всех сразу»,
лишняя нагрузка появляется только на медленных запросах. Напишите
`Hedged`.

Что проверяют скрытые тесты:

- первая реплика ответила быстро — вторая не запускается вовсе;
- первая молчит — через `delay` запускается вторая, её ответ
  возвращается, первая получает отмену, третья не запускается;
- реплика упала — следующая стартует сразу, а не через `delay`
  (здесь он — час);
- все упали — ошибка содержит каждую из ошибок; нет реплик —
  `ErrNoReplicas`;
- отмена родителя с причиной — причина;
- тридцать запросов не оставляют висящих горутин.

```go
func Hedged(ctx context.Context, delay time.Duration, replicas []Replica) (string, error) {
	if len(replicas) == 0 {
		return "", ErrNoReplicas
	}
	ctx, cancel := context.WithCancel(ctx)
	defer cancel()

	type result struct {
		i   int
		v   string
		err error
	}
	results := make(chan result, len(replicas))
	next, running := 0, 0
	launch := func() {
		i := next
		next++
		running++
		go func() {
			v, err := replicas[i](ctx)
			results <- result{i, v, err}
		}()
	}

	launch()
	timer := time.NewTimer(delay)
	defer timer.Stop()
	var errs []error
	for {
		select {
		case r := <-results:
			running--
			if r.err == nil {
				return r.v, nil
			}
			errs = append(errs, fmt.Errorf("реплика %d: %w", r.i, r.err))
			if next < len(replicas) {
				launch()
				timer.Reset(delay)
			} else if running == 0 {
				return "", errors.Join(errs...)
			}
		case <-timer.C:
			if next < len(replicas) {
				launch()
				timer.Reset(delay)
			}
		case <-ctx.Done():
			return "", context.Cause(ctx)
		}
	}
}
```

**Один общий производный контекст на все реплики.** `defer cancel()`
отменяет всех проигравших одной строкой при любом выходе — с ответом,
с ошибкой или по отмене родителя. Реплика, которая слушает `ctx`, сразу
освобождает соединение.

**Буфер канала на всех реплик — защита от утечки.** Мы возвращаемся,
не дождавшись проигравших; когда те закончат, им нужно куда-то записать
результат. С небуферизованным каналом каждая проигравшая висела бы на
`results <-` вечно.

**Когда сдаваться — по счётчику, а не по числу ошибок.** «Все упали»
значит: реплик больше нет *и* никто не работает. Пока хоть одна жива,
она ещё может ответить.

**Таймер один, `Reset` после каждого запуска.** С Go 1.23 `Reset` у
таймера безопасен без предварительного дренажа канала. Упавшая реплика
запускает следующую сразу и перезапускает отсчёт — ждать `delay` после
заведомого отказа бессмысленно.

**Что спросят дальше:** почему hedging допустим только для идемпотентных
запросов, как ограничить его долю (не больше N % запросов, иначе при
общей деградации нагрузка удвоится) и откуда брать `delay` — из
скользящего p95 латентности.
