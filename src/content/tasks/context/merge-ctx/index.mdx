Напишите тело `Merge`. Типичный случай: обработка должна прерваться и
когда клиент ушёл (контекст запроса), и когда сервис останавливается
(контекст сервиса).

Что проверяют скрытые тесты:

- отмена `a` отменяет результат;
- отмена `b` с причиной отменяет результат, и `context.Cause` — эта
  причина;
- истёкший дедлайн `b` → причина `DeadlineExceeded`;
- значения берутся из `a`, пока никто не отменён — результат жив;
- возвращённая `cancel` отменяет результат, повторный вызов безопасен;
- сто пар `Merge` + `cancel` не оставляют горутин.

<Reveal>

```go
func Merge(a, b context.Context) (context.Context, context.CancelFunc) {
	ctx, cancel := context.WithCancelCause(a)
	stop := context.AfterFunc(b, func() {
		cancel(context.Cause(b))
	})
	return ctx, func() {
		stop()
		cancel(context.Canceled)
	}
}
```

**У контекста один родитель.** Всё, что приходит от `a` — значения,
дедлайн, отмена, — наследуется обычным `WithCancelCause(a)`. От `b` нужна
только отмена, и её пробрасывают вручную.

**`context.AfterFunc` (Go 1.21) — пробросить отмену без горутины.** Раньше
писали так:

```go
go func() {
	select {
	case <-b.Done():
		cancel()
	case <-ctx.Done():
	}
}()
```

Это горутина на каждый вызов, а стоило забыть вторую ветку `select` — и она
жила вечно. `AfterFunc` регистрирует функцию прямо в
`b` и запускает её только при отмене.

**`stop()` в `cancel` обязателен.** Если `b` долгоживущий (контекст
сервиса), без `stop` каждая регистрация висела бы в нём до остановки
сервиса — утечка на каждый запрос.

**`WithCancelCause`** сохраняет *почему*: `context.Cause(m)` скажет,
остановка сервиса это или таймаут, а `m.Err()` по-прежнему будет
стандартным `Canceled` или `DeadlineExceeded`.

</Reveal>
