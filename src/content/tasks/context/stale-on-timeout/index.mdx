Карточка товара кэшируется на минуту. Когда TTL истёк, запрос идёт в
базу, а база под нагрузкой отвечает 300 мс при бюджете запроса 50. Если
загрузка идёт с контекстом запроса, она отменяется вместе с ним — и кэш
не обновится никогда: каждый следующий запрос тоже не успеет. Напишите
`Get`, который в такой ситуации отдаёт устаревшее значение, а загрузку
доводит до конца в фоне.

Что проверяют скрытые тесты:

- свежее значение — из кэша, без загрузки; после TTL — новая загрузка;
- загрузка медленнее дедлайна вызывающего — сразу устаревшее значение
  со `stale = true`; загрузка при этом не отменяется и кладёт свежее
  значение в кэш;
- устаревшего нет, а вызывающий ушёл — причина его отмены;
- ошибка загрузки без устаревшего — ошибка, с устаревшим — устаревшее;
  ошибки не кэшируются;
- двадцать одновременных промахов по одному ключу — одна загрузка.

<Reveal>

```go
func (c *Cache[K, V]) Get(ctx context.Context, key K) (V, bool, error) {
	c.mu.Lock()
	old, have := c.data[key]
	if have && c.now().Sub(old.at) < c.ttl {
		c.mu.Unlock()
		return old.val, false, nil
	}
	f, ok := c.inflight[key]
	if !ok {
		f = &flight[V]{done: make(chan struct{})}
		c.inflight[key] = f
		lctx, cancel := context.WithTimeout(context.WithoutCancel(ctx), c.loadTimeout)
		go func() {
			defer cancel()
			v, err := c.load(lctx, key)
			c.mu.Lock()
			if err == nil {
				c.data[key] = entry[V]{v, c.now()}
			}
			delete(c.inflight, key)
			f.val, f.err = v, err
			c.mu.Unlock()
			close(f.done)
		}()
	}
	c.mu.Unlock()

	select {
	case <-f.done:
		if f.err == nil {
			return f.val, false, nil
		}
		if have {
			return old.val, true, nil
		}
		var zero V
		return zero, false, f.err
	case <-ctx.Done():
		if have {
			return old.val, true, nil
		}
		var zero V
		return zero, false, context.Cause(ctx)
	}
}
```

**Загрузка и ожидание — разные сроки жизни.** Вызывающий ждёт, пока
жив его запрос; загрузка живёт, пока не наполнит кэш. Поэтому загрузка
в своей горутине с `WithoutCancel(ctx)` (значения для трейсинга
сохраняются) и собственным `loadTimeout` — без него зависшая база
держала бы горутину вечно. Ожидающий просто выбирает в `select` между
результатом и своим `ctx.Done()`.

**Устаревшее лучше ошибки.** Для каталога, настроек, курсов валют
минутная задержка данных почти всегда приемлемее, чем 504. Это
stale-while-revalidate и stale-if-error из HTTP-кэширования (RFC 5861),
только в памяти процесса. `stale = true` наружу — чтобы вызывающий мог
пометить ответ или записать метрику.

**Одна загрузка на ключ — иначе давка.** Когда TTL популярного ключа
истекает, сотни запросов одновременно видят промах. Без `inflight` все
они пошли бы в и так медленную базу — классический cache stampede.
Запись в `data` и удаление из `inflight` — под одной блокировкой:
следующий `Get` либо присоединится к загрузке, либо увидит свежее
значение, но не запустит лишнюю.

**Часы — параметром.** TTL проверяется по `now()`, и тест двигает время
вручную, не засыпая на минуту.

**Что спросят дальше:** как обновлять горячие ключи заранее, до
истечения TTL (probabilistic early expiration), и почему устаревшее
значение нельзя отдавать для остатков на складе или баланса.
