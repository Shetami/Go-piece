Контекст не пересекает границу процесса. Чтобы дедлайн запроса
доехал до соседнего сервиса, его передают заголовком — так делает gRPC
(`grpc-timeout`). Клиент пишет остаток, сервер восстанавливает контекст
и не работает дольше, чем клиент готов ждать. Напишите `Inject` и
`Extract`.

Что проверяют скрытые тесты:

- `Inject`: 1 с минус запас 100 мс — около `900`, целыми миллисекундами
  вниз; остаток меньше запаса — `"0"`; нет дедлайна — заголовок
  удаляется;
- `Extract`: `"300"` — около 300 мс; просьба больше серверного лимита
  обрезается до лимита; `"0"` — контекст уже истёк;
- `"abc"`, `"-5"`, `"1.5"`, пустая строка, пробел в начале, число за
  пределами `int64`, отсутствие заголовков — таймаут по лимиту;
- `"9000000000000000"` мс — корректное число, но не должно превратиться
  в отрицательную `Duration` и мгновенный таймаут;
- дедлайн и значения родителя сохраняются, `cancel` работает.

<Reveal>

```go
func Inject(ctx context.Context, h map[string]string, reserve time.Duration) {
	dl, ok := ctx.Deadline()
	if !ok {
		delete(h, TimeoutHeader)
		return
	}
	ms := max((time.Until(dl) - reserve).Milliseconds(), 0)
	h[TimeoutHeader] = strconv.FormatInt(ms, 10)
}

func Extract(parent context.Context, h map[string]string, limit time.Duration) (context.Context, context.CancelFunc) {
	timeout := limit
	if s, ok := h[TimeoutHeader]; ok {
		if ms, err := strconv.ParseInt(s, 10, 64); err == nil && ms >= 0 {
			if ms < math.MaxInt64/int64(time.Millisecond) {
				timeout = min(time.Duration(ms)*time.Millisecond, limit)
			}
		}
	}
	return context.WithTimeout(parent, timeout)
}
```

**Передают остаток, а не момент времени.** Абсолютный дедлайн
(«до 12:00:03.250») зависит от синхронности часов на машинах; расхождение
в полсекунды сделает его бессмысленным. Длительность от момента отправки
переживает рассинхрон — ценой того, что время в сети не учтено. Для
этого и `reserve`.

**Заголовок — пользовательский ввод.** Сервер не доверяет ему вслепую:
мусор игнорируется, а просьба «дайте мне час» обрезается собственным
лимитом. Иначе один клиент держал бы горутины и соединения к базе
сколько захочет.

**Переполнение — самая коварная ловушка.** `ParseInt` честно разберёт
9·10¹⁵, но умножение на `time.Millisecond` (10⁶) выходит за `int64` и
даёт отрицательную `Duration`. `WithTimeout` с отрицательным таймаутом —
мгновенно истёкший контекст: запрос с «бесконечным» бюджетом падает
сразу. Сравнение с `MaxInt64 / 1e6` до умножения это исключает.

**Родитель остаётся родителем.** Если у сервера свой, более ранний
дедлайн (например, от HTTP-сервера), `WithTimeout` его не продлит — ни
один производный контекст не живёт дольше родителя.

**Что спросят дальше:** что делать, если заголовок пришёл `"0"` —
отвечать сразу, не трогая базу, — и как этот же механизм защищает от
каскадных отказов: сервис не делает работу, результат которой клиент
уже не ждёт.
