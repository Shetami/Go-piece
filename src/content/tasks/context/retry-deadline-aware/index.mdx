Клиент к внешнему API повторяет запросы с экспоненциальной паузой. У
запроса есть дедлайн, и бессмысленно засыпать на две секунды, если до
дедлайна осталось 200 мс: проснёмся — а делать уже нечего. Напишите тело
`Do`.

Что проверяют скрытые тесты:

- паузы растут `1, 2, 4, 8…` от `Base`, упираются в `Max` и при
  семидесяти попытках не переполняются в отрицательные;
- после последней попытки паузы нет;
- ошибка с `RetryAfter()` (даже обёрнутая) задаёт паузу сама, без
  `Jitter` и потолка;
- пауза не помещается до дедлайна — `Do` возвращается сразу, с `ErrNoTime`
  и последней ошибкой;
- отмена во время часовой паузы прерывает её, ошибка несёт и причину
  отмены, и последнюю ошибку `f`;
- отменённый заранее контекст — `f` не вызывается.

```go
func Do(ctx context.Context, p Policy, f func(context.Context) error) error {
	var last error
	for k := 1; ; k++ {
		if ctx.Err() != nil {
			return fmt.Errorf("retry: попытка %d отменена: %w", k, errors.Join(context.Cause(ctx), last))
		}
		if last = f(ctx); last == nil {
			return nil
		}
		if k >= p.Attempts {
			return last
		}

		pause := p.backoff(k)
		var ra RetryAfterError
		if errors.As(last, &ra) {
			pause = ra.RetryAfter()
		} else if p.Jitter != nil {
			pause = p.Jitter(pause)
		}

		if dl, ok := ctx.Deadline(); ok && time.Now().Add(pause).After(dl) {
			return errors.Join(ErrNoTime, last)
		}

		t := time.NewTimer(pause)
		select {
		case <-t.C:
		case <-ctx.Done():
			t.Stop()
			return fmt.Errorf("retry: пауза после попытки %d прервана: %w", k, errors.Join(context.Cause(ctx), last))
		}
	}
}

func (p Policy) backoff(k int) time.Duration {
	d := p.Base
	for i := 1; i < k; i++ {
		if d >= p.Max/2 {
			return p.Max
		}
		d *= 2
	}
	return min(d, p.Max)
}
```

**Сначала сравнить, потом удваивать.** `Base << (k-1)` или `Base *
math.Pow(2, k)` при k за 40 переполняет `int64`: пауза становится
отрицательной, таймер срабатывает мгновенно, и ретраи превращаются в
DDoS. Проверка `d >= Max/2` до умножения гарантирует, что переполнения не
будет никогда.

**Дедлайн — часть решения «ждать или нет».** `ctx.Deadline()` сообщает,
сколько осталось. Если пауза кончится позже, честнее сдаться сразу с
понятной ошибкой: вызывающий успеет вернуть клиенту ответ, а не упадёт
по таймауту посреди сна. Сравнивают уже *фактическую* паузу, после
`Jitter`.

**`errors.As` для Retry-After.** Ошибка приходит обёрнутой слоями
`fmt.Errorf`, так что простое приведение типа её не найдёт. Сервер,
приславший 429, знает свою нагрузку лучше нашей формулы — поэтому без
разброса и без потолка.

**Отмена не должна прятать последнюю ошибку.** `errors.Join(Cause, last)`
позволяет и понять, что запрос отменили, и увидеть, с чем сервис падал до
этого. Дальше спросят, какие ошибки вообще нельзя повторять (4xx,
неидемпотентные операции) и почему нужен jitter — синхронные ретраи
тысячи клиентов бьют в сервис волнами.
