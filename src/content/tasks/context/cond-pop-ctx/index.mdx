Очередь заданий построена на `sync.Cond`: `Pop` засыпает в `Wait`, пока
кто-нибудь не сделает `Push`. Всё работало, пока воркеры не начали
останавливаться по контексту: воркер на пустой очереди спит в `Wait` и
отмену не видит. Перепишите `Pop` так, чтобы он слышал `ctx`. `Push` и
остальное трогать не нужно.

Что проверяют скрытые тесты:

- `Pop` дожидается `Push` и соблюдает порядок FIFO;
- отмена контекста будит `Pop` на пустой очереди, ошибка — причина
  отмены;
- отменённый заранее контекст — ошибка, и элемент остаётся в очереди;
- двадцать ожидающих, половину отменили, потом положили десять
  элементов — каждый элемент достаётся ровно одному живому ожидающему;
- двести успешных `Pop` не оставляют горутин.

<Reveal>

```go
func (q *Queue[T]) Pop(ctx context.Context) (T, error) {
	stop := context.AfterFunc(ctx, func() {
		q.mu.Lock()
		defer q.mu.Unlock()
		q.cond.Broadcast()
	})
	defer stop()

	q.mu.Lock()
	defer q.mu.Unlock()
	for {
		if ctx.Err() != nil {
			var zero T
			return zero, context.Cause(ctx)
		}
		if len(q.items) > 0 {
			v := q.items[0]
			var zero T
			q.items[0] = zero
			q.items = q.items[1:]
			return v, nil
		}
		q.cond.Wait()
	}
}
```

**`Cond.Wait` нельзя положить в `select`.** Поэтому отмену превращают в
пробуждение: `context.AfterFunc` (Go 1.21) вызовет функцию при отмене, а
она сделает `Broadcast`. Это ровно пример из документации пакета
`context`. Все ожидающие проснутся, перепроверят условие, и отменённые
уйдут, а остальные уснут снова.

**`Broadcast` под мьютексом — ключ к корректности.** Без `Lock` возможна
гонка: `Pop` проверил `ctx.Err()` (ещё `nil`), в этот момент контекст
отменили, и `Broadcast` прошёл, когда в `Wait` ещё никого нет. Затем
`Pop` засыпает — навсегда. С мьютексом `Broadcast` не может случиться
между проверкой и `Wait`: `Wait` отпускает мьютекс атомарно с постановкой
в очередь ожидания.

**`stop()` обязателен.** Если `Pop` ушёл с элементом, регистрация
осталась бы в долгоживущем контексте воркера до его отмены — утечка на
каждый вызов. Вариант с горутиной `<-ctx.Done(); Broadcast()` ещё хуже:
тест на двести `Pop` поймает двести висящих горутин.

**Сначала `ctx.Err()`, потом элемент.** Иначе отменённый воркер заберёт
задание, которое уже некому выполнить. Дальше спросят, почему здесь
вообще `Cond`, а не буферизованный канал, — и в каком случае `Cond`
всё-таки удобнее (сложное условие, `Broadcast` многим).
