`withRequestID` кладёт в контекст `"a1b2"`, `logf` достаёт его для лога.
Программа печатает:

```
[без id] заказ создан
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 17: `ctx.Value("request_id")`.

**Ключи контекста сравниваются вместе с типом.** Значение положили по ключу
`requestIDKey` — это `ctxKey("request_id")`. Ищут по `"request_id"` — это
`string`. Текст одинаковый, типы разные, и для `==` на интерфейсах это разные
значения. `Value` ничего не находит, приведение к `string` даёт `""`.

**Как правильно** — искать по той же константе:

```go
id, _ := ctx.Value(requestIDKey).(string)
```

**Как устроить, чтобы ошибиться было нельзя.** Сделать ключ
неэкспортируемым типом (`type ctxKey struct{}`) и не давать трогать его
напрямую — только через пару функций:

```go
func WithRequestID(ctx context.Context, id string) context.Context
func RequestID(ctx context.Context) (string, bool)
```

Тогда ключ живёт в одном пакете, и ни опечатка, ни чужой пакет с такой же
строкой до значения не доберутся. Так сделаны почти все библиотеки, которые
кладут что-то в контекст.

</Reveal>
