`WithCancelCause` дважды отменяют с разными причинами. Потом смотрят
`Cause` у обычного отменённого контекста и отвязывают отменённый контекст
через `WithoutCancel`.

Напишите весь вывод программы.

<Reveal>

**`Err()` не меняется.** Ради совместимости `Err()` у отменённого контекста
всегда одно из двух: `context.Canceled` или `context.DeadlineExceeded`.
Причина живёт отдельно, её достают через `context.Cause`.

**Срабатывает только первая отмена.** Повторный `cancel` ничего не делает —
ни `Err`, ни причину он не меняет. `Cause` — «клиент ушёл».

**У обычного `WithCancel` причина — это `Err()`.** Если причину не задавали,
`Cause` возвращает то же, что `Err`: `context canceled`. Поэтому `Cause`
можно звать на любом контексте, не выясняя, как его создали.

**`WithoutCancel` отрезает отмену.** Получается контекст с теми же
значениями, но без отмены: `Err()` — `nil`, а `Done()` возвращает `nil`-канал,
из которого никогда ничего не придёт.

Итого:

```
context canceled
клиент ушёл
context canceled
<nil> true
```

**Зачем всё это.** В логах «context canceled» ничего не объясняет: отменил
клиент, балансировщик, ваш же таймаут или завершение сервиса? С
`WithCancelCause` (и `WithTimeoutCause` для дедлайнов) источник отмены
передаёт причину, а место, где ошибку логируют, её показывает.

</Reveal>
