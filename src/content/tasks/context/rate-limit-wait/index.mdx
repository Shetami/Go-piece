Партнёрский API разрешает не больше одного запроса в `every`. Все
горутины сервиса перед запросом вызывают `limiter.Wait(ctx)`. Наивный
лимитер спит под мьютексом и ничего не знает про контекст: запросы с
истёкшим дедлайном всё равно занимают очередь, а ушедшие клиенты
забирают слоты у живых. Напишите `Wait` по образцу
`golang.org/x/time/rate`.

Что проверяют скрытые тесты:

- пять горутин одновременно: первая проходит сразу, ни одна не проходит
  раньше своего слота;
- слот через 100 мс, дедлайн через 10 — `ErrDeadlineTooSoon` сразу, и
  этот отказ не сдвигает следующий слот;
- отмена во время ожидания — сразу, с причиной, а слот возвращается
  следующему;
- отменённый заранее контекст — ошибка и никакого резервирования.

```go
func (l *Limiter) Wait(ctx context.Context) error {
	if ctx.Err() != nil {
		return context.Cause(ctx)
	}
	l.mu.Lock()
	now := time.Now()
	slot := l.next
	if slot.Before(now) {
		slot = now
	}
	if dl, ok := ctx.Deadline(); ok && dl.Before(slot) {
		l.mu.Unlock()
		return ErrDeadlineTooSoon
	}
	l.next = slot.Add(l.every)
	l.mu.Unlock()

	wait := time.Until(slot)
	if wait <= 0 {
		return nil
	}
	t := time.NewTimer(wait)
	defer t.Stop()
	select {
	case <-t.C:
		return nil
	case <-ctx.Done():
		l.mu.Lock()
		if l.next.Equal(slot.Add(l.every)) {
			l.next = slot
		}
		l.mu.Unlock()
		return context.Cause(ctx)
	}
}
```

**Резервирование вместо сна под мьютексом.** Под мьютексом только
арифметика: взять ближайший слот и сдвинуть `next`. Ждём уже без
блокировки, в `select` с отменой. Наивное `time.Sleep` под `Lock`
выстраивает всех в очередь за спящим и делает отмену невозможной.

**Дедлайн известен заранее — используйте его.** Если слот наступит
позже дедлайна, результат ожидания предрешён: запрос всё равно упадёт.
Отказать сразу лучше для всех: клиент быстрее получит ответ, а слот
достанется тому, кто успеет. Так делает `rate.Limiter.Wait`.

**Отменённый возвращает слот — если может.** Если за ним уже
зарезервировали следующие, вернуть «дырку» посреди очереди просто так
нельзя: сдвигать чужие слоты сложно, и `x/time/rate` делает это
приближённо. Здесь — простое правило: вернуть, если мы последние.

**Только монотонные часы.** `time.Now()` в Go несёт монотонную
составляющую, и `Before`/`Until` не ломаются от перевода системных
часов. Но `Equal` для сравнения, а не `==`: у `time.Time` есть поле
локации.

**Что спросят дальше:** как добавить burst (token bucket вместо
«одного в интервал»), и почему распределённый лимит на много реплик
в памяти не сделать — нужен Redis или лимит на стороне шлюза.
