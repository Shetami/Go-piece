Push-сервис принимает текст не длиннее N байт, колонка в старой базе —
`VARCHAR(255)` в байтах. Обрезать надо так, чтобы пользователь не увидел
ни `�`, ни «и» без кратки, ни полсемьи из эмодзи. Напишите `TruncateBytes`
по правилам из комментария — это упрощённая сегментация на графемы, без
сторонних пакетов.

Что проверяют скрытые тесты:

- строка, которая помещается, не меняется — даже без запаса на `…`;
- `…` занимает 3 байта и входит в лимит; лимит меньше 3 → `""`;
- кириллица: не остаётся половины буквы — на любом лимите от 0 до 40
  результат валидный UTF-8;
- «й», записанная как «и» + U+0306, и «é» как «e» + U+0301 не теряют
  знак;
- эмодзи-семья через ZWJ, сердце с вариационным селектором, палец с
  тоном кожи — целиком или никак;
- пробелы перед многоточием убираются; байт невалидного UTF-8 не
  ломает разбор.

```go
const ellipsis = "…" // 3 байта в UTF-8

func TruncateBytes(s string, limit int) string {
	if len(s) <= limit {
		return s
	}
	budget := limit - len(ellipsis)
	if budget < 0 {
		return ""
	}
	end := 0 // граница последнего целого кластера, который помещается
	for i := 0; i < len(s); {
		next := clusterEnd(s, i)
		if next > budget {
			break
		}
		end, i = next, next
	}
	return strings.TrimRightFunc(s[:end], unicode.IsSpace) + ellipsis
}

func clusterEnd(s string, i int) int {
	_, size := utf8.DecodeRuneInString(s[i:]) // невалидный байт: size == 1
	i += size
	for i < len(s) {
		r, size := utf8.DecodeRuneInString(s[i:])
		switch {
		case r == '‍':
			// ZWJ склеивает с кластером следующую руну.
			i += size
			if i < len(s) {
				_, sz := utf8.DecodeRuneInString(s[i:])
				i += sz
			}
		case isExtend(r):
			i += size
		default:
			return i
		}
	}
	return i
}

func isExtend(r rune) bool {
	return unicode.In(r, unicode.Mn, unicode.Me) ||
		(r >= 0xFE00 && r <= 0xFE0F) ||
		(r >= 0x1F3FB && r <= 0x1F3FF)
}
```

**Три уровня «символа».** Байт, руна и то, что человек видит как одну
букву, — графемный кластер. `s[:n]` режет байты и может разорвать руну.
Переход на `[]rune` спасает от `�`, но «й» в NFD — это две руны, и
обрезка между ними оставит голую «и», а семья 👨‍👩‍👧 — пять рун, и
отрезанный хвост покажет одинокого папу. Честная сегментация описана в
UAX #29 (в Go — пакет `github.com/rivo/uniseg`), здесь — её ядро:
«расширяющие» руны и ZWJ приклеиваются к предыдущему символу.

**Бюджет считаем заранее.** `limit - len("…")` — место под текст. Частая
ошибка — сначала обрезать до `limit`, потом дописать многоточие и
вылезти за лимит на 3 байта. Вторая — дописывать `…`, когда строка
помещается целиком: пользователь увидит обрезку там, где её нет.

**Идём по кластерам, а не по рунам.** `clusterEnd` возвращает границу
следующего кластера; как только она выходит за бюджет — останавливаемся
на предыдущей. `utf8.DecodeRuneInString` на битом байте возвращает
`RuneError` и размер 1 — поэтому невалидный вход не зацикливает разбор и
не теряется.

**Пробелы перед многоточием — косметика, которая бросается в глаза.**
«слово …» выглядит как баг вёрстки, поэтому `TrimRightFunc` по
`unicode.IsSpace`. Дальше на собеседовании спросят: а если лимит в
«ширине на экране» (иероглифы занимают две клетки), и почему для базы
иногда лучше нормализовать текст в NFC до записи.
