В конфиге лимиты пишут по-человечески: `max_body: 10MB`,
`cache: 1.5 GiB`. Напишите `ParseSize`, который превращает такую строку в
число байт по правилам из комментария.

Что проверяют скрытые тесты:

- десятичные (`KB`, `MB`…) и двоичные (`KiB`, `MiB`…) единицы, короткие
  формы `k`, `Ti`, любой регистр, пробелы;
- `"1.1GB"` — ровно 1 100 000 000, `"4.35 MB"` — ровно 4 350 000;
- нецелое число байт (`"0.5B"`, `"1.0001KiB"`) — ошибка;
- запятая вместо точки, `"1."`, `".5K"`, знак, экспонента, hex,
  неизвестная единица, пробел внутри единицы — `ErrSize`;
- переполнение `int64` — `ErrOverflow`, включая граничное значение;
- текст ошибки содержит исходную строку.

<Reveal>

```go
var (
	// ErrSize — строка не похожа на размер.
	ErrSize = errors.New("некорректный размер")
	// ErrOverflow — размер не помещается в int64.
	ErrOverflow = errors.New("размер слишком большой")
)

var sizeUnits = map[string]int64{
	"": 1, "b": 1,
	"k": 1e3, "kb": 1e3, "m": 1e6, "mb": 1e6, "g": 1e9, "gb": 1e9, "t": 1e12, "tb": 1e12,
	"ki": 1 << 10, "kib": 1 << 10, "mi": 1 << 20, "mib": 1 << 20,
	"gi": 1 << 30, "gib": 1 << 30, "ti": 1 << 40, "tib": 1 << 40,
}

func ParseSize(s string) (int64, error) {
	bad := func(e error) (int64, error) { return 0, fmt.Errorf("%w: %q", e, s) }
	t := strings.TrimSpace(s)
	i := 0
	for i < len(t) && (t[i] >= '0' && t[i] <= '9' || t[i] == '.') {
		i++
	}
	num, unitStr := t[:i], strings.ToLower(strings.TrimSpace(t[i:]))
	intPart, frac, hasDot := strings.Cut(num, ".")
	if intPart == "" || (hasDot && (frac == "" || strings.Contains(frac, "."))) {
		return bad(ErrSize)
	}
	unit, ok := sizeUnits[unitStr]
	if !ok {
		return bad(ErrSize)
	}
	// Точная арифметика: 1.1 во float64 — это 1.100000000000000088…,
	// и 1.1GB превратилось бы в 1100000000.0000002.
	mant, _ := new(big.Int).SetString(intPart+frac, 10)
	scale := new(big.Int).Exp(big.NewInt(10), big.NewInt(int64(len(frac))), nil)
	total := new(big.Int).Mul(mant, big.NewInt(unit))
	q, r := new(big.Int).QuoRem(total, scale, new(big.Int))
	if r.Sign() != 0 {
		return bad(ErrSize) // нецелое число байт
	}
	if q.Cmp(big.NewInt(math.MaxInt64)) > 0 {
		return bad(ErrOverflow)
	}
	return q.Int64(), nil
}
```

**float64 здесь врёт.** `strconv.ParseFloat("1.1") * 1e9` даёт
`1100000000.0000002`, `4.35 * 1e6` — `4349999.999999999`. После
приведения к `int64` это то на байт больше, то на байт меньше, а
проверка «число байт целое» ломается совсем. Поэтому число разбираем как
«мантисса и число знаков после точки» и считаем в целых: `mant · unit /
10^k`, остаток от деления ненулевой — нецелые байты.

**Переполнение — через `big.Int` или проверку до умножения.**
`8388608TiB` — ровно 2⁶³, на единицу больше `MaxInt64`. `mant * unit` в
`int64` молча завернётся в отрицательное число, и лимит «минус восемь
эксабайт» отключит проверку размера вообще. `math/big` делает решение
прямолинейным; без него — проверка `mant > MaxInt64 / unit` до умножения.

**Единицы — в мапе, а не в каскаде `if`.** Ключ — нижний регистр
суффикса после числа, значение — множитель. Добавить `PB` — одна строка.
Пустой суффикс тоже ключ: «без единицы — байты».

**Строгость к формату.** `1,5MB` — не 15 MB и не 1 MB, а ошибка:
молча прочитанная запятая — это конфиг, который работает не так, как
думал автор. На собеседовании дальше просят обратную функцию —
`FormatSize` с округлением до одного знака и выбором единицы.
