---
title: Конфиг, который не прочитался
description: JSON разбирается в структуру, но поля остаются нулевыми, а Unmarshal возвращает странную ошибку. Почините.
kind: fix
topic: interfaces
level: easy
order: 50
---

Программа печатает:

```
json: Unmarshal(non-pointer main.Config)
{Port:0 Debug:false}
```

Почините. Ожидаемый вывод:

```
<nil>
{Port:8080 Debug:true}
```

<Reveal>

**Параметр `any` принимает что угодно — и копию тоже.** `json.Unmarshal(data,
cfg)` кладёт в `any` копию структуры. Даже если бы `Unmarshal` заполнил
её, изменения остались бы в копии, а `cfg` — нулевой. Поэтому `Unmarshal`
первым делом проверяет, что ему дали указатель, и если нет — возвращает
ошибку `InvalidUnmarshalError`.

Компилятор этого не видит: сигнатура `Unmarshal(data []byte, v any)` честно
принимает значение. `go vet` видит — у него есть проверка `unmarshal`.

**Как чинят:**

```go
err := json.Unmarshal(data, &cfg)
```

**Где ещё то же самое.** `fmt.Sscan`, `binary.Read`, `rows.Scan` в
`database/sql`, `flag.Var`, `errors.As` — все функции, которые *заполняют*
переданное через `any`, ждут указатель. И все узнают об ошибке только в
рантайме. Поэтому ошибку, которую они возвращают, всегда проверяют — здесь
её просто напечатали, и это уже подсказка.

</Reveal>
