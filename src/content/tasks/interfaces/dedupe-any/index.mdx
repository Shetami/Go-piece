Батч событий приходит как `[]any` — например, после разбора JSON или из
очереди с разными типами сообщений. Нужно убрать повторы, сохранив порядок.
Первое, что приходит в голову, — `map[any]struct{}`. На первом же слайсе
программа упадёт с `runtime error: hash of unhashable type`.

Напишите `Dedupe` по контракту из заготовки.

Что проверяют скрытые тесты:

- `1` и `int64(1)` — разные значения, порядок первых вхождений сохраняется,
  входной слайс не меняется;
- одинаковые по содержимому слайсы и мапы склеиваются, `[]int{2, 1}` —
  отдельное значение;
- структура с полем `any`, в котором лежит слайс, и массив `[1]any` со
  слайсом — без паники;
- `NaN` склеивается с `NaN` того же типа (float64 и float32 — разные);
  `nil` и `(*int)(nil)` — разные, `(*int)(nil)` и `(*string)(nil)` — тоже;
- тип, реализующий `Keyer`, сравнивается по ключу — даже если сам он
  несравнимый (слайс); одинаковые ключи у разных типов — не повтор.

<Reveal>

```go
type Keyer interface {
	DedupKey() string
}

type keyerKey struct {
	t   reflect.Type
	key string
}

type nanKey struct{ t reflect.Type }

func Dedupe(xs []any) []any {
	out := make([]any, 0, len(xs))
	seen := map[any]struct{}{}
	var loose []any
	add := func(k any, x any) {
		if _, dup := seen[k]; !dup {
			seen[k] = struct{}{}
			out = append(out, x)
		}
	}
	for _, x := range xs {
		if k, ok := x.(Keyer); ok {
			add(keyerKey{reflect.TypeOf(x), k.DedupKey()}, x)
			continue
		}
		if x == nil {
			add(nil, x)
			continue
		}
		switch f := x.(type) {
		case float64:
			if math.IsNaN(f) {
				add(nanKey{reflect.TypeOf(x)}, x)
				continue
			}
		case float32:
			if f != f {
				add(nanKey{reflect.TypeOf(x)}, x)
				continue
			}
		}
		if reflect.ValueOf(x).Comparable() {
			add(x, x)
			continue
		}
		dup := false
		for _, y := range loose {
			if reflect.DeepEqual(x, y) {
				dup = true
				break
			}
		}
		if !dup {
			loose = append(loose, x)
			out = append(out, x)
		}
	}
	return out
}
```

**Сравнимость типа ≠ сравнимость значения.** `reflect.TypeOf(x).Comparable()`
для `struct{ V any }` вернёт `true`: интерфейсные поля сравнимы по правилам
языка. Но `==` сравнивает динамические значения внутри, и если там слайс —
паника во время выполнения. Ровно так же паникует вставка такого значения в
`map[any]`. `reflect.Value.Comparable()` (Go 1.20) заглядывает в содержимое
и отвечает честно.

**NaN как ключ мапы — ловушка.** `NaN != NaN`, поэтому каждый NaN, положенный
в мапу, создаёт новую запись, которую невозможно найти. Отсюда отдельный
ключ `nanKey{тип}`. Тип в ключе — чтобы float32 NaN и float64 NaN
оставались разными, как и прочие значения разных типов.

**Ключ интерфейса — пара «тип, значение».** `any(1) == any(int64(1))` —
ложь, потому что типы разные. `nil` — пустой интерфейс, а `(*int)(nil)` —
интерфейс с типом `*int`; они не равны, и мапа их различает без
дополнительного кода.

**Keyer проверяется первым.** Это опциональный интерфейс: тип сообщает свою
семантику равенства — здесь «теги без учёта порядка». Проверять его нужно до
сравнимости, иначе `chkTags` уйдёт в `DeepEqual`, и `[go db]` с `[db go]` не
склеятся. Ключ дополнен типом — одинаковые строки-ключи у разных типов не
должны совпадать.

**Несравнимые — квадратичный проход.** Хешировать произвольное значение без
сериализации нельзя, поэтому несравнимые сравниваются `DeepEqual` со всеми
ранее встреченными несравнимыми. На больших батчах лучше требовать `Keyer`
или хешировать канонический JSON — об этом и спросят дальше.
