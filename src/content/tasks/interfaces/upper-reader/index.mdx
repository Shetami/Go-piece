Напишите `NewUpperReader`: он возвращает `io.Reader`, который отдаёт те же
данные, что `r`, но латинские буквы `a`–`z` — заглавными. Тип-обёртку
объявите сами.

Что проверяют скрытые тесты:

- `"hello, go 1.27!"` → `"HELLO, GO 1.27!"`;
- кириллица не меняется;
- работает, даже если нижний reader отдаёт данные по одному байту
  (`iotest.OneByteReader`);
- ошибка нижнего reader'а доходит до вызывающего.

<Reveal>

```go
type upperReader struct{ r io.Reader }

func (u upperReader) Read(p []byte) (int, error) {
	n, err := u.r.Read(p)
	for i := range p[:n] {
		if 'a' <= p[i] && p[i] <= 'z' {
			p[i] -= 'a' - 'A'
		}
	}
	return n, err
}
```

**Контракт `Read`.** Метод заполняет `p[:n]` и возвращает `n` и ошибку.
Важно: `n > 0` и `err != nil` могут прийти *одновременно* — например,
последние байты и `io.EOF`. Поэтому сначала обрабатываем данные, потом
возвращаем ошибку, а не наоборот.

**Только `p[:n]`.** Остаток буфера после `n` — мусор от прошлых чтений.

**Почему `bytes.ToUpper` здесь опасен.** Он работает с UTF-8 и переводит в
верхний регистр кириллицу. Но граница чтения может пройти посреди
двухбайтовой буквы — тест с `OneByteReader` устроен ровно так. Половинку
буквы `ToUpper` превратит в `U+FFFD` и испортит данные. ASCII-байты никогда
не бывают частью многобайтовых символов, поэтому побайтовая замена
безопасна. Для полноценного Unicode нужен буфер для незаконченной руны или
`transform.Reader` из `golang.org/x/text`.

**Почему возвращаем `io.Reader`, а не свой тип.** Тип-обёртка — деталь
реализации. Наружу торчит только интерфейс, и тип можно поменять, не
ломая вызывающих.

</Reveal>
