`io.MultiWriter` останавливается на первой ошибке: один сломанный получатель
(отвалившийся сокет, переполненный диск) — и данные не доходят до остальных.
Напишите `Fanout` — рассыльщик «по возможности»: сломанный получатель выбывает,
остальные продолжают получать данные. Так пишут логи сразу в файл, stdout и
сетевой коллектор.

Контракт — в комментариях заготовки. Что проверяют скрытые тесты:

- `*Fanout` — это `io.Writer`, с ним работает `fmt.Fprintf`;
- получатель, вернувший ошибку, выбывает: во втором `Write` его не зовут, а
  получатели после него в списке получают всё;
- получатель, который записал меньше `len(p)` и ошибки **не** вернул, тоже
  выбывает — с `io.ErrShortWrite`;
- в тексте ошибки — индекс получателя из исходного списка, даже если перед
  ним в списке был `nil`;
- если упали все — `n = 0` и все ошибки видны через `errors.Is`; следующий
  вызов — `ErrNoWriters`.

<Reveal>

```go
type target struct {
	idx int
	w   io.Writer
}

type Fanout struct{ live []target }

func NewFanout(ws ...io.Writer) *Fanout {
	f := &Fanout{}
	for i, w := range ws {
		if w != nil {
			f.live = append(f.live, target{i, w})
		}
	}
	return f
}

func (f *Fanout) Write(p []byte) (int, error) {
	if len(f.live) == 0 {
		return 0, ErrNoWriters
	}
	var errs []error
	kept := f.live[:0]
	for _, t := range f.live {
		n, err := t.w.Write(p)
		if err == nil && n < len(p) {
			err = io.ErrShortWrite
		}
		if err != nil {
			errs = append(errs, fmt.Errorf("writer %d: %w", t.idx, err))
			continue
		}
		kept = append(kept, t)
	}
	clear(f.live[len(kept):])
	f.live = kept
	if len(kept) == 0 {
		return 0, errors.Join(errs...)
	}
	return len(p), errors.Join(errs...)
}

func (f *Fanout) Alive() int { return len(f.live) }
```

**Индекс хранится вместе с writer'ом.** Как только из слайса удалили
элемент, позиция перестаёт совпадать с исходным индексом. Если печатать
позицию в текущем слайсе, во втором сбое будет «writer 1» про совсем другой
получатель — в логах инцидента это путает.

**Короткая запись — тоже ошибка.** Контракт `io.Writer` требует ненулевую
ошибку при `n < len(p)`, но чужие реализации его нарушают. Если такого
получателя оставить, он будет молча терять хвосты. `io.Copy` и
`io.MultiWriter` поступают так же: подставляют `io.ErrShortWrite`.

**Фильтрация на месте: `kept := f.live[:0]`.** Удалять элемент из слайса
внутри `range` по нему же — классическая ошибка: индексы съезжают, и
следующий элемент пропускается. Запись в префикс того же массива безопасна:
запись никогда не обгоняет чтение. `clear` хвоста отпускает ссылки на
выбывших, чтобы их мог собрать GC.

**`errors.Join` вместо первой ошибки.** Вызывающему важно знать про все
сбои, и `errors.Is` проходит по всем веткам объединённой ошибки. Если
ошибок нет, `errors.Join()` возвращает `nil` — отдельная проверка не нужна.

Что спросят дальше: как сделать `Fanout` безопасным для параллельных `Write`
(мьютекс на весь вызов, иначе у получателей перемешаются куски) и как не
ждать медленного получателя: у каждого своя горутина и буферизованный канал,
а при переполнении — отбрасывать или отключать.
