Сервис принимает файлы: размер не больше `max`, а по дороге считается
контрольная сумма (sink — это `sha256.New()` или файл-копия). Хочется
собрать всё из `io.LimitReader` и `io.TeeReader`, но у этой пары
есть беда: `LimitReader` на слишком большом файле просто вернёт `io.EOF`, и
сервис молча сохранит обрезанный файл — и сумма сойдётся, ведь её считали по тому же обрезку.

Напишите `Upload` по контракту из заготовки.

Что проверяют скрытые тесты:

- ровно `max` байт — нормальный `io.EOF`, в sink — всё;
- 10 байт при `max = 4` — вызывающий и sink получили ровно 4 байта, затем
  `ErrTooLarge`, и повторный `Read` снова `ErrTooLarge`; проверяется с
  буфером в 1, 3 и 64 байта;
- из источника прочитано не больше `max + 1` байт;
- `max = 0`: пустой источник — `io.EOF`, непустой — `ErrTooLarge`;
- ошибка sink и ошибка источника возвращаются как есть.

<Reveal>

```go
var ErrTooLarge = errors.New("upload: too large")

type upload struct {
	r    io.Reader
	left int64
	sink io.Writer
	err  error
}

func Upload(r io.Reader, max int64, sink io.Writer) io.Reader {
	return &upload{r: r, left: max, sink: sink}
}

func (u *upload) Read(p []byte) (int, error) {
	if u.err != nil {
		return 0, u.err
	}
	if len(p) == 0 {
		return 0, nil
	}
	if u.left == 0 {
		var one [1]byte
		n, err := io.ReadFull(u.r, one[:])
		switch {
		case n == 1:
			u.err = ErrTooLarge
		case err == io.EOF:
			u.err = io.EOF
		default:
			return 0, err
		}
		return 0, u.err
	}
	if int64(len(p)) > u.left {
		p = p[:u.left]
	}
	n, err := u.r.Read(p)
	u.left -= int64(n)
	if n > 0 {
		if _, werr := u.sink.Write(p[:n]); werr != nil {
			return n, werr
		}
	}
	return n, err
}
```

**Чтобы отличить «ровно max» от «больше», нужен ещё один байт.** По `max`
прочитанным байтам нельзя понять, кончился ли источник. Стандартный трюк —
`io.LimitReader(r, max+1)` и проверка «прочитали больше max». Но если так
сделать в лоб, лишний байт уже уйдёт к вызывающему и в хеш. Поэтому
пробный байт читаем отдельно, только когда лимит исчерпан, и никуда его не
отдаём.

**Буфер обрезается до чтения.** Если прочитать в `p` целиком, а потом отдать
часть, байты сверх лимита уже вычитаны из источника — это нарушает
«не больше max+1». Отсюда `p = p[:u.left]` до вызова `Read`.

**Ошибка запоминается.** После `ErrTooLarge` источник мог ещё что-то держать;
повторный `Read` не должен снова читать из него «пробный» байт и вдруг
ответить `io.EOF`. Липкая ошибка (`u.err`) делает поведение стабильным —
так же устроены `bufio.Reader` и `bufio.Scanner`.

**Та же семантика, что у `io.TeeReader`.** В sink пишется ровно то, что
отдано вызывающему, и ошибка sink возвращается вместе с `n`: данные
вызывающий уже получил, а хеш — нет, продолжать нельзя.

Что спросят дальше: чем это отличается от `http.MaxBytesReader` (тот
вдобавок закрывает соединение) и почему проверять `Content-Length` мало —
заголовок может врать.
