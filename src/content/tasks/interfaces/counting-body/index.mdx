HTTP-клиент хочет знать, сколько байт тела ответа реально прочитали и чем
кончилось чтение. Для этого `resp.Body` оборачивают: обёртка — тоже
`io.ReadCloser`, код, который читает тело, ничего не замечает.

Напишите `NewBody` по контракту из заготовки. Что проверяют скрытые тесты:

- `io.ReadAll` + `Close`: отчёт один, с верным числом байт и `nil`;
- источник отдаёт последние байты **вместе** с `io.EOF` в одном вызове —
  они должны попасть в отчёт;
- ошибка чтения посреди тела уходит в отчёт, последующий `Close` второго
  отчёта не порождает, но источник закрывает;
- `Close` на середине: отчёт с тем, что успели прочитать, а `Read` после
  него — `ErrBodyClosed` без обращения к источнику;
- `onDone == nil` — допустимо;
- 20 параллельных `Close`: источник закрыт один раз, отчёт один, ошибку
  нижнего `Close` получил ровно один вызывающий. Тест идёт под `-race`.

<Reveal>

```go
type body struct {
	rc        io.ReadCloser
	onDone    func(n int64, err error)
	n         int64
	closed    bool
	doneOnce  sync.Once
	closeOnce sync.Once
}

func NewBody(rc io.ReadCloser, onDone func(n int64, err error)) io.ReadCloser {
	return &body{rc: rc, onDone: onDone}
}

func (b *body) done(err error) {
	b.doneOnce.Do(func() {
		if b.onDone != nil {
			b.onDone(b.n, err)
		}
	})
}

func (b *body) Read(p []byte) (int, error) {
	if b.closed {
		return 0, ErrBodyClosed
	}
	n, err := b.rc.Read(p)
	b.n += int64(n)
	switch {
	case err == io.EOF:
		b.done(nil)
	case err != nil:
		b.done(err)
	}
	return n, err
}

func (b *body) Close() error {
	var err error
	b.closeOnce.Do(func() {
		b.closed = true
		b.done(nil)
		err = b.rc.Close()
	})
	return err
}
```

**Сначала учесть `n`, потом смотреть на ошибку.** Контракт `io.Reader`
разрешает вернуть данные и `io.EOF` одним вызовом. Код в стиле
`if err != nil { report(); return }` до `b.n += n` теряет последний кусок —
на маленьких ответах это весь ответ.

**Два разных «ровно один раз».** Отчёт должен случиться при первом из трёх
событий, а закрытие источника — только по `Close`. Поэтому два `sync.Once`:
один на `onDone`, другой на `rc.Close`. Флаг `reported bool` вместо `Once`
в последнем тесте даст гонку.

**Ошибку повторного Close — в локальную переменную.** `sync.Once` гарантирует,
что остальные вызывающие дождутся первого, но функцию выполнит только один.
Пишем результат в локальную `err` внутри замыкания — её увидит только тот,
кто закрывал. Если хранить ошибку в поле и потом обнулять, параллельные
`Close` устроят гонку на этом поле.

**Почему это вообще важно.** Непрочитанное и незакрытое тело держит
соединение: оно не вернётся в пул keep-alive. Обёртка с метриками — отличный
способ найти такие места: отчёт, пришедший только из `Close` с `n` меньше
`Content-Length`, означает, что тело бросили недочитанным.

Что спросят дальше: если обёртка скрывает у тела `io.WriterTo`, то `io.Copy`
пойдёт медленным путём. Как пробросить опциональный интерфейс, не потеряв
подсчёт?
