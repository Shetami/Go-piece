`User` реализует `Namer` методом на значении. В интерфейс кладут сначала
саму структуру, потом указатель на неё, и после каждого раза меняют поле
`name` исходной переменной.

Напишите весь вывод программы.

<Reveal>

**Присваивание в интерфейс копирует значение.** `var n Namer = u` кладёт в
интерфейс копию структуры — с именем «Аня». Дальнейшие изменения `u` на неё
не влияют. `n.Name()` — «Аня», `u.Name()` — уже «Боря».

**Указатель копируется тоже, но это копия указателя.** `var np Namer = &u`
кладёт в интерфейс адрес `u`. Метод `Name` объявлен на значении, но для
`*User` он тоже доступен: Go разыменует указатель при вызове. Разыменует в
момент вызова, поэтому видит свежее имя — «Вика».

Итого:

```
Аня Боря
Вика
```

**Почему это важно.** Интерфейс со значением внутри — снимок на момент
присваивания. Если вы складываете в `[]Namer` структуры, а потом правите
оригиналы, слайс этого не увидит. И наоборот: если кладёте указатели, любой
держатель интерфейса видит все изменения — и может сам их вносить.

Заодно о цене: структура крупнее машинного слова при помещении в интерфейс
обычно уезжает в кучу — интерфейс хранит указатель на копию. Поэтому
`any`-интерфейсы на горячем пути дают аллокации даже там, где их не видно.

</Reveal>
