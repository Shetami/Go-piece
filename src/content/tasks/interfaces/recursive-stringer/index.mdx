Программа хочет напечатать `User(Аня 30)`, а вместо этого падает:

```
fatal error: stack overflow
```

Отметьте строку, в которой заложена поломка. Кнопка «Запустить» покажет
заодно и предупреждение `go vet`.

<Reveal>

Сломано в строке 11: `fmt.Sprintf("User(%v)", u)`.

**`%v` для значения со `String()` вызывает `String()`.** `fmt` проверяет,
реализует ли аргумент `fmt.Stringer`, и если да — печатает то, что вернул
метод. `u` — это `User`, у него есть `String`. Значит, `String` вызывает
`Sprintf`, `Sprintf` вызывает `String`, и так, пока стек не кончится.

Go растит стеки горутин динамически, поэтому переполнение наступает не
сразу, а когда стек дорастает до предела в 1 ГБ. Это `fatal error`, а не
паника: `recover` её не поймает.

**Как правильно.** Печатать поля явно:

```go
return fmt.Sprintf("User(%s, %d)", u.Name, u.Age)
```

Или, если хочется `%v` всей структуры, привести к типу без методов:

```go
type plain User
return fmt.Sprintf("User(%v)", plain(u))
```

У `plain` те же поля, но нет метода `String`, и рекурсия обрывается.

**`go vet` это ловит**: «Sprintf format %v with arg u causes recursive
String method call». Ещё одна причина не выключать его.

</Reveal>
