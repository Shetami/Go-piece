`Animal` умеет `Sound` и `Speak`, причём `Speak` внутри зовёт `Sound`.
`Dog` встраивает `Animal` и объявляет свой `Sound`. Вызываем всё это
напрямую и через интерфейс.

Напишите весь вывод программы.

<Reveal>

**Встраивание — это автоматическая делегация, а не наследование.** У `Dog`
есть свой `Sound`, он «затеняет» `Animal.Sound`. Поэтому `d.Sound()` —
`гав`.

**Но `d.Speak()` — это `d.Animal.Speak()`.** Компилятор просто подставляет
поле. Внутри `Speak` получатель — `Animal`, а не `Dog`. `Animal` ничего не
знает о структуре, в которую его встроили, и `a.Sound()` — это
`Animal.Sound`. Никакой виртуальной диспетчеризации: в Go её нет у методов
структур, только у интерфейсов.

**Интерфейс не меняет картину.** `s.Speak()` находит метод `Speak` в наборе
методов `Dog` — а это повышенный метод `Animal.Speak`. Дальше всё то же.

Итого:

```
гав
говорит ...
говорит ...
...
```

**Как получить «виртуальность»**, если она действительно нужна: передать
поведение явно. Например, `Animal` хранит поле `sound func() string` или
интерфейс, и `Speak` вызывает его. На собеседовании этот вопрос обычно
задают, чтобы проверить, не переносит ли кандидат ООП из Java как есть: шаблон
«базовый класс с шаблонным методом» в Go через встраивание не работает.

</Reveal>
