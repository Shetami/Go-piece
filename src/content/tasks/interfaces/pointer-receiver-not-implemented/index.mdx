---
title: Circle не реализует Shape
description: У круга есть метод Area, у интерфейса — тоже только Area. Компилятор всё равно говорит, что Circle не подходит. Почините.
kind: fix
topic: interfaces
level: easy
order: 30
---

Программа не компилируется:

```
Circle does not implement Shape (method Area has pointer receiver)
```

Почините. Ожидаемый вывод:

```
площадь: 7
```

<Reveal>

**Набор методов значения не включает методы на указателе.** У `Circle`
метод `Area` объявлен с получателем `*Circle`. Поэтому `Area` есть у типа
`*Circle`, а у `Circle` — нет. Интерфейс `Shape` реализует только `*Circle`.

Почему так строго, если на обычной переменной `c.Area()` работает? Потому
что там компилятор сам берёт адрес: `(&c).Area()`. Значение внутри
интерфейса неадресуемо — это копия, спрятанная в рантайме. Если бы метод на
указателе можно было вызвать на ней, он менял бы копию, и изменения молча
терялись бы. Язык запрещает это заранее.

**Две починки:**

- класть в интерфейс указатель: `&Circle{R: 1}` — так в решении;
- объявить `Area` на значении: `func (c Circle) Area()` — метод ничего не
  меняет, так что это даже естественнее.

Обратное всегда работает: метод на значении есть и у значения, и у
указателя. `Square` можно положить в `Shape` и как `Square`, и как `*Square`.

</Reveal>
