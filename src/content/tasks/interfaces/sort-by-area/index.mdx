Допишите три метода `ByArea`, чтобы `sort.Sort(ByArea(shapes))` упорядочил
фигуры по возрастанию площади.

Что проверяют скрытые тесты:

- `ByArea` реализует `sort.Interface`;
- смесь прямоугольников и кругов сортируется по площади;
- `sort.Stable` сохраняет порядок фигур с равной площадью;
- `Len` возвращает длину.

<Reveal>

```go
func (s ByArea) Len() int           { return len(s) }
func (s ByArea) Less(i, j int) bool { return s[i].Area() < s[j].Area() }
func (s ByArea) Swap(i, j int)      { s[i], s[j] = s[j], s[i] }
```

**Почему `Swap` на значении работает.** Обычно метод, который меняет
данные, должен быть на указателе. Но `ByArea` — слайс, и копия слайса
смотрит в тот же массив. `Swap` меняет элементы массива, а не заголовок
слайса, — вызывающий это видит. Вот если бы метод делал `append`, указатель
был бы обязателен.

**`ByArea(shapes)` — конверсия, а не копия.** У `[]Shape` и `ByArea` один
базовый тип, конверсия меняет только набор методов и ничего не копирует.

**Как это пишут сейчас.** `sort.Interface` — стиль до дженериков. Сегодня
то же самое — одна строка:

```go
slices.SortFunc(shapes, func(a, b Shape) int {
	return cmp.Compare(a.Area(), b.Area())
})
```

Но на собеседовании `sort.Interface` спрашивают по-прежнему: это хороший
пример того, как алгоритм общается с данными только через интерфейс из
трёх методов. Так же `container/heap` строит кучу поверх `sort.Interface`
плюс `Push` и `Pop`.

</Reveal>
