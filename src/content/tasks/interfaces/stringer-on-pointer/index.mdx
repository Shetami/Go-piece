---
title: String, который fmt не видит
description: У точки есть метод String, но fmt печатает её как обычную структуру. Почините.

У `Point` есть метод `String`, а программа печатает:

```
{1 2}
[{3 4}]
точка {1 2}
```

Почините. Ожидаемый вывод:

```
(1, 2)
[(3, 4)]
точка (1, 2)
```

<Reveal>

**`fmt` получает значение, а `String` объявлен на указателе.** `fmt.Println(p)`
кладёт `p` в `any` — копию значения типа `Point`. Дальше `fmt` проверяет,
реализует ли оно `fmt.Stringer`. У `Point` метода `String` нет — он есть
только у `*Point`. Проверка не проходит, и `fmt` печатает поля.

Та же история со слайсом: его элементы — значения `Point`.
`fmt.Println(&p)` сработал бы — но так никто писать не будет.

**Как чинят** — объявить `String` на значении:

```go
func (p Point) String() string
```

Метод на значении есть и у `Point`, и у `*Point`, так что печатается
правильно в любом случае. `String` ничего не меняет, поэтому указатель ему
и не был нужен.

**Правило.** `String`, `Error`, `MarshalJSON` и прочие методы, которые
вызывает кто-то снаружи, почти всегда объявляют на значении. Иначе они
работают «иногда» — в зависимости от того, что именно передали.

</Reveal>
