`WithLogging` оборачивает хранилище: печатает ключ и вызывает настоящий
`Get`. Программа печатает

```
get lang
panic: runtime error: invalid memory address or nil pointer dereference
```

Отметьте строку, в которой заложена поломка.

<Reveal>

Сломано в строке 24: `return LoggedStore{}`.

**Встроенный интерфейс — это обычное поле.** `LoggedStore` встраивает
`Store`, то есть у структуры есть поле с именем `Store` и типом `Store`.
Литерал `LoggedStore{}` оставляет его нулевым — `nil`-интерфейсом.
Параметр `s` функция получила и забыла.

`LoggedStore.Get` печатает ключ и вызывает `l.Store.Get(key)` — метод
`nil`-интерфейса. Вызывать нечего, паника.

**Компилятор не помогает**: структура с незаполненным встроенным интерфейсом
законна и даже удовлетворяет `Store` — все методы интерфейса «повышены» из
поля. Ошибка видна только при вызове.

**Как правильно:**

```go
return LoggedStore{Store: s}
```

**Где ещё встречается.** Тот же приём используют в тестах: встраивают
интерфейс в заглушку и переопределяют один метод, а остальные «наследуются».
Если тест случайно вызовет непереопределённый метод — будет ровно эта
паника. Иногда это даже удобно: сразу видно, что вызвали то, чего не ждали.

</Reveal>
