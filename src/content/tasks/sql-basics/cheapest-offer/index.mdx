На карточке товара маркетплейс показывает одно «лучшее предложение»:

- берутся только предложения в наличии: `stock > 0`. Если склад не прислал
  остатки (`stock IS NULL`), предложение не показывается;
- лучшее — самое дешёвое; при равной цене — у продавца с более высоким
  рейтингом (продавцы без рейтинга — ниже всех); при равенстве и рейтинга —
  у продавца с меньшим `id`.

Выведите **все** товары каталога. Если купить товар негде, продавец и цена —
`NULL`.

Колонки: `product`, `seller`, `price`. Порядок: по `product`.

<Reveal>

```sql
SELECT p.name AS product, b.seller, b.price
FROM products p
LEFT JOIN (
  SELECT DISTINCT ON (o.product_id)
         o.product_id, s.name AS seller, o.price
  FROM offers o
  JOIN sellers s ON s.id = o.seller_id
  WHERE o.stock > 0
  ORDER BY o.product_id, o.price, s.rating DESC NULLS LAST, s.id
) b ON b.product_id = p.id
ORDER BY p.name;
```

Ответ:

```
Кружка | Дельта | 300.00
Сито | NULL | NULL
Термос | Альфа | 990.00
Турка | NULL | NULL
Чайник | Гамма | 1890.00
```

**`min(price)` отвечает не на тот вопрос.** Минимальная цена находится, а
вот *чья* она — нет: `GROUP BY` по товару и продавцу даёт строку на каждое
предложение. Нужна целая строка-победитель, и в Postgres для этого есть
`DISTINCT ON`: одна строка на ключ, первая в порядке `ORDER BY`.

**Правило выбора целиком живёт в `ORDER BY`.** Цена по возрастанию, затем
рейтинг по убыванию, затем `id`. У Термоса три предложения по 990 ₽: Бета
без рейтинга, Альфа и Гамма по 4.8. `rating DESC` без `NULLS LAST` поставит
Бету первой — в Postgres `NULL` при `DESC` идёт в начало. Альфу от Гаммы
отличает только `id`; без последнего ключа ответ меняется от запуска к
запуску.

**`stock > 0` сам отсекает `NULL`.** У Чайника самое дешёвое предложение
(1790 ₽) — от Беты с неизвестным остатком, `NULL > 0` не истина. Здесь
трёхзначная логика работает на нас, но если бы правило было «показывать,
пока остаток не известен как нулевой», понадобилось бы `stock IS DISTINCT
FROM 0`.

**`LEFT JOIN` сохраняет пустые товары.** Турку продают только с нулевым
остатком, у Сита предложений нет вовсе. Фильтр наличия стоит внутри
подзапроса, а не в `WHERE` внешнего запроса — иначе `LEFT JOIN`
превратился бы во внутренний.

**Что спросят дальше.** `DISTINCT ON` — расширение Postgres. Переносимый
вариант — `row_number() OVER (PARTITION BY product_id ORDER BY …) = 1`.
А для одного товара на карточке быстрее `LATERAL (… ORDER BY … LIMIT 1)`
с индексом `(product_id, price)`.
