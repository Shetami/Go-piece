Отчёт показывает долю отменённых заказов в процентах. Отменённых трое из
восьми, а запрос возвращает `0`.

Почините. Ожидается одна строка — процент с одним знаком после запятой:

```
37.5
```

<Reveal>

**`count` возвращает целое, а целое делится нацело.** `3 / 8` в Postgres —
`0`, остаток отбрасывается. Дальше `0 * 100` — всё тот же ноль. Та же
история, что `7 / 2 == 3` в Go.

```sql
round(100.0 * count(*) FILTER (WHERE status = 'cancelled') / count(*), 1)
```

**Порядок важен.** `100.0 * x` превращает выражение в `numeric` до деления.
Вариант `x / count(*) * 100.0` снова даст ноль: деление успеет пройти в
целых. Можно явно привести: `x::numeric / count(*)`.

**`FILTER (WHERE ...)`** — условие для одного агрегата. Эквивалент для других
СУБД: `sum(CASE WHEN status = 'cancelled' THEN 1 ELSE 0 END)`.

**`round(numeric, n)`** работает с `numeric`; для `double precision`
двухаргументного `round` в Postgres нет — ещё одна причина делить в `numeric`.

</Reveal>
