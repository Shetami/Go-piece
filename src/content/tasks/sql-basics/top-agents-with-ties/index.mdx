По итогам **марта 2024** поддержка награждает трёх лучших операторов по
числу решённых тикетов.

- Решённый тикет — статус `resolved` в любом регистре, закрытый
  (`closed_at`) в марте — с 1 марта 00:00 до конца 31 марта.
- В топ входят первые три места рейтинга **и все, кто набрал столько же,
  сколько третий**: делить приз при ничьей справедливее, чем выбирать по
  алфавиту.

Колонки: `name`, `resolved`.
Порядок: `resolved` по убыванию, при равенстве — `name`.

<Reveal>

```sql
WITH r AS (
  SELECT a.name, count(*) AS resolved
  FROM tickets t
  JOIN agents a ON a.id = t.agent_id
  WHERE lower(t.status) = 'resolved'
    AND t.closed_at >= '2024-03-01' AND t.closed_at < '2024-04-01'
  GROUP BY a.id, a.name
  ORDER BY resolved DESC
  FETCH FIRST 3 ROWS WITH TIES
)
SELECT name, resolved
FROM r
ORDER BY resolved DESC, name;
```

Ответ:

```
Анна | 5
Борис | 4
Вера | 3
Гоша | 3
```

**`WITH TIES` сравнивает по ключам `ORDER BY`.** `FETCH FIRST 3 ROWS WITH
TIES` берёт три строки и добавляет все следующие, у которых значения
сортировки *равны* значениям третьей. Если в том же `ORDER BY` стоит
тай-брейкер `name`, ничьих больше нет — Вера и Гоша различаются по имени,
и Гоша отрезается. Поэтому отбор — во внутреннем запросе по одной метрике,
а стабильный порядок вывода — во внешнем.

**Аналог через окна.** `rank() OVER (ORDER BY resolved DESC) <= 3` даёт то же
самое. А вот `dense_rank() <= 3` — уже «три *разных* значения»: при
результатах 5, 4, 3, 3, 2 он вернул бы и Дину с двумя тикетами, если бы
значений было меньше. Разницу между `rank` и `dense_rank` спрашивают почти
всегда.

**Границы месяца.** `BETWEEN '2024-03-01' AND '2024-03-31'` на `timestamp`
отрезает 31 марта после полуночи — Гоша теряет тикет, закрытый в 23:30, и
выпадает из топа. А `BETWEEN '2024-03-01' AND '2024-04-01'` захватит тикет
Дины, закрытый ровно в полночь 1 апреля. Полуоткрытый интервал
`>= начало AND < начало следующего` не ошибается ни в одну сторону.

**Регистр статуса.** Один из тикетов Бориса — `'Resolved'`: без `lower`
у Бориса 3 тикета вместо 4, и рейтинг перекраивается. `reopened` тикеты не
считаются, хотя `closed_at` у них заполнен.

**`GROUP BY a.id, a.name`.** Группировка по имени склеит двух тёзок в одного
оператора. Ключ группировки — идентификатор, имя — для вывода.
