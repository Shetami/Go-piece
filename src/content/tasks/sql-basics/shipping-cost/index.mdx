Служба доставки берёт деньги за **оплачиваемый вес** — больший из двух:

- фактический вес `weight_kg`;
- объёмный вес: `длина × ширина × высота / 5000` (сантиметры → килограммы).

Если посылку не взвешивали (`weight_kg IS NULL`), платят по объёмному весу;
если не мерили габариты — по фактическому. Посылки, у которых нет ни того
ни другого, в расчёт не попадают.

Стоимость — по тарифу зоны из `tariffs`: `base` за первый килограмм плюс
`per_kg` за **каждый начатый** килограмм сверх первого (1,2 кг — это один
начатый сверх первого, ровно 1 кг — ни одного). Посылки с нераспознанной
зоной (`zone IS NULL`) везут по самому дорогому тарифу — зоне 3.

- колонки: `id`, `billable_kg` — оплачиваемый вес, `round(…, 2)`, `cost`;
- порядок: по `id`.

Что проверяют скрытые данные: объёмный вес с дробной частью, вес ровно
1 кг, посылки без веса, без габаритов и без зоны.

<Reveal>

```sql
SELECT p.id,
       round(b.kg, 2)                                   AS billable_kg,
       t.base + t.per_kg * ceil(greatest(b.kg - 1, 0))  AS cost
FROM parcels p
CROSS JOIN LATERAL (
  SELECT greatest(p.weight_kg, p.length_cm * p.width_cm * p.height_cm / 5000.0) AS kg
) b
JOIN tariffs t ON t.zone = coalesce(p.zone, 3)
WHERE b.kg IS NOT NULL
ORDER BY p.id;
```

Ответ:

```
1 | 0.80 | 300
2 | 1.20 | 350
3 | 2.00 | 530
4 | 6.00 | 550
5 | 1.00 | 300
6 | 3.30 | 960
8 | 12.00 | 1330
```

**Деление целых.** Габариты — `int`, и `30 * 20 * 10 / 5000` — это `1`, а
не `1.2`: оба операнда целые, результат тоже. У посылки 2 объёмный вес
больше фактического, и потерянные 0,2 кг стоят 50 ₽. Достаточно одного
нецелого операнда: `/ 5000.0` или `::numeric`.

**`greatest` в Postgres пропускает `NULL`.** `greatest(NULL, 1.2)` — это
`1.2`, а `NULL` получится, только если все аргументы `NULL`. Поэтому
«фактический или объёмный, что есть» записывается без `coalesce`. Это
особенность Postgres: в MySQL и Oracle `greatest` с `NULL` возвращает
`NULL` — на собеседовании полезно это сказать.

**«Каждый начатый килограмм» — `ceil`, а не деление.** Сверх первого
килограмма — `kg - 1`, для лёгких посылок оно отрицательное, отсюда
`greatest(…, 0)`. `ceil(0.2) = 1`, `ceil(0) = 0` — посылка ровно в 1 кг
платит только `base`.

**`JOIN` с `coalesce` в условии.** Посылка 6 без зоны при обычном
`t.zone = p.zone` просто пропадёт из отчёта: `NULL = 3` не истина. Подмена
в условии соединения решает дело, но такой `JOIN` уже не использует индекс
по `parcels.zone` — на большой таблице лучше чинить данные при записи.

**`LATERAL` — чтобы не повторять выражение.** Оплачиваемый вес нужен
дважды: в выводе и в формуле цены. Подзапрос `CROSS JOIN LATERAL` считает
его один раз и даёт имя; альтернатива — CTE.
