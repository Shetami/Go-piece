Пользователей не удаляют, а помечают: в `deleted_at` пишется момент удаления.
У активных там `NULL`. Рассылка берёт адреса активных этим запросом — и
отправляет ноль писем, хотя активных трое.

В какой строке ошибка?

<Reveal>

**`= NULL` никогда не бывает истиной.** В SQL трёхзначная логика: кроме
`TRUE` и `FALSE` есть `UNKNOWN`. Любое сравнение с `NULL` — `=`, `<>`, `<`, —
даёт `UNKNOWN`, даже `NULL = NULL`. А `WHERE` пропускает только строки, где
условие — строго `TRUE`.

```sql
WHERE deleted_at IS NULL
```

`IS NULL` и `IS NOT NULL` — специальные предикаты, они всегда возвращают
`TRUE` или `FALSE`. Для сравнения двух значений, любое из которых может быть
`NULL`, есть `IS DISTINCT FROM` / `IS NOT DISTINCT FROM`.

**Ошибки Postgres не будет.** Запрос синтаксически правильный и честно
возвращает пустоту — поэтому такой баг живёт в коде долго.

**Что спросят следом.** Как ускорить выборку активных, если удалённых
большинство: частичный индекс `CREATE INDEX ... WHERE deleted_at IS NULL`
— в нём только живые строки.

</Reveal>
