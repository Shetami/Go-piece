К распродаже маркетологи добавили в названия акционных товаров метку
`50%`. Найдите товары для витрины акции:

- в **названии** есть подстрока `50%` — именно цифры `5`, `0` и знак
  процента подряд;
- в описании нет слова «уценка» в любом регистре (уценённые товары идут на
  отдельную витрину). Товары без описания подходят.

Для каждого посчитайте цену по акции — половину `price` с копейками.

- колонки: `id`, `name`, `promo_price` — `round(price / 2, 2)` без потери
  дробной части;
- порядок: по `id`.

<Reveal>

```sql
SELECT id, name, round(price / 2.0, 2) AS promo_price
FROM products
WHERE name LIKE '%50\%%'
  AND (description IS NULL OR description NOT ILIKE '%уценк%')
ORDER BY id;
```

Ответ:

```
1 | Кружка −50% SALE | 499.50
5 | Термос 50% | 1249.50
7 | Сито 50% | 150.50
```

**`%` в шаблоне — это «что угодно».** `LIKE '%50%%'` означает «где-то есть
`50`», и в выдачу попадают «Набор 500 мл» и «Чай 50 пакетиков». Чтобы найти
сам символ, его экранируют: в Postgres обратный слеш — escape-символ
`LIKE` по умолчанию, поэтому `'%50\%%'`. То же с `_` — он означает «любой
один символ». Если шаблон собирается из пользовательского ввода, `%`, `_`
и `\` надо экранировать всегда — иначе поиск «100%» найдёт всё. Можно и
без шаблонов: `strpos(name, '50%') > 0`.

**`NOT ILIKE` по `NULL` — это `NULL`.** У Кружки и Термоса описания нет, и
`description NOT ILIKE …` для них не `true`, а `NULL` — строка выпадает.
Нужно явное `description IS NULL OR …` (или `coalesce(description, '')`).

**Регистр.** «УЦЕНКА» у Чайника `LIKE '%уценк%'` не найдёт. `ILIKE` сравнивает
без регистра, в том числе кириллицу — если база создана с нормальной
локалью. Под `C`-локалью `lower('УЦЕНКА')` может остаться прописным — стоит
знать, где это проверить (`SHOW lc_ctype`).

**Деление целых.** `price` — `int`, и `999 / 2` — это `499`. Для денег
нужно `/ 2.0` (или `price::numeric / 2`), а уже потом `round(…, 2)`:
`round(999 / 2, 2)` честно округлит неправильные `499`.

**Что спросят дальше.** Индекс по `name` для `LIKE '%…%'` не помогает — шаблон
начинается с `%`. Для поиска по подстроке нужен триграммный GIN-индекс
(`pg_trgm`), а метку акции правильнее хранить отдельной колонкой или
таблицей, а не в названии.
