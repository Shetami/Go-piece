Клиенты покупают доступ периодами, которые могут пересекаться: продлили
заранее, получили бонусный месяц поверх годового и т.д. Для отчёта нужны
непрерывные отрезки доступа.

- обе даты периода — включительно;
- периоды склеиваются, если пересекаются **или идут вплотную** (следующий
  начинается на следующий день после конца предыдущего);
- если между периодами есть хотя бы один неоплаченный день — это разные
  отрезки;
- колонки: `customer`, `starts_on`, `ends_on`, `days` (длина отрезка в днях,
  включительно);
- порядок: по `customer`, `starts_on`.

Что проверяют скрытые данные: период, целиком лежащий внутри другого, и
следующий за ним ещё один вложенный; смежные периоды; разрыв ровно в один
день; два периода с одинаковым началом; високосный февраль.

<Reveal>

```sql
WITH ordered AS (
  SELECT customer, starts_on, ends_on,
         max(ends_on) OVER (PARTITION BY customer ORDER BY starts_on, ends_on
                            ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS prev_max_end
  FROM periods
),
flagged AS (
  SELECT *,
         CASE WHEN prev_max_end IS NULL OR starts_on > prev_max_end + 1 THEN 1 ELSE 0 END AS is_start
  FROM ordered
),
grouped AS (
  SELECT *,
         sum(is_start) OVER (PARTITION BY customer ORDER BY starts_on, ends_on
                             ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS grp
  FROM flagged
)
SELECT customer,
       min(starts_on)                    AS starts_on,
       max(ends_on)                      AS ends_on,
       max(ends_on) - min(starts_on) + 1 AS days
FROM grouped
GROUP BY customer, grp
ORDER BY customer, starts_on;
```

Ответ:

```
c1 | 2024-01-01 | 2024-02-29 | 60
c1 | 2024-03-05 | 2024-03-10 | 6
c2 | 2024-01-01 | 2024-06-30 | 182
c2 | 2024-07-02 | 2024-07-10 | 9
c3 | 2024-05-01 | 2024-05-10 | 10
```

**`lag(ends_on)` ломается на вложенных периодах.** У c2 годовой период
(январь–июнь), внутри — 1–10 февраля и 1–5 марта. `lag` для мартовского
периода — 10 февраля, и 1 марта «начинает новый отрезок», хотя доступ
непрерывен с января. Сравнивать нужно с **максимальным концом среди всех
предыдущих** периодов: `max(ends_on) OVER (… ROWS BETWEEN UNBOUNDED
PRECEDING AND 1 PRECEDING)`.

**Рамка, заканчивающаяся на `1 PRECEDING`** — «все строки до текущей, без
неё». Для первой строки рамка пуста, и `max` даёт `NULL` — это начало
первого острова.

**Смежность — `+ 1`.** Для дат `ends_on + 1` — следующий день. Условие
`starts_on > prev_max_end + 1` склеивает январь с февралём, но не 30 июня
с 2 июля.

**Дальше обычная схема островов:** флаг начала → нарастающая сумма → `GROUP
BY` по номеру острова. Порядок строк с одинаковым `starts_on` (c3) на
результат не влияет — нарастающий максимум всё равно покрывает оба периода.

**Что спросят дальше.** В PostgreSQL 14+ есть мультидиапазоны:
`range_agg(daterange(starts_on, ends_on, '[]'))` склеивает пересекающиеся
и смежные диапазоны одной функцией. Но на собеседовании обычно хотят именно
оконное решение.
