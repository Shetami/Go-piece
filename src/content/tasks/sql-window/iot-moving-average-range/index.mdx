Датчики температуры шлют показания несколько раз в день, иногда молчат целые
сутки, иногда присылают `NULL` вместо значения. Для дашборда нужно
сглаживание.

Для каждого устройства и каждого дня, когда от него пришла **хотя бы одна
запись** (даже с `NULL`):

- `daily_avg` — среднее показаний за день, `NULL`-показания не учитываются
  (если за день только `NULL` — `daily_avg` тоже `NULL`);
- `avg_3d` — среднее значений `daily_avg` за этот день и **два предыдущих
  календарных дня**; дни, когда устройство молчало, и дни с `NULL` в окно
  просто не попадают;
- колонки: `device`, `day` (дата), `daily_avg`, `avg_3d` — оба `round(…, 2)`;
- порядок: по `device`, `day`.

Что проверяют скрытые данные: пропущенные дни; день, в котором только
`NULL`; день с одним нормальным и одним `NULL`-показанием.

<Reveal>

```sql
WITH daily AS (
  SELECT device, ts::date AS day, avg(temp) AS daily_avg
  FROM readings
  GROUP BY device, ts::date
)
SELECT device, day,
       round(daily_avg, 2) AS daily_avg,
       round(avg(daily_avg) OVER (
         PARTITION BY device
         ORDER BY day
         RANGE BETWEEN INTERVAL '2 days' PRECEDING AND CURRENT ROW
       ), 2) AS avg_3d
FROM daily
ORDER BY device, day;
```

Ответ:

```
d1 | 2024-06-01 | 21.00 | 21.00
d1 | 2024-06-02 | 24.00 | 22.50
d1 | 2024-06-03 | NULL | 22.50
d1 | 2024-06-05 | 30.00 | 30.00
d1 | 2024-06-06 | 27.00 | 28.50
d2 | 2024-06-01 | 10.00 | 10.00
d2 | 2024-06-04 | 16.00 | 16.00
d2 | 2024-06-05 | 14.00 | 15.00
```

**`ROWS` считает строки, `RANGE` — значения ключа.** `ROWS BETWEEN 2
PRECEDING` берёт две предыдущие *строки*, а они могут быть неделей раньше:
для d1 за 5 июня такое окно захватило бы 2 и 3 июня и дало 27 вместо 30.
`RANGE BETWEEN INTERVAL '2 days' PRECEDING AND CURRENT ROW` берёт строки, у
которых `day` в пределах `[day − 2, day]`, — сколько бы их ни было.

**Сначала агрегат по дню, потом окно.** Окно по сырым показаниям дало бы
вес дню с двумя замерами вдвое больше, чем дню с одним. Условие просит
среднее *дневных* значений.

**`NULL` не надо заменять нулём.** `avg` сам пропускает `NULL` — и в
дневном среднем, и в скользящем. `coalesce(temp, 0)` превратит сбой датчика
в «ноль градусов» и уронит график. День 3 июня остаётся в выдаче с `NULL`, а
в окно 5 июня он ничего не добавляет.

**Альтернатива — `generate_series`** по календарю с `LEFT JOIN` и `ROWS`:
тоже верно, но тогда в отчёте появятся строки за дни без записей, а условие
их не просит.

**Что спросят дальше.** `RANGE` с интервалом требует ровно одну колонку в
`ORDER BY` и тип, для которого определено `ключ − интервал` (даты, числа,
timestamp). На больших данных такие сглаживания обычно считают в TSDB или
заранее агрегируют в витрину по дням.

</Reveal>
