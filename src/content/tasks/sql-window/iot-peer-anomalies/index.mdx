В каждой комнате несколько датчиков температуры, опрашиваются синхронно.
Датчик считается аномальным в момент `ts`, если его показание отличается от
**среднего по остальным датчикам** той же комнаты в тот же момент на **5
градусов и больше**.

- `NULL`-показания в среднем не участвуют и сами аномалией не бывают;
- если других показаний нет (датчик в комнате один или остальные `NULL`) —
  сравнивать не с чем, аномалии нет;
- колонки: `room`, `sensor`, `ts` (`'HH24:MI'`), `temp`, `others_avg`
  (`round(…, 2)`);
- порядок: по `room`, `ts`, `sensor`.

Что проверяют скрытые данные: выброс, который сам тянет общее среднее к
себе; `NULL` у одного из датчиков; комната с одним датчиком.

<Reveal>

```sql
WITH compared AS (
  SELECT room, sensor, ts, temp,
         avg(temp) OVER (
           PARTITION BY room, ts
           ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
           EXCLUDE CURRENT ROW
         ) AS others_avg
  FROM readings
)
SELECT room, sensor, to_char(ts, 'HH24:MI') AS ts, temp,
       round(others_avg, 2) AS others_avg
FROM compared
WHERE abs(temp - others_avg) >= 5
ORDER BY room, compared.ts, sensor;
```

Ответ:

```
lab | s3 | 10:00 | 30.00 | 21.33
lab | s3 | 10:05 | 27.00 | 21.50
lab | s3 | 10:10 | 28.00 | 22.00
lab | s1 | 10:15 | 15.00 | 21.67
```

**Среднее с самим собой прячет выброс.** В 10:05 s3 показывает 27, соседи —
21 и 22. Среднее по всем трём — 23.33, отклонение 3.67: «норма». Среднее по
соседям — 21.5, отклонение 5.5: аномалия. Выброс всегда тянет общее среднее
к себе.

**`EXCLUDE CURRENT ROW` — исключение из рамки.** Рамка «весь раздел»
(`ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`) минус текущая
строка. Бывают ещё `EXCLUDE GROUP` (текущая строка и её пиры по `ORDER BY`)
и `EXCLUDE TIES` (только пиры). Без `EXCLUDE` пришлось бы писать `(sum − temp)
/ (count − 1)` и отдельно разбирать `NULL`.

**`NULL` работают сами.** `avg` пропускает `NULL`; если в рамке остались
одни `NULL` — результат `NULL`, и `abs(temp − NULL) >= 5` — не истина. Так
комната hall отсеивается без специальных условий. `coalesce(temp, 0)`,
наоборот, сделал бы «нулевой» датчик соседом и сломал среднее.

**Оконную функцию нельзя поставить в `WHERE`** — окна считаются после фильтрации, отсюда CTE.

**Что спросят дальше.** Как сравнивать с медианой соседей (устойчивее к
двум выбросам сразу — оконного `percentile_cont` в PostgreSQL нет, нужен
`JOIN LATERAL` или агрегат по группе) и как быть, если датчики опрашиваются
не синхронно (окно `RANGE` по времени вместо раздела по `ts`).
