Для каждой трансляции найдите пик одновременных зрителей и первый момент,
когда он был достигнут.

- зритель смотрит в полуинтервале `[started_at, ended_at)`: вышедший в
  момент T и зашедший в момент T **одновременно не смотрят**;
- `ended_at IS NULL` — сессия не закрылась, зритель смотрел до конца
  трансляции (`streams.ended_at`);
- `peak_at` — самый ранний момент, когда зрителей стало столько, сколько в
  пике;
- в отчёте все трансляции; без зрителей — `peak = 0`, `peak_at = NULL`;
- колонки: `title`, `peak`, `peak_at` (`'HH24:MI'`);
- порядок: по `title`.

Что проверяют скрытые данные: вход и выход в одну минуту; незакрытые
сессии; пик, повторившийся позже; трансляция без зрителей.

<Reveal>

```sql
WITH events AS (
  SELECT stream_id, started_at AS ts, 1 AS delta FROM views
  UNION ALL
  SELECT v.stream_id, coalesce(v.ended_at, s.ended_at), -1
  FROM views v
  JOIN streams s ON s.id = v.stream_id
),
running AS (
  SELECT stream_id, ts,
         sum(delta) OVER (PARTITION BY stream_id ORDER BY ts, delta
                          ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS online
  FROM events
),
peaks AS (
  SELECT stream_id, online, ts,
         row_number() OVER (PARTITION BY stream_id ORDER BY online DESC, ts) AS rn
  FROM running
)
SELECT s.title,
       coalesce(p.online, 0)      AS peak,
       to_char(p.ts, 'HH24:MI')   AS peak_at
FROM streams s
LEFT JOIN peaks p ON p.stream_id = s.id AND p.rn = 1
ORDER BY s.title;
```

Ответ:

```
Разбор | 2 | 18:15
Тест | 0 | NULL
Финал | 3 | 20:20
```

**Приём «линия событий».** Каждый просмотр — два события: `+1` в момент
входа и `−1` в момент выхода. Нарастающая сумма по времени — число зрителей
после каждого события; её максимум — пик.

**Порядок на одинаковом времени решает ответ.** В 20:30 зритель 101 вышел,
а 103 зашёл. Если сначала обработать вход, сумма на мгновение станет 4 —
несуществующий пик. `ORDER BY ts, delta` ставит `−1` раньше `+1`, и выход
учитывается первым — это и есть полуинтервал из условия.

**Другой корректный вариант — `RANGE` по одному `ts`.** Если сортировать
только по времени без `ROWS`, все события одного момента станут пирами и
получат общую сумму — число зрителей *после* всех входов и выходов этого
момента. Ложного пика тоже не будет. Ошибка — смешать подходы: `ROWS` с
порядком, где вход идёт раньше выхода.

**Незакрытая сессия — `coalesce` с концом трансляции.** Если такие события
выкинуть, у «Разбора» пик станет 1: зритель 203 будто бы и не приходил.

**Первый момент пика — `row_number` по `online DESC, ts`.** У «Финала» пик
3 был и в 20:20, и в 21:30; нужен ранний.
