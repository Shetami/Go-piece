# Go-piece

Понятные лекции по технологиям с интерактивными стендами и задачами по Go. Курсы: рантайм Go — планировщик (G, M, P), сборщик мусора, память и каналы; паттерны конкурентности — владение горутинами, конвейеры и fan-out, пулы воркеров, общее состояние, время и таймауты, координация и остановка сервиса; брокеры сообщений — Kafka от `send()` до коммита оффсета; базы данных — хранение, транзакции и изоляция, PostgreSQL изнутри, индексы на практике, репликация; system design — нагрузка и очереди, балансировка и масштабирование, кэширование, шардирование, устойчивость, согласованность между сервисами; Kubernetes — желаемое состояние и контроллеры, поды, выкатка без простоя, сеть, ресурсы и Go в контейнере, конфигурация и состояние, размещение и масштабирование, отладка. Плюс раздел практики: задачи в форматах собеседования, с редактором Go прямо на странице.

Сайт почти целиком статический: Astro + MDX + React-острова + Tailwind, поиск — Pagefind. Серверных маршрутов ровно три — `/api/run`, `/api/check` и `/api/fmt`; они проксируют песочницу go.dev, потому что компилировать Go в браузере нечем. Всё остальное собирается заранее.

## Запуск

```sh
pnpm install
pnpm dev        # http://localhost:4321
pnpm test       # unit-тесты движка и разборов
pnpm build      # сборка в dist/ + индекс поиска
pnpm preview    # посмотреть собранный сайт (поиск работает только здесь)
pnpm demo skew-and-stealing   # текстовый прогон сценария планировщика
pnpm demo:gc write-barrier    # то же для сборщика мусора
pnpm demo:mem contention      # и для аллокатора
pnpm demo:chan buffer         # и для каналов
pnpm demo:kafka journey 80 1  # и для Kafka; третий аргумент — путь сообщения m1
pnpm demo:txn lost-update isolation=repeatable-read retry=true  # и для транзакций; дальше — правки настроек
pnpm demo:repl failover standbys=any-1  # и для репликации
pnpm demo:load retry-storm cancelOnTimeout=true  # и для сервиса под нагрузкой
pnpm demo:lb black-hole outlier=true    # и для балансировщика
pnpm demo:cache ttl-sync coalesce=true  # и для кэша
pnpm demo:shard add-shard scheme=ring   # и для шардов
pnpm demo:resil cascade timeout=8       # и для сервиса с зависимостью
pnpm demo:saga dual-write publish=outbox  # и для обмена событиями
```

Задачи практики требуют сети: код уезжает на компиляцию в песочницу go.dev. Остальной сайт работает офлайн.

Нужен Node 20+ (в `mise.toml` закреплены Node 24 и pnpm 10).

## Устройство

```
src/

  content/
    lectures/<курс>/<тема>.mdx лекции; id = путь, курс = первый сегмент
    glossary/<id>.mdx          справочник: один термин — один файл
  components/
    content/                   Term, Predict, Callout — доступны в лекциях без import
    stands/gmp/                стенд «Планировщик Go»

      explain/                 разбор событий: текст привязан к ТИПУ события

      GmpStand.astro           обёртка для MDX: подтягивает термины, проверяет сценарий
    stands/gc/                 стенд «Сборщик мусора» — то же устройство
      engine/                  трёхцветная разметка, барьер записи, пейсер, подметание
    stands/mem/                стенд «Память»

    stands/chan/               стенд «Каналы»

    stands/kafka/              стенд «Kafka»

    stands/txn/                стенд «Транзакции»

    stands/shard/              стенд «Шарды»

    stands/resil/              стенд «Устойчивость»
      engine/                  воркеры, занятые ожиданием зависимости, таймауты, предохранитель, переборки, заглушки
    stands/saga/               стенд «Согласованность»
      engine/                  outbox против двух записей, дубли доставки, идемпотентность, сага с компенсациями
    diagrams/kafka/            статичные схемы для лекции (SVG на токенах темы)

      client.ts                обращения к /api/run, /api/check, /api/fmt
      practice.test.ts         проверки целостности задач
      ui/editor.ts             сборка CodeMirror: грамматика Go, тема, выбор строки
      ui/TaskRunner.tsx        остров страницы задачи: вся разница между типами задач
  content/tasks/<тема>/<задача>/  условие, код и скрытые проверки — см. ниже
  lib/playground.ts            клиент песочницы go.dev (только на сервере)
  lib/task-files.ts            starter.go и solution.go — открытая часть задачи
  lib/task-secrets.ts          check.go и expect.txt — ответы, только для /api
  data/courses.ts              курсы и анонсы будущих тем

  pages/api/                   run, check, fmt — единственные несобираемые заранее маршруты

```

Стенды независимы друг от друга: у каждого свой движок, свои разборы и свой остров. Повторяющиеся части UI (лента, перемотка, ручки) дублируются сознательно — так стенд можно менять, не оглядываясь на соседний.

Главное правило — **движок отделён от отрисовки**. `Simulation` прогоняет сценарий по тикам и хранит полный снимок мира на каждом тике. UI только двигает курсор по этой истории. Отсюда пауза, шаг назад, перемотка и ссылка на прогон в адресе. Объяснения привязаны к типам событий, а не к кадрам.

## Как добавить…

**Термин.** Файл `src/content/glossary/<id>.mdx` с полями `title`, `short` (одна строка для подсказки), `category`, `related`. В лекции: `<Term id="<id>" />` или `<Term id="<id>">своя подпись</Term>`. Опечатка в id роняет сборку.

**Лекцию.** Файл `src/content/lectures/<курс>/<тема>.mdx` с `title`, `description`, `order`. В тексте доступны `<Term>`, `<Predict>`, `<Callout>`, `<GmpStand scenario="…" />`, `<GcStand scenario="…" />`, `<MemStand scenario="…" />`, `<ChanStand scenario="…" />`, `<KafkaStand scenario="…" />`, `<TxnStand scenario="…" />`, `<ReplStand scenario="…" />`, `<LoadStand scenario="…" />`, `<LbStand scenario="…" />`, `<CacheStand scenario="…" />`, `<ShardStand scenario="…" />`, `<ResilStand scenario="…" />` и `<SagaStand scenario="…" />`. Страница, навигация, оглавление и список терминов появятся сами. Из `planned` в `src/data/courses.ts` уберите анонс этой темы.

**Сценарий стенда.** Объект сценария в `engine/scenarios.ts` нужного стенда и в массиве `SCENARIOS` / `GC_SCENARIOS` / `MEM_SCENARIOS` / `CHAN_SCENARIOS` / `KAFKA_SCENARIOS` / `TXN_SCENARIOS` / `REPL_SCENARIOS` / `LOAD_SCENARIOS` / `LB_SCENARIOS` / `CACHE_SCENARIOS` / `SHARD_SCENARIOS` / `RESIL_SCENARIOS` / `SAGA_SCENARIOS`. Поле `claim` обязательно: одна мысль, которую сценарий доказывает. Утверждение из `claim` стоит закрепить тестом в `engine.test.ts`.

**Новый тип события.** Добавить в `EventType` (или `GcEventType`, `MemEventType`, `ChanEventType`, `KafkaEventType`, `TxnEventType`, `ReplEventType`, `LoadEventType`, `LbEventType`, `CacheEventType`, `ShardEventType`, `ResilEventType`, `SagaEventType`) и `EVENT_IMPORTANCE`, затем разбор в `explain/events.ts`. Без разбора TypeScript сборку не пропустит, а тест проверит, что термины из разбора есть в справочнике.

**Задачу практики.** Папка `src/content/tasks/<тема>/<задача>/`:

```
index.mdx     условие; всё, что после <Reveal>, — разбор под спойлером
starter.go    что лежит в редакторе при открытии
solution.go   эталон; для kind: fix и implement его показывает кнопка «Решение»
check.go      скрытые тесты — только kind: implement
expect.txt    эталонный вывод — только kind: fix
```

Во фронтматтере обязательны `title`, `description`, `kind` и `topic`; `topic` обязан совпадать с именем папки темы. Допустимые значения `kind`, `topic` и `level` перечислены в `src/data/practice.ts` — там же описано, чем типы задач отличаются:

- `output` — «что выведет программа». Вердикт выносится по **нетронутой** заготовке с сервера, а не по тому, что сейчас в редакторе, иначе ответ можно подогнать.
- `bug` — «найди баг». Отвечают кликом по строке; правильная строка — `bugLine` во фронтматтере, считая с единицы по `starter.go`.
- `fix` — «почини». Запускается код пользователя, вывод сверяется с `expect.txt`.
- `implement` — «реализуй». К коду дописывается `check.go`, недостающие импорты проставляет goimports, всё это уходит как `go test`.

Две вещи, на которых легко обжечься:

- **Тестовый режим песочницы включается только для однофайловой отправки.** Многофайловый txtar компилируется, но всегда запускается как программа. Поэтому `check.go` дописывается к коду пользователя текстом, без своего блока импортов, а `func main` не должен встречаться ни в одном файле задачи `implement`.
- **`check.go` и `expect.txt` — это ответы.** Их читает только `src/lib/task-secrets.ts`, а его имеет право импортировать только маршрут в `src/pages/api/`. Тест `practice.test.ts` за этим следит: стоит острову дотянуться до этого модуля, и ответы окажутся в бандле.

Ожидаемый вывод стоит получить от настоящего Go, а не выписать из головы:

```sh
curl -s -X POST https://go.dev/_/compile -d version=2 -d withVet=true \
  --data-urlencode body@src/content/tasks/<тема>/<задача>/solution.go
```

`pnpm test` проверит, что все файлы на месте, `bugLine` указывает внутрь заготовки, у задачи есть разбор, а термины и лекция из фронтматтера существуют.

## Деплой

Vercel: импортировать репозиторий, настройки подхватятся из `vercel.json`. Каждый push в `main` публикует сайт, каждая ветка получает превью-ссылку.

Если адрес будет не `go-piece.vercel.app`, поправьте `site` в `astro.config.mjs`.

Из-за адаптера сборка кладёт результат не в `dist/`, а в `.vercel/output`: статику в `.vercel/output/static`, три маршрута `/api` — в одну серверную функцию. Поэтому `outputDirectory` в `vercel.json` нет, а Pagefind индексирует именно `.vercel/output/static`. Там же и причина, по которой `pnpm preview` — свой маленький сервер, а не `astro preview`: адаптер собирает раскладку для чужой платформы, запускать её нечем.

Ключей и переменных окружения раздел практики не требует: go.dev/_/compile открыт всем. Ограничения там по IP, и на Vercel этот IP общий для всех посетителей — если раздел когда-нибудь станет популярным, упрётся в 429. Маршруты это переживают: `/api` отвечает «go.dev просит подождать», а не пятисоткой.
